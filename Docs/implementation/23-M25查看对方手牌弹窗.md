# M25 · 查看对方手牌弹窗（雷云 / 狂躁蘑菇的第 2 个 α 效果）

> **性质**：现行实现记录 —— 查看对方手牌（雷云 / 狂躁蘑菇）；牌背翻面；多段节奏浮层的写法（与当前代码一致，可照此改）
> **最后核对**：2026-09-23

日期：2026-09-21。
> 里程碑号说明：`M24` 已用于「基础冷却 + 区域点选 + 卡面统一」。本批顺延为 **M25**。

## 用户口径（原话要点）

1. 弹出一个额外界面，显示对方当前**所有手牌**、**牌背朝上**，供玩家**随机选择**。
2. 参考 `Assets/Art/Reference-2.png` 的弹窗样式（只参考样式）。
3. 牌的数量取决于对方当时手牌数，界面大小**自适应**。
4. 玩家点击其中一张 → 该牌**翻面成正面** → **结算效果** → **界面关闭**。
5. **动画要流畅**。

**这轮不是纯 UI 补丁。** 起始症状是「雷云（`ad`）第 2 个 α 效果未能正常生效」——
排查后确认引擎的 `LookAndCool` 逻辑本身是对的，问题在于它**自动随机选一张**，
玩家既看不到过程、也感觉不到发生过。所以本质是「引擎自动选 → 玩家在牌背里点一张」的
**交互流改造**：`Core/` 也要动（新增一种决策类型）。

## ① 引擎侧：把「自动随机」改成「问一次再结算」

`Core/` 这一轮只加了三个东西，规则口径一个字节没变。

### 新增决策类型 `RequestKind.ChoosePeekCard = 11`

```csharp
/// <summary>查看对方手牌：从对方的牌背里点一张。<b>本拍只认序号，不看内容。</b></summary>
ChoosePeekCard = 11,
```

### `BattleEngine.IssuePeekSelection(EffectDef ef)`

替换掉原先直接 `HandleImmediateStage3(ef)` 的做法。对手没手牌时返回 `false`（退回原来的「无事发生」），
否则按**对手手牌**逐张生成选项：

```csharp
options.Add(new Option {
    Kind   = OptionKind.ChooseCard,
    Seat   = opponent.Seat,
    Card   = opponent.Hand[i],
    Value  = i,                                // 手牌下标，DoPeekSelection 靠它回填 SlotIndex
    Label  = "翻开第 " + (i + 1) + " 张",       // ⚠ 不带牌名
});
```

`MinSelect = 1`、`MaxSelect = 1`、`ContextNoSkip = true` —— 牌背全一样，「放弃」没有意义。

### `BattleEngine.DoPeekSelection(List<Option> picked)`

按 `ef.B`（`LookAtMost` / `LookAtLeast`）判 `Power <= ef.A` / `>= ef.A`，
命中就 `CooldownOps.PutIntoCooldown(opponent, target, cd: Def.Cooldown + ef.C, ...)`。

**引擎不信任上层**：没回填、或回填了一张已经不在对手手牌里的牌，一律安全降级成
「`State.Rng.Next` 随机抽一张」—— 既不卡死对局，也不破坏概率口径。

### `HandRevealedEvent.SlotIndex`

新增 `public int SlotIndex = -1;`（被翻的这张在**拥有者手牌里**的下标）。
UI 靠它确认「翻的正是玩家点的那张」。用下标而不是对象引用 —— 表现层不该为了做一次配对去持有 `CardInstance`。

### AI 侧：盲选要可复现

`SimpleAiAgent` 新增 `BlindPickSeed`（默认 `20260921`）+ 自实现线性同余
（`_blindState = _blindState * 1103515245 + 12345`），**不用 `System.Random`** ——
后者跨运行库/跨版本不一致，会让「同一颗种子跑出不同结果」。
`RuleSelfTest` 的万局循环也相应改成**每颗种子一个 `SimpleAiAgent` 实例**（否则盲选状态每次重建会退化成查表）。

## ③ 表现层：`PeekView` / `PeekCardSlot`（新文件 `Assets/Scripts/Unity/Ui/PeekView.cs`）

### 只有一个 Image 的牌位

`PeekCardSlot` = 一张 `Image`（`Face`）+ 一个结果角标（`Badge` + `Label`）。
翻面靠「**换 sprite + 横向压缩**」，不是正反两张图对叠 —— 对叠在 `scale.x` 掠过 0 的那一帧
会同时看到两面。

用 `IPointerClickHandler` 而不是 `Button`：① 绕开 `Selectable` 的「颜色是替换不是乘算」
（底图会被刷成灰）；② 点完立刻 `raycastTarget = false` 就彻底失效，不依赖 EventSystem 的选中态。

### 三段节奏

| 段 | 触发 | 做什么 |
|---|---|---|
| **点击** | 玩家点牌背 | 同一帧起播前半段（原面 → 侧薄 `0.15s`），**同时**把选项序号抛给上层回填引擎 |
| **翻面** | 引擎的 `HandRevealedEvent` 到达（约下一拍） | 接后半段（侧薄 → 正面 `0.22s`，带回弹），再亮结果角标 |
| **关闭** | 后半段播完 | 停 `1.25s` 让玩家看清 → 淡出 `0.18s` → `SetActive(false)` |

**为什么翻面必须分两段**：正面卡面只有引擎事件才拿得到。等引擎回话（下一拍）才开始动，
手感上就是「点了没反应」。所以前半段跟手起播，后半段由事件接上；
接缝由 `_flipOutDone` 这个状态位兜住（而不是「这是第几次回调」），点得快或回得快都不会截断。

面板的弹出**单独一支补间**（`0.22s`，`OutBack`）—— 它把「结束」接到了翻面状态机上就不能共用：
玩家手快时弹出先结束，会把翻面的前半段误判成已完成。

### 自适应：面板只往纵向长

`Layout(count)`：1–4 张一行、5–8 张两行（上行取多的一张：5→3+2、6→3+3、7→4+3、8→4+4）。
宽度恒为 `PeekPanelWidth = 992`；两行时高度 = `PeekPanelHeightOneRow + PeekCardHeight + PeekRowGap`
（九宫格把那 271 行纯色躯干拉到 551 行，约 ×2.03，肉眼零差别）。

### 「随机查看」不许退化成「定向查看」

`PeekView` **只读 `Option.Index` / `Option.Value`，绝不碰 `Option.Card`**。
一旦拿去取牌名，玩家就能挑走「自己想看的那张」——那是另一张强度完全不同的卡。
这条也写进了 `Decision.cs` 的注释里。

## ④ 节点由 M8 构建器生成（`BattleUiBuilder`）

新增 `BuildPeekLayer` / `BuildPeekSlot`，并把 `"PeekLayer"` 加进 `OwnedNodes`：

```
PeekLayer                (铺满画布 + CanvasGroup，默认 alpha 0 / 不挡射线 / 整块失活)
├── Veil                 (铺满 + PeekVeil，raycastTarget=true ← 唯一挡输入的那层)
└── Panel                (992×447，Sliced，Peek_Panel)
    ├── Title            (420×46，距顶边 4)
    └── Slot0 … Slot7    (186×256，各挂 PeekCardSlot)
        ├── Face         (Image，preserveAspect)
        └── Badge        (无 Sprite 的纯色矩形 + Label)
```

三条必须守住的约定：

1. **必须排在最后一个建。** Canvas 里同层节点的绘制顺序 = 兄弟顺序，最后建 = 画在最上面。
   这块浮层要压住准备标记条（`PreparedAura` 自己还会 `SetAsLastSibling`）、飞牌层与中央提示。
2. **牌位由构建器生成、不手摆。** `Cleanup` 会整棵删掉 `PeekLayer` 再重建 ——
   M21 在 `PreparedAura` 上手摆的 `Slot0…7` 正是这么丢的，且零报错。
3. **初始隐藏写进 Prefab**（结尾 `go.SetActive(false)`），不在 `Awake` 里 `Hide()`。
   「构建器置失活 + 运行时 Show」的组件在 `Awake` 里 `Hide()` 会把本局第一次 Show 一起关回去
   （本工程已在 `DropArrowView` / `PlayedCardView` 上中过两次）。

### `EnsurePeekImporters`

与 `UiKitBuilder.EnsureCardBoxImporters` 同一套理由：`spriteBorder` / `spritePixelsPerUnit`
只活在 `.meta` 里，图一旦被重导就会悄悄丢 —— 丢了的症状是圆角被抻成椭圆，且 **Unity 零警告**。
每次构建对一遍成本几乎为零。顺带补一次 `AssetDatabase.ImportAsset`，
解决「干净检出上第一次跑 M8 取不到 Sprite、面板退化成一块纯白矩形」的问题。

角标底衬**不赋 Sprite**（UGUI 无图时画的就是纯色矩形，形状完全由 RectTransform 决定）——
角标是 186×34 ≈ 5.5:1，拿任何一张无 border 的圆角图去 Simple 拉伸都会把圆角抻成一段弧
（与 M21 `AuraDropHint` 同一条教训）。

## ⑤ `BattleUi` 接线

| 位置 | 做什么 |
|---|---|
| `_peek` 字段 | M8 构建器写入 |
| `Awake` | `_peek.CardPicked += OnPeekCardPicked` |
| `HandleDecision` | `Kind == ChoosePeekCard` → `_peek.Show(snap.Options)`，并让 `_picker.Hide()`（不列「翻开第 N 张」的按钮） |
| `ClassifyOptions` | 这一拍**整体跳过分类**并 `return` |
| `HandleBeat` → `HandlePeekReveal` | `HandRevealedEvent` → `_peek.Reveal(CardSnapshot.From(hr.Card), hr.Cooled, hr.SlotIndex)` |
| `HandleStarted` / `HandleFinished` | `_peek.HideImmediate()`（重开一局 / 终局不许留半透明遮罩） |

### `ClassifyOptions` 为什么要整拍跳过

这一拍选项挂的牌是**对手**手牌（`Option.Card = opponent.Hand[i]`）。
走通用分类会把它们的 uid 当成「玩家的可选牌」塞进 `_handPlayable` ——
眼下靠 uid 不撞才不会误点亮，**太依赖巧合**。这一拍的输入由 `PeekView` 独占，所以一个都不发出去。

### 演出闸门（`BeatHold`）

`HandlePeekReveal` 里 `_pendingHold = Mathf.Max(_pendingHold, UiLayout.PeekBeatHoldSeconds)`，
其中

```csharp
public const float PeekBeatHoldSeconds = PeekResultHoldSeconds + PeekFadeSeconds + 0.1f;   // = 1.53
```

必须把「结果停留 + 淡出结束」整段盖住：淡出没走完就换下一拍的话，下一拍的选项已经亮起、
而界面上还压着一层半透明遮罩 —— 遮罩期间 `blocksRaycasts` 是开着的，**玩家看得见却点不动**。
末尾 `0.1` 是「淡出最后一帧到 `SetActive(false)`」的余量。

这一句特意放在 `HandleBeat` 里 `_stage == null` 空判**之前**：它不只是演出，
还是「接回引擎待决策」的一步，不能因为顶部提示条没接上就一起失效。

## ⑥ 一个把整批代码卡在编译期的坑

`PeekView` 初版把补间写成链式：

```csharp
FadeFor().Setup(0f, 1f, UiLayout.PeekFadeSeconds, UiEaseKind.OutQuad).Play();   // ✗ 编译不过
```

`UiTween.Setup(...)` 的返回类型是 **`void`** —— 不能链 `.Play()`。
报错是 `CS0023: Operator '.' cannot be applied to operand of type 'void'`（5 处）。
全工程只有这个新文件这么写，改成两句即可：

```csharp
TweenCanvasAlpha fadeIn = FadeFor();
fadeIn.Setup(0f, 1f, UiLayout.PeekFadeSeconds, UiEaseKind.OutQuad);
fadeIn.Play();
```

### 附：`_closing` 不只是「已经关过了」

`OnFadeFinished` 靠它区分「这次淡入结束」和「这次淡出结束」：

```csharp
private void OnFadeFinished()
{
    if (!_closing) return;   // 淡入结束 → 什么都不做
    HideImmediate();         // 淡出结束 → 真关掉
}
```

所以在 Play 里为了截图而「临时把 `_closing` 置 true，让 `Hide()` 变成空操作」是**不行的** ——
淡入那支补间（`Show` 里 0.18 s 那支）结束时同样会看到 `_closing == true`，
然后一路 `HideImmediate()` 把浮层直接关掉。
要挂住自动关闭，正确做法是停掉「结果停留」协程（`StopHold()`），别碰 `_closing`。

## ⑦ 进 Play 之后才暴露的三个真缺陷

> 这三个编译期与「构建器跑通」全都看不出来 —— 前两个甚至**零报错**，
> 第三个只在控制台留了几行容易被当成噪音的 Error。它们正是「必须实机跑一遍」的理由。

### ① `PeekCardSlot` 与 `PeekView` 同文件 → 存 Prefab 时脚本引用被丢掉

`PeekCardSlot`（牌位）与 `PeekView`（浮层）一开始写在同一个 `PeekView.cs` 里。
构建器跑得通、字段也写进去了，但 `SaveAsPrefabAssetAndConnect` 存盘时，
**8 个牌位的 `m_Script` 全被写成 `{fileID: 0}`**：

```yaml
--- !u!114 &2225777419656815112
MonoBehaviour:
  m_GameObject: {fileID: 5553245661040751876}
  m_Script: {fileID: 0}          # ← 脚本没了，字段还在
  _face: {fileID: 5623277271821814167}
```

重开工程/进 Play 就是 8 条 `The referenced script (Unknown) on this Behaviour is missing!`
加一条 `Scripted Object has unknown format!`（后面还跟着 Unity 打的字段布局）。
**症状是牌位全部变成「空脚本组件」**：`Clicked` 事件、`Face`/`Badge` 访问器全没了。

**原因**：Unity 只认**与文件同名**的那个 MonoBehaviour 能挂到 GameObject 上 ——
`MonoScript` 与类的对应关系靠文件名，同文件里的其它 MonoBehaviour 存进 Prefab 会丢脚本引用。

**修法**：拆成 `Assets/Scripts/Unity/Ui/PeekCardSlot.cs`（文件名 = 类名）。

> **同类隐患**：`CooldownView.cs` 里有第二个 MonoBehaviour `ZoneClickCatcher`。
> 它至今没出事，只因为它**只在运行期 `AddComponent`**、从不进 Prefab
> —— 一旦哪天有个构建器把它写进 Prefab，就会以完全相同的方式炸掉。
> **规则：要进 Prefab 的 MonoBehaviour = 一个文件一个、文件名与类名一致。**

### ② `PeekTitleTop = 4` 把标题摆到了面板外面

第一版截出来标题是**飘在弹窗上方**的（悬空压在背景上）。

原因是我把「牌位中心」当成了「文字框顶边距」。量一下原图就清楚了
（`Peek_Panel.png` 的逐行不透明像素剖面）：

| 行范围 | 不透明像素数 | 是什么 |
|---|---|---|
| 0…44 | 2 → 129 | 牌位的**尖顶**（只有中间一小条） |
| 45…78 | 330 → 461 | 牌位的**横 band**（中心 ≈ 61） |
| 80…127 | 938 → 991 | 面板外框顶边 |
| 128…446 | 991+ | 纯色躯干（可无损纵向拉伸的那段） |

所以文字中心该落在 **61**，即 `PeekTitleTop = 38`（`38 + 46/2 = 61`）。
⚠ 这也解释了九宫格上边界为什么是 128：正好卡在「牌位 + 外框顶边」之后。

### ③ 牌背取不到图 → 8 个牌位全刷成灰方块

`PeekView.ResetSlots` 取牌背走的是 `BattleArtLibrary.Instance.PeekCardBack`，
而那本库由 `ArtImportBuilder.RunAll()` 生成 —— 新素材 14:59 才切出来，
库资产还停在 09:23，`_peekCardBack` 是空的。于是：
`sprite = null` + `color = UiTheme.MiniCardFace` → **八个灰色方块，零报错**。

两处都补：

1. **补跑建库流程**：反射调 `ArtImportBuilder.RunAll()`（菜单入口带 `DisplayDialog`，
   MCP 触发会挂住主线程），5 张 `Peek_*` 进库，`_peekCardBack` 指向 `Peek_CardBack.png` 的 guid。
2. **加兜底**（`PeekView._cardBackFallback`）：构建器在构建期直接从 `AssetDatabase`
   取一份 `Peek_CardBack.png` 写进 prefab，库还没建到这一批时用它顶上。
   这样视图不再依赖「建库与建界面的先后顺序」—— 而这个顺序在本工程里本来就不固定
   （M7 推倒重建 Canvas、M8 接线、整理菜单随时可能被单独跑）。
