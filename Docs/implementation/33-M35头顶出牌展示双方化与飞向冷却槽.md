## 1. 交付

| # | 用户口径 | 落地 |

## 2. 为什么这么改

### 2.1 「玩家不需要看自己打了什么」这个前提被推翻了

M13/M20 的口径是「对手头顶的出牌展示只给 AI 座位」，理由是玩家自己点出去的牌当然知道是什么。
用户实测后否掉了它，而且理由很硬：**光环加值 / 双发之后的牌，数值与手牌上看到的并不一样**
—— 玩家恰恰需要在这一刻从头顶确认「我这一刀实际打出去的是哪张、多大」。

### 2.2 旧口径里有两个写死的时长，都被同一件事替掉

- **怪物进攻牌**：常驻到「玩家把这一刀挡下 / 掉血」（`DefenseResolvedEvent` 里显式 `Hide()`）。
- **怪物防御牌**：固定停 `PlayedCardDefenseHold = 2s` 再淡出，并把这段时长报给
  `BattleDriver.BeatHold` 当节拍闸门。

用户口径 2 把这两个都收了：**离场时机只有一个 —— 它进冷却区了没有。**

这条判据之所以成立，靠的是引擎的既有事实：

```
BattleEngine.DoStage4()
    ├─ PutIntoCooldown(_atk.Card, …)          ← 本次进攻牌
    ├─ PutIntoCooldown(_defenseCards[i], …)   ← 本次防御牌（可能两张 / 可能为空）
    └─ FlushCooldown()                        ← 一起发出
```

**两张牌是同一批进冷却的**，所以「一方进攻牌入冷却 = 另一方防御牌入冷却」这条用户口径
不需要任何额外协调 —— UI 只要照着快照走，就已经是同时的。

## 3. 设计细节

### 3.1 判据：快照里出现了没有

```
BattleUi.RefreshAll()
    ├─ _transit.CaptureBeforeBind(hand, playerCooling, enemyCooling)   ← 记「旧位置」
    ├─ CollectHand / CollectCooling ×2                                 ← 取「新快照」
    ├─ Bind 各视图
    ├─ BindArtLayer()
    ├─ DetectPlayedDepartures()      ★ M35：头顶该飞走的 → 登记飞行起点 + 撤下
    └─ _transit.AnimateAfterBind(hand, playerCooling, enemyCooling)    ← 消费起点、生成飞行卡
```

`DetectPlayedDepartures` 遍历两侧冷却快照，凡是 uid 还在 `_onHead`（在册名单）里的：

1. **先** `_transit.PrimePlayedOrigin(uid, 头顶那张卡的矩形)`
2. **再** `HideFaces([uid])` 把它从头顶撤下

⚠ **顺序不能反**：撤下会把卡位失活，之后就再也读不到那块矩形，飞行起点会退化成零尺寸。

### 3.2 在册名单为什么是 `Dictionary<uid, seat>` 而不是「每侧几张」

同一次双发的两张牌是**各自独立离场**的，而两侧的牌又会**在同一帧**触发离场。
按 uid 记账是唯一能同时表达「哪张、属于谁」的形式。`PlayedCardView` 那边配套地按**卡位**存
`_faceUid`（空位填 -1）—— 详见 §4.1。

### 3.3 节点结构（新增的部分）

```
ArtLayer
├─ Bg_Dungeon / Char_Hero / Char_Monster / Orb / 两侧冷却列 / Hud
├─ PlayedCard_Hero        ← M35 新增（锚点 y 与怪物侧同高：902）
│  ├─ Backdrop / Edge
│  └─ Card1 / Card2       ← 运行时由 PlayedCardView.Layout(count) 摆
├─ PlayedCard_Monster     ← M13/M20 既有
└─ HudBuff / HandCount_Monster
```

### 3.5 起飞路径由谁决定

`CardTransitView.DepartCooling` 里，冷却区「新面孔」的起点优先级：

1. `_playedOrigins[uid]` —— **头顶**（刚打出的牌，M35 新增，最高优先）
2. `_coolingOrigins[seat][uid]` —— **手牌**（效果直接送进冷却，如雷云「送入冷却」）
3. 都没有 → 不做动画，直接出现在冷却槽

## 4. 踩坑

### 4.1 ⚠ `PlayedCardView` 的 uid 账必须按「卡位」存，不能按「列表下标」

第一版写的是 `List<int> _shownUids` + 下标即卡位。双发一次交两张，第一张先撤下之后
列表缩短一位 —— 第二张的下标与卡位**错开**，`TryGetFaceRect` 会去问一个已经失活的卡位、
恒返回 `false`。表现是「第一张飞走了、第二张永远留在头顶」。
改成 `int[] _faceUid`（长度 = 卡位数、空位 −1）之后两个卡位互不影响。

### 4.2 ⚠⚠ 冷却区查询曾经硬编码玩家座位（**M35 才暴露的既有盲区**）

`CardTransitView.Find(uid, hand)` 里那一句是：

```csharp
return hand ? _hand.FindCard(uid)
            : _cooldown.FindCard(BattleState.SeatPlayer, uid);   // ← 永远是玩家侧
```

M12 写它的时候只有玩家的牌会走「手牌 → 冷却」这条动画路径，写死座位看不出问题。
M35 让**怪物的牌也走这条路**，于是：`Launch` 里 `Find` 恒返回 null → 飞行卡被静默跳过，
而 `_playedOrigins` 里那条**已经 Remove 了**，谁也不知道它没飞成。

**判据**（实测）：采样 `_playedOrigins` 的条数 —— 修复前会**只增不减**地留下怪物侧的条目，
修复后归零。所以这一批把 `_coolingOrigins` / `_previousCooling` 都改成了**按座位的数组**，
`Flight` 也加上了 `Seat`。

> 教训：**凡是「按 uid 在某个视图里查实体的卡」的地方，座位必须是显式参数。**
> 写死某一侧在那个功能只有一侧时不会报错，等另一侧接进来就是零报错的功能缺失。

### 4.3 ⚠ `HashSet<T>` 不实现非泛型 `ICollection`（反射探针的坑）

在 `execute_code` 里做反射探针时：

```csharp
var ic = (System.Collections.ICollection)hashSet;   // ← InvalidCastException
```

`HashSet<T>` 实现的是 `ICollection<T>` / `IEnumerable` / `IReadOnlyCollection<T>`，
**不是**非泛型的 `System.Collections.ICollection`。`Dictionary<,>` / `List<T>` 都实现它，
所以「有的集合能转、有的不能」，很容易误判成别的问题。
取值一律走 `obj.GetType().GetProperty("Count").GetValue(obj, null)`。

### 4.4 ⚠ `CardView.HasCard` / `Card` 是**属性**不是字段（M32 的老坑又踩一次）

反射探针里 `GetField("HasCard")` 返回 null → 下一句 `.GetValue()` 抛 `NullReferenceException`，
而 `execute_code` 只给 IL 偏移、**没有行号**。
稳妥做法仍然是：拿完每个 `MemberInfo` 先打一遍「是不是 null」，再往下走。

### 4.5 `DecisionSnapshot` 是 struct，`== null` 编不过

`if (drv.Pending == null)` → `CS0019`。driver 待决策为空时 `Pending` 是
`default(DecisionSnapshot)`，于是 `Kind` 读出来是 **`RequestKind` 的 0 值**
（正好是 `ChooseAttackCard`）。探针脚本里看到 `pending=ChooseAttackCard@0` 并**不代表**
真的在等玩家 —— 它可能只是默认值。判断「有没有在等玩家」要看 `BattleDriver._waitingPlayer`。

## 6. 还没做的 / 已知退化

- **同侧连击覆盖**：一回合内同一侧连打两张（连击）时，第二张会整体覆盖头顶面板，
  第一张的 uid 从在册名单里被划掉 → 它进冷却时**不走飞行动画**（直接出现在冷却槽）。
  属于可接受的退化，已在 `ShowOnHead` 的注释里写明。
- **超过两张**：面板只有两个卡位（规则上防御双发最多两张，进攻一张）。
- **玩家侧头顶牌与中央信息条的相对高度**只在下沿贴了一下，没有留净空；
  如果后续要把 `PlayedCardAboveBadge` 调小，玩家侧会先撞上 `PlayerBar`。
- **`PlayedCardDefenseHold` 已成为废常量**（保留定义只为不让旧文档的引用变悬空）。
  顶栏的「节拍闸门」现在只有查看对方手牌那一个使用者。
