## ① 取消使用光环：从「瞬间复位」改成「自己走回去」

### 改之前到底发生了什么

取消的入口是「再拖一下那枚标记」（M21 口径）：`AuraIconView.OnBeginDrag` →
`PreparedAuraView.OnAuraDragBegin` → 发 `Cancelled` → `BattleUi.OnPreparedAuraCancelled`。
老实现里那条链只有**两个瞬间动作**：

1. `RefreshPreparedMarkers()` → `_preparedBar.Bind(...)`：多出来的那枚标记被
   `Release()`（`SetActive(false)`）—— **左侧当场消失**；
2. HudBuff 里那枚原图标在下一次 `Bind` 时重新建出来 —— **原位当场出现**。

也就是用户看到的「立即消失、然后回到原位」，中间没有任何过渡。

### 现在做了什么

**这一枚标记自己滑回它的默认位，落地那一刻图标才在原位显出来。**

| 位置 | 改动 |
|---|---|
| `UiLayout` | 新增 `AuraReturnSeconds = 0.30f`（飞回时长）、`AuraReflowSeconds = 0.16f`（其余标记补位） |
| `AuraIconView` | 飞行状态机加了「两端缩放」与「落地回调」：`FlyIn` 仍是 `0.55 → 1`（OutBack，飞入的读感），新增 `GlideTo(...)` = **缩放恒 1** 的纯位移（OutCubic），落地后回调一次 |
| `PreparedAuraView` | 新增 `FlyHome(key, target, duration)`：把那一枚从 `_shown` 摘下、其余几枚**先记旧世界坐标再重排**、然后让它们滑到新槽位（`AuraReflowSeconds`）；被取消的那枚 `GlideTo(要回的槽位)`，落地收回池子并发 `ReturnLanded(key)`；另加 `AbandonReturns()`（换局 / 决策结束时放弃在飞的标记，见下） |
| `HudBuffView` | 新增 `PlayerSlotAt(index)`（给「回哪一格」量落点） |
| `BattleUi` | 新增 `_returningKeys`（正在飞回的那些指示物的键）；取消时先算 **`HomeSlotFor`（回默认位后占第几格）**，再让它在「HudBuff 里继续隐着」的前提下起飞；落地事件 `OnPreparedAuraReturnLanded` 把键摘掉并刷新，图标才在原位出现 |

### 三个不显然但必须这么写的地方

1. **「回哪一格」必须按取消之后的可见序列算**：HudBuff 的图标是按
   `_playerAuras` 顺序**一格发一个**、被隐起来的**不占格**（`Collect` 第 3 步）。
   所以 `HomeSlotFor` 数的是「前面有几枚**没被隐起来**的」，而不是数组下标 ——
   否则它会飞到旁边那一枚身上。
2. **落地之前 HudBuff 里那枚必须继续隐着**：`_hidden` 这份名单现在 = `_preparedKeys` +
   `_returningKeys`（`BattleUi.HiddenAuraKeys()`）。少算后者就会出现
   「图标已经回到原位」+「标记还在往那儿飞」**两份同时在屏幕上**。
3. **必须有一条「打断也要收尾」的路**：`AuraIconView.CancelFly()` 会丢掉落地回调
   （被 `ResetState` 打断时只能这样），所以 0.3 s 的飞行窗口里正好换局 / 决策结束时，
   那枚图标就再也没人收了 → `PreparedAuraView.AbandonReturns()`。
   `Clear()` 现在 = `AbandonReturns()` + `Bind(null)`。

### 视觉上为什么接得住

飞回的那枚标记与 HudBuff 里那枚原图标**是同一个模板、同一个槽位尺寸、同一个图案与数值**
（都来自 `HudBuffView.IconTemplate`），而且飞回**不做缩放**（两端都是 1）——
所以「落地即换成真图标」这一步在屏幕上是看不出来的，读感就是「它回到了自己的位置」。

截图（`Captures/art-review/`）：

|---|---|
| `m34_aura_01_prepared.png` | 准备态：左侧两枚标记（剑 +1 / 感叹号 ≤3），HudBuff 只剩没准备的那一枚（盾 +2） |

## ② 齿轮点不动：不是被遮挡，是**按钮上根本没有监听器**

### 结论先写

**功能没接上**（不是遮挡）。用户报的现象与排查结果：

| 检查项 | 结果 |
|---|---|
| `ArtLayer/Hud/GearButton` 存在？ | ✅ 在，`interactable = true`，`targetGraphic` 指向自己的 `Image` |
| 被遮挡？ | ❌ **没有**：对着齿轮中心做 `GraphicRaycaster.Raycast`，**只命中 GearButton 一个**（`ResultRoot` / `PeekLayer` 那两层全屏遮罩此刻是关闭的；`PromptBar` 的底图与文字都是 `raycastTarget = false`） |
| 点击区与烘在条上的齿轮对得上？ | ✅ 对得上：`Hud_Bar.png` 里那颗齿轮的亮部包围盒 `x 619…663 / y 24…68`，点击区 `x 617…662 / y 22…67`，中心差 ~1.5 px |
| `HudView._gearButton` 接上了？ | ✅ 非空（`SerializedObject` 写的序列化字段是好的） |
| `HudView.GearClicked` 有人订？ | ✅ `BattleUi.OnAgainClicked` 一个订阅者 |
| **`gear.onClick` 上有监听器？** | ❌ **0 个**（`m_Calls.m_RuntimeCalls` 计数为 0）← 真因 |

### 真因：构建器在**编辑模式**里接的监听器，存盘时会被丢掉

`HudView.SetGear()` 用 `gear.onClick.AddListener(OnGear)` 把「按钮 → 视图」这半条链接上，
而**它的唯一调用者是构建器**（M11 菜单在编辑模式里 `Configure(...)`）。
`UnityEvent` 的**运行时监听器不是序列化数据** —— 存 Prefab / 存场景时直接蒸发。
于是进 Play 之后：按钮在、射线在、引用在、`interactable` 在，**只有 onClick 是空的**，
点下去什么都不会发生，而且**零报错、零警告**。

### 修法

`HudView.Awake()` 里按**序列化字段**自己再接一次：

```csharp
private void Awake()
{
    SetGear(_gearButton);   // 先 Remove 再 Add，幂等，与构建器留下的那份不冲突
}
```

### 这条坑的通用形态（值得记住）

> **凡「把监听器交给构建器去接」的写法都会在存盘时蒸发。**
> 序列化字段才是真值来源，运行时自己接。
> 判据（30 秒）：进 Play 读按钮的 `onClick.m_Calls.m_RuntimeCalls` 数量；
> 或者看 `onClick.GetPersistentEventCount()`（这份是持久监听器，会存盘，但没人用它）。
> ⚠ 本项目其余的按钮都没这个毛病 —— 它们的 `onClick` 是**运行时**在 `BattleUi.Awake`
> 里订视图事件（`_deal.Confirmed`、`_handPick.Confirmed` …），或者走 `IPointerClickHandler`
> （`CardInteractor`、`PressZone`），**不依赖**构建期 `AddListener`。
