## 3. 「已知」情报：判定落点与登记点

### 3.1 为什么判据落在 `BattleUi`

「谁算已知」是一条**情报规则**，但它的判据（打出过 / 看过）散在事件流里，
只有 `BattleUi` 订阅得到。所以：

- `BattleUi` 持有 `HashSet<int> _seenMonsterCards`（键 = `Uid`）
- `MonsterHandView.Bind(hand, known)` **只负责显示**，不订阅事件、不持引擎引用
  —— 与「表现层只读快照」那条铁律一致。

### 3.2 三个登记点

| # | 事件 | 位置 | 条件 |
|---|---|---|---|
| ① | `AttackDeclaredEvent` | `PlayCharacterBeats` | `Seat == SeatAi && Card != null` |
| ② | `DefenseResolvedEvent` | `PlayCharacterBeats` | `DefenderSeat == SeatAi` → 遍历 `dr.Cards` |
| ③ | `HandRevealedEvent` | `HandleBeat` | `OwnerSeat == SeatAi` |

> **⚠ ③ 必须放在 `HandlePeekReveal(e)` 之前**：
> 那个方法开头是 `if (hr == null || _peek == null || !_peek.IsShowing) return;` ——
> **AI 侧翻牌时浮层本来就没开**，会直接早退。情报不能跟着一起丢。

### 3.3 为什么用 `uid` 而不是手牌下标

同一张牌回手后再打出、手牌增删导致下标漂移，**记忆都应当延续**。
`Uid` 是唯一稳定的身份（用户口径：「打出过的 + 看过的」）。

### 3.4 新一局清零

`HandleStarted()` 里 `_seenMonsterCards.Clear()` + `_monsterHandBuf.Clear()` + `HideImmediate()`。
理由：新一局 `uid` 从头分配，留着旧集合只会**误判成已知**。

## 4. `PressHoldButton`：为什么需要四处兜底

```csharp
OnPointerDown  → _held = true, 发 Pressed
OnPointerUp    → Raise()
OnPointerExit  → Raise()            // _releaseOnExit
Update()       → _held && !Input.GetMouseButton(0) → Raise()
OnDisable()    → Raise()
```

`OnPointerUp` **在指针甩出按钮后不送达**（这是 UGUI 的固有行为）。
只挂它的话，玩家「按住 → 手指滑出标签 → 松手」会让面板**永远挂着**。
三处任意一处先到都算结束，`_held` 保证 `Released` 只发一次（幂等）。

`OnDisable` 那一处是给「按着标签时点齿轮重开一局」兜的 —— 否则新一局里
`_held` 还是 true，第一次按下会被吞掉。

`ResetState()` 供外部强制复位（`HandleFinished` 里用）。

## 5. 构建器归属：谁建节点谁挂组件

**这是本轮踩到的一个真坑。**

`PressHoldButton` 一开始我挂在 `BattleUiBuilder` 里。结果：
**跑 M9 挂上 → 再跑 M11，组件静默消失**（零报错）。

原因：`BattleArtLayerBuilder.RunAll()` 会 `DestroyImmediate` 整棵旧 `ArtLayer` 推倒重建，
而 `HandCount_Monster` 在这棵树里 —— 挂在它上面的组件跟着一起没。

**修法**：组件改由 `BattleArtLayerBuilder.BuildHandCount` 挂（谁的节点谁负责，
组件与节点同生命周期）。`BattleUiBuilder` 只保留「捞一把 + 回填 serialized 字段」，
并在捞不到时给一句 warning 提示先跑 M11。

> **一般规律**：跨构建器的组件挂载 = 定时炸弹。
> 只要目标节点归另一条构建链所有，那条链一推倒重建就会静默清掉你的组件。

## 6. 本轮修掉的两个真缺陷

### 6.1 `MonsterHandView.cs` 漏 `using MagicBrawl.Core;`

编译错误 `CS0246: 'CardSnapshot' could not be found`。
`Bind` 的签名用到 `CardSnapshot`，但文件头只有 `System.Collections.Generic / TMPro / UnityEngine / UnityEngine.UI`。
后果很隐蔽：**M11 先保存了 prefab（所以文件变大、看起来"构建成功"），
M9 因为编译不过根本没跑** → `MonsterHandLayer` 不在 prefab 里。

### 6.2 已知/未知被「有没有图」绑架

初版：
```csharp
IsUnknown = face == null;                        // Slot
_active[i].Bind(isKnown ? FaceSpriteFor(...) : null, back);   // View
```
卡面图来自 `CardArtLibrary`（构建器生成）。**库还没这一批素材时 `FaceSpriteFor` 返回 null**
→ 一张**明明看过**的牌被静默画成牌背。

那是**把美术缺料伪装成情报缺失**，玩家会以为自己的记忆不对。
修法：`Button.Bind(bool isKnown, Sprite face, Sprite back)` ——
「知不知道」与「有没有图」分开传；缺图时退化成深色矩形，但仍是「亮着」的那一格。

### 6.3 `Layout` 的槽位复用没重新激活 + 基准用错

```csharp
for (int i = count; i < _slots.Length; i++)   // ← 两个毛病
```

- **用 `count`（手牌总数）当基准**，而不是 `_active.Count`（本轮真正用到的张数）。
  手牌上限 8 时两者恰好相等，但 `count > 槽位数` 时会把**用到的槽也停掉**。
- **更严重**：被停用的槽在下一轮 `Bind` 张数变多时被放进 `_active`，
  却**没人把它 `SetActive(true)`** → 连续 Bind（1 张 → 2 张）时后面那张不显示。

实测证据（修前）：`n=1 active=0` / `n=2 active=0` / `n=3 active=0`（全是 0）。
修后：`n=1 active=0` / `n=2 active=0,1` / `n=8 active=0..7`。
