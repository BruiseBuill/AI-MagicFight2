# 2026-09-26 · 商店场景实施（P4 第一个事件切片）

>
> 前置：[冒险事件架构](../design/冒险事件架构.md)（规则与独立场景契约 E1–E4）、
> [冒险事件架构与商店场景定稿](2026-09-26-冒险事件架构与商店场景定稿.md)（设计定稿，零代码）。

## 背景与目标

设计定稿做完之后，商店要**真的能进 Play 看**：4 个货位摆本作真实卡面、价格、
左上角沿用战斗那套顶栏（生命 / 金币）、进货 / 缺货 / 买不起三种状态都要能演出来。

用户口径（2026-09-26）：

1. 卡片必须是**本作实际的卡**，不是参考图里那个游戏的卡；
2. 左上角金钱 / 生命**参考战斗场景的 reference**；
3. 美术已放进 `Art/`（参考图 + 成品背景 + UI 套件）。

**本次不做**：地图层、真实存档读写、删牌 / 强化服务、`AdventureCommand` 落地
（`ShopSceneEntry` 里那段扣钱是**调试实现**，见 §7）。

## 方案与影响

### 1. 场景骨架由构建器生成（幂等）

`Assets/Scripts/Unity/Editor/ShopUiBuilder.cs`（菜单 `魔法乱斗/P4 · 构建 Shop 场景`，
**不带确认弹窗**，可脚本 / MCP 反射调用 `RunAll()`）。

它做四件事：开 / 建 `Assets/Scenes/Shop.unity` → 建唯一的 `ShopCanvas`
（背景 · 顶栏 · 标题 · 货架 · 离开按钮）→ 一次性接好序列化字段 →
存 `Assets/Prefabs/Ui/ShopCanvas.prefab` 与场景。

节点层级（运行时实测）：

```text
ShopCanvas
├─ Bg_Shop                 1936.6×1080（cover 铺法）
├─ Hud                     顶栏：Hud_Bar / Name / Subtitle / HpNumber / ResNumber(=金币)
├─ Title                   「商店」
├─ Shelf                   ← 零尺寸锚点，坐在整排正中
│  └─ ShopSlotTemplate     失活模板（Card / Dim / PricePlate / SoldOut / Hit）
└─ LeaveButton             「离开」
```

另补一台相机（空场景没有）与 `EventSystem`（本工程无 inputsystem，用 `StandaloneInputModule`）。

### 2. 顶栏直接吃战斗那份美术

`Hud_Bar` 取自 `BattleArtLibrary.Instance.HudBar`（战斗美术的唯一取图入口），
文字位置照抄 `UiLayout.Hud*` —— 两条顶栏是**同一张图 + 同一套常量**，
所以拿商店截图和战斗截图对读时数字位置能对得上。

⚠ 但**不挂 `HudView`**：那个类整条逻辑是为战斗写的（`Bind(PlayerSnapshot, …)`
会把 💰 刷成「未用光环数」、还会给能量球做脉冲动画）。商店只需要三行数字，
字段直接接进 `ShopView`。**`ResNumber` 这个节点名因此与语义不符**——
它的**位置**是战斗 💰 那一格，口径改成金币；名字保留是为了两边截图对读时能对上。

### 3. 货位 = ShopSlotView + CardView 子节点

`Assets/Scripts/Unity/Ui/ShopView.cs`（整排 / 资源栏 / 标题 / 离开）
与 `Assets/Scripts/Unity/Ui/ShopSlotView.cs`（单格）。

- **卡面复用唯一那份 `CardView_Hand.prefab`**（红线 9），尺寸由 `SetFaceWidth` 给；
  货位数不预建，运行时按 `UiLayout.ShopSlotCount` 克隆失活模板。
- 一个货位里除卡面之外还有：价格牌、买不起压暗纱、「卖光了」空位、透明命中区。
  这些**不属于卡面**——塞进 `CardView` 会让「卡面」这一件事多出商店专属分支，
  而 `CardView` 是四个界面共用的。
- **点击自己实现 `IPointerClickHandler` 而不用 `Button`**：卡面自带 `Button` +
  `CardInteractor`，叠上去会出两套选中态、一次点击冒泡两遍。构建时把卡面子树里
  的 `Graphic.raycastTarget` / `Button.enabled` / `CardInteractor.enabled` **全部关掉**，
  由货位统一吃点击。
- 监听器一律在运行时按序列化字段自接（红线 8）。

### 4. 版式：对着背景量，cover 公式进 `UiLayout`

`UiLayout` 新增三件套：`ShopBgCoverSize()` / `ShopBgCoverOffset()` / `ShopBgPointToCanvas()`。

关键数字（画布 1920×1080，本机实际屏 2880×1620 → 世界坐标 = 画布 × 1.5）：

| 项 | 值 | 来历 |
|---|---|---|
| cover 显示尺寸 | **1936.6×1080** | 1664×928 等比放大到盖住画布（**放大 1.16379**，裁掉左右各 8.3） |
| 柜台台面 | x 275…1525 · y 410…475 | 在参考图上量出来的 |
| 店主伸出的手 | x ≈1185…1350 | 占住台面右侧，货架不能压过去 |
| 整排中心 | `ShopShelfCenterX = 730` | 可用台面 = 275…1185，中心取 730 |
| 步进 | `ShopSlotSpacing = 196 + 34 = 230` | 4×196 要塞进 910 宽 → 步进 ≤234，取 230（两侧各余 12） |
| 卡面中心 Y | `ShopCardCenterY = 608` | 卡底落在柜面后棱线（475）附近，读作「摆在柜台上」 |
| 价格牌 | 卡中心下移 194 | 牌中心 414，正压在柜面上 |

#### 4.1 · 2026-09-27 调整（用户手调 + 尺寸微调）

用户在编辑器里改了场景，同时提了卡 / 价格牌的尺寸 ——
**四处改动都已写回 `UiLayout` 与构建器源码**，所以「重跑构建器」不会再抹掉它们：

| 项 | 改动 | 落点 |
|---|---|---|
| 货架整排位置 | 用户把场景里的 `Shelf` 右移 246（`x: −230 → 16`，= 画布 976） | `ShopShelfCenterX = 976`。**用户手调，不要改回去** |
| 出售的卡牌 | **+10%**：`196×272 → 215.6×299.2` | `ShopCardWidth/Height = HandCard × 1.1`；**背包里的卡不受影响**（`ShopBagCardFaceWidth` 仍是 196） |
| 价格牌（玩家读作「购买键」） | **−10%**：`236×94 → 212.4×84.6`，价格字号 `40 → 36` | `ShopPricePlateWidth/Height`、`FontSizeShopPrice` |
| 离开按钮 | 底图 `Image.Type` 由 `Sliced` 改成 **`Simple`**；`Label` 下边内收 5（`sizeDelta.y = −5`、`pos.y = +2.5`） | 构建器 `BuildLeaveButton`。**用户手调，不要改回去** |

三条**连带口径**（都不是「顺手改的」，是上面四条逼出来的）：

1. **步进不再跟着卡宽走**：`ShopSlotSpacing` 的基准由 `ShopCardWidth` 改成 `HandCardWidth`
   （仍是 230）。卡放大后若步进跟着长，整排会一口气宽出近 9%、把最右一张推去压店主的手；
   而现在卡视觉宽 215.6 < 230，卡与卡的缝从 34 收到 14.4，依旧不重叠。
2. **价格牌的下移量改成表达式**：`ShopPricePlateDrop = 卡高/2 + 牌高/2 + 11`（现 202.9）。
   卡高与牌高在同一天都变了，原来写死的 194 会让价格牌**被卡面盖住一角**，而且零报错。
3. **命中区向下包到价格牌底边**：`ShopSlotHitWidth/Height/CenterY`（215.6 × 394.8，中心 y = −47.8）。
   价格牌挂在卡面**下方**，原来「一张卡那么大」的命中区**收不到点它的指针** ——
   用户要求的「点购买键与点卡面都能买」就是靠这一条实现的
   （不必给价格牌开 `raycastTarget`，也不必多接一套事件：`Hit` 仍是货位里唯一吃射线的东西）。

⚠ 另外发现并绕开的一处：**构建器在编辑模式里调 `CardView.SetFaceWidth` 写下的
`CardRoot.localScale` 没有跟着嵌套 Prefab 存进 `ShopCanvas.prefab`**（存下来的仍是
`CardView_Hand.prefab` 里那份旧值 0.32）。症状是「改了 `UiLayout` 常量、卡面纹丝不动」
且零报错 —— `ShopSlotView.Bind` 现在**每次都按当前常量重申一次尺寸**，不再信 Prefab 里的烘值。

## 踩坑记录（都是「零报错」那一类，值得单独记）

1. **货位步进被写成 `卡宽 + 步进`** → 整排多算 3 个卡宽，4 张卡落在
   canvas x = −24 / 424 / 872 / 1320，**最左那张一半在屏幕外**，而且不报任何错。
   `ShopSlotSpacing` 的语义是**相邻中心间距（步进）**，`ShopShelfTotalWidth`
   与 `ShopSlotCenterX` 都必须只用它一次。已在常量注释里写死这条。
2. **cover 是「放大」不是「缩小」**：1080/928 = **1.16379**（>1）。
   第一版按 0.7903 算，于是「按背景量的坐标」整排错位。
   `ShopBgPointToCanvas` 第一版也漏了乘缩放——**换算函数必须自己乘**，
   不能指望调用方记得。
3. **Screen Space - Overlay 的 Canvas 不进任何相机的 `targetTexture`**。
   用 `Camera.Render()` → `RenderTexture` → `ReadPixels` 回读，得到的是
   一片纯相机底色（`UiTheme.Backdrop`）——UI 一个像素都没有，且不报错。
   正确做法是走 `manage_camera{action:'screenshot'}`（**不传 `camera`**，
   它默认用 ScreenCapture API，能抓到 Overlay UI），并且**必须在 Play 且帧在推进时**抓。
   本轮还踩了一次：`isPlaying=False` 时抓到的仍是空帧，先确认
   `UnityEditor.EditorApplication.isPlaying` 再截。
4. **`RoundedRectangle.png` 的 `spriteBorder` 是 0**，而且它被战斗的光环图标
   （`BattleArtLayerBuilder.BuildAuraIcon`）以 Sliced 引用着——
   **不能改它的 meta** 去让「卖光了」底板能九宫格。改用 `Image.Type.Simple`
   拿一个接近 1:1 的矩形去拉伸，圆角只被压一点点。
5. **空位不能只有一行灰字**：空槽背后是商店的浅色木质内景，灰字浮上去几乎读不清。
   改成「比卡面小一圈的暗色圆角剪影 + 居中文字」，文字立住了，
   整排节奏也不塌（与左右卡面同宽同高）。
