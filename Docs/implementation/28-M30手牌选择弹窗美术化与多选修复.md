## 1. 用户口径（原文逐条）

1. 「对于可以选择多个的效果（磁暴，充能），则玩家选择多个手牌之后，都可以加入到此框中
   （因此这个界面的大小需要可变……**目前这个效果未能实现好，导致只能选择一张**）」
2. 「对于必须要选择一个的效果（电弧），则在玩家填入手牌之前**确认键不得亮起**。
   玩家放入一个之后就亮起，但是**不能放入多个**。」
3. 「页面的标题**不应当使用法术（卡）的名称**来命名，而应当用**效果**（改简洁一些）来命名。」
4. 「**确认图标应当用素材当中提供的图标**，而不应当用自己放一个灰蓝色的方块。」
5. 追加：「素材 148cae8c-…，661ca76a-…。ae67a6sgshbf-… **是目标界面**（还没有选择卡的情况时）」
6. 追加：「电弧/磁暴/充能：送入冷却/送入冷却增加力量/送入冷却获得加速；
   **磁暴的选择界面需要在对方防御之前**（因为防御之前必须先知道有多少点力量）」

## 2. 改动清单

### 2.1 引擎（`Core/`）—— 这是「只能选一张」的真根因

**`BattleEngine.IssueCoolHandSelection`**（约 1060–1150 行）

```csharp
// 修前（错）：
MaxSelect = ef.Op == EffectOp.CoolHandForAtk ? options.Count : Math.Max(1, ef.A),
```

`ef.A` 是「**每冷却一张的收益**」（磁暴 A=3 → 每张 +3 力量；充能 A=1 → 每张 1 次加速），
不是「张数上限」。把它当上限 → 充能（A=1）永远只能选 1 张，点第二张毫无反应
（**用户报的正是这条**）；磁暴（A=3）因 A ≥ 3 侥幸看不出问题。

```csharp
// 修后：
bool single = ef.Op == EffectOp.CoolHandForCombo;   // 只有电弧是「恰好 1 张」
...
MinSelect = single ? 1 : 0,
MaxSelect = single ? 1 : options.Count,   // 多选 = 候选数
```

同时补上 `Title`（**效果**命名，见 2.3）。

**⚠ 这条修复有回归断言钉着**（`Tools/RuleSelfTest/CoolHandScenario.cs`）：
`MaxSelect` 必须等于候选数（磁暴/充能）或 1（电弧）。断言经「临时把缺陷写回去」验证过
—— 它会报 `[FAIL]`。

### 2.2 确认键底图换成素材（用户口径 4）

- 新素材 `Assets/Art/Ui/HandPick_Confirm.png`（626×174），由
  `Tools/art-audit/slice_handpick_kit.py` 从 `Art/148cae8c-….png` 底部那条切出。
- `BattleUiBuilder.BuildHandPickLayer`：`Image.sprite` 从「纯色方块」改为该 Sprite +

| `HandPickConfirmBorderX` | 96 | 素材两端造型宽（量图：躯干从 x≈98 起） |

### 2.3 标题改成「效果」（用户口径 3 + 6）

引擎给标题（UI 不猜是哪张牌在结算）：

| 效果 | 卡 | 标题 | Min/Max |
|---|---|---|---|
| `CoolHandForAtk` | 磁暴 | `冷却·加力量` | 0 / 候选数 |
| `CoolHandForHaste` | 充能 | `冷却·获加速` | 0 / 候选数 |
| `CoolHandForCombo` | 电弧 | `冷却·换连击` | 1 / 1 |

能多选时后缀 `（可多选）`；只在**真能多选**时加（手牌只剩 1 张时不加，否则玩家以为界面坏了）。

**⚠ 有长度预算**：短标题要落在 `Peek_Frame` 顶部 title band 的**平直段**里。
量图：`y=58` 那一行暗色内槽 x ≈ 83…340 → **宽 257**。
所以标题口径是「4 字效果 + 最多 3 字后缀」，`UiLayout.HandPickTitleWidth = 257`，
字数上限由 `CoolHandScenario` 断言钉住（≤ 11 字）。

`DecisionSnapshot.Title` / `DecisionRequest.Title` 的注释同步更新（写「效果」不写「卡名」）。

### 2.4 磁暴在防御之前（用户口径 6）

**引擎本来就对**：`AttackContext.EffectStage` 把 `CoolHandForAtk` 归在 `Stage1Power`，
跑在防御结算之前 —— 防御方要拿这个力量去比。本轮只把「必须在防御前」这件事
写进 `IssueCoolHandSelection` 的注释，免得将来有人把这段挪到后面。

## 3. 版式对齐（本轮新发现并修掉的三处）

### 3.1 标题框捅出面板（截图一眼可见）

`HandPickTitleWidth` 原写 470「怕被截成省略号」—— 但**470 &gt; 431（单张态面板宽）**，
标题框左右各捅出 20 px，文字直接压在面板外框上。改为 257（= 原图 band 平直段宽）。

### 3.2 卡框伸出内框

原 `HandPickSlotAreaPadding = 24` 且「卡槽区上限 = 1800（屏幕级）」——
屏幕级上限**比面板能长的宽度还大 = 等于没有约束**。3 张态截图里牌横着捅出内框、
压到面板躯干上。

修正口径（全部量图得来）：

```
面板宽 = 卡槽区宽 + 2 × HandPickPanelSideMargin(112)
卡槽区宽 = N×207 + (N−1)×8 + 2 × HandPickSlotAreaPadding(12)
卡槽区上限 = 8×207 + 7×8 + 2×12 = 1736   （8 = 手牌上限）
面板上限   = 1736 + 224 = 1960
```

> ⚠ 上限必须用**常量表达式**写，不能让「卡槽区上限 ↔ 面板上限」互相引用
> （属性取值器在静态初始化顺序上不可靠，会绕成死循环）。

逐张验证（`n=1` 例外：单张就是内框的设计尺寸）：

| N | 卡槽区 | 面板 | 内框可用宽 | 牌跨度 | 放得下 |
|---|---|---|---|---|---|
| 2 | 446 | 670 | 426 | 422 | ✅ |
| 3 | 661 | 885 | 641 | 637 | ✅ |
| 8 | 1736 | 1960 | 1716 | 1712 | ✅ |

### 3.3 确认键「双下巴」

换成素材后，它与 `Peek_Frame` **自带的**底部按钮座叠成两个轮廓。
逐行量原图按钮座内槽（431×556 原图）：PNG y ≈ 469…526、x ≈ 85…341
→ Unity 坐标（原点面板中心、y 向上）：

```
y = 556−1−526 … 556−1−469 = 29 … 86      （高 58、中心 57.5）
x = 85…341 − 215.5 = −130.5 … 125.5      （宽 257、中心 −2.5 ≈ 居中）
```

把按钮改成 **258×58、中心 57.5** —— 实测偏差 **±0.5 px**，正好盖住自带的座。
（按钮 pivot 是 `(0.5, 0)`，`Box` 的 offset 已在构建器里减掉一半高，行为正确。）

### 3.4 副标题贴住标题

副标题原来距标题框底边写死 2 px → 标题的降部几乎撞上「0 / 6」。
新增 `HandPickSubTitleGap = 8f`、`HandPickSubTitleHeight = 32f`。

### 3.5 角标变成白方块（借错常量）

`IndexBadge` 的底图颜色借用 `UiTheme.HandPickConfirmOn`；而该常量在换素材时被我
从 `#1D5C8C` 改成了 `Color.white` —— 角标**跟着变成纯白方块**，把每张牌左上角糊掉。

修法：新增**语义独立**的 `UiTheme.HandPickIndexBadge = #1B4A6E`。
**教训：借用一个会随别处口径漂移的常量，是这次翻车的根因。**
