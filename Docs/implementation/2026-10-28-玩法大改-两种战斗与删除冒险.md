# 2026-10-28 · 玩法大改：只剩两种战斗，冒险与强化整套删除

> 状态：变更记录 · 本文为当时实现的快照，旧规则、卡牌及完成状态不代表当前版本。现行内容见 [当前基线](../00-当前基线.md) 与 [规则基线](../rules/01-规则基线.md)。

> 需求（用户原话）：
> 「我现在打算对游戏的玩法进行大改，不再保留任何和冒险强化相关的任何内容，只保留两种战斗玩法。
> ① 标准战斗，玩家和怪物都随机发 8 张牌。
> ② 自定义战斗，在标准战斗的基础上，在战斗开始之前会让玩家可以自定义选择自己的牌组和怪物的牌组。」
>
> 追问确认（同日）：**标准战斗的发牌口径 = 怪物调整成和人类一致**；
> **自定义战斗只挑双方的 8 张**（怪物本体不给玩家选）；**主菜单里和冒险有关的内容都删**；
> **6 个冒险场景与其脚本、构建器彻底删除**。

## 1. 改完之后的游戏

```
Home（主菜单）
 ├── 标准战斗 ──────────────► SampleScene（战斗）
 └── 自定义战斗 ──► DeckSelect（挑双方各 8 张）─► SampleScene
```

- **标准战斗**：进战斗时由**本局种子**从整张卡表里抽两副 8 张（玩家一副 / 怪物一副，互不重叠的概率由座位混种保证）。
- **自定义战斗**：`DeckSelect` 里两边各挑满 8 张 → 点「开战」→ 把两套 ID 交给 `BattleLaunch` → 战斗场景照单组装。
- **8 张牌分三次到手**：**开局 6 张（可换 3 张）**，**第 2、3 回合各补 1 张**（补牌当拍可换 1 张）。
  用掉的进冷却区、冷却完回手。

## 2. 发牌口径（Core）

`Core/Cards/DealProfile.cs` 新增 `Duel()`（**2026-10-28 第二次修正后的最终口径**）：

```csharp
public static DealProfile Duel()
{
    return new DealProfile(
        BattleState.InitialHandSize,        // 6
        BattleState.ReplaceLimitInitial,    // 可换 3
        2,                                  // 从第 2 回合开始补
        BattleState.DrawTurnsMax,           // 补到第 3 回合
        1,                                  // 每回合补 1 张
        1);                                 // 补牌当拍可换 1
}
```

- 数值上等于历史上的 `Human()`，但**语义是「两种玩法统一的那一套」** ——
  以后调节奏只改这里，不要去向 `Monster()`（8 张不补）靠。
- `CharacterDefinition.WithDeal(...)` 是新增的换口径入口。`BattleDriver.BuildSetup` 会把**场上每个角色**都覆盖成 `Duel()` ——
  不去改角色资产，避免「漏改一只怪 → 它开局张数不一样」这种零报错的偏差。

> ⚠ **两轮口径修正**（同一天）：
> ① 最初按字面把「随机发 8 张」实现成「开局一次发满 8 张、不补不换」；
> ② 用户纠正为「**刚开始双方都是 6 张，第 2、3 回合各补一张**」→ 即**牌组 8 张、分三批到手**。
> 现在代码里是 ②。`Monster()`（8 张不补）仍在，但战斗不再用它。

### 12.4 解耦检查结论（没动的地方 + 为什么）

- **Core 仍然零引擎引用**：`noEngineReferences: true`，三个出现「UnityEngine」字样的文件都只是注释。
- **依赖方向没被破坏**：`Core ← App ← App.Editor`，没有反向引用。
- **`BattleLaunch`（静态）不落盘**是对的：它要跨场景，而场景切换会销毁对象；换成 ScriptableObject 反而要处理「谁清它」。
- **`BattleDriver` 仍然是唯一组装点**：牌组来源（自定义 / 按种子随机）都在 `DeckFor` 一处，UI 不参与。
- **没拆 `BattleUi`（3581 行）/ `UiLayout`（2284 行）**：拆分要动 `BattleCanvas.prefab` 的组件挂载与 M7→M8→M11 链路，
  收益（可读性）与风险（重建整个战斗界面）不成比例。真要拆，先写一份「节点归属表」再动。
- **`CharacterConfig.DealPreset` 与 `CardPoolConfig.preferUpgraded` 保留**：前者被 `BuildSetup` 的强制覆盖架空、
  后者已短路，但它们是**资产上的序列化字段** —— 删字段会让老 `.asset` 的反序列化报错，只留注释说明失效。
