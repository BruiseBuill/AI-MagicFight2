## 2. 为什么这么改

### 2.1 全屏闪红把「谁挨打」这件事抹掉了

原来是 `StageView.FlashDamage()`：一块铺满上部的红色 `Image`，`sin` 冲一下 0.30 透明度。
它压在所有界面之上，**玩家掉血和 AI 掉血看到的画面一模一样**，而且盖住的正是真正的信息载体 ——
挨打那个角色自己的动作。删除后受击反馈只剩一条：`DamageTakenEvent → PlayPose(BeHit)`，
败方 `GameOverEvent → PlayPoseHold(Death)`（玩家有 behit / death 素材，怪物暂时只有待机 / 攻击 / 防御，
空 clip 会安静退回待机，不会卡住 —— 见 13 号文 §6）。

### 2.2 AI 的区域类打分被「张数」盖过

旧打分是 `张数 × 2 + (有利 ? 1 : 0)`。那 1 分的立场加权**必然被 2 倍张数淹没**：
对面 3 张的档（6 分）压过自己 2 张的档（5 分），AI 会把「区域加速」放给对手。
用户口径是「加速一律给自己、减速一律给对方」，所以改成**先按立场过滤、再在有利档里比密度**；
一张都不占优就放弃（宁可不做，也不做资敌的那一步）。

同一个毛病还藏在 `ChooseRefreshTarget` 的默认分支里：那一拍混着两种语义 ——
水刃「使一张法术立即冷却完成」（对自己有利）与寒流「重置对方一个法术的冷却时间」（对对方不利），
而 `FirstNonSkip` 是**按座位顺序**取第一个非放弃项，AI（座位 1）会排到玩家（座位 0）的牌后面，
于是它拿水刃去把**玩家**的牌冷却完。现在按 `DecisionRequest.ContextHaste`（极性）选目标。

### 2.3 头顶展示的两个时间语义

- **进攻牌**：玩家还在挑防御牌的时候，那张卡必须还挂着。旧版是「亮 2.6 s 自动淡出」，
  玩家一犹豫卡就没了；而且 `Show()` 的时长是写死的，没有「常驻」这个模式。现在 `holdSeconds = 0` = 常驻，
  由 `BattleUi` 在**防御方是玩家的那一拍**（成功 / 放弃 / 挡不住都会发这个事件）显式收掉。
- **防御牌**：反过来了 —— 它没有「后续决策」可以等，必须**停够时间**再收；
  而且收完之前不能翻下一回合。这需要 driver 配合，于是加了 `BattleDriver.BeatHold`：
  `wait = max(BeatDuration(e), BeatHold(e)) × _beatScale`。
  UI 在 `OnBeat` 里把本拍要等的秒数算好（`_pendingHold`），driver 只负责等。
  这样「跳过演出」照样能把这部分时间一起压掉。

## 4. 踩坑

### 4.1 ⚠ 「构建器置为失活 + 运行时 Show」的组件不能在 Awake 里 Hide（又一次）

`PlayedCardView.Awake()` 里那句 `Hide()` 让**本局第一次 Show 完全不显示**：
根节点在 prefab 里是失活的（`Configure → Hide` 写进去的），而 `Awake` 要等 GameObject 第一次被激活才跑 ——
也就是 `Show()` 里那句 `SetActive(true)` 会同步把 `Awake` 叫起来，`Awake` 里的 `Hide()`
转头就把刚点亮的面板按灭；`Show` 剩下的代码照跑（布局、贴图、alpha 全设好了），屏幕上什么都没有。
**第二次起就正常**，所以特别容易被当成偶发。

判据（实测）：连续两次 `Show` → 第 1 次 `IsVisible=False`、第 2 次 `True`。
修法 = 删掉 `Awake`，并在注释里写明原因（`DropArrowView` 2026-09-17 踩过同一脚）。

### 4.2 driver 的委托要在 OnBeat 之后取

`BattleUi` 用「`HandleBeat` 算好 `_pendingHold` → driver 紧接着读 `BeatHold`」这条时序，
它依赖 `CoPlayBeats` 里 `OnBeat(e)` 排在 `BeatHold(e)` 之前。改那段回放顺序时**必须一起改这里**。

### 4.3 编辑器失焦时 Play 模式的帧循环会停

排查过程中发现：Unity 窗口失焦后 `Time.unscaledDeltaTime == 0`、`frameCount` 不涨
（编辑器自身的事件循环还在跑，所以 MCP 命令照常返回），
此时「等 2.35 秒看它有没有消失」这类验证会全部失败。
运行时 `Application.runInBackground = true` 可以立刻恢复（退出 Play 即失效，不动工程设置）。
**副作用**：这么做的会话里 screenshot 可能给到旧帧 —— 判据仍然是「连续两张图 md5 相同」。

## 5. 验收

```
cd Tools/RuleSelfTest && dotnet run -- 10000 20260916
→ 结果：全部通过 ✅  10000 局 / 异常 0 / 事件 1,185,192
```

新增断言 `RuleAssertions.CheckingAgent.CheckTargetPolarity`：
加速 / 立即冷却完成的目标必须是自己，减速 / 重置冷却必须是对手，区域类按 `ContextHaste` 判（`Seat = −1` 的雪崩不判）。
