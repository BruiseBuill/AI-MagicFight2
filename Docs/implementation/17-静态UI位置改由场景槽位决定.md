# 17 · 静态 UI 的位置改由场景槽位决定（M18，2026-09-19）

> **性质**：现行实现记录 —— 静态 UI 的**坐标**搬进 Prefab / 槽位节点（与当前代码一致，可照此改）
> **最后核对**：2026-09-23

> 承接 16 号文档。16 号解决的是「**节点**不要在代码里 new」，本轮解决的是
> 「**位置**不要在代码里算」——凡是**位置固定、不随战局运动**的 UI，坐标一律搬到
> `BattleCanvas.prefab` 里，用户可以直接在 Hierarchy / Scene 里拖。

## 1. 用户口径（原话）

> 「手牌和冷却区域里面的东西是不用改的，我说的是除了手牌和冷却区里面的这些**本身由程序控制运动的东西**之外，
> 其他一些**静止的 UI**，例如像**光环的位置**等等，这些静止的东西**不要将位置写到代码当中**。」

补充说明：手牌区与冷却区是「随状态运动」的（扇形按牌数反解、冷却列按剩余冷却分行），**保持原样不动**。

## 2. 先复查：哪些位置真的被运行时代码覆盖

不是「代码里出现过坐标」都要改 —— 只有**运行时每次刷新都覆盖**的才对手调有害。复查结果：

| 元素 | prefab 现状 | 运行时覆盖？ | 结论 |
|---|---|---|---|
| `ArtLayer/Hud` 顶栏（名字/血量/资源/齿轮） | 位置齐全 | **否** | 本来就满足，不动 |
| `ArtLayer/Orb_Energy` 能量球 | 22,22 | 否 | 不动 |
| `ArtLayer/PlayedCard_Monster` 的 `Card1/Card2` | -63 / +63 | **否**（`Layout()` 从未被调用） | 只清理死代码 |
| `ArtLayer/HudBuff` 里的光环图标 | 模板 `IconTemplate` | **是**，每次 `Layout()` 全覆盖 | **改** |
| `PreparedAura` 的标记 + 落区高亮 | 只有 `ZoneHighlight` | **是**，每次 `Layout()` 全覆盖 | **改** |
| `TopArea/DetailPanel` 浮层 | 396×550.23 | **是**，每次 `Show()` 重设 | **改**（值本来就一样，删掉覆盖即可） |

关键巧合（省了一堆换算）：prefab 里现成的值与代码算出来的**完全相等**——
`DetailPanel` 396×550.23 == `UiLayout.DetailFaceWidth/Height`；
`Card1` 的 -63 == `-(2-1)×(116+10)×0.5`。所以这几处只是**覆盖**，不是**改版**。

## 3. 做法：槽位节点

在 `BattleCanvas.prefab` 里预置空节点，**坐标只存在于它们身上**；运行时只把图标挂过去、不写坐标。

| 节点 | 位置 |
|---|---|
| `ArtLayer/HudBuff/PlayerGroup/Slot0…Slot7` | 一排 2 枚 × 4 行 |
| `ArtLayer/HudBuff/EnemyGroup/Slot0…Slot7` | 同上，镜像 |
| `PreparedAura/Slot0…Slot7` | 判定区左侧往右排 |
| `PreparedAura/ZoneHighlight` | 位置/尺寸一并固化进 prefab（原先每次重算） |

槽位统一 `anchor = pivot = (0.5, 0.5)`、`size = 72×72`（= `UiLayout.BuffIconSize`），
与 `IconTemplate` 的对齐方式一致 —— 所以图标挂上去后 `anchoredPosition = 0` 就正好落在槽位中心。

**坐标怎么来的**（保持与原渲染完全等价，逐项验算）：

- 玩家组的 `PlayerGroup`：`anchor=pivot=(0,1)`、`pos=(566,-119)`、`size=160×72`。
  原算式把图标 `pivot(左上)` 放在「组左上 + (col·80, −row·80)」，图标 72×72 ⇒
  图标中心相对组中心 = `(col·80 − 44, −row·80)` → 即 `Slot(0,0)=(-44,0)`、`Slot1=(36,0)`、`Slot2=(-44,-80)`…
- 敌人组同理镜像：`Slot0=(44,0)`、`Slot1=(-36,0)`…
- 标记条：判定区 `PlayZone` 左缘 = −600，`first = −600 + 28 + 36 = −536`，垂直居中 25
  → `Slot0=(-536,25)`，步进 80。

槽位数量上限取 **8**（一排 2 枚 × 4 行 = 原算法在「光环 0~8」口径下的最大行数）。
图标多于槽位时 `SlotAt()` **退回最后一个槽位**（宁可叠在一起，也不要滑到画面别处）。

## 4. 改了哪些代码

| 文件 | 改动 |
|---|---|
| `Ui/HudBuffView.cs` | `LayoutGroup` 删掉 `anchor/pivot/anchoredPosition/SetSiblingIndex` 的全套算式，改为「第 i 枚挂到 `Slot{i}` + 归零」；新增 `SlotAt()`；`LayoutGroup` 去掉已无用的 `leftSide` 参数 |
| `Ui/PreparedAuraView.cs` | `Layout()` 删掉「跟判定区矩形实时推」的算式与 `ZoneHighlight` 的重设，改为挂槽位；新增 `SlotAt()` |
| `Ui/CardDetailView.cs` | `ConfigureFaceOnly()` 删掉 `panelRect.sizeDelta` 与 `_art` 的 anchor/offset 重设（prefab 已是同值），只保留显隐 |
| `Ui/PlayedCardView.cs` | `Layout(int)` 由「重算坐标」改为「只按数量开关卡位」（位置已在 prefab） |
| `Ui/UiLayout.cs` | 删 `BuffIconRowPitch` / `PreparedAuraLeftInset` / `PreparedAuraSpacing` / `PreparedAuraZoneInset`（均无引用）；`BuffIconSpacing` / `BuffIconPerRow` 注记为「只用于给组定宽」 |

⚠ **`HomeGroup` 必须指向槽位**，不能是组：`AuraIconView.ReturnHome()` 会把图标挂回 `HomeGroup`，
指向组的话拖拽松手会落到组的 `(0,0)`。这一条是本轮最容易漏的接线。

## 5. ⚠ 遗留与代价

1. **构建器仍会重算位置。** `BattleArtLayerBuilder` / `BattleUiBuilder` 里建节点时用的是
   `UiLayout.PlayedCard*` / `DetailFace*` / `BuffIconSpacing` 等常量。
   **重跑 M7/M8/M11 菜单仍会推倒重建**，在 prefab 里手调的结果会丢。
   → 要么别重跑，要么后续把构建器改成「已存在的节点不覆盖 RectTransform」的幂等版。
2. **标记条不再跟随判定区。** 原来它是拿 `PlayZone.rect` 实时算的；改成固定槽位后，
   判定区若挪位，这排槽位不会自动跟 —— 改判定区时记得顺手拖一下。
3. `AuraIconView` 内部的符号 / 数值位置（`PlaceGlyph`）没动：那是**图标内部的内容布局**
   （随「单符号 / 双符号」两档变化），不是面板位置。
