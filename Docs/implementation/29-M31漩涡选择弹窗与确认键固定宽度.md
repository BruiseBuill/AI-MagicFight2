# M31 · 漩涡改用卡牌选择弹窗 + 确认键不再随面板变宽

> **性质**：现行实现记录 —— 漩涡从冷却区强制选一张；确认键固定宽度（与当前代码一致，可照此改）
> **最后核对**：2026-09-23

> 用户口径（2026-09-22，原话见 §1）。本轮把 M27/M30 建好的「卡牌选择弹窗」**复用到冷却区**，
> 顺手修掉确认键底框随面板变宽的版式问题。

## 1. 用户口径（原文逐条）

1. 「**卡牌漩涡**：其效果应当也弹出一个卡牌的选择界面，类似于充能等卡，只需要注意**标题文字的不同**，
   以及漩涡是**从冷却区当中选**，**强制选择一张**。
   （这意味着**冷却区域当中的所有卡牌上都要加上点击判定**）」
2. 「对于磁暴/充能等的卡牌选择界面，**确认键的背景框不需要随着卡牌的逐渐增多而变宽**。」

## 2. 改动清单

### 2.1 引擎：漩涡从「自动随机」改成「问一次，且强制选一张」

**`BattleEngine.IssueRemoveFromGame`**（约 2137 行）由 `void` 改为 **`private bool`**：

```csharp
private bool IssueRemoveFromGame(EffectDef ef)
{
    PlayerState attacker = State.Of(_atk.AttackerSeat);

    // 冷却区空 → 没有可移出的目标，本效果整个跳过（不是「问一次再放弃」）。
    if (attacker.CoolingZone.Count == 0) { return false; }

    var options = new List<Option>();
    for (int i = 0; i < attacker.CoolingZone.Count; i++)
    {
        CardInstance c = attacker.CoolingZone[i];
        options.Add(new Option
        {
            Kind = OptionKind.ChooseCard,
            Seat = attacker.Seat,
            Card = c,
            Label = "永久移出 " + c.Def.Name + "，随后获得 " + ef.A + " 次加速",
        });
    }
    for (int i = 0; i < options.Count; i++) { options[i].Index = i; }

    Pending = new DecisionRequest
    {
        Seat    = _atk.AttackerSeat,
        Kind    = RequestKind.ChooseRemoveFromGame,
        Title   = RemoveFromGameTitle,          // 「移出·获加速」
        Prompt  = "漩涡：选一张冷却区法术永久移出游戏，获得加速 ×" + ef.A,
        Options = options,
        MinSelect = 1,
        MaxSelect = 1,                          // ← 「强制选一张」
    };

    return true;
}
```

调用点（约 1787 行）同步：

```csharp
case EffectOp.RemoveFromGame:
    return IssueRemoveFromGame(ef);   // 原：IssueRemoveFromGame(ef); return true;
```

**三个口径要点**：

| 项 | 决定 | 理由 |
|---|---|---|
| 候选来源 | `State.Of(_atk.AttackerSeat).CoolingZone` | 用户口径「从冷却区当中选」；**只列进攻方自己的**冷却区（效果是「**你**移出」） |
| 强制 | `MinSelect = MaxSelect = 1`，**不给 Skip 选项** | 用户口径「强制选择一张」。界面上「强制」只有两个来源：Min/Max 与「有没有 Skip」，两者都改了才算数 |
| 冷却区空 | 返回 `false` = 本效果整个跳过 | 没有合法目标时**不能弹一个空面板**。这是铁律第 3 条（非法项在生成 Options 时过滤）的延伸：没有合法目标 = 不产生决策 |

**标题**（新常量 `RemoveFromGameTitle = "移出·获加速"`）：
口径完全照 `IssueCoolHandSelection` —— 命名**效果**、不写卡名，且要短
（title band 平直段仅 257 px，≤ 11 字才不缩号）。

**AI 侧零改动**：`SimpleAiAgent.cs:92-93` 的 `default: return Of(request, FirstNonSkip(request));`
本来就会挑第一个非 Skip 选项 —— Skip 拿掉后它照挑不误。

**⚠ 有回归断言钉着**（`Tools/RuleSelfTest/RemoveFromGameScenario.cs`）：
`候选 > 0`、`手牌混入候选 == 0`、`出现 Skip == 0`、`Min == Max == 1`、`标题不是卡名`、`标题 ≤ 11 字`。
断言经「**临时把 Skip 写回去**」反证过 —— 会报 `[FAIL] … 出现 Skip 4 次`。

### 2.2 表现层：`HandPickView` 增加「候选区」维度

`HandPickView` 原来只会从**手牌**取候选。本轮加一个 `CardZone` 参数把它泛化：

```csharp
private CardZone _zone = CardZone.Hand;   // 新增字段

// 重载链：
Show(snap, title)               → 委托 Show(snap, title, null, CardZone.Hand)
Show(snap, title, hand)         → 委托 Show(snap, title, hand, CardZone.Hand)   // 旧签名保持兼容
Show(snap, title, hand, zone)   // 新增：真正干活的那个
```

筛选条件改成按区域：

```csharp
if (o != null && !o.IsSkip && o.Card != null && o.Card.Zone == zone)
```

三个「手牌专属」的动作全部加 `zone` 闸门，免得漩涡拍误触手牌：

| 位置 | 加的保护 |
|---|---|
| `ApplyHandSelection()` | `if (_hand == null \|\| _zone != CardZone.Hand) { return; }` |
| 手牌多选联动 | `if (_hand != null && zone == CardZone.Hand)` |
| `SetTitle` 兜底 | `_zone == CardZone.Cooling ? "选择冷却区法术" : "选择手牌"` |
| `HideImmediate()` | `_zone = CardZone.Hand;`（复位，防串味） |

**类注释同步改写**：标题从「手牌选择弹窗」改成通用的「卡牌选择弹窗」，
并写明 `zone` 参数与漩涡的强制单选场景。

### 2.3 表现层：`BattleUi` 接线 + 冷却区点击判定

`HandleDecision` 的 M27 分支加一条：

```csharp
if (_handPick != null)
{
    if (snap.Kind == RequestKind.ChooseCoolHandCards)
        _handPick.Show(snap, snap.Title, _hand);
    else if (snap.Kind == RequestKind.ChooseRemoveFromGame)
        _handPick.Show(snap, snap.Title, null, CardZone.Cooling);   // ← 候选来自冷却区
    else if (_handPick.IsShowing)
        _handPick.Hide();
}
```

**冷却区点击判定**（用户口径里那句「冷却区当中的所有卡牌上都要加上点击判定」）：
`CooldownView` **本来就有**点击承载体与 `OnCardClicked` 冒泡，
`ClassifyOptions`（`BattleUi.cs:1458-1462`）也已把「冷却区卡牌选项」收进 `_coolingPlayable`
并把 `_coolingTargeted = true` → `RefreshAll` 里 `_cooldown.SetPlayable(_coolingPlayable)`
让迷你卡变得可点。**本轮只需把点击先路由给浮层**：

```csharp
// BattleUi.OnCoolingCardClicked
if (_handPick != null && _handPick.IsShowing)
{
    _handPick.Toggle(card.Card.Uid);   // 浮层开着 → 这一下算「勾选」
    return;
}
PickCardOption(card.Card.Uid);         // 否则才是原来的「直接提交」
```

同时把 `_picker` 分支的匹配条件补上 `ChooseRemoveFromGame`，
让「浮层开着时点冷却区」不会同时触发旧的直接提交路径。

### 2.4 表现层：确认键从 `Panel` 里搬出来（用户口径 2）

**根因**：确认键原本是 `Panel` 的子节点。而 `Panel` 的宽随候选张数变
（`HandPickPanelWidthFor` → 431 / 670 / 885…），子节点若非写死尺寸就会跟着拉长 ——
于是「牌越选越多，确认键越拉越宽」。

**修法**：在 `BattleUiBuilder.BuildHandPickLayer` 里新建一个**固定宽度**的 `ConfirmSeat`
挂在**满屏根 `HandPickLayer`** 下（不在 `Panel` 下），确认键再挂到它底下：

```csharp
GameObject seatGo = NewUi("ConfirmSeat", go.transform);          // go = HandPickLayer 根
RectTransform seat = Rt(seatGo);
Box(seat, new Vector2(0.5f, 0.5f), new Vector2(0.5f, 0.5f),
    new Vector2(0f, UiLayout.HandPickPanelHeight * 0.5f
                    - UiLayout.HandPickConfirmCenterFromBottom),   // = 556/2 − 57.5 = 220.5
    new Vector2(UiLayout.HandPickPanelBaseWidth, UiLayout.HandPickConfirmHeight));  // 431 × 58

GameObject btnGo = NewUi("ConfirmButton", seatGo.transform);
Box(Rt(btnGo), new Vector2(0.5f, 0.5f), new Vector2(0.5f, 0.5f), Vector2.zero,
    new Vector2(UiLayout.HandPickConfirmWidth, UiLayout.HandPickConfirmHeight));     // 258 × 58
```

- Y 值算式 `556/2 − 57.5 = 220.5` 与搬动前**像素等价**（锚点是满屏中心，Panel 也在满屏中心）。
- `ConfirmSeat` 宽取 **`HandPickPanelBaseWidth`（431）** = 最窄态面板宽 → 单张态下按钮仍居中于面板。
- `_confirmButton` / `_confirmImage` / `_confirmLabel` 的 `SerializedObject` 接线**按组件引用**，
  不按路径 → 搬家后**无需改接线**。

## 5. 本轮踩的坑（供后来者）

1. **Unity 在 Play 模式下不重编译脚本**。新增 `M31Smoke.RunMulti()` 后调它会得到
   `MissingMethodException`，而磁盘上的 `MagicBrawl.App.Editor.dll` 时间戳**已经更新**
   —— 因为域重载被推迟到退出 Play 才发生。**修法：`manage_editor {"action":"stop"}` 退出 Play
   再 `refresh_unity`**。判断「到底重载没有」的唯一可靠依据是**运行时反射能不能看到新成员**，
   不是 DLL 时间戳。
2. **`execute_code` 必须传 `compiler: "codedom"`**（C# 6 语法），且需要 `action` 参数。
   `compiler: "auto"/"roslyn"` 在本工程返回裸 `{"success":false}`。
3. **`delete_script` 的参数名是 `uri`**（不是 `path`），删完 `.meta` 会一并进回收站。
4. **`refresh_unity` 不接受任何参数**（传 `action`/`compile` 都报 validation error）。
5. **`manage_camera` 的截图参数形状不确定** → 直接用
   `UnityEngine.ScreenCapture.CaptureScreenshot("<绝对路径>")` 最省事；
   但**必须在 Play 模式下**才渲染，Edit 模式调用会静默不落盘。
6. **MCP 桥在域重载后会短暂失联**（`Session not found` / `ECONNREFUSED` / `502`）——
   备用通道是 python 直打 `http://127.0.0.1:8080/mcp`（脚本 `E:/UnityProject/_tmp_build/mcp.py`）。
