# M22 · 光环触发符号（α/β/γ）+ 冷却槽校准 + 两处交互顺手改

> **性质**：现行实现记录 —— **α/β/γ = 结算时机**的落地说明；冷却槽宽校准（与当前代码一致，可照此改）
> **最后核对**：2026-09-23

日期：2026-09-20（用户 4 条调整）。里程碑号沿用 M22。

本轮改动的总口径：**卡面上的 α / β / γ 就是结算时机**（`rules/01-规则基线.md` §0），
任何「效果什么时候触发」的判断都必须回到这三个符号上，不能靠旁证推。

## ① 把用户在 Prefab 里手改的冷却槽同步进构建器

**用户的改动**：`Prefabs/Ui/BattleCanvas.prefab` → `ArtLayer/CoolingScroll_Enemy/SlotR_Col/SlotR_CD1`
的 RectTransform 被手工改成 **183 × 86**（成品图 `SlotR_CD1.png` 是 185 × 86）。

**为什么构建器会把它改回 224**：`BattleArtLayerBuilder.BuildSlotColumn` 里有一条老分支

```csharp
// 右列只有「冷却区1」那张带内嵌卡面、宽一截
if (!playerSide && w > UiLayout.SlotEnemyWidth + 1f) w = UiLayout.SlotEnemyWidthWithCard;  // = 224
```

它服务的是「右列冷却区1 那张槽图**烘了一张假卡面**」的老素材。那张假卡面在 M11 就擦掉了
（见 `11-美术层实现说明.md`），重切出来的成品只有 185 宽 —— 于是每次重建都会
**把 185 的图横向拉 21% 成 224**，而且 224 宽的行会让这一行第 4 张迷你卡的
最左端伸到 x≈1226 之外，被视口的 `RectMask2D` 裁掉。

**改法**（两处）：

| 位置 | 改动 |
|---|---|
| `UiLayout` | 新增 `SlotEnemyCD1Width = 183f`（= 185 减掉成品图右侧 2 px 透明边，用户校准值）；把 `SlotEnemyWidthWithCard` 改名为 `SlotColumnBudgetWidth` 并重新写明它**只是列宽预算**，不是任何一行的实际宽度 |
| `BattleArtLayerBuilder.BuildSlotColumn` | 删掉那条 `w > SlotEnemyWidth + 1 → 224` 分支，改成右列最后一行（行下标 3 = 冷却区1）直接取 `SlotEnemyCD1Width` |

`CooldownView.ConfigureColumn` 只把常量换名，视口宽度**仍是 674 不变** ——
多出来的 41 px 当遮罩余量（一行的迷你卡超过 4 张时会继续往中间长，留余量才不会被裁）。

**核对**：改完之后构建器对 8 个槽行产出的尺寸与当前 Prefab **逐行一致**
（玩家 190×95 / 191×96 / 193×96 / 192×100，敌方 182×84 / 182×84 / 183×84 / **183×86**），
所以重跑 M11 不再改动任何槽行。

## ② 光环（以及所有效果）严格按 α / β / γ 触发

### 问题一：光环的激活不看触发符号

`BattleEngine.DoStage5` 原来对 `_atk.Card` 和全部 `_defenseCards` 一视同仁地点亮**全部**光环，
理由是 2026-09-18 写下的「光环与该牌是攻是防无关」。

按 `rules/02-卡牌图鉴.md`，本批 **12 张带光环的卡，光环全部标着 α**（`b 冰风暴 / n 引雷 /
af 冰封铠甲 / ag 淬火 / ah 烈焰斗篷 / ai 爆燃 / aj 火灾 / ak 石化 / al 石盾`），
所以那句话是错的：**拿它们去防御，一枚指示物都不该亮**。

**改法**：`ActivateAura(card)` → `ActivateAuras(card, role)`，按本次角色取符号 ——
进攻牌取 `EffectTrigger.Attack`、防御牌取 `EffectTrigger.Defend`；
本角色下没有该符号的光环就一枚都不点（`AuraLive` 保持 false）。
数量取自新增的 `CardDef.AuraTokenCountOf(EffectTrigger)`。

### 问题二：β「防御时力量 +A」从头到尾没有结算点

`EffectOp.DefPlus`（潮汐 e / 地动波 z 的「β 防御时力量 +1」）**在引擎里没有任何引用** ——
从卡表录入那天起就是静默失效的：引擎一直拿 `CardInstance.EffectivePower` 当防御力量，
而那个字段只反映进攻侧。表现是「地动波 7 挡不住 8」，可卡面上明明写着 +1。

**改法**：`DefenseResolver` 新增

```csharp
DefendBonus(card)    // 卡面 β「防御时力量 +A」合计
DefensePower(card)   // = EffectivePower + DefendBonus
```

`RequiredBonus` 改用 `DefensePower`，选项标题也会写出实际用来挡的数
（「打出 地动波（力量 7，防御 +1 → 8）」）。
`EffectClassifier` 里把 `DefPlus` / `Guard` 登记为 `Stage2Defense` ——
它们本来就不走进攻队列，登记是为了「落到 default 被当成 Stage1Power」不再悄悄发生。

### 顺带钉住的约束

- `CardLibrary.ValidateAuraTriggers(out report)`：同一张牌的光环必须**同符号**
  （`AuraResolver` 用「剩余指示物 = 效果列表尾部 N 条」建模，混符号会静默给错效果）；
  算子与光环类型必须配套；光环标成 `Passive` / `γ` 一律报错
  （第 ⑤ 步只按 α / β 点亮，γ 光环需要单独接触发点，尚未实现）。
- 自测里两条断言**翻面**（原来方向相反，2026-09-18 写的）：
  `EventWatcher` 现在要求「带 α 光环的进攻牌**必须**点亮」「带光环的防御牌，卡面没有 β 就**一枚都不能亮**」；
  并输出 `光环断言覆盖` 行（一次 3000 局 = 进攻牌 6649 张 / 防御牌 4788 张），
  避免断言悄悄变成空跑。
- 新增 `Tools/RuleSelfTest/BetaDefenseScenario.cs`：脚本化逼出「8 力量打地动波」的局面，
  断言「打出 地动波」是合法选项且判防御成功 —— 这是 DefPlus 唯一能被证明的地方
  （引擎在缺陷状态下是自洽的，万局统计完全无声）。

## ③ 拖光环一开始就点亮手牌区提示底

`BattleUi.OnAuraDragMove` 原来的判据是 `usable && _hand.IsInHandArea(screenPos)` ——
**指针要先进到手牌区**才亮。可这层提示底的作用是「告诉玩家该往哪儿拖」，
等他自己摸到落区才亮就等于没提示。

改成只看 `usable`（本拍这枚指示物确实在引擎的 `Options` 里）：
`IconDragBegin` 与 `IconDragMove` 都走这个方法，于是**一拖就亮、拖多久亮多久**，
松手 / 挪开由 `OnAuraGestureEnded` 收掉。落点合法与否仍然只在松手那一拍判
（`OnAuraDropped` 里的 `IsInHandArea` 没动）。
颜色依旧只写在 Prefab 的 `Image.color` 上，代码只切 `activeSelf`。

## ④ 第 2 / 3 回合换牌不再要求点那张牌

补牌那趟的替换候选**只有刚到手的那一张**（`BattleEngine.DrawCardToHand` 的产物，
经 `BeginReplacePass(drawn)` 传进来），`MaxSelect = min(1, 1) = 1`。
这时再让玩家点它一下是多余的一步 —— 两个按钮本身已经把「换 / 不换」问清楚了。

**改法**：`DealView.Show` 里，当 `_replaceOptions.Count == 1 && _maxSelect == 1` 时
**预先标记**那唯一一个候选（`_autoSelected`），提示行改口为
「已选中刚补到的这张 —— 点「确认替换」换掉它，或直接保留」。
判据用「候选数 + 上限」而不是「第几回合」：开局那趟的候选是整副手牌、`MaxSelect > 1`，两者不会混。
玩家点那张牌照样能取消标记（`Toggle` 是对称的），此时提示行会退回「点这张牌即可标记替换」，
不会出现「界面写着已选中、计数行却 0 / 1」的自相矛盾。

## 遗留 / 已知取舍

- `SlotColumnBudgetWidth = 224` 比实际最宽槽（183）大 41 px，是**故意留的遮罩余量**。
  真要收窄，得同时确认「某一行 5 张以上迷你卡」的边界，别只为省这 41 px 换来裁切。
- Prefab 里 `SlotR_Col` / `SlotL_Col` 的 `anchoredPosition.y = 183.79993` 是
  ScrollRect 滚到底的状态残留（两侧同值、场景里又被覆盖成 0），**不是**手改；
  重跑 M11 会被写成 0，视觉无差别。
- 防御牌的光环图标现在不会出现（因为本批光环全是 α）。若将来要给某张卡加「防御时获得」的光环，
  把那张卡的光环效果改成 `D(...)` 造出来即可 —— 引擎两条路径都已就位。
