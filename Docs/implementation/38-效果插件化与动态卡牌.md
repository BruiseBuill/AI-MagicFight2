# M40 · 效果插件化与动态卡牌

## 规则边界

六步结算顺序保持不变：力量与结构、​​防御、冷却效果、进冷却区、光环、连击。
进攻、防御、特殊仍是卡牌效果的三种触发时机。只有单体加速与区域加速同时存在，或单体减速与区域减速同时存在时，效果窗口才合并为可自由交错的选择；其他效果按卡面顺序结算。回血、快速回填、光环获取等无目标效果自动执行；加速、减速及其区域版本可以跳过。

## Core API

`EffectDef` 现在是不可变的效果配方：

- `Trigger`：Attack、Defend、Special。
- `HandlerId`：行为注册名。内置算子使用 `EffectOp.ToString()`，插件效果使用自己的 ID。
- `Arguments`：命名参数，避免新效果继续依赖含义不明的 A/B/C。
- `Conditions`：可复用条件；条件只读取 `EffectContext`，不修改战斗状态。
- `DistinctTargetGroup`：一次进攻内的目标去重范围，瀑流用 `torrent`。
- `SpecialEvent`：特殊触发事件，例如 `cooldown.completed`。

`EffectRegistry` 在开局创建后冻结。通过 `Register` 添加插件行为，通过 `RegisterCondition` 添加插件条件。处理器实现 `IEffectHandler`，可以自动执行，也可以通过 `EffectChoice` 产生一次外部选择。

`EffectWindow` 维护每条效果自己的迭代器和选择状态。它只合并同一上下文、同一触发时机、同一效果族且目标形状互补的效果，因此海涌会同时暴露“卡牌加速”和“区域加速”，烈焰斗篷的加速不会和自动光环获取形成顺序选择。

## 动态卡牌

`CardDef` 现在包含 `ArtId`、版本和完整效果定义；`CardInstance` 仍只保存本局运行状态。`CardCatalog` 是一局内容快照，战斗开始后即使编辑器资产改变，本局仍使用原定义。

Unity 层新增：

- `CardDefinitionAsset`：一个可编辑卡牌定义和效果列表。
- `CardCatalogAsset`：组合内置卡、自定义卡和生成卡，放在 `Resources/CardCatalog.asset` 后会被 `BattleDriver` 自动加载。
- `GeneratedCardAssetUtility`：菜单“魔法乱斗/卡牌/创建动态卡牌资产”，创建的资产会自动登记到资源卡目录。
- `BattleDriver.CreateGeneratedCard`：游玩中从 `CardDefinitionAsset` 生成一张本局卡牌；生成卡跨局保存依靠其 ScriptableObject 资产和 `CardCatalogAsset` 引用。

表现层从 `CardSnapshot.Definition` 和 `ArtId` 取数据，不再要求卡牌 ID 必须存在于固定 `CardLibrary`。

## 扩展步骤

1. 在 Core 创建一个无 Unity 依赖的 `IEffectHandler`。
2. 在创建 `BattleSetup` 时注册处理器和条件，然后把同一个 `EffectRegistry` 传入。
3. 在 `CardDefinitionAsset.effects` 中填写 `handlerId` 和命名参数。
4. 若效果需要新 UI 输入，只扩展 `EffectChoice` 生成的 `DecisionRequest`，不修改卡牌或表现层的规则判断。
