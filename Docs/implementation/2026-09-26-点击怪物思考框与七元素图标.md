## 2. 七元素体系

### 2.1 元素枚举放在 Core（不是表现层）

`Assets/Scripts/Core/Cards/CardElement.cs` 新增 `enum CardElement { None, Ice, Water, Electric, Fire, Grass, Stone, Curse }`，
以及文案/资源名映射 `CardElementInfo`（`DisplayName` / `ResourceId` / `Count`）。

**为什么它必须在 Core、而不是塞在 UI 层维护一张「卡 ID → 元素」的字典**：

> 元素是**卡牌的静态属性**（和力量、冷却、效果一样写在卡表里）。
> 表现层如果自己养一份映射，那就是**第二份卡表** —— 迟早与 `CardLibrary` 对不上，
> 而症状是「卡表改了、符号还按老映射显示」，静默且难查。这与铁律「规则约束只收敛在一处」是同一条精神。

⚠ `None = 仅表示「未标注」`，**不是第八种元素**。表现层拿到 `None` 一律**不显示符号**，
不许兜底成某个元素（兜底 = 把「不知道」画成「知道」，比不画更坏）。

### 2.2 每张卡都标了元素，且有硬断言

`CardLibrary` 的 `Add(...)` 增加一个带 `CardElement` 的重载，40 张卡逐张标注（分配见
[卡牌图鉴](../rules/02-卡牌图鉴.md)）。

新增校验钩子 `CardLibrary.ValidateElements(out report)`：**不允许任何一张卡是 `None`**，
并把各系张数一并报出来。已接进 `Tools/RuleSelfTest/RuleAssertions.cs` 的数据类断言：

```
[PASS] 元素标注 OK：冰:7 水:7 电:8 火:6 草:4 石:7 诅咒:1（共 40 张）
```

**为什么是硬断言而不是「信息输出」**：元素唯一的消费者是思考框，它拿到 `None` 的表现是
「玩家点怪物时**偶尔什么也不弹**」—— 不报错、不复现、也说不清是哪张卡漏标。钉在校验里最便宜。

⚠ 诅咒目前只有**模仿（x）** 这一张（它的美术主题是「模仿 / 抄袭」，归入诅咒是最贴的一档）。
用户口径「牌堆当中暂时还没有诅咒相关的卡」指的是**没有纯诅咒系的设计**，
这张是现有的唯一归属，`Element_07_Curse.png` 是**先备着**的——将来加纯诅咒卡不用再动枚举。

## 3. 预判口径：与 AI 同源

新增 `Assets/Scripts/Core/Ai/AttackForecast.cs`（**在 Core，不在 UI**）：

```csharp
CardInstance StrongestInHand(BattleState state, int seat);   // 下一张会打的牌（手牌空 → null）
CardElement  ElementOfNextAttack(BattleState state, int seat); // 只要元素（表现层只该调这个）
```

三条设计约束：

1. **口径 = `SimpleAiAgent.PickStrongestAttack` 的进攻策略**：「有牌就打，选当前**有效力量**最高的一张」。
   平手时比较符必须与 AI 一致（AI 用的是 `>`，所以相等不替换 = 取最早那张）。改成 `>=` 会变成
   「同力量取最后一张」，与 AI 实际行为不符 —— 而提示框只显示元素，这种偏差**极难被发现**。
2. **不依赖 `DecisionRequest`**：玩家点怪物时引擎往往正停在「等玩家自己出牌」那一拍，
   此刻**根本不存在**「AI 进攻决策」这个对象。所以直接读 `PlayerState.Hand` 现算。
3. **它是预判、不是保证**：AI 策略将来会换（规划里的 `HeuristicAgent`），
   手牌也会在玩家点开提示框之后继续变化。写文案时**不要**写成「它一定会打冰系」。

`BattleDriver` 只暴露一个转发口 `ForecastAttackElement(int seat)`，UI 不直接碰 `AttackForecast`。

## 4. 表现层

### 4.1 点击面：`ArtLayer/Char_Monster_Click`

由 `BattleArtLayerBuilder.BuildMonsterClickFace` 生成：

- 节点 `ArtLayer/Char_Monster_Click`，尺寸 **320×340**，中心 `(1246.5, 577)`
  （`UiLayout.ThinkBubbleClick*`；基准 = 脚底 `CharGroundY` + `ThinkBubbleClickCenterY`）。
- 挂一张**全透明** `Image`（`color = (0,0,0,0)`、`raycastTarget = true`）+ `MonsterClickCatcher`。
- **用 `IPointerClickHandler` 而不是 `Button`**：`Button` 会带来 Selectable 的状态机
  （悬停 / 按下要换色），而这里要的是一块**完全不可见**的点击面。
- 独立文件 `Assets/Scripts/Unity/Ui/MonsterClickCatcher.cs`（**必须一个文件一个类** ——
  否则写进 Prefab 时 `m_Script` 会变 `{fileID: 0}`、Unity 直接拒绝保存整份 Prefab，
  而构建返回值 / 日志 / 场景全看不出异常；`ZoneSlotClickCatcher` 踩过一次）。

接线走「运行时按序列化字段自己接」：`BattleUi.Awake` 里 `_monsterClick.Owner = this`
（构建期在编辑模式下 `AddListener` 接的那份**不是序列化数据**，存 Prefab 时会蒸发 —— 铁律 10）。

### 4.2 提示泡：`Canvas/ThinkBubble`

`BattleUiBuilder.BuildThinkBubble` 生成三个节点：

```
Canvas/ThinkBubble          ← CanvasGroup（alpha 0 / 不吃射线）+ ThinkBubbleView
  ├─ Backdrop               ← 象牙白底（UiTheme.ThinkBubbleBackdrop + CardBox.png Sliced，168×168）
  └─ Icon                   ← 元素符号（104×104，preserveAspect，enabled=false）
```

- **框里只有一张图，没有 `TMP_Text`**：口径要的是**符号本身**，一张元素图比「冰」这个字更直观，
  也不受字体 / 字号 / 换行影响（构建器不用给每个元素配文案）。
- **底色刻意用浅色**（`new Color(0.96f, 0.95f, 0.91f, 0.95f)`，偏冷象牙白）——
  与 `FloatTip` / 中央横幅那两条**深色浮层**反着来，让「这是怪物的内心活动」和「这是系统提示」
  在余光里就能分辨。
- **三段动画**（与 `FloatTipView` 同一套节奏口径）：弹出（缩放 `OutBack` 0.72→1 + 淡入，
  `ThinkBubblePopSeconds = 0.16`）→ 停留 → 渐隐（淡出 + 上浮 `ThinkBubbleRise = 36`）。
  总时长 `ThinkBubbleSeconds = 2.0` —— 直接对应「显示约两秒之后渐隐消失」。
- ⚠ **坐标口径**：本节点锚在**画面正中** `(0.5,0.5)`，而 `CharMonsterX = 1246.5` 等常量是
  **底边口径**（锚在左下）。所以 `UiLayout.ThinkBubbleX = CharMonsterX − ReferenceWidth/2`、
  `ThinkBubbleY = 866 − ReferenceHeight/2 = 326`。**直接把底边口径的值填进去会让节点跑到
  1920×1080 画布外**，症状是「点了有反应但什么都看不见」。

### 4.3 取图入口

`Assets/Scripts/Unity/Ui/ElementIconLibrary.cs`：

```csharp
Resources.Load<Sprite>("Elements/Element_" + ((int)element).ToString("D2") + "_" + CardElementInfo.ResourceId(element));
```

带字典缓存（**null 也缓存**，避免每次点击都去 Load 一次失败路径）+ 一次性告警。
缺图时返回 null → `ThinkBubbleView.Show` **静默不出**（宁可不弹，也不弹空框或错符号）。

### 4.4 何时不该弹

`BattleUi.NotifyMonsterClicked()` 的守卫（本类**不含任何规则判断**，铁律 3，只做时机判断）：

| 情形 | 行为 | 理由 |
|---|---|---|
| `_deal.IsOpen`（发牌台还开着） | 不弹 | 对局没真正开始，这一拍不存在「下一次进攻」 |
| `_resultRoot.activeSelf`（结算浮层已铺） | 不弹 | 已经结束了，再弹是干扰 |
| 怪物手牌为空 → 元素为 `None` | 不弹 | `AttackForecast` 返回 null；不兜底成某个元素 |
| 该元素缺图 | 不弹 | 同上 |
| 连点怪物 | **原地重播**（后一次盖掉前一次） | 玩家看到的是「同一个泡重新弹一次」，而不是几个泡叠在一起 |

另外 `HandleStarted` / `HandleFinished` 各加一次 `Hide()` —— 重开一局 / 终局时提示泡不许留在画面上。
