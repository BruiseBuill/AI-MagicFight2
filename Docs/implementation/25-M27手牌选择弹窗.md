> **性质**：现行实现记录 —— 从手牌选（磁暴 / 充能 / 电弧）；`HandPickLayer`（与当前代码一致，可照此改）
> **最后核对**：2026-09-23

日期：2026-09-21（接在 M26 之后，用户 1 条需求 + 2 条澄清）。

本轮是 **UI 为主 + 引擎加一个字段**：表现层新增一整块浮层，引擎侧只补
「这一拍是哪张牌在结算」这一个事实（`DecisionRequest.Title`）与
「最少选几张」（`MinSelect`）。规则约束本身没有改动。

## 用户口径

> 1. 对于要选择手牌中的一张牌或者若干张牌的效果（包括磁暴，充能，电弧），这类效果触发时，
>    应该弹出一个额外的界面。这个界面的参考图如 reference-3 所示……用到的素材已经放在 Art 文件夹下。
> 2. 效果触发时，弹出此界面，此界面初始只有一张空的卡框，玩家选择手牌之后，手牌进入到卡框的位置。
> 3. 玩家点击界面中的卡时，视为取消选择该卡。
> 4. 对于可以选择多个的效果（磁暴，充能），则玩家选择多个手牌之后，都可以加入到此框中
>    （因此这个界面的大小需要可变），点击确认就确认选择。
> 5. 如果没有填入任何手牌，点击确认，则视为没有选择任何手牌。
> 6. 对于必须要选择一个的效果（电弧），则在玩家填入手牌之前确认键不得亮起。
>    玩家放入一个之后就亮起，但是不能放入多个。
> 7. 注意此卡牌选择界面的标题，磁暴充能和电弧的文字应当不同。
> 8. 注意动画流畅

两条澄清（回答「界面怎么变 / 内框装饰怎么办」）：

- **面板整体横向加宽**（不是换行、不是缩放）。
- 多张时**隐藏原图内框装饰，只留纯色底**。

## ① 引擎侧：只补两个事实

### `DecisionRequest.Title`（新增字段）

三种效果共用同一个 `RequestKind.ChooseCoolHandCards`，但规则不同
（磁暴每张 +A 力量、充能每张一次加速、电弧换一次连击）。
界面必须看得出「这一拍是哪一张在结算」，而这个事实**只有引擎知道**
（它手上才有正在生效的那张牌）。

如果让 UI 去猜：磁暴与充能都是「多选」，靠 `MaxSelect` 猜不开；
靠 `Prompt` 文案猜等于把文案当协议。所以**把牌名作为一个字段直接给出来**：

```csharp
public string Title = string.Empty;   // Decision.cs
```

在 `IssueCoolHandSelection` 里填：

```csharp
Title = _atk.Card != null && _atk.Card.Def != null ? _atk.Card.Def.Name : string.Empty,
```

`DecisionSnapshot` 同步加 `public string Title;` 与 `Title = r.Title,`
（`Snapshot.From`）。

> 这条守的是铁律 3 的反面：界面**不替引擎判断**，但界面需要知道的事实，
> 由引擎**明确地给**，而不是让界面从别的东西反推。

### `MinSelect`（改值，不是新字段）

```csharp
bool single = ef.Op == EffectOp.CoolHandForCombo;   // 电弧
...
MinSelect = single ? 1 : 0,
```

- 磁暴 / 充能：0 张也合法（只是没有加值 / 没有加速）→ `MinSelect = 0`。
- 电弧：卡面写的是「可将手中一张其它法术进入冷却，获得连击」，
  不选就没有任何事发生 → `MinSelect = 1`，确认键在选择之前不可用。

`MaxSelect` 保持原样：磁暴 = 全部手牌数；充能 = `max(1, A)`；电弧 = 1
（`A = 1` 天然就是 1）。**「电弧不能放第二张」是 `MaxSelect = 1` 的结果，
不是界面上另写一条 if。**

Prompt 也按效果分了三句。

## ② 表现层：三个新文件 + 三处接线

### 新节点从哪来

`HandPickLayer` 整棵子树由 `BattleUiBuilder.BuildHandPickLayer` 生成，
**排在 `PeekLayer` 之后建 = 画在所有浮层之上**（Canvas 同层节点的绘制顺序 = 兄弟顺序）。

```
HandPickLayer            CanvasGroup(alpha 0) + HandPickView      ← 构建器置失活，运行时 Show
├─ Veil                  铺满画布，吃掉下层点击（比 M25 的浅：背后要能看见自己的手牌）
└─ Panel                 九宫格 Peek_Frame，初始 431×556
   ├─ Title              大字 = 引擎给的短标题（磁暴 / 充能 / 电弧）
   ├─ SubTitle           「n / max」
   ├─ SlotArea           按张数变宽的那一条
   │  ├─ Backdrop        **铺满 SlotArea**，躯干纯色，盖住被拉变形的内框装饰（有牌才亮）
   │  ├─ EmptyFrame      一张没选时露出的空卡框（四根细条描边 + 暗底）
   │  ├─ Slot0 … Slot7   预建 8 个，运行时只激活前 N 个
   └─ ConfirmButton      按钮座 + Label
```

`HandPickLayer` 已加入 `OwnedNodes`（重跑菜单会整棵删掉重建）。

> ⚠ 顺序不能反：`Backdrop` 在 `SlotArea` 的子节点里必须排在 Slot 之前，
> 否则它会盖住卡框。这正是本轮踩到并修掉的坑之一（见「踩坑」）。

### `HandPickSlot`（单张已选卡框）

一个极薄的表现组件：`_face`(Image) / `_edge`(Image) / `_indexBadge`+`_indexText`，
实现 `IPointerClickHandler`，点它 = 取消选择这张，抛 `Clicked` 事件。
对外只读暴露 `SlotIndex / OptionIndex / CardUid / Face / Edge / IndexBadge / IndexText`。

序号角标是 **1 起的**（让玩家看出选的顺序），与 `RefreshSlots` 里 `i + 1` 对齐。

### `HandPickView`（浮层本体）

```csharp
public event Action<List<int>> Confirmed;
public bool IsShowing { get; }
public int SelectedCount / MaxSelect / MinSelect { get; }
public void Show(DecisionSnapshot snap, string title, HandView hand);
public void Toggle(int uid);      // 手牌被点
public void Hide() / HideImmediate();
```

**收候选**：只收 `!o.IsSkip && o.Card != null && o.Card.Zone == CardZone.Hand`
的选项 —— `Skip` 由「一张不选直接确认」表达，别的 Kind 不是这一栏的语义。
候选为空时**静默收起来**（引擎那边无候选本来就不会发这一拍），绝不弹一个点不动的空框。

**`_maxSelect = max(1, snap.MaxSelect)`**：`<= 0` 是引擎不可能给的值，真给了就退化成单选。

**`Toggle` 的三条分支**：
1. 已在框里 → 移除（点框内 = 取消选择）。
2. `_selected.Count >= _maxSelect` → **静默 return**（电弧就是这条：放了一张就不能再放第二张）。
   不弹提示条 —— 确认键已经亮了，玩家能看出「只能一张」。
3. 否则加入，并让新落进来的那一格播放大回弹。

**`Layout(int popIndex)`** —— 版式唯一的收口点：

```csharp
int count = _selected.Count;
_panel.sizeDelta = new Vector2(UiLayout.HandPickPanelWidthFor(count), HandPickPanelHeight);
_slotArea.sizeDelta = new Vector2(UiLayout.SlotAreaWidthFor(count), HandPickSlotAreaHeight);
_slotArea.anchoredPosition = new Vector2(0f, areaCenterY);

_emptyFrame.gameObject.SetActive(count == 0);        // 一张没选 → 露出原图的空卡框
_slotAreaBackdrop.gameObject.SetActive(count > 0);   // 有牌 → 压住变形的内框装饰

RefreshSlots(popIndex);
```

宽度算法（`UiLayout`）：

```csharp
SlotAreaWidthFor(count)      // 0/1 → 207；n → n*207 + (n-1)*8 + 2*24，封顶 1800
HandPickPanelWidthFor(count) = SlotAreaWidthFor(count) + 2 * 112
```

`112` = 单张时「内框到面板外框」的距离（(431 − 207) / 2），沿用它面板就跟着长。
8 张 = 8×207 + 7×8 + 48 = 1760 < 1800，正好是手牌上限，实际上不会换行。

**`RefreshConfirm`**：

```csharp
bool ok = _selected.Count >= _minSelect;
// ColorTint 是替换不是乘算 → 全部用本身就压到底的实色
cb.normalColor = cb.highlightedColor = cb.pressedColor = cb.selectedColor = HandPickConfirmOn;
cb.disabledColor = HandPickConfirmOff;
_confirmButton.interactable = ok;
_confirmLabel.color = ok ? TextPrimary : HandPickConfirmTextOff;
_subTitle.color = _selected.Count > 0 ? SelectionGlow : TextSecondary;
```

**动画**（`UiTween`，全部在 `UiLayout` 里有常量）：

| 动作 | 时长 / 缓动 |
|---|---|
| 浮层淡入 / 淡出 | 0.18 s |
| 面板出现弹一下 | 0.94 → 1.0，0.24 s，`OutBack` |
| 新卡落进卡框 | 放大回弹 0.2 s |
| 取走一张 | 缩小回弹 0.16 s |

> ⚠ `UiTween.Setup(...)` 返回 **void**，不能链式 `.Play()` —— 必须分两句写。
> 这类浮层的 `_group.blocksRaycasts = true` 只在 `Show` 里打开；`Awake` 里**绝不**
> `Hide()`（「构建器置失活 + 运行时 Show」的组件在 `Awake` 里关一次会把本局第一次
> Show 一起关回去，本工程已在 `DropArrowView` / `PlayedCardView` 上中过两次）。

### 三处接线（`BattleUi.cs`）

1. `Awake`：`_handPick.Confirmed += OnHandPickConfirmed;`
2. `HandleDecision`：`snap.Kind == ChooseCoolHandCards` → `_handPick.Show(snap, snap.Title, _hand)`；
   否则若正在显示就 `Hide()`。同时**浮层下面不列按钮**（`_picker.Hide()`）。
3. `OnHandCardClicked`：**在通用 `PickCardOption` 之前**加一条分流 ——
   `if (_handPick != null && _handPick.IsShowing) { _handPick.Toggle(card.Card.Uid); return; }`
   （否则「点一张就立刻提交」那条老路会抢走点击）。
4. `ClearDecision` / `HandleStarted` / `HandleFinished`：补 `Hide()` / `HideImmediate()`。

`OnHandPickConfirmed`：**先拷成数组再 `ClearDecision()`**（后者会走 `Hide()` 清掉弹窗内部那份列表），
然后 `_driver.SubmitPlayerDecision(picks)`。一张没选也照样提交空数组 ——
磁暴 / 充能的 `MinSelect = 0` 让「什么都没选」本身就是合法答案；
电弧的 `MinSelect = 1` 由弹窗自己拦住，这里不重复判断。

## 踩坑（本轮实际踩到并修掉的）

### 1. `Toggle` 只调 `RefreshSlots`，忘了 `Layout`

最初 `Toggle` / `OnSlotClicked` 里写的是 `RefreshSlots(-1)`，
而**面板宽度、SlotArea 宽度、空框显隐、遮挡条显隐全在 `Layout()` 里**。
于是出现「已选 3 张、副标题写 3 / 6、但面板仍是单张宽」的半调子状态 ——
插槽倒是按新宽度摆好了位置，只是那个新宽度没被写进面板，结果全挤在框外看不见。

**修法**：把 `Layout` 拆成 `Layout()`（= `Layout(-1)`）与 `Layout(int popIndex)`，
所有改动已选集合的地方**一律收口到 `Layout`**。

### 2. `Show()` 没刷确认键 → 电弧一张没选时按钮是亮的

`SetTitle` / `Layout` 都不碰 `interactable`，于是按钮保留 prefab 里的初值
（`Button` 默认 `interactable = true`）——**恰恰是用户点名要拦的那条没拦住**。

**修法双保险**：
- `Show()` 在 `Layout()` 之后补一句 `RefreshConfirm()`；
- 构建器把初始值写成 `confirm.interactable = false`，
  让「万一没走到那段代码」时按钮偏向不可按，而不是偏向可按。

### 3. ⚠ `RefreshSlots` 的 `SetSiblingIndex(i)` 把牌埋到 Backdrop 底下

**这是本轮最隐蔽的一个**，前两次都被误判成「Play 会话的旧内存副本」。

现象：面板**宽度对了**（909）、副标题「3 / 6」也对，**但框里一张牌都看不见** ——
截图里就是一块空的深蓝面板。

查了三处口径后确认 **prefab 资产与场景实例都是对的**
（`Backdrop[0] → EmptyFrame[1] → Slot0…7[2..9]`，`assetType = Regular` / `instanceStatus = Connected`），
**是运行期被改掉的**。真凶在 `RefreshSlots` 里：

```csharp
slot.transform.SetSiblingIndex(i);   // ✗ 假定槽位从下标 0 开始
```

`SlotArea` 的子节点是 `[Backdrop, EmptyFrame, Slot0…Slot7]`，
而 `SetSiblingIndex(0/1/2)` 把前三个 Slot **挤到了 Backdrop 前面** ——
同层绘制顺序 = 兄弟顺序，于是 **Backdrop 反过来盖住已经放好的牌**。
第 4 张起又回到 Backdrop 后面，所以 `Slot3…7` 没事，
这才让错序看起来像 `Slot0,1,2, Backdrop, EmptyFrame, Slot3…7`。

**修法**：槽位下标要从「装饰之后」起算，且基准要取**装饰**的下标（槽位自己会被写坏，
读它们的下标会得到 0、无法自愈）：

```csharp
int slotSiblingBase = SlotSiblingBase();   // = Backdrop / EmptyFrame 中挂在 SlotArea 上的个数
...
slot.transform.SetSiblingIndex(slotSiblingBase + i);
```

修后实测层级：`Backdrop[0] EmptyFrame[1] Slot0[2] Slot1[3] Slot2[4]` ✔，
截图 `m27_handpick_07_3cards_fixed.png` 三张牌正常显示。

> 教训：**「先怀疑陈旧会话」不能连用两次**。第一次 refresh 后仍复现，
> 就该去读**运行期**谁动了 `transform` —— `SetSiblingIndex` 这类写法在
> 「父节点前面还有装饰节点」时必然出错，而它在父节点只有槽位时完全正常（M25 的 Peek 就是这样，所以没暴露）。

其实构建器已经把 `Backdrop` 建在 `EmptyFrame` 与 Slot 循环**之前**（这条是对的，不要再动），
问题只出在运行期的重排没把这段前置量算进去。上面的 8 px 上下 bleed
（`Stretch(rt, 0, -8, 0, -8)`）是为了盖住原图内框描边外面那层薄辉光 ——
只盖到 280 会在上下各留一条发亮的边。

## 遗留 / 已知取舍

- **`HandPickFlySeconds` / `HandPickRemoveSeconds` 目前没有对应的补间**：
  常量已在 `UiLayout` 里定义，但 `HandPickView` 现在落位用的是 Slot 自己的
  放大回弹（`HandPickAddSeconds`），没有做「从手牌位置飞进卡框」那一段位移。
  用户口径里的「手牌进入到卡框的位置」当前表达为**卡面直接出现在卡框里 + 回弹**，
  没有飞行动画。若要求「看得见牌飞过去」，下一步要接 `CardTransitView`（M20 就有的飞牌层）。
- **背板（Backdrop）必须排在 Slot 之前**：这条依赖构建器的建造顺序，
  不是运行时能纠正的。若将来有人调整 `BuildHandPickLayer` 里的语句次序，要连这里一起看。
- `Peek_Frame.png` 被 M25 的 `PeekLayer` 与本轮的 `HandPickLayer` **共用** ——
  九宫格 border 由 `EnsurePeekImporters()` 统一对账，改动要一次改到位
  （`UiLayout.HandPickPanelBorder*` ↔ meta ↔ `UiTheme.HandPickPanelTorso` 三处一致）。

## 测试踩坑（写给下次做同类反射验证的人）

**`Option.Index` 必须给唯一值**。`HandPickView.IndexOfSelected()` 是按
`Option.Index` 配对的（不是按引用、也不是按 `Card.Uid`）：

```csharp
if (_selected[i].Index == option.Index) { return i; }
```

于是用反射手搓合成 `Option` 时，如果忘了设 `Index`，**所有选项的 `Index` 都是 0**，
第二次 `Toggle()` 就会命中 `_selected[0]`、被当成「再点一下 = 取消」，
现象是「选第 2 张 → 已选反倒变成 0」，看着极像产品 bug，其实是测试夹具的错。
真引擎走 `BuildOptions` 时 `Index` 是唯一递增的，所以真机不会触发。

本次排查路径（可复用）：先怀疑数据 → 打出 `avail` 里的 `Card.Uid` 看是否重复（不重复）
→ 再看 `FindByUid` / `IndexOfSelected` 的返回值 → 定位到按 `Index` 配对 → 补 `Index` 即通过。
