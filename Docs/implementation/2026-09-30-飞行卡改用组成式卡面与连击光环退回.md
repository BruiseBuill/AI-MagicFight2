# 飞行卡改用组成式卡面 + 连击光环「按取消处理」

> 状态：已落地 · 日期：2026-09-30 · 范围：战斗界面 `CardTransitView`（飞行卡）+ 光环提交口径（`AuraResolver` / `BattleEngine` / `BattleUi`）

## 背景与目标

用户口径（2026-09-30）：

> 1. 玩家头顶上的牌进入到冷却区时，中途会突然出现牌面内容消失，只留插画向冷却区移动，
>    然后移动到冷却区之后，牌面又立即出现。显然牌面内容不应该消失。
>    你应当将这个动画彻底播完，即头顶的牌完全移动到了冷却区。
> 2. 对于连击光环，由于连击效果不可叠加，所以又使用了连击光环、又打出了一张带有连击效果的卡时，
>    这个连击光环应当处理为玩家最终取消了使用该光环
>    （在玩家打出牌之后，播放光环归原位的动画，即取消使用的动画）。

两件事各自独立，但都落在「表现层两个瞬变之间要有一段真的在动的过程」这一条上。

### 问题 1：飞行卡是无框无字的插画

[上一轮](2026-09-30-头顶出牌展示改用组成式卡面.md)已经把**头顶出牌展示**换成组成式卡面，
于是同一次飞行的**起点**（头顶那张牌）与**终点**（冷却迷你卡）都是卡框 + 卡名 + 力量 + 冷却 +
效果文字，**中间那段**却还是一张纯 `Image` 吃插画（`CardTransitView.Launch` 里
`face.sprite = library.GetIllustration(...)`）。三处拼起来就是用户描述的现象：
牌面内容在起飞的一瞬间消失、只剩插画飞过去、落地又「啪」地冒出来。

**目标**：飞行卡也画成组成式卡面 —— 起点与终点是同一张脸，中间这段才读得出「就是这张牌飞过去了」。

本次**不含**：飞行轨迹 / 时长 / 弧线（全部照旧），也不含「插画槽 cover 算法」等卡面内部版式。

### 问题 2：用不上的连击光环被白白花掉

连击不可叠加（`AttackContext.HasCombo` 只有 true/false）。玩家准备一枚连击光环、又打出一张
**卡面自带连击**的牌时，那枚光环被 `AuraResolver.Consume` 消耗掉，而 `_atk.HasCombo` 本来就是 true
—— 一边白花一枚指示物，一边屏幕上的表现是「准备标记瞬间消失、图标瞬间回原位」（两个瞬变）。

**目标**：这种情形按「玩家最终取消了使用这枚光环」处理 ——
**引擎不消耗它**，**界面**在出牌之后把那一枚从准备位**滑回默认位**（复用它已有的取消动画）。

## 方案与影响

### 一、飞行卡改画组成式卡面（`CardTransitView`）

| 位置 | 改动 |
|---|---|
| `TakeGhost` | 由「返回 `Image`」改成 `RectTransform TakeGhost(out CardView face)`：**优先**实例化/复用组成式卡面，拿不到那份 Prefab 才退回插画那条老路 |
| `Flight` | 多一个 `public CardView Face`（`null` = 走的是插画那条退化路径） |
| `Launch` | `cardFace.Bind(snapshot, ViewMode.Mini, 0)` + `SetFaceWidth(起点卡宽)`；**不**调 `SetInteractable(false)`（它会连带 `SetDimmed(true)` 把卡面压暗），改用 `SetGestureHold(true)` 只停 `Button` |
| `LateUpdate` | `ApplyPose` 之后按当帧位姿宽度重申一次 `SetFaceWidth(pose.Size.x)` —— 卡面的内部缩放只有这一个入口 |
| `ReleaseGhost` | 收两个池子：`_cardPool`（组成式，`Clear()` 后回收）/ `_ghostPool`（插画，退化路径） |

**卡面 Prefab 从哪来**：向 `CooldownView` 新开的只读口 `CooldownView.CardPrefab` 要
（它就是唯一那份 `CardView_Hand.prefab`，铁律 9）。这样**不需要动任何 Prefab** ——
`CardTransitView` 本来就已经持有冷却区引用，而「飞行卡与冷却迷你卡必须是同一份」正是落地那一刻不跳的前提。

**为什么接缝看不见**：起点那帧，飞行卡的「根矩形尺寸 = 头顶卡位那块矩形、`SetFaceWidth` = 头顶卡宽」，
与头顶卡位里那个 `CardFace`（同样是 `CardView_Hand` 的实例、同样四角拉伸 + 同一个卡宽）**逐项相同**；
终点那帧同理等于冷却迷你卡。两端的 `sizeDelta` 都是每帧从同一次 `ReadPose` 里读出来的。

**射线**：卡面自带 `Button`，但 `CardTransitLayer` 的 `CanvasGroup.blocksRaycasts = false`
已经让整棵子树退出射线判定（`Graphic.Raycast` 沿父链查 `CanvasGroup`）；
`SetGestureHold(true)` 是第二道保险。

### 二、连击光环「按取消处理」

**判据只写一处**：`Core/Battle/Resolvers/AuraResolver.cs` 新增

```csharp
public static bool CardGrantsCombo(CardDef card)              // 卡面 α 效果里有 EffectOp.Combo
public static void CollectRefunded(List<Option> auras, CardDef card, List<int> into)
```

`CollectRefunded` 把**三条**既有/新增判据收在一处，填出「准备了、但最终不消耗」的下标：

1. **沉重打击**（`card.ForbidsAtkBuff`）→ 本次准备的光环**整批**都不生效（原本就是整批 `continue`，口径不变）；
2. **连击阈值**：连击光环只对「基础力量 ≤ A」的牌有效，超了无事发生（原本就有）；
3. **连击不可叠加**（新增）：卡面自带连击、或本次进攻前面已经有一枚连击光环真的生效了，后面的连击光环没有意义。

两个消费者调**同一个函数**：

| 消费者 | 落点 | 做什么 |
|---|---|---|
| 引擎 | `BattleEngine.ApplyPreparedAttackAuras` | 名单里的**不调用** `ApplyAuraOnAttack` → 既不生效、也不 `Consume` |
| 界面 | `BattleUi.RefundUnusedAuras`（新） | 名单里的从 `_preparedKeys` 摘掉 → 记进 `_returningKeys` → `PreparedAuraView.FlyHome(0.30 s)` |

> ⚠ 两边各写一份判据迟早分叉成「图标回到原位了、指示物却已经被消耗」——
> 这正是铁律 3「规则约束只收敛在引擎一处」要避免的。界面这边只是**消费** Core 给的名单。

**界面的时序（`BattleUi.Pick`）**：

```
RefundUnusedAuras(option)          ← 必须先于下面两句
  ├ 从 _preparedKeys 摘掉该退的键（摘掉之后才不会被提交给引擎）
  ├ HomeSlotFor(key) 算它回默认位后占第几格（按「已删掉它」的集合算）
  ├ _returningKeys.Add(key)        ← HudBuff 那枚继续隐着
  └ _preparedBar.FlyHome(key, home, AuraReturnSeconds)
PreparedAuraIndices()              ← 只提交「真的会用掉」的那几枚
ClearDecision(keepReturning: true) ← 只收还没起飞的标记，别把刚起飞的这段掐掉
_driver.SubmitPlayerDecision(...)
```

`ClearDecision` 为此多了一个 `bool keepReturning` 重载（原有无参版转调 `false`，行为不变）；
`PreparedAuraView` 相应新增 `ClearMarkers()`（= `Bind(null)`，**不**走 `AbandonReturns`）。

**明确不覆盖**：「放弃防御」（Skip 选项，没有 `Card`）时准备的力量光环同样不被消耗，
但那条路上不播归位动画 —— 行为与改动前一致（见「后续事项」）。

## 后续事项

- **「放弃防御」时准备的力量光环不播归位动画** —— 引擎同样不消耗它，界面上是
  「准备标记消失 → 图标立刻出现在默认位」两个瞬变（与改动前一致）。
  要补齐只需在 `RefundUnusedAuras` 放行 `option.Card == null` 的 Skip 分支，
  并在界面侧也知道「这一拍没有牌」时按「不适用」处理（口径待确认，本次故意没做）。
- **头顶卡宽仍是 `UiLayout.PlayedCardWidth = 116`**（= 手牌的 0.59 倍）：
  飞行途中卡面最小会被 `0.72` 的起跳缩放压到 ~83 px，效果文字在那个尺寸下读不出细节
  （能看出「是什么牌」）。要放大只动这一个常量，但头顶纵向余量要重新核。
- 真机端到端（真人拖拽出牌 → 头顶展示 → 飞进冷却区）那条链路照旧未跑。
