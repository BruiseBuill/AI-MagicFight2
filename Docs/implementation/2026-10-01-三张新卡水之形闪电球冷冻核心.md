## 2. 水之形：第一处「跨回合不消失」的力量

在此之前，引擎里的力量改动全是**本次攻防范围内**的（`AtkPlus` 写在
`AttackContext` 的临时增量上，攻防结束即蒸发）。水之形的「**基础力量**加 X」不是那种东西 ——
用户明确写了「仅针对于本场战斗」，也就是**改的是牌，不是这一刀**。

### 2.1 落点

| 位置 | 做了什么 |
|---|---|
| `CardInstance.BattlePowerBonus` | 累计成长（`internal set`，本场战斗内一直有效） |
| `CardInstance.ResetEffectivePower()` | **唯一**重算有效力量的地方：`EffectivePower = Def.Power + BattlePowerBonus` |
| `CardInstance.ToHand` / `ToPool` | 原来写的是 `EffectivePower = Def.Power` → 改成调 `ResetEffectivePower()` |
| `CooldownOps.PutIntoCooldown` | 同上（这一处最阴，见 §2.3①） |
| `EffectOp.GrowBasePower = 33` | 新算子，`EffectStage.Power`，α / β 各一条，自动效果（无决策） |
| `BasePowerGrownEvent` | 新事件：成长的凭据（自测与回放都靠它） |
| `CardInstance.PowerLabelText` | **显示侧同口径**的新入口：模仿 `"X"`，其余取当前有效力量 |
| `Snapshot.PowerText` / `BattleEngine` 出牌文案 | 改读 `PowerLabelText`（见 §2.3④） |

### 2.2 「进攻后 / 防御后」是自然得到的，不需要新时机

算子归 `EffectStage.Power`：

- **α** 在 ① 力量阶段跑。但 `_atk.BasePower` 是在**选牌那一刻**就取好的快照
  （`DoChooseAttackCard` 里 `_atk.BasePower = card.EffectivePower`），① 阶段里再改牌面也不会回头改它；
- **β** 带 `EffectTrigger.Defend`，被 `BattleEngine.StageOf` 从「力量阶段」**改派到 ② 防御阶段**跑
  （与潮汐 / 地动波的 β 力量 +1 同一个机制）。而防御比拼在**提交那一刻**就算完了
  （`DefenseResolver.BuildOptions` / `RequiredBonus`），② 阶段跑的时候已经晚了一步。

两处都「晚一步」，正好就是卡面写的「每次进攻 / 防御**后**」。**本次不追认** ——
用户 2026-10-01 明确选了这一口径。

### 2.3 三个容易做错的点

**① 只改 `EffectivePower` 会被静默抹掉。**
牌进冷却区（`PutIntoCooldown`）、回手（`ToHand`）、回牌池（`ToPool`）都会重算有效力量。
第一版只写 `EffectivePower += amount`，表现是「第一次打完明明加了 2，回手又变回 1」——
**不报错、不崩**，只有把「进冷却区之后再看一眼」写进断言才抓得到（`NewCardsScenario` 就是这么干的）。

**② β 那条靠 `StageOf` 的改派，漏了就整条不结算。**
`EffectStage.Power` + `Trigger == Defend` → `EffectStage.Defense` 是引擎里唯一一处
「按触发符号换阶段」的地方。忘了这条，防御侧永远不加力量，而万局统计全绿。

**③ 模仿（x）不吃成长。**
模仿的 α 能复制「基础冷却 ≤ 3 且无光环」的法术 —— 水之形（冷却 2、无光环）正在其中。
复制过来之后 `EffectContext.Source` 是**模仿自己**，于是「此卡的基础力量 +2」会写到模仿身上，
与它卡面恒定的「未复制时力量视为 1」+ 力量显示为 `X` 直接矛盾。
处理：`BuiltinEffects` 里 `GrowBasePower` 遇到 `Def.HiddenPower` 直接 return（一行，写在算子内）。

**④ 显示侧必须同口径 —— 引擎按 3 打、卡上却写着 1。**
卡面的力量一直读的是 `CardSnapshot.PowerText`，而那一位以前直接取自**卡表的静态** `CardDef.PowerText`。
对既有 42 张卡这没问题（卡面力量从不变），但水之形会长 —— 第一版做完之后，
**引擎按 3 打、手牌上还写着 1、出牌提示也写着 1**，整条效果在界面上是隐形的。
修法：新增 `CardInstance.PowerLabelText`（模仿 `"X"`，其余取 `EffectivePower`），
`Snapshot.PowerText` 与 `BattleEngine` 的出牌选项文案都改读它；
自测里也钉了一条「进冷却区那一刻快照力量文本必须是 \"3\"」。
> 这与此前那条「手牌的力量预览不体现**虚弱**」（见 [00-当前基线](../00-当前基线.md) §4）是**不同**的事：
> 虚弱是「这一拍的临时折扣」，成长是**这张牌自己的属性** —— 后者不显示就是纯 bug。

## 3. 闪电球：「最后一张手牌 → 连击」是一条**不可达**的条件

⚠ 这是本轮唯一需要用户拍板的地方，记录在此以免以后被当成 bug 反复查。

**问题**：现行规则里「连击」= 本次进攻结算完后**再打出 1 张**（`01-规则基线.md` §3 关键字表），
而追加进攻的门槛在 `DoStage6`：

```csharp
bool chain = _atk.HasCombo && attacker.Hand.Count > 0 && State.ComboDepth < MaxComboChain;
```

「最后一张手牌」意味着打出后 `Hand.Count == 0` → **条件恒不成立，连击永不发生**。

**用户 2026-10-01 的决定**：「连击如果不出牌，实际上也不会扣血（每次进攻回合只需要至少打出一张牌即可），
这张牌就按照字面意义上来即可」→ **按字面实现**（条件 `hand-at-play = 1`）。

顺带确认了一件好事：`Hand.Count == 0` 时 `DoStage6` 不会进追加进攻，所以也**不会**走到
`DoAnnounceHalfTurn` 里那条「手上无牌 → 掉 1 点」的惩罚分支。**这条效果既不会生效、也不会反噬。**

**实现**：`EffectOp.ComboIfLastHand = 34`，构造 `EffectDef` 时自动挂
`hand-at-play = 1`（与地震 `SlowIfLastTwoHand` 的自动挂条件同源，只是阈值 2 → 1）。

**测试只能做反面对照**：手牌 ≥2 张时打出闪电球，**不得**出现 `IsComboFollowUp = true` 的半场开始事件。
条件若被漏掉（退化成无条件 `Combo`），这条立刻变红。

> ⚠ 另记一条**有意为之**的口径：`AuraResolver.CardGrantsCombo` 只认 `EffectOp.Combo`，
> 所以准备了「连击光环」再打闪电球时，那枚光环**不会被按「卡面自带连击」退回**。
> 理由是闪电球的连击带条件，把它当「自带」会让光环在这一拍无谓地弹回去。

## 4. 冷冻核心：纯录入

`α 减速 + α 光环（防御力量 +3）`。两个算子（`Slow` / `Aura` + `AuraKind.DefPower`）都是既有的，
唯一要注意的是 `ValidateAuraTriggers`：**同一张牌的光环必须同符号** —— 这里只有一枚 α 光环，天然满足。

行为侧只证明了两件事（`NewCardsScenario` 的第四条）：进冷却区真的点亮了那枚 `DefPower / 3` 指示物；
防御拍它真的出现在候选里，准备之后 `DecisionRequest.ContextDefenseBonus` 真的变成 3。

### 6.3 ⚠ 自测的最终结果仍是 ❌，原因是一条**既有**噪声

12 条 `区域类选项的 k 或匹配张数非法`（本次落在 seed 20261700 ×9 + 20261701 ×3，列表封顶 12）：

- 判据在 `RuleAssertions.cs` 里：`OptionKind.ZoneValue` 的选项要满足 `Value >= 1 && Count >= 1`；
- 根因**早已定位**（见 [00-当前基线](../00-当前基线.md) §4）：`BuiltinEffects.Cooldown` 生成区域档选项时
  **没有设 `Option.Count`**；
- **与本次改动无关**：本次没碰区域档那条路径，违规类别与上一轮逐字相同。

> 为什么不顺手修：补上 `Count` 会**改变 AI 行为** —— `SimpleAiAgent.PickDensestZone` 正是按
> `o.Count` 挑「影响面最大的那一档」。现在因为 `Count` 恒为 0（初始 `bestScore = -1`），
> AI 实际是「取第一个有利档」；补上之后它会真的去挑最密的那一档。那需要单独一轮回归，
> 不属于「加三张卡」的范围。

   战斗池 `BattlePool` 是 `useAllCards`，自动包含 45 张。

   三张都已经在了。
