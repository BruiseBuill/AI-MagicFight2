## 用户口径

> 1. 不要显示这些黄色的提示方块，真正需要高亮显示的只有 `ArtLayer/coolingScroll`（双方）
>    当中的 `Slotcol` 当中的 4 个 image，这共 8 个 image 在此时被点击到时，就代表玩家选择了这个区
> 2. 移除掉中间的文字提示，只需要显示一个不执行选项即可

补充澄清（回答「高亮范围怎么定」）：
- 高亮范围 = **只亮槽底图本身**，不是整个行范围、更不是整片视口。
- 点击语义 = **先判属于哪一方 → 再判属于哪一个区 → 对该区域内的所有牌加速 / 减速**。

## 改之前的实际画面对不上（先说清病因）

M24 #2 的做法是：把**滚动视口的 `Image`**（`ArtLayer/CoolingScroll_Player` /
`CoolingScroll_Enemy`，平时全透明、只当遮罩载体）涂一层暖金 @ alpha 0.16。

那块视口是 **674 × 621**（`SlotColumnBudgetWidth` 224 + 卡宽 137.8 + 3 × 步进 101.4 = 674，
高度 = 1080 − 手牌区 344 − top 115 = 621），而实际有内容的「槽图」只有 182～193 宽、84～100 高，
缩在视口左上角。于是屏幕上看到的是——

- 一大片黄框盖住整个上半屏，**把迷你卡也蒙进去了**（用户截图里卡面发黄正是这个）；
- 而真正表达「这一格是什么」的槽位徽标（「N / 冷却区N」）反而被同一块黄色糊住。

一句话：**高亮的矩形与它想表达的东西形状不一致**。

## ① 高亮改成 8 个槽位底图

### 数据来源

`CooldownView` 一直持有两侧的行挂载点数组
（`_playerRows` / `_enemyRows`，由 `BattleArtLayerBuilder.BuildSlotColumn` 生成
`SlotL_Col/SlotL_CD4…1` 与 `SlotR_Col/SlotR_CD4…1`，每侧 4 个）。这些行节点的
`Image.sprite` 就是那 8 张槽位图，平时 `color = 纯白 1.0`（把槽图画成原色）。

于是「点亮」= 把这 8 个 `Image.color` 换成 `UiTheme.ZonePickableEdge`，
「复位」= 换回 `Color.white`：

```csharp
private void ApplyZoneHighlight(int seat)
{
    RectTransform[] rows = RowsFor(seat);
    if (rows == null) return;

    bool on = _zonePickable && _zoneSeats.Contains(seat);
    Color c = on ? UiTheme.ZonePickableEdge : Color.white;

    for (int i = 0; i < rows.Length; i++)
    {
        Image img = rows[i].GetComponent<Image>();
        if (img == null) continue;
        img.color = c;
        img.raycastTarget = on;   // 见下
    }
}
```

- **不新增任何节点**，改的还是构建器预建的那 8 个 —— M21 的教训（运行时 new 的节点
  会被构建器推倒重建冲掉）继续避开。
- `ViewportFor` 保留（`ZoneClickCatcher` 时代留下的），但**高亮不再用它**。

### ⚠ 槽图的 `raycastTarget` 要按状态开合

构建器建槽图时写的是 `raycastTarget = false`（理由：「不挡操作」）。
这在本轮之前没问题（点击由视口接），但现在**接收入口挂在槽图自己身上**，
`raycastTarget = false` 时它根本收不到射线。

所以 `ApplyZoneHighlight` 顺手把 `raycastTarget` 跟着状态一起切：
**区域决策那一拍打开、平时关回去**。平时关着这一点不能省 ——
槽图是 `Cards` 容器的父节点，把它一直开着会在「点槽图露出部分」时
多出一条与常态不同的命中路径（虽然冒泡链上没人处理、不会有后果，
但让一个平时不该接射线的节点接射线，是给下一个改版式的人埋雷）。

## ② 点击语义：从「哪一片」精确到「(座位, 行) → k」

### 槽位徽标就是行的语义

槽图上烘的「`N` / 冷却区`N`」= **这一行的牌还剩 N 回合**（`k = 4 − 行下标`，
行 0 = 冷却区4 → k=4；行 3 = 冷却区1 → k=1，与 `BindGrouped` 的
`rowIndex = Clamp(4 − RemainingCooldown, 0, 3)` 完全同口径）。

所以**点第 N 行 = 选 k=N 这一档**，不需要任何文字提示 ——
玩家看得见的徽标就是答案。这也是用户第 2 条「移除中间文字提示」能成立的前提。

### `CooldownView` 侧

`ZoneClicked(int seat)` → **`ZoneRowClicked(int seat, int rowIndex)`**（两参数）。
接收器从「视口一个」改成「8 个槽位各一个」：

```csharp
public sealed class ZoneSlotClickCatcher : MonoBehaviour, IPointerClickHandler
{
    public int Seat;
    public int RowIndex;
    public CooldownView Owner;
    // → Owner.NotifyZoneRowClicked(Seat, RowIndex)
}
```

`EnsureZoneClickCatchers`（`Awake` 里调）遍历两侧的 4 行，逐个
`AddComponent<ZoneSlotClickCatcher>()` 并回填 `Seat` / `RowIndex`。
运行时 `AddComponent` **不落盘**，所以 Prefab 不会被写脏（实测确认，见「验证」）。

### 落在卡面上的点击（`OnCardClicked`）也要跟上

迷你卡是行节点的下层子节点，`EventSystem` 派发 `pointerClick` 时**遇到第一个能处理的
节点就停**，卡片自己带 `Button` —— 所以点在牌面上永远到不了槽位接收器。
这条补路原来就在（M24 #2 的教训），本轮只把「报座位」改成「报座位 + 行」：

```csharp
if (_zonePickable)
{
    int seat = SeatOf(card);
    if (seat >= 0 && _zoneSeats.Contains(seat))
    {
        int row = RowIndexFor(card);      // 从祖先名 Slot*_CD* 解析
        if (row >= 0) { NotifyZoneRowClicked(seat, row); return; }
    }
}
```

`RowIndexFor` 沿 `transform.parent` 往上找第一个名字以 `SlotL_CD` / `SlotR_CD`
开头的祖先，再用 `RowIndexFromSlotName` 取名字末位数字 `N`、算 `行 = 4 − N`。

### `BattleUi` 侧

`OnCooldownZoneClicked(seat)` → **`OnCooldownZoneRowClicked(seat, rowIndex)`**：

```csharp
int value = 4 - rowIndex;
for (int i = 0; i < options.Count; i++)
    if (options[i].Value == value) { Pick(options[i]); return; }

// 这一格没有对应的档（该剩余冷却值上没有牌 / 引擎没给这一项）——
// 不做任何事，也不退回浮层：玩家点的是空格，理应没有后果。
```

**仍然是「拿 (座位, k) 去本拍 `Options` 里找那一项」**（铁律 3）：
界面不替引擎判断，点了一格没有牌的槽 = 那个档在引擎里根本不存在 = 无事发生。

顺带删掉了旧的分支「该侧多档 → 退回浮层只列该侧的档」——
那是因为「点整片」表达不了「选哪一档」而被迫做的折中；
现在一格子对应一档，这个折中**不再需要**，代码反而更短。

`SkipOnlyList` 这个私有辅助也随之删除（`TargetPicker.ShowSkipOnly` 自带同样的逻辑）。

## ③ 浮层只留「不执行」

`BattleUi.HandleDecision` 里区域那一拍：

```csharp
else if (_zonePickMode)
{
    _picker.ShowSkipOnly(snap.Options);

    // 例外：若本拍**只有**「双方」档（雪崩 SlowZoneBoth），没有任何侧别可点，
    // 那就没有「点哪一格」这回事，只能把档列出来让玩家挑。
    if (_zoneBySeat[0].Count + _zoneBySeat[1].Count == 0)
        _picker.Show(string.Empty, _zoneBothOptions);
}
```

复用了 M24 #2 就写好的 `TargetPicker.ShowSkipOnly`（它内部只挑出 `IsSkip` 那一条，
标题传空字符串 → 标题行隐藏）。这一次**不再有档位文案**，
所以用户截图上那两行「我方冷却区剩余冷却 = 2 的 1 张牌全体加速」整段消失。

**雪崩（`SlowZoneBoth`）的例外必须保留**：它只有一个 `Seat = -1` 的选项，
两侧的槽位都不该被点亮（`SetZoneSeats` 收到空集），也就没有「点哪一格」这回事 ——
不给它列档就等于这张牌无路可走。

## 引擎侧

**一个字符都没改。** `BattleEngine.IssueZoneValue` 仍然按
「(座位, 剩余冷却 = k)」一档一个 `Option{Kind=ZoneValue}`，
`SlowZoneBoth` 仍然是单个 `Seat = -1`。本轮改的全部是「玩家用哪个手势挑出那一项」。

## 遗留 / 已知取舍

- **槽图只有 3 行可见**：视口 674×621 里 4 行内容共 804.8 高，所以要滚——
  截图里两侧都只看到「冷却区4 / 3 / 2」三格，「冷却区1」在滚动区下方。
  这是 M11 就定下的版式（`SlotRowPitch` / `SlotMiniCardHeight`），
  本轮没动；被点亮但需滚动才够得着的第 4 格同理（它的 `color` 与
  `raycastTarget` 都已被正确设置，只是不在视口内）。
- **雪崩（`SlowZoneBoth`）仍走浮层列档**：见 ③ 的例外。它没有「哪一侧 / 哪一格」可言，
  这是规则形状决定的，不是实现偷懒。
- **`RowIndexFor` 依赖节点名**：靠 `SlotL_CD` / `SlotR_CD` 前缀 + 末位数字解析。
  若将来槽位节点改名，这里要跟着改（比记一个索引更稳，因为 `BindGrouped`
  会把迷你卡在行之间搬来搬去，索引会失效，名字不会）。
- 提示类颜色（`ZonePickableEdge`）仍然**只在 `UiTheme` 里定义一次**，
  运行时只改 `Image.color` 的值，prefab 里存的是复位值纯白 ——
  与「提示色只写在 prefab」那条不冲突（那一条约束的是需要手调的判定底色）。
