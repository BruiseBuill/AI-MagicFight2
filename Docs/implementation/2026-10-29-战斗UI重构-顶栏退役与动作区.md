> 状态：变更记录 · 本文为当时实现的快照，旧规则、卡牌及完成状态不代表当前版本。现行内容见 [当前基线](../00-当前基线.md) 与 [规则基线](../rules/01-规则基线.md)。

> 用户口径：「当前很多信息都塞在战斗界面顶部横条里，太丑；逐条判断每条信息该放哪、以什么形式显示。

> 本文是**落地记录**，方案原文见工作区 `_plan/2026-10-28-战斗UI重构方案.md`。

## 1. 结论：顶栏整条删掉

原来的 `ArtLayer/Hud`（708×95 `Hud_Bar`）里有 6 项信息，**其中 4 项与别处重复**：

| 顶栏项 | 重复对象 |
|---|---|
| 生命 `4/4` | 角色头顶徽标 |
| 未用光环数 `0` | 徽标外侧的光环图标（一枚图标 = 一枚指示物） |
| 手牌数 `×6` | 手牌就摊在屏幕上（≤8 张全可见） |
| 齿轮（设置） | 全局覆盖层右上角那枚 84×84（M44，五场景统一） |

真正"只有顶栏有"的是头像 + 名字，而固定 1v1 里这两个没有信息量。
所以不是重排，是**删掉整条**，把信息下沉到它描述的对象旁边。

同批退役的还有：左下 150×150 能量球（只表达 `0/1` 的相位）、
屏幕正中的 54pt `ActionBanner`（正好压在两个角色身上）。

## 4. 规则改动：有牌也能结束进攻

原实现是硬禁：`BattleEngine.IssueAttackCard` 里 `ContextNoSkip = true`，
且 `DoChooseAttackCard` 对"没选牌但手上有牌"会**兜底打第一张**。

现口径（用户 2026-10-29）：

- 手牌 > 0 时，进攻拍额外给一条 `Skip`（文案「结束进攻」），`ContextNoSkip = 手牌为空`；
- `DoChooseAttackCard` 删掉兜底：没选牌 = 结束进攻，走 `EndHalfTurn`
  （与角色能力 `SkipAttack` 同一条收尾路径，**不掉血、不消耗**已准备光环）；
- 手牌为空时不补 Skip —— 那一拍仍按规则「无法攻击 → 掉 1 点」处理。

> ⚠ **2026-10-30 修订**：上面「结束进攻不掉血」已按用户口径**回退** —— 进攻半场一张牌都没打出
> 就掉 1 点（动作区同时把「−1」标出来）。现在两条路（主动结束 / 手牌为空）走同一段结算，
> 只有日志里的原因不同。规则文档 §3 与 §11 的对照表已同步。


⚠ AI 两个 agent 扫选项都用 `IsCardOption`（排除 `IsSkip`），行为不变。
规则文档 `rules/01-规则基线.md` §进攻 已同步。

## 9. 坑

- `DecisionSnapshot` 是 **struct**，不能写 `snap == null`。
- `PromptBar` 默认 `SetActive(false)`（有文案才亮），别以为它坏了。
- 动作键与 `TargetPicker` 会重复：浮层必须按 `_dockSubmit` 把同一个选项滤掉，否则屏幕中央多一个同样的键。
- 改完代码**要等编译真正结束**再跑构建器：`refresh_unity` 返回 `idle` 不代表编译完了；
  判据是反射查新符号（例如 `UiTheme.IvoryPanel` 是否存在），否则会用旧程序集重建出旧颜色。
- Play 用 MCP 的 `manage_editor{action:'play'}`；`EditorApplication.isPlaying = true` 在这条链上不生效。
