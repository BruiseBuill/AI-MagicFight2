> 状态：已落地 · 日期：2026-09-30 / 10-01 · 范围：`Upgrade.unity` 单场景（点石台 → 选牌 → 力量 +2 → 播动画 → 结束节点）、Core 强化规则、三场景卡池分离、强化卡的资产落盘、`Assets/Art` 根目录散图归类

## 背景与目标

用户口径（2026-09-30）：

> 有很多没有被归到子文件夹下的图片，请你之后也进行归类。首先，reference4 是你需要参考的
> 最终的效果图片，Background 是这个场景的背景。
>
> 这个场景中的效果应当被描述为，当玩家点击图中的台面时，弹出一个浏览自己卡池的界面，
> 类似于商店当中的背包效果，但是在强化场景的界面当中，玩家需要选择卡池当中的一张牌，
> 被选中的牌边缘发光，确认之后，这张牌将会被强化，其余基础力量永久加 2。
> （现在的游戏还在测试阶段，你需要将各个场景的卡池进行分离，基础力量永久加 2 的本质是

> 以及最多只能将基础力量提升到 9。基础力量为 X 的牌无法提升，沉重打击也无法提升。

## 方案与影响

### 一、Core：强化的唯一口径（`CardUpgrade`）

新增 `Assets/Scripts/Core/Cards/CardUpgrade.cs`（零 `UnityEngine` 依赖）：

| 成员 | 口径 |
|---|---|
| `PowerStep = 2` / `PowerCap = 9` | 每次 +2，结果封顶 9 |
| `CanUpgrade(def, out reason)` | 三条拒绝：`HiddenPower`（模仿 `x`，力量显示 X）/ `ForbidsAtkBuff`（沉重打击 `h`，卡面写着「进攻力量不能增加」）/ 力量已达 9 |
| `UpgradedPower(def)` | `min(9, def.Power + 2)`，取的是**当前**力量（反复强化是在它自己身上再加） |
| `UpgradedId / UpgradedName` | 基础 ID / 卡名挂一个 `+`，**去重不叠加**（反复强化不会变成 `暴风雪++`） |
| `Apply(def, index)` | 造一份新的不可变 `CardDef`：只改力量与卡名，**冷却 / 效果 / 元素 / `HiddenPower` / `ArtId` 逐项沿用** |

**为什么判据不写卡 ID**：`HiddenPower` 与 `ForbidsAtkBuff` 是卡表里已有的事实（见 `CardDef`），
以后再加一张「力量不能增加」的牌，只要它在卡表里带上 `NoAtkBuff` 就自动生效，
不需要回来补一个 ID 分支。

**为什么 `ArtId` 必须沿用**：卡面插画是按 `ArtId` 查 `CardArtLibrary` 的，
强化卡的 ID 是 `a+` 而插画表里只有 `a` —— 让新 ID 自己去查会得到一张纯色板，且零报错。

### 二、三场景卡池分离（`CardPoolConfig`）

新增 `Assets/Scripts/Unity/Configuration/CardPoolConfig.cs`（ScriptableObject：`poolId` /
`displayName` / `useAllCards` / `cardIds` / `preferUpgraded`），并在
`Assets/Resources/Pools/` 落地三份资产：

| 资产 | 内容 | 消费者 |
|---|---|---|
| `BattlePool` | `useAllCards = true`（全部卡表，与改造前逐字一致） | `CharacterConfig.cardPool`（`DefaultPlayer.asset` 已指向它） |
| `ShopPool` | 8 张起始牌池 | `ShopSceneEntry`（**原先写死在这里的那份静态数组已搬走**） |
| `UpgradePool` | 8 张起始牌池 | `UpgradeSceneEntry` |

**`preferUpgraded`（默认开）是这次的关键规则**：解析卡池时，若卡表里存在 `<id>+`，
就用强化版顶掉基础版。它同时解决两件事 ——
① 设计规格 §10.2 明文禁止的「基础版与强化版作为两张牌同时进卡池」；
② **「永久 +2」的闭环**：卡池资产里写的永远是基础 ID，但强化版一旦落盘，
下次进来解析出来就是强化版，不需要额外的存档层。

⚠ 这条规则的判据是「**卡表里**有没有 `<id>+`」，不是「清单里有没有」——
第一版写成看清单，于是永远不触发（强化完回场景那张牌又变回 4 点，零报错）。

### 三、强化卡的落盘（新 SO）

- 编辑器侧：`Assets/Scripts/Unity/Editor/GeneratedUpgradeCardUtility.cs`
  - 路径 `Assets/Resources/Cards/Generated/Card_<基础ID>_Up.asset` ——
    **一个基础卡只对应一个资产**，反复强化是**就地更新**（否则 8→9 会留下 `Card_a_Up` / `Card_a_Up2`）。
  - 把 `CardDef` 的效果写回资产（`Fill` / `BuildEffects`），并登记进 `CardCatalog.generatedCards`。
  - **落盘后校验**：把资产再读回一个 `CardDef`，与内存那份逐项比对（含**主参数键名下的数**，
    不是 `A` 字段本身 —— 键名写错时两边都读成 0，只比 `A` 会「一致地错」）。
    不一致就放弃资产版、用内存版并打 `LogError`：宁可这次没落盘，也不能让玩家拿到一张效果坏掉的牌。
- 运行时侧：`Assets/Scripts/Unity/Configuration/CardUpgradeWriter.cs` ——
  一个**能力插槽**（`PersistHandler` 委托）。编辑器在 `[InitializeOnLoadMethod]` 里把实现插进去；
  构建版里 `Handler == null` → 退化成「只在本局内存里生效」并写明日志。
  ⚠ 这不是「两条实现」：规则只有 `CardUpgrade.Apply` 一条，插的只是「要不要写成资产文件」。
- 顺带修好 `CardEffectAsset.CreateDefinition`：原来只有 `handlerId` 为空的分支才按算子取主参数键名
  （`count` / `threshold` / `amount`），填了 `handlerId` 的反而一律写 `amount` ——
  加速 / 减速这类算子的 `A` 会**静默读成 0**（效果栏写着「加速」但一点也不加速）。
  同时给 `CardEffectAsset` 补上原本缺失的 `targets` 字段（毒刺那种「只给对方挂虚弱」的效果
  一旦被复制进资产就会走样）。

### 四、场景（`Upgrade.unity`）

| 文件 | 职责 |
|---|---|
| `Assets/Scripts/Unity/Editor/UpgradeUiBuilder.cs` | 构建器（菜单「魔法乱斗/P5 · 构建 Upgrade 场景」）：建场景 + Canvas + 存 Prefab + 场景根挂调试入口。幂等、无确认弹窗（可被脚本 / MCP 反射调） |
| `Assets/Scripts/Unity/Ui/UpgradeView.cs` | 场景视图：三个可点项（石台 / 离开 / 弹窗）冒泡成事件 + 转发「开弹窗 / 播动画」+ 管引导文字显隐 |
| `Assets/Scripts/Unity/Ui/UpgradePickerView.cs` | 选牌弹窗（只画、只收点击）：遮罩 + `Peek_Panel` 面板 + 标题 + 计数 + 预览 + 可滚动网格 + 确认 / 关闭 |
| `Assets/Scripts/Unity/Ui/UpgradePickerCell.cs` | 一格：卡面 + 整格命中区 + 「不可强化」压暗纱（含原因文字） |
| `Assets/Scripts/Unity/Ui/UpgradeFxView.cs` | 强化动画（四段协程，四段时长都在 `UiLayout.UpgradeFx*Duration`） |
| `Assets/Scripts/Unity/Ui/UpgradeSceneEntry.cs` | 单场景调试入口（E1–E4 契约）：读卡池 → 开弹窗 → 确认后落盘 + 换掉卡池里那一张 + 播动画 → 结束节点 |

**版式复用**：弹窗除「确认」与「预览」外**直接取 `UiLayout.ShopBag*` 常量**
（同一张 `Peek_Panel` 底图、同一套面板尺寸与网格参数、同一个「关闭」位置）——
用户口径就是「照商店背包那套」，抄一份同值常量只会让以后两边分叉。
底部一行排成 **关闭（左下）· 选中预览（正中）· 确认（右下）**。

**选中描边不新增节点**：`CardView_Hand.prefab` 上本来就有 `Glow`（`EdgeLine` + `BGLIne`，
颜色就是暖金 `1,0.95,0.86` / `1,0.92,0.8`），`CardView.SetSelected` 只切它的 `active`。
所以「统一暖金」是**复用**，不需要动那份被用户手调过的 Prefab。

**石台命中区**：一整块透明矩形，四角坐标是**对着背景图量的像素**
（`UiLayout.UpgradeTableBg*` = (170,292)–(1525,698)），换算走
`UiLayout.UpgradeBgPointToCanvas`（背景 cover 放大 1.149×；忘了乘缩放会整块缩在画面左上角，零报错）。

**动画时间线**（总 1.26 s，串行四段）：

| 段 | 时长 | 内容 |
|---|---|---|
| 蓄力 | 0.18 s | 整体淡入 + 卡面缩到 0.90 |
| 光爆 | 0.30 s | 暖金星芒由小炸到大（光在卡面**背后**）；光最亮那一刻换成**新卡** |
| 亮相 | 0.42 s | 光散去、卡面弹回 1.0 |
| 读数 | 0.36 s | 卡面下方的大号力量数字从旧值滚到新值，颜色由灰转暖金 |

用协程而不是 `UiTween`：`UiTween` 是「一个组件演一条曲线」，这里是四段**带状态切换**的连续演出
（第二段中途要换卡面），拆成四个组件反而要把中间状态在组件之间传递。缓动仍复用 `UiEase`。

### 六、顺带修掉的两个既有隐患

1. **`CardCatalogAsset` 与 `CardDefinitionAsset` 挤在同一个 `.cs` 里** ——
   Unity 的 `m_Script` 指向「一个文件一个 MonoScript」，而那个 MonoScript 的类型 =
   **与文件同名的那个类**。于是创建 `CardCatalog.asset` 时 Unity 报
   `No script asset for CardCatalogAsset`，把资产写成 `m_Script: {fileID: 0}`
   —— 重开工程它就是空壳，**强化卡整批从卡池里消失且零报错**。
   已把 `CardCatalogAsset` 拆成同名文件；并给 `GeneratedCardAssetUtility.EnsureCatalog`
   加了自愈（读不出来的空壳就删掉重建），另加菜单「从 Generated 目录重建卡目录」
   （清单可推导的东西不该靠手工维护）。
   > 这与既有的「MonoBehaviour 一文件一类，否则 Prefab `m_Script` 变 `{fileID:0}`」是同一条规则，
   > 只是 ScriptableObject 这边以前没真的落过盘，所以一直没暴露。

2. **`GeneratedCardAssetUtility`（用 `UnityEditor`）落在运行时程序集 `MagicBrawl.App` 里** ——
   编辑器里能编过，**打包必炸**。它只被编辑器侧引用（`GeneratedUpgradeCardUtility` /
   `CardPoolBuilder`），已连 `.meta` 一起挪进 `Assets/Scripts/Unity/Editor/`（GUID 不变，
   程序集变成 `MagicBrawl.App.Editor`）。

## 与 P4U 强化规格的关系

`Docs/design/冒险模式实施规格.md` §10 那版（**待实施**）与本场景口径不同，**两套并存、互不覆盖**：

| | 本文（已落地） | P4U 规格 §10（待实施） |
|---|---|---|
| 方向数 | **1 个**（力量 +2） | ≥ 2 个有实际差异的方向 |
| 次数 | 同一张可反复强化到封顶 9 | 每张牌一次，`UpgradeId` 非空即拒绝 |
| 载体 | 落盘成 `CardDefinitionAsset` | 强化信息只存在 `OwnedCardRecord`，`Id`/`Name` 不变 |
| 入口 | 独立 **强化事件节点**（`Upgrade.unity`） | 休息点 / 商店服务 / 事件**共用同一套流程** |

本场景是「先把强化这一个交互做出来、能单独进 Play 调试」的纵向切片；
正式接入冒险链路时，本文的**选牌 → 确认 → 落盘 → 动画 → 结束节点**这段流程可原样留用，
需要替换的是「卡池从哪来」（换成 run 的持有卡）与「方向从哪来」（接 §10 的方向表）。

## 遗留

- 战斗卡池（`BattlePool`，`useAllCards`）目前仍是「全部卡表」——
  「强化过的卡要不要、以及怎么进战斗」是冒险 run / 存档那条线的事，本次不碰；
- `UpgradeSceneEntry` 里「从卡池资产解析持有牌」那段是**调试实现**，正式接入时换成从 run 读；
- 强化卡的资产会进版本控制（每强化一张基础卡多一个 `.asset`）—— 若以后不想要，
  改成写 `persistentDataPath` 的 JSON 即可，与 `PlayerCardPoolStore` 同路子；
- 动画里的大号力量读数是独立的 TMP（不是卡面自己的数字）——
  因为 `CardView` 没有暴露「改写卡面力量文本」的口子，这是刻意的（不让视图层能篡改卡面数值）。
