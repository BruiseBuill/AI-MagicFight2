# 回合宣告拍与补牌时序（2026-11-01 · 已实施）

> 用户口径：**第 2、3 回合的补牌不能在第 1 回合还没结束时就开始** —— 必须「进入第 N 回合」之后才补。
> 结论：规则本来就对（`TurnNumber` 自增之后才补），错在两处表现 —— 补牌牌提前一整批进手牌，且补牌拍本身没有可见的回合边界。

---

## 1. 症状

| 回合 | 观感（修前） |
|---|---|
| 第 1 回合 | 玩家交出防御牌 → **补牌立刻飞进手里**，而防御结算 / 回合收尾还在演 |
| 第 2 回合 | 同样：对手最后一下还没演完，补牌已到 |
| 第 3 回合 | 同上 |

## 2. 根因（两条，缺一不可）

1. **界面读的是整批终态。** 一次 `Submit` 会把「防御结算 → 第 1 回合收尾 → 第 2 回合开始 → 补牌 → 换牌决策」整批算完
   （`BattleDriver.CoRun` → `_engine.Submit`），事件再逐拍回放。`CollectHand` 读的是
   `_engine.State.Of(seat).Hand`，于是补到的那张牌从这一批的**第一拍**就已经在手里了。
   这和 `_coolingLive`（2026-10-31 修的「减速后牌原地不动」）是同一个病。
2. **补牌拍前没有回合边界。** 回合标签 `第 N 回合 · …` 只在 `TurnStartedEvent`（半场开始）时写，
   而补牌发生在它**之前**。所以即使牌准时到，画面上也没有「新的回合开始了」这一刻可供对齐。

## 3. 修法

| 层 | 文件 | 改动 |
|---|---|---|
| Core | `Battle/BattleLog.cs` | 新增 `RoundBeganEvent`（一回合一条，早于补牌） |
| Core | `Battle/BattleEngine.cs` | `DoBeginTurn` 在 `TurnNumber++` 之后、刻印/补牌之前 `Emit(new RoundBeganEvent())` |
| App | `Unity/BattleDriver.cs` | 新增 `_handArrivalPending`：开播前把本批所有 `CardDrawnEvent` / `CardReturnedEvent` 的 uid 记下，演到那一条才放行；`CollectHand` 据此过滤。`BeatDuration(RoundBeganEvent)` = 0.5s |
| UI | `Unity/Ui/BattleUi.cs` | `RoundBeganEvent` 拍：收掉上一回合的攻防读数与手牌提示，写 `第 N 回合 · 回合开始` |

要点：

- **放行点必须在「连续发牌合成一拍」的 `continue` 之前** —— 被跳过的中间那几张也要在各自那一拍放行，
  否则它们会一直悬着，直到整批结束才出现。
- 回放结束与 `StopBattle` 都清空 `_handArrivalPending`；回放之外 `CollectHand` 行为不变（引擎真值）。
- 冷却归零的 `CardReturnedEvent` 走同一条闸门，回手的牌也不再提前出现。

## 4. 验证

无头对局（`BattleSetup.Default()` + 双 `SimpleAiAgent`，种子 20261101，5 回合、121 条事件）逐条扫描补牌拍：

| 补牌拍 | 前三条事件 |
|---|---|
| #27（第 2 回合） | `DamageTakenEvent` → `CooldownChangedEvent` → `RoundBeganEvent` |
| #28（第 2 回合） | `CooldownChangedEvent` → `RoundBeganEvent` → `CardDrawnEvent` |
| #47（第 3 回合） | `CooldownChangedEvent` → `AuraActivatedEvent` → `RoundBeganEvent` |
| #48（第 3 回合） | `AuraActivatedEvent` → `RoundBeganEvent` → `CardDrawnEvent` |

结论：**每一次补牌都在对应回合的宣告拍之后**；回合宣告 5 次 = 引擎回合数 5。编译无错误。

## 5. 未验证 / 已知边界

- 未做实机逐帧截图验收（按「轻量检查原则」只做编译 + 定向事件检查）。
- 对方的「手牌 ×N」仍读 `PlayerSnapshot.HandCount`，若对手也补牌（仅自定义战斗），
  那个数字会比牌面早 0.5s 变化；玩家自己的信息条不显示手牌数，不影响本诉求。
- 血量条同样读引擎现值（既有行为），本次未改。
