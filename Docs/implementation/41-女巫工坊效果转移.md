# 女巫工坊 · 效果转移（P6 的效果）

> **性质**：现行 · **最后核对** 2026-10-02
> **范围**：`WitchWorkshop` 的效果口径（Core）、浏览层的「选一条效果」屏（UI）、
> 「消耗 + 转移」的一次性写回（存档）、自测与 Play 验证。
> **不动**：卡表、结算、其它场景。

## 1. 用户口径（2026-10-02 原话）

> 1. 该强化效果实际上是将第 1 张卡牌的一个效果，转移给第 2 张的卡牌，
>    也就是使第 2 张卡牌增加一个效果
> 2. 当第 1 张卡牌只有一个效果时，则将其效果转移给第 2 张。如果第 1 张卡牌拥有多个效果，
>    这需要在选择卡牌的界面当中额外，显示一个让玩家选择获得哪一项效果的选项
> 3. 一些特殊的卡牌，因为他们的效果存在连锁，因此他们没有办法被放到第 1 张。
>    例如沉重打击和模仿

这一批把 2026-10-01 那版「只做流程、效果待做」补齐了。**流程一行没改**
（卡池门槛 ≤ 8 禁止开工 / 目标恰好 1 条效果且未强化 / 两张不能相同 / 第一张被消耗），
新增的只有「效果本身」。

## 2. 效果怎么落地：转移轴 + 效果画像

目标牌身上不是「多了一张牌」，而是多了一条**效果**。落点是
2026-10-02 那版「强化 = 一条配方，读的时候合成」模型的**第四条轴**：

| 轴 | 内容 |
|---|---|
| `Power` | 力量 ± N |
| `Cooldown` | 冷却 ± N |
| `Effect` | 追加一条**词条**（`UpgradeTraits`，9 条固定词条） |
| **`Transfer`（本批新增）** | **把另一张牌的一条效果并进来** |

```csharp
CardUpgradeMod.Transfer(EffectSpec)   // UpgradeAxis.Transfer = 3
```

**为什么效果要「拍平」存下来**（`Core/Cards/EffectSpec.cs`）：转移是**永久**的 ——
源牌当场被消耗，而目标牌今后在任何场景都得带着这条效果。
若只存「从 `h` 的第 1 条搬来」，就等于把「这张牌长什么样」挂在一张**已经不存在的牌**上，
而且卡表以后调效果顺序（插一条、删一条）会让它**静默变成另一条效果**。
`EffectSpec` 是 `EffectDef` 的逐项镜像（`[Serializable]` + public 字段），
所以搬过去的效果**真正成为目标牌自己的一部分**。

⚠ **参数按「名字」存**（`primaryKey` = `count` / `threshold` / `amount`）：
按算子猜键名会让 `A` 静默读成 0 —— 症状是「效果搬过来了、一点也不生效」。
自测里专门有一条往返断言（`SlowIfLastTwoHand` + `hand-at-play:2` 逐项一致）。

⚠ **光环类效果的触发符号要按目标牌改派**（`EffectSpec.ToEffectDef(trigger)` →
`UpgradeTraits.AuraTriggerFor`）：`AuraResolver` 把「剩余指示物」建模成
「光环效果列表的**尾部 N 条**」，一张牌出现两种符号的光环时消耗顺序会与卡面符号错位 ——
表现是「亮了两枚、效果算的是另一条」，零报错。
（卡表里 45 张的光环全是 α，这条路径目前只能靠自测里合成的 β 光环牌验。）

## 3. 第 3 条：什么算「效果连锁」

判据在 `WitchWorkshop.ChainedOps`，**写成算子表而不是卡 ID**：

| 算子 | 卡 | 为什么不能单独搬走 |
|---|---|---|
| `NoAtkBuff` | 沉重打击 `h` | 「此法术的进攻力量不能增加」是对本牌力量的**性质声明**，不是一条能用出来的能力。搬出去等于给目标挂一条莫名的限制；只搬走「额外伤害」又会把那条效果的代价抽掉 |
| `Copy` | 模仿 `x` | 效果依赖「本牌力量视为 X」这个身份，而 X 是**卡级标记**（`CardDef.HiddenPower`）搬不走 |
| `DoubleAtkBonus` | 飞叶连击 `u` | 「此牌获得的额外进攻力量翻倍」是**倍增器**，没有别的加值来源时等于一条空效果 |

加上卡级的 `HiddenPower`，全表 **42 张可献祭 · 3 张被挡**（`u` / `h` / `x`）。

**含任一条 ⇒ 整张不能进第一个空位**（用户口径就是「这张牌不能放到第 1 张」）。
同一个判据也用在**第二个空位**上：否则「力量 X 的模仿」会出现在候选里、
点了才在确认那一步被拒，玩家会以为界面坏了。

## 4. 第 2 条：多条效果时选一条

浏览层（`WitchPickerView`）现在是**两屏共用一块面板**，靠 `active` 切换：

```
Panel
├─ Cards            卡池六列网格（原来那一屏）
└─ EffectChoice     2026-10-02 新增：一行一条效果
   ├─ EffectTitle   「《雷云》有 2 条效果，选一条转移」
   ├─ Options → OptionTemplate   WitchEffectOptionView（失活模板，运行时按需克隆）
   ├─ EffectHint    「这条效果会加到右边那张牌上，并成为它自己的效果」
   └─ BackButton（右下）          返回 = 回卡池列表换一张牌
```

点一张牌的**三条分支**（`WitchPickerView.OnCellClicked`）：

| 情况 | 行为 |
|---|---|
| 这一层不问效果（给右空位选目标） | 直接返回，`effectIndex = -1` |
| 献祭牌**只有 1 条**效果 | 直接返回 `0` —— 用户口径「只有一个效果时，则将其效果转移给第 2 张」 |
| 献祭牌**有多条**效果 | 切到 `EffectChoice` 那一屏，等玩家点一条才返回 |

⚠ **背板必须吃射线**：`EffectChoice` 与 `Cards` 位置重合，而 `Cards` 原本靠自己的 Image
挡射线。少了背板，点这一屏的空白处会**穿过**到下面那层遮罩（`Veil` 是「点它关闭」）
把整层关掉 —— 玩家以为点了就崩了，而且零报错。

⚠ 效果行的高度靠 `LayoutElement` 的 `preferredHeight` 给（`VerticalLayoutGroup` 读它）——
少了那个组件，行会被压成 0 高、全叠在一起，同样是零报错。

行池上限 `UiLayout.WitchEffectMaxOptions = 4`；自测有一条断言盯着
「卡表里最大效果条数 ≤ 4」（目前 **2**），以后加一张 5 效果的牌会立刻变红。

## 5. 存档：一次写完「消耗 + 转移」

新入口 `SaveStore.TryConsumeAndUpgrade(slot, 消耗的ID, 目标的ID, mod)`。

**为什么不复用两次调用**：两次调用 = 两次「读 → 改 → 写」。中间那次失败（磁盘满 / 文件被占）
会留下**「牌已经吃掉、效果却没拿到」**的存档 —— 玩家的损失是实打实的，而且没有任何提示。
一次写进同一个文件，只有「全成」与「全不成」两种结果。

落盘形态（`axis: 3` = Transfer）：

```json
"upgrades": [ { "baseId": "g", "mods": [ { "axis": 3, "value": 0, "trait": "",
  "effect": { "trigger": 0, "handlerId": "LookAndCool", "primaryKey": "threshold",
              "primary": 4, "secondary": 1, "aura": 0, "mandatory": true,
              "targets": 0, "text": "随机查看对方一张手牌，力量 ≤4 则立即进入冷却",
              "sourceBaseId": "ad", "conditions": [] } } ] } ]
```

`sourceBaseId` **只作追溯与显示**，合成时完全不看它（源牌早被消耗）。

## 6. 界面接线：⚠ 改 Prefab 不够，场景里那份不是 Prefab 实例

构建器（`WitchUiBuilder.RunAll`）是「**在场景里建 → 存一份 Prefab**」，而
`SaveAsPrefabAsset` **不会**把场景里那份变成 Prefab 实例 ——
场景里留的是它**自己的一份拷贝**（`PrefabInstanceStatus = NotAPrefab`）。

所以本轮加了菜单 **`魔法乱斗/P6 · 给浏览层补「效果选择」区`**
（`WitchUiBuilder.PatchPickerEffectArea`），它**补两处**：Prefab 内容 + 当前打开的场景。
**只补 Prefab 的后果**：进 Play 跑的是场景那份 → 新节点一个都不存在，
界面看起来「就是原来那样」，**零报错**。（本轮真的踩了一次，见 §7。）

这条补丁路刻意**不重跑整场景**：`RunAll` 是「拆掉整棵 Canvas 重建」，
而那份界面上可能有手工调过的值。补丁只动 `Picker` 那一支，幂等、可反复跑。

  12 条既有噪声不变。本批只动 `WitchWorkshop` / `CardUpgrade` 的转移轴 / 新增 `EffectSpec`，
  不碰结算。
- **自测 `WitchWorkshopScenario` 扩到七层（[PASS]）**：① 卡池门槛；② 目标判据；
  ③ 全表扫描（判据与「恰好 1 条效果 + 未强化 + 不连锁」逐张对齐）；④ 两个空位；
  ⑤ **连锁牌不能进献祭位**（全表重写一遍判据、不去调被测实现）；⑥ **单 / 多效果两条分支**；

### 7.1 没验到的

- **没跑真人鼠标**：上面那次 Play 是用反射直接调 `OnSlotClicked` / `OnCellClicked` /
  `OnEffectClicked` / `OnConfirmClicked` 驱动的（与既有做法一致），
  真实指针事件的射线归属没验；不过这几个入口都是同一批方法，界面层没有第二条路径。
- **旧存档的兼容**：没造「v1 老存档 + 已有强化册」的组合样本 ——
  不过 v1 → v2 的迁移在上一批验过（缺键 → 空列表），而本批只是往 `upgrades` 里多了一种
  `axis = 3`，`JsonUtility` 对未知字段是宽容的。
- 女巫工坊**只能做一次**（目标强化过之后就不再是合法目标），
  这是既有口径（目标必须「恰好 1 条效果且未强化」）的结果，本批没有放宽。

## 8. 遗留 / 下一步

- **「效果从目标身上再搬走」没做**：现在没有回退入口（`UpgradeBook.Without` 存在但没有界面）。
- **转移是单向的**：一次转移搬一条，两个方向要两次节点。
- **图鉴 / 详情浮层不显示来源**：`EffectSpec.sourceBaseId` 记了「从哪张牌搬来的」，
  但目前只有日志用得到；要不要在长按放大的卡面上写「（来自 雷云）」是设计口径，未定。
