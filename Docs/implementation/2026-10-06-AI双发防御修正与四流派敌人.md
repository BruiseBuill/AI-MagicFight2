## 2. 双发「行动修正」（`HeuristicAgent`）

### 2.1 为什么要有这条

本作「防御成功 = 不掉血、防御失败 = 掉 1 点」，而 AI 的口径是**能挡就挡**。双发（`Double`）
要**交两张牌**才挡得住，于是「能挡就挡」的最优 AI 让双发**永远打不穿**：

- 玩家侧：双发卡毫无威胁（对方总能凑出两张）；
- AI 对 AI 侧：这一条是 [AI 四流派重构](2026-10-03-AI四流派重构.md) §10 那个
  「双方都能一直补值挡住、只能靠 100 回合上限收场」的直接原因之一。

所以给双发加一条**行动修正**：挡得住、但挡得很勉强时，改成一次赌博。

### 2.2 口径落地

| 「能挡住该双发的卡」张数 | 防御概率 |
|---|---|
| ≥ **4** | **100%**（一定防，且不消耗掷骰） |
| **3** | **80%** |
| **2** | **40%** |
| ≤ **1** | **0%**（凑不出两张，本来也挡不住） |

**「能挡住该双发的卡」的判据**（`HeuristicAgent.CountDoubleDefenders`）——
手牌里**单张**就能吃下这次进攻力量（`DecisionRequest.ContextPower`）的牌：

```
DefenseResolver.HasGuard(card)            // 守护：无视力量差必定挡（石化 ak / 石盾 al / 冰风暴 b）
  或  CardRole.DefensePotential(card) >= 进攻力量
```

`DefensePotential` = 防御时的有效力量（含 β「防御时 +A」）+ **卡自带的防御光环加值** ——
也就是用户那句「如果有防御光环，则也要考虑到防御光环的加成」。
它与**流派判定**里「防御力量 ≥8，包括防御光环的数值在内」是**同一个函数、同一个口径**
（冰封铠甲 af 5+2+2 = 9、冷冻核心 as 6+3 = 9），没有第二套算法。

量的是**张数**不是组合数：双发必须交两张牌，所以「有几张能挡」直接等于「能不能凑出一对」。

⚠ 上表**只管「靠交牌挡住」**那条路：如果本拍有**可用的免疫光环**（石化 / 石盾那类，不交牌就免掉
整次攻击含双发），恒防、不掷骰 —— 见 §2.5。

### 2.3 两个实现上的硬要求

**① 只有双发才走这条闸门。** 判据是 `DecisionRequest.ContextDouble`（引擎发本拍时填的，
`BattleEngine.IssueDefense`）。单发、以及所有非防御的决策一拍都不受影响。

**② 同一次进攻只掷一次骰。** 防御是**两拍**：引擎先按 `appliedDefenseBonus = 0` 发本拍 →
AI 报备要用的防御力量光环（`DecisionResponse.PrepAuras`）→ **引擎按新预算重发同一拍** →
AI 第二次进 `DecideDefense`。若第二次重新掷骰，就会出现「报备完光环又放弃」——
白白烧掉一批光环、玩家看到的是 AI 在乱点。

落点：`_gambleKey`（回合号 + 座位 + 进攻力量 + 挡牌数 + 手牌内容）命中就复用上一次结果。
键里带**手牌内容**，所以「新的一次进攻」必然重新掷骰（打完两张牌手牌必变），
而「同一次进攻的重发」必然命中缓存。

**③ 随机必须可复现。** 用 Core 的确定性 `Rng`（铁律：Core 内禁止 `System.Random` /
`UnityEngine.Random`），种子是**新的独立属性** `HeuristicAgent.DoubleDefendSeed`
（默认 20261006；`MonsterAgentFactory.Create` 按 `blindSeed` 派生为
`blindSeed * 486187739 + 12345`）。

⚠ **刻意与 `BlindPickSeed` 分成两条随机流**：混用一条流时，「多一次防御决策」会改变
后面所有盲选（查看对方手牌）的结果，而每条流各自可复现是「同种子 → 同对局」的前提。

### 2.4 闸门放在哪一步

`DecideDefense` 的**最前面**（在「不用光环就能挡住 → 直接出」那条分支之前）。
否则能挡住时永远 100% 防，这条修正形同虚设。

### 2.5 例外：有可用的**免疫光环** → 恒防

（2026-10-06 用户追加口径：*「有免疫光环选项 → 恒防」*。）

免疫光环一发就把**整次攻击（含双发）**免掉、而且**不需要交牌**（规则 §6.5：空手也能用）——
那是白拿的手段，没有理由把它赌掉。所以闸门里先插一条：

```
if (UseAuras && style != AvoidComboAndZone && 本拍有可用的免疫光环选项) → 恒防（不掷骰）
```

判据 `HasImmuneAuraOption(req)` **复用管线那一步用的同一个函数**（`FirstAuraIndex(req, true)`），
所以「闸门说恒防」与「管线真的会用掉那枚免疫」永远是同一件事。
（引擎那边也已经按本次攻击力量过滤过区间 —— 免疫区间不含这一击的选项根本不会出现在 `Options` 里，
见 `BattleEngine.BuildDefenseAuras`。）

⚠ 例外上带的两个条件不是装饰：

- `UseAuras`：为 false 的调用点**根本不会消耗光环**，放行只会得到「闸门放行、管线放弃」；
- `style != AvoidComboAndZone`：连击流派在管线里于「用免疫」那一支**之前**就放弃防御了
  （它刻意不动用任何光环）—— 同样会造成上面那种自相矛盾。

**它是例外，不是新规则**：例外不成立时，张数 → 概率那套照旧（`HasImmuneAuraOption` 为假
就落到 §2.2 的表）。

## 3. 四种流派敌人

### 3.1 一只怪 = 三份东西

沿用既有框架（[怪物框架](2026-10-03-怪物框架与自爆怪.md) + [怪物卡池](2026-10-05-怪物卡池与玩家带伤入场.md)）：
角色资产（`Resources/Monsters/*.asset`）+ 卡池资产（`Resources/Pools/MonsterPool_*.asset`）
+ **`aiProfile`**（字符串 → `MonsterAgentFactory` → 代码子类）。

本批新增 4 只，**每只 8 张卡池**（= 怪物开局抽满的手牌数 ⇒ **卡池就是它这一局的手牌**）：

| 档案名 | 资产 | 名字 | 攻击逻辑 | 卡池（8 张） |
|---|---|---|---|---|
| `power` | `Monster_Power` | 烈焰傀儡 | **高攻**：力量 ≥8 的连击 → 进攻光环卡 → 力量 ≥7 → 加速 → 按力量 | `j` 闪电 · `ai` 爆燃 · `aj` 火灾 · `ag` 淬火 · `g` 陨石 · `f` 滚石冲击 · `i` 地震 · `d` 寒流 |
| `double` | `Monster_Double` | 荆棘傀儡 | **双发**：防御光环卡 → 双发卡 → 加速 → 按力量 | `t` 荆棘 · `u` 飞叶连击 · `v` 藤蔓 · `w` 狂躁蘑菇 · `af` 冰封铠甲 · `as` 冷冻核心 · `ah` 烈焰斗篷 · `ab` 湍流 |
| `combo` | `Monster_Combo` | 雷霆傀儡 | **连击**：连击卡 → 区域加速 → 加速 → 按力量 | `j` 闪电 · `k` 电弧 · `l` 磁暴 · `m` 雷鸣 · `n` 引雷 · `ap` 击穿 · `ar` 闪电球 · `q` 海涌 |
| `slow` | `Monster_Slow` | 冰霜傀儡 | **减速**：区域减速（须满足开启条件）→ 防御光环卡 → 连击 → 双发 → 加速 → 按力量 | `a` 暴风雪 · `b` 冰风暴 · `an` 雪崩 · `c` 凝固 · `ad` 雷云 · `i` 地震 · `as` 冷冻核心 · `af` 冰封铠甲 |

配池的两条口径：

- **8 张正好等于 `minimumCardCount`**，也等于怪物开局手牌数 —— 配少一张就不是「少发几张」，
  而是**进战斗当场抛异常**（既有约束，`MonsterBuilder` 会提前打警告）。
- **四份卡池都不放回血卡（过载 o / 自燃 p）**：它们是 `HealMinusMax`（强制回血 + **削自己生命上限**），
  1 血时打出去等于自杀。连击池里本来最合适的那张区域加速是自燃（p），换成了海涌（q）。

### 3.2 强制流派：`ForcedArchetypeAgent`

四只怪走的是 `Core/Ai/MonsterAgents.cs` 新增的一层：

```
ForcedArchetypeAgent (abstract)  ←  只覆写 HeuristicAgent.SelectArchetype
   ├── PowerAgent  (HighPower)
   ├── DoubleAgent (Double)
   ├── ComboAgent  (Combo)
   └── SlowAgent   (Slow)
```

**为什么不让卡池自己决定流派**：卡池已经按流派配好了，`ArchetypeJudge` 按理也能判对 ——
但那是**打分**：手牌里恰好有几张力量 ≥8 的牌，就可能把「双发怪」判成「高攻怪」。
用户要的是「4 种类型的敌人**分别对应** 4 种攻击逻辑」，是**身份**不是概率。
（`SelectArchetype` 仍然跑一遍 `ArchetypeJudge.Analyze` 并把明细留在
`LastAnalysis` 里 —— 只是为了排查时能看见「判分明细说什么」，返回值一律以强制流派为准。）

出牌优先级、防御口径、双发行动修正**全部沿用父类**，一行都没改 ——
包括「连击流派自动切到『不用连击 / 区域加速的牌来防』」那条（`DefenseStyleOf` 按流派判定）。

新增档案名**只加 `case`、不动既有**：`berserker` / `trickster` 两个示例原样保留
（未知档案名仍然静默回退到通用 AI）。

## 4. 测试期 1 血

`MonsterBuilder` 新增常量 **`TestHp = 1`**，六只怪（含原有的自爆傀儡 / 基础傀儡）
的 `initialHp` / `maxHp` 一律写它。

**为什么要覆盖而不是「缺失才建」**：卡池那种「只补空位」的口径保护的是**从未配过的字段**；
血量是「已经配过、但需求变了」—— 用户明确说「目前所有的 AI 都是 1 血」，
而六个资产都已存在，「缺失才建」一个都改不到。所以新增 `MonsterBuilder.PointHp`：
**主动同步 + 每一次改动都打进构建报告**（不静默改数据）。

⚠ **改回去只有一个旋钮**：把 `TestHp` 改成 4，重跑菜单，六只怪一起恢复常规血量。
⚠ 副作用：在 Inspector 里手调过的血量，下次跑菜单会被拉回 `TestHp`。

- **1 血 ≠ 一回合结束**。防御成功 = 不掉血，所以「会防御的敌人」即使只有 1 血也能拖很久：
  上面那局 Play 打到第 7 回合玩家还一次都没打穿它（它靠把冰封铠甲 / 冷冻核心 / 烈焰斗篷
  打进冷却区、再消耗那几枚防御力量光环来补值）。
  想让某个敌人快速死掉，选**卡池里没有防御光环**的那种（`power` / `combo`），
  或者改它的 `initialHp`。
- **双发行动修正**只对 `ContextDouble == true` 生效。单发仍然「能挡就挡」——
  这是用户明确限定的范围。
- **`_monsterConfig` 仍指向自爆傀儡**（构建器只在它为空的时侯才接第一只怪）。
  要试四只新怪：`Assets/Prefabs/Ui/BattleCanvas.prefab` → `BattleDriver` → **怪物**那一格拖进去
  （单场景调试），或等冒险地图接入「按节点选怪」。
- **卡池 8 张 ⇒ 这局的手牌就是全部牌** —— 怪物不会补牌，所以「能打什么」在开局那一刻就定死了。
  想让某只怪的打法有变化，得把卡池配大一点（> 8 张，多出来的进牌堆）。
- 上面「荆棘傀儡」的出牌分布里，双发卡（t/u/v/w）的次数明显低于三张防御光环卡 ——
  那是**档位表的字面结果**（防御光环卡恒在 tier 0，只要它冷却好了就优先打），
  不是漏配。要让双发卡更常出现，得调整 `HeuristicAgent.DoublePriority` 的档位。
- 万局水位不变只说明「万局那条路径（SimpleAiAgent）没被碰到」——
  **新 AI 的行为变化只在 300 局那一层被覆盖**，它的分布变化见 §6.1。

## 8. 原文歧义处的取舍（**请重点复核这一节**）

1. **「如果有防御光环，则也要考虑到防御光环的加成」= 按卡自带的那份光环算**
   （`CardRole.DefensePotential` = 防御时有效力量 + 卡自带防御光环加值）。
   依据：这与流派判定里用户已确认过的那条（「防御时力量能达到八的卡，**包括防御光环的数值在内**」）
   **是同一句话的另一种说法**，而那一句的落地就是 `DefensePotential`；两处用同一个函数，
   不会出现「判定算 9、防御算 5」的分叉。
   ✅ 若你要的是另一种读法（**只数「不需要光环补值就挡得住」的牌**，即 `DefenseResolver.DefensePower`），
   把 `CountDoubleDefenders` 里的 `CardRole.DefensePotential(card)` 换成
   `DefenseResolver.DefensePower(card)` 即可 —— 一行、且自测的期望值要跟着改。
2. ~~闸门在「不用光环就能挡住」之前 ⇒ 免疫光环也不再有豁免~~ → **已按用户 2026-10-06 追加口径改掉**：
   **有可用的免疫光环选项 → 恒防（不掷骰）**，见 §2.5。
   免疫是白拿的（不交牌、免整次攻击），赌掉它没有道理；
   例外在连击流派与 `UseAuras = false` 时不生效（那两种情况下管线根本不会用光环，
   放行只会得到「闸门放行、管线放弃」的自相矛盾）。
3. **挡牌数 ≤ 1 时判 0%**。原文只给了 2 / 3 / ≥4 三档；≤1 张时凑不出两张（双发要交两张），
   所以取 0%，而不是「维持旧口径能挡就挡」。
4. **「双发」的判据 = 引擎的 `ContextDouble`**（由 `EffectOp.Double` 置位），
   不是「对手打出的牌带双发字样」—— 连击的追加进攻、模仿复制出来的双发都走同一条。
5. **掷骰是确定性伪随机**（Core 的 `Rng`，种子随开局种子派生），
   不是 `UnityEngine.Random`。理由是铁律：同种子必须复现同一局。
   ⚠ 代价：**同一颗开局种子 + 同一个局面 → 必得同一个结果**，
   所以「40%」是指「换一颗种子就换一次结果」，不是「每次点都像真随机」。
6. **概率只按「张数」算**，不按「能凑出多少对」。原文说「能防御住的卡的数量」，
   而双发必须交两张 ⇒ 张数 ≥2 就等于「凑得出一对」。
7. **不存在「3 张里只有 1 张是真挡牌」这种细分**：`DefensePotential` 把「靠自带光环达标」和
   「硬力量达标」一视同仁（与流派判定一致）。若要让它们不同权重，那是新一版的规则。
8. **测试期 1 血写死在 `MonsterBuilder.TestHp`**，不是每只怪各写一遍 ——
   目的是让「改回去」只有一个旋钮。⚠ 它会**覆盖** Inspector 里的手调血量。
9. **`DoubleDefendSeed` 与 `BlindPickSeed` 分成两条流**，且工厂按 `seed + seat` 派生 ——
   同一局的两个座位、不同种子局之间的掷骰序列都不同。
   `blindSeed == 0`（自测里直接 `new HeuristicAgent(state)`）时用默认值 20261006，
   所以自测里所有 agent 的掷骰序列相同（那条统计断言是靠**逐样本换种子**避开的）。
