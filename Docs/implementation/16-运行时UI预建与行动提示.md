# 16 · 运行时 UI 预建 + 中央行动提示（2026-09-19）

> **性质**：现行实现记录 —— 运行时 UI 一律**场景预建**；中央行动提示；开局种子（与当前代码一致，可照此改）
> **最后核对**：2026-09-23

> 本轮把「还在代码里 new 出来的 UI 物体」全部改成**场景里预建的节点**，
> 并加了三样东西：开局随机种子、屏幕中央的行动提示、两名角色间距 −10%。

## 1. 用户口径（原话）

1. 所有**不是 prefab** 的 UI 物体都不要在代码里生成，要在场景中预先做好，方便调整 ——
   **尤其是拖拽光环那一部分**，以及**手牌的生成**（手牌最好要有 prefab）；
2. 开局的种子**随机**；
3. 加入**行动提示**（例如「轮到你进攻」「进攻结束」），在屏幕中间闪一下就行；
4. 玩家和怪物之间的距离**减少 10%**。

## 3. 关键设计

### 3.1 「代码里不生成 UI」这条线画在哪

- **可以运行时做的**：`Instantiate(场景里的失活模板)`（光环图标、准备标记、飞行卡）
  —— 这就是 Unity 的常规池化做法，模板本身在 Hierarchy 里看得见、调得动。
- **不能运行时做的**：`new GameObject(...)` / `AddComponent` 现搭节点。
  这类节点在编辑器里**根本不存在**，版式只能靠猜。
- 因此本轮把**仅剩的三处**（光环准备条、飞牌层、冷却滚动层）全部预建；
  另外把两张卡 prefab 上运行时 `AddComponent` 的组件改成预置。
  > 复查：`Assets/Scripts/Unity/Ui/**` 下已无 `new GameObject`。
  > 仅剩两处 `AddComponent` 兜底（`HandView.InstantiateState`、`CardInteractor.Attach`），
  > 只在「有人手工塞了一张没配组件的卡」时才触发。

### 3.2 手牌为什么不预置实例、而保持 Prefab 实例化

用户要的是「手牌要有 Prefab」——它**本来就是**（`Assets/Prefabs/Ui/CardView_Hand.prefab`）。
预置 N 个空实例在 `HandRow` 下并不会让调整更容易：
手牌的位置/角度每帧由 `HandView.Update` 的圆弧算式决定，预置位置会被立刻覆盖；
而卡本身的版式改 prefab 一次就全局生效。所以**改 prefab，而不是往场景里摆实例**。

### 3.3 节点绘制顺序（Canvas 根，从下往上）

```
… TopArea / HandArea / ResultRoot / LogPanel / PlayZone / DropArrow
CardTransitLayer   ← 飞牌只是画面，关掉射线
ActionBanner       ← 一闪而过，不吃射线
PreparedAura       ← 必须在最上：拖拽中的光环图标不能被任何东西盖住
```

### 3.4 角色间距的唯一口径

```csharp
public const float CharSpacing = 783f;               // 870 × 0.9
public const float CharCenterX = 855f;               // 注意不是画面正中 960，历史上整体偏左
public const float CharHeroX    = CharCenterX - CharSpacing * 0.5f;   // 463.5
public const float CharMonsterX = CharCenterX + CharSpacing * 0.5f;   // 1246.5
```
下次只想改间距，动 `CharSpacing` 一个数即可（`PlayedCard_Monster` 也跟着走，它引用 `CharMonsterX`）。

## 4. ⚠ 踩的坑（本轮新增）

1. **Unity 只认「文件名 == 类名」的 MonoBehaviour —— 挤在一起就存不进 Prefab。**
   `HandCardState` 原本和 `HandView` 挤在 `HandView.cs` 里，运行时 `AddComponent` 能用，
   但保存 Prefab 时**组件变成 `<MISSING>`**（脚本引用写不出去）。
   → 拆成同目录的 `HandCardState.cs`。
   **症状极具迷惑性**：`Type.GetType` 找得到类型、`AddComponent` 返回成功，
   但**存盘后组件消失**。判定手段：`AssetDatabase.LoadAssetAtPath<MonoScript>(path).GetClass()`
   —— 返回 **null** 就是没建立脚本↔类的映射。

2. **`CoolingScroll_Player/Enemy` 其实是「运行时 new 出来、又被连带存进 Prefab」的假预建。**
   它在 Hierarchy 里看得见，所以一直以为 M11 建的；实际是 `CooldownView.ConfigureColumn`
   在 `scroll == null` 分支里 `new GameObject` 出来的，然后某次
   `PrefabUtility.SaveAsPrefabAssetAndConnect` 把它一起存了。
   **M11 每次重建 ArtLayer 都会把它整个删掉**（它挂在 ArtLayer 下）——症状就是
   `[Cooldown] 冷却列里找不到预建的 ScrollRect`。
   → 真正的修法是在 `BuildSlotColumn` 里建出来。
   **教训：「Hierarchy 里看得见」不等于「构建器建出来的」。**

3. **`PolySprite/RoundedRectangle` 没有 border**（`border = (0,0,0,0)`），
   用它 + `Image.Type.Sliced` 做横向长条（560×104，5.4:1）会把圆角抻成椭圆；
   退化成 `Simple` 也一样变形。
   → 中央横幅的底衬改用 `Art/Ui/CardBox.png`（`border = 38`，九宫格拉伸不变形）。

4. **`WaitForSecondsRealtime` / `unscaledDeltaTime` 会让「一闪而过」的东西在脚本化环境里失真。**
   频繁调 MCP（每次占用主线程）时帧率极低、帧间隔很长，
   `ActionBannerView` 的淡入几乎走不完（`alpha` 停在 0.6）、或一个长帧就直接走完整个 1.3 秒。
   **验证这类动画要么冻结状态（`_playing = false` + 手设 `alpha`），要么别用 MCP 高频插进去。**
   正常游玩时不受影响。

5. **M7 会推倒整个 Canvas** —— 本轮改了 `UiKitBuilder`（卡片 prefab 加组件），
   必须 `M7 → M8 → M11` 连跑，只跑其中一个是半截状态。
   （`BattleArtLayerBuilder` 的改动只需单独重跑 M11。）
