# 18 · 光环落区改回手牌区 + 飞入动画 + 提示色交回 Prefab

> **性质**：现行实现记录 —— 光环落区 = 手牌区；标记飞入动画；提示色交回 Prefab（与当前代码一致，可照此改）
> **最后核对**：2026-09-23

> 2026-09-19 · 用户口径：光环的判定区域是**手牌区**（不同于出牌的判定区）；
> 拖进手牌区即视为使用 → 标记**飞**到出牌区左侧、原图标消失；把标记拖出该位置即取消、恢复原位。
> 另：**这类提示方块的颜色不要用代码写**，由用户在 Prefab 里自己调。

---

## 1. 落区：手牌区，不是出牌判定区

| 手势 | 落区 | 判定函数 |
|---|---|---|
| 出牌（进攻 / 防御） | 中央 `Canvas/PlayZone` | `HandView.IsInPlayZone` |
| 光环「准备使用」 | 底部 `HandArea`（通栏 × 344） | `HandView.IsInHandArea` |
| 已准备标记「取消」 | 中央 `PlayZone`（标记就摆在它的左侧） | `PreparedAuraView.IsInPlayZone` |

- `BattleUi.OnAuraDragMove`：拖动中点亮 **手牌区**提示底，同时把判定区那层高亮收掉
  —— 两处同时亮会让玩家以为判定区也能落。
- `BattleUi.OnAuraDropped`：`IsInPlayZone` → `IsInHandArea`。免疫类仍是「松手即结算」，其余进准备态。
- `HandView` 的 M15 段注释同步（M16 一度改成判定区，这里改回来）。

用整块 `HandArea` 而不是扇面本身那个「每帧都在动」的弧：弧上每张牌的位置/角度都是平滑趋近的，
拿它当判定框会「看着放进去了其实没进」。代价是左下角能量球也落在这块里 ——
它不参与光环语义，放着不影响（不做规则判断，铁律 3）。

## 2. 原图标消失：HudBuff 藏一份「已准备」的键

引擎那边的指示物在出牌之前**一直还在**（真正的消耗发生在交牌那一刻），所以光靠快照筛不掉它。
`HudBuffView` 新增 `_hidden`（键集合）与 `SetHidden(keys)`：

- `Collect` 的两处（刷新已有 / 补新建）都跳过被藏的键 → 图标落回池子（`SetActive(false)`）；
- `SetHidden` 自己还会**当场**把命中的图标失活，不等下一次 `Bind`
  —— 松手那一刻原图标就该消失，否则会出现「手里那份和判定区那份同时亮着」的一两拍；
- `BattleUi.RefreshPreparedMarkers`（含 `HandleDecision` 末尾那次重发）与 `ClearDecision`
  各同步一次。**放弃防御时准备的力量光环并不消耗**，`ClearDecision` 里空集一设，图标就回到 HudBuff。

## 3. 飞入动画

`AuraIconView.FlyIn(surface, fromWorld, target, duration)`：

- 起点 = **松手时指针的位置**（`BattleUi.OnAuraDropped` 通过 `PreparedAuraView.SetSpawnOrigin` 传下来），
  终点 = 判定区左侧的槽位；
- 飞行期间父节点挂在铺满画布的 `PreparedAura`（`_surface`）上 —— 挂在 72×72 的槽位里
  就得用几千像素的 anchoredPosition 当偏移，槽位或祖节点一旦有缩放/旋转就算歪；
- 位置走 `OutCubic`、缩放从 `0.55` 走 `OutBack` 回到 1，同一个 t 两条曲线
  （`UiLayout.AuraFlySeconds = 0.32`、`AuraFlyStartScale = 0.55`）；
- 落地时挂回槽位、坐标归零 —— 与 `PreparedAuraView.Layout` 的「对齐槽位」是同一种终态。
- 期间 `IsFlying` 生效：`Layout` / `Bind` 跳过它，`OnPointerDown` / `OnBeginDrag` 也不接
  （否则指针正好压在掠过的图标上，飞行一结束就弹出一层说明浮层）。

## 4. 提示底的颜色：一个字节都不写代码

涉及两个节点，颜色**只**写在 `BattleCanvas.prefab` 的 `Image.color` 上，在 Hierarchy 里随时调：

```
HandArea/AuraDropHint        ← 拖 HudBuff 图标经过手牌区时亮（HandView.SetAuraDropHighlight）
PreparedAura/ZoneHighlight   ← 拖「已准备」标记时的保留区高亮（PreparedAuraView.SetZoneHighlight）
```

- 删掉 `UiTheme.AuraDropHint` 常量（代码里不再有任何一处「这类提示的色号」）；
- `PreparedAuraView.Configure` 原来有 `_highlight.color = UiTheme.AuraDropHint`，
  **这是最坑的一处**：用户在 Inspector 调完色，一进 Play 就被它冲回去。已删除。
- `BattleUiBuilder` 里新建节点时只给一个中性占位色（`HintPlaceholder`），
  ⚠ **重跑 M8 会按占位色重建这两个节点**，调完色就别再跑了
  —— 与 M18「位置搬进 Prefab，但构建器仍会按常量重算」是同一笔代价。

## 5. 本次不需要重跑构建器

`AuraDropHint`（挂在 `HandArea` 第一个子节点）与 `PreparedAura/ZoneHighlight`、`Slot0…Slot7`
在现成的 `BattleCanvas.prefab` 里**都已经存在并接好线**（`HandView._auraDropHint` 非空）。
本次只改了运行时脚本 + 两类注释，所以：**让 Unity 重新编译 → 直接 Play 即可**。
只有想换提示底的颜色时才需要在 Prefab 里选中对应节点改 `Image.color`。

```bash

dotnet build MagicBrawl.App.csproj        --nologo -p:UseSharedCompilation=false \
  -p:OutputPath=<临时目录> -p:IntermediateOutputPath=<临时目录>
dotnet build MagicBrawl.App.Editor.csproj --nologo -p:UseSharedCompilation=false \
  -p:OutputPath=<临时目录> -p:IntermediateOutputPath=<临时目录>
```

结果：`MagicBrawl.App.dll` 与 `MagicBrawl.App.Editor.dll` 均 **0 错误**。
输出全部重定向到临时目录 —— 验收过 `Library/ScriptAssemblies/` 与 `obj/` 都没被改写（不污染 Unity 工程）。

⚠ **还没跑的**：Play 模式的实机手感（飞入动画是否跟手、提示底亮起的时机、取消手势）。
