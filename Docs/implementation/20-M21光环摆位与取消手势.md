# 20 · M21 光环摆位（徽标旁）与「再拖一下取消」

> **性质**：现行实现记录 —— 光环**默认位**（徽标旁）/ **准备位**（手牌区左侧）/「再拖一下取消」（与当前代码一致，可照此改）
> **最后核对**：2026-09-23

> 2026-09-20 · 用户 4 条口径：
> ① 光环的**默认位**改成排在**角色头顶血量徽标**旁边（主角在徽标**右侧**、怪物镜像到徽标**左侧**，一行横排）；
> ② 拖进手牌区即「准备使用」，标记**吸附到「手牌区的左方」**；已吸附的标记**再被拖拽就取消**，回到默认位；
> ③ 手牌区落区提示底改成**方块**并**降低不透明度**；
> ④ 出牌判定区**加宽到与屏幕左右两端对齐**。
>
> 用户对 ② 的原文是「吸附到**出牌区**的左方」，随后澄清为**手牌区**（笔误）。

## 0. 先说一个必须一起修的现状：槽位全丢了

`HudBuff/PlayerGroup`、`EnemyGroup` 与 `PreparedAura` 下的 `Slot0…Slot7` **在 prefab 里已经不存在**：

| 槽位 | 谁建的 | 谁删的 |
|---|---|---|
| `ArtLayer/HudBuff/*Group/Slot0…7` | M18 时**手摆**在 Prefab 里 | `BattleArtLayerBuilder.RunAll()` 第一步 `DestroyImmediate` 整棵 ArtLayer（M20 重跑 M11 时没了） |
| `PreparedAura/Slot0…7` | M18 时**手摆**在 Prefab 里 | `BattleUiBuilder.Cleanup()` 按名字删掉 `PreparedAura` 再重建（M20 重跑 M8 时没了） |

后果：`SlotAt()` 一律返回 null → 图标与准备标记**都没有落点**，只是停在松手/新建的位置。
所以这 4 条改动**必须顺带把槽位改成由构建器生成**，否则改了常量也不会生效。

**M21 起**：槽位由 `BattleArtLayerBuilder.BuildBuffGroup`（每侧 8 个）与
`BattleUiBuilder.BuildPreparedBar`（8 个）按 `UiLayout` 常量生成。
代价 = 手拖槽位活不过一次重跑（以前也活不过，只是当时没人发现）。

## 1. 默认位：贴在角色血量徽标旁边

**版式账**（画布 1920×1080，坐标从屏幕左上算）：

| 量 | 值 | 来源 |
|---|---|---|
| 主角徽标 | x 397.5…529.5、y 244…286（中心 463.5 / 265） | `CharHeroX + CharBadgeWidth/2`、`CharGroundY + CharBadgeGroundOffset` |
| 怪物徽标 | x 1180.5…1312.5（中心 1246.5 / 265） | 关于 `CharCenterX` 对称 |
| 图标行中心线 | y = **265** | `UiLayout.AuraIconRowCenterY`（= 徽标中心线） |
| 图标与徽标净空 | **36** | `AuraIconBadgeGap`（用户第 2 张参考图：图标左缘 564 / 徽标右缘 529.5） |
| 玩家块左缘 | **565.5** | `HudBuffPlayerX = CharHeroX + CharBadgeWidth/2 + AuraIconBadgeGap` |
| 怪物块右缘 | **1144.5** | `HudBuffEnemyX = 1920 − (CharMonsterX − CharBadgeWidth/2 − AuraIconBadgeGap)` |
| 槽位步进 / 个数 | 80 / 8 | `BuffIconSpacing` / `BuffIconSlots` |

- 两个常量改成**由徽标推导**（`566`/`598` 那两个写死的数删了）：徽标一动，这行跟着动。
- 组的锚点就是「徽标外侧那条线」：玩家侧锚左上、怪物侧锚右上，槽位 = 组内 `+(半个图标 + 80×i)`。
  两侧都是「**从自己的徽标往外走**」，所以两侧都往画面中间长。
- ⚠ 已知代价：一排 8 枚 × 80 = 640 px，**双方各准备 4 枚以上时两排会在画面正中叠在一起**。
  实际对局同一拍通常 1~3 枚，先按用户口径实现；真要更多，减少 `Slot` 节点即可
  （`SlotAt` 找不到编号就退回前一个槽位，不会崩）。

## 3. 取消手势：再拖一下（不再看落点）

M19 是「把标记拖出**判定区**即取消」。标记本来就摆在判定区**外面**（手牌区里），
「拖出去」多半是误触，用户要求改成**拖一下本身就是取消意图**：

- `AuraIconView` 新增 `public bool CancelOnDrag`；`OnBeginDrag` 里命中它就
  **不进拖拽态、不换父节点**，只把这次拖拽转发给 Host；
- `PreparedAuraView.OnAuraDragBegin` 发 `Cancelled` → `BattleUi.OnPreparedAuraCancelled`
  → 从准备集合删键 → 重发本拍 → `Bind` 把标记收进池子、`HudBuff.SetHidden` 放行原图标
  → 原图标回到**默认位**（徽标旁那行）；
- 因此 `PreparedAuraView` 不再需要判定区：`Configure(playZone, template)` → `Configure(template)`，
  `HandView.IsInPlayZone(Vector2)` / `HandView.PlayZone` 两个公开成员一并删除；
- `PreparedAura/ZoneHighlight` 节点（「标记的保留区高亮」）**整块删除** ——
  取消不再有落点约束，它没有含义了（连同 `PreparedAuraView.SetZoneHighlight` 与 `BattleUi` 里三处调用）。

⚠ **踩坑**：`CancelOnDrag` 的置位**必须排在 `v.Bind(...)` 之后**。
`AuraIconView.Bind()` 末尾会调 `ResetState()`，而 `ResetState()` 也要清 `CancelOnDrag`（池化防串味）——
写进 `Take()` 会被无声冲掉，实测表现是「标记照样被拎着走、还顺手取消了」。

## 4. 落区提示底：方块 + 更低不透明度

`HandArea/AuraDropHint`：

- 原来赋的是 `ThirdParty/PolySprite/RoundedRectangle.png` + `Type.Simple` —— 那张图 256×256
  **没有 border**，Simple 模式拉到 1920×344（5.6:1）时圆角被抻成一大段弧，整片像个畸形胶囊；
- 现在**不赋 Sprite**：UGUI 的 Image 没图时画的就是纯色矩形，形状完全由 RectTransform 决定；
- 占位色 alpha **0.13 → 0.06**（`BattleUiBuilder.HintPlaceholder`）。
  ⚠ 正式颜色依旧只写在 `BattleCanvas.prefab` 的 `Image.color` 上，运行时不写；
  **重跑 M8 会按占位色重建这个节点**（老规矩）。

## 5. 出牌判定区：通栏

`Canvas/PlayZone` 从「居中 1200×270」改成**锚点 0…1 横向拉伸、`sizeDelta.x = 0`**，
纵向仍是下沿距底边 430、高 270。`UiLayout.PlayZoneWidth` 常量**删除**
（拉伸写法不需要宽度，换任何画布宽度都贴到两端）。

代价（有意接受）：拖牌经过左右冷却列那两条竖带时也算「进了判定区」—— 判定只看纵向 430…700。

## 7. 验收

**类型检查**（关着 Unity 也能做）：`MagicBrawl.App.csproj` / `MagicBrawl.App.Editor.csproj` 各 0 错误。

**重建**：`refresh_unity` → **M8 菜单** → 反射调 `BattleArtLayerBuilder.RunAll()`
（M11 菜单带 `EditorUtility.DisplayDialog`，MCP 触发会挂死主线程，走反射）→ `manage_scene save`。

**节点几何**（Play 中反射读）：

```
PlayZone        anc=(0.00,0.00)~(1.00,0.00) sd=(0,270) pos=(0,430) rectW=1920 rectH=270
PreparedAura    children=8 slots=8 zoneHighlight=0  slot0=(-900,-324) slot7=(-340,-324)
AuraDropHint    sprite=NULL->square  color=RGBA(1,1,1,0.060)  active=False  siblingIndex=0
PlayerGroup     pos=(566,-229) slots=8 slot0=(36,-36) slot7=(596,-36)
EnemyGroup      pos=(-776,-229) slots=8 slot0=(-36,-36) slot7=(-596,-36)
```

`PreparedAura/Slot0` 的世界中心 = **(90, 324)** = 画布 (60, 216) × 画布缩放 1.5 —— 与常量完全对上。

**接线**（反射逐字段）：`BattleUi._preparedBar/_hand/_hudBuff`、`HandView._cardPrefab/_row/_playZone/_arrow/_auraDropHint/_peek`、
`HudBuffView._playerGroup/_enemyGroup/_iconTemplate/_tip` 全部非空；`PreparedAuraView._highlight` 字段**已不存在**。

**手势**（Play 中注入合成指示物 + 合成 `PointerEventData`）：

- 标记：`CancelOnDrag=True`、拖动前 `IsDragging=False`、parent=Slot0；
  调 `OnBeginDrag` 后 **`Cancelled` 触发 1 次**（收到「冰封铠甲 +2」）、`IsDragging` 仍 False、**parent 仍是 Slot0**（没有被拎走）。
- HudBuff 图标（对照组）：`CancelOnDrag=False`，`OnBeginDrag` 后 `IsDragging=True`、parent 换成画布根（自由拖拽），`OnEndDrag` 后复位。
- 飞入：`SetSpawnOrigin(key, 屏幕点)` + `Bind` → T+0 `flying=True`、parent=PreparedAura、
  `anchoredPos=(-320,-460)`（正是所给屏幕点换算来的）、`scale=0.55`；
  T+1.2 落地 → parent=**Slot0**、`anchoredPos=(0,0)`、`scale=1.00`。

**截图**（`Captures/art-review/`）：

- `m21_02_aura_default_rows.png` —— 两侧默认位：主角 4 枚在徽标右侧、怪物 3 枚在徽标左侧，都与徽标同高。
- `m21_03_prepared_markers_and_hint.png` —— 3 枚准备标记排在能量球上方、手牌左侧，落区提示底点亮。
- `m21_05_drophint_shape_temp45.png` —— 提示底 alpha 临时调到 0.45 的形状验收图：
  **通栏纯矩形、直角、无圆角**（拍完即改回 0.06，运行时不落盘）。
- `m21_06_all_combined.png` —— 三样同时出现的总览。

**还没验的（下轮补）**：真实对局里「拖光环 → 飞到手牌区左侧 → 再拖取消 → 原图标回默认位」的完整往返。
本轮用自动代打（`_autoPlay` + 小 `_beatScale`）跑了两局，没有出现玩家侧的可消耗光环
（第二局怪物侧出现过 1 枚，说明布局在真实数据下也走同一条路）。
上面的分层验证已覆盖这条链路的每一段，缺的只是「一次真实数据串起来」。

## 8. 观察到的理论重叠（实际不同屏，先记着）

默认位那一行占 y 229…301（从屏幕顶）、x 565…1205：

- `TopArea/DealPanel`（发牌台）y 86…298、x 750…1170 → 纵向压到 229…298；
- `TopArea/PickerPanel`（替换选项）y 84…384、x 750…1170 → 压得更多。

但这两个面板只在**换牌阶段**出现，而换牌阶段双方冷却区都是空的（不可能有指示物）——
