# M29 · 修复「开局黑屏 + 角色不显示」

> **性质**：现行实现记录 —— Canvas 兄弟序 = 绘制顺序（开局黑屏 / 角色被盖）（与当前代码一致，可照此改）
> **最后核对**：2026-09-23

> 2026-09-22。用户报告：开局黑屏（backdrop）、双方角色模型不显示（疑似被遮挡）。
> **一个根因，两个症状** —— UGUI 的 Canvas 兄弟序 = 绘制顺序，越靠后越上层。

## 症状

| # | 现象 | 归因 |
|---|---|---|
| 1 | 进游戏整屏 `#0F131B` 纯色，什么都看不到 | `Backdrop` 排在 `ArtLayer` **之后**，不透明底板糊住整个美术层 |
| 2 | 背景图 / 主角 / 怪物全不见 | 同上（被 Backdrop 一并盖住），**不是**被某个 UI 面板遮挡 |

## 根因

### 主因：Canvas 子节点顺序错了

`Backdrop` 是 `<c>UiTheme.Backdrop</c>` = `0F131B`、**alpha = 1** 的全屏不透明 `Image`，
由 **M7（UiKitBuilder.BuildCanvasInActiveScene）最先建**，本该垫在画布最底。

实机（修复前）Canvas 子节点顺序：

```
[0] ArtLayer      ← 画得最早 = 在下面
[1] HandArea
[2] Backdrop      ← 画在 ArtLayer 之上，整块糊住它
[3] TopArea
...
```

`ArtLayer` 落在了 `Backdrop` **之前**，于是不透明底板盖住了背景图、两个角色、
四行冷却槽与顶栏 —— 全屏只剩底板颜色，就是「黑屏 + 角色不显示」。

### 为什么 `SiblingIndexAfterBackdrop` 没能兜住

原实现返回 `backdrop.GetSiblingIndex() + 1`（语义本身没错：要在 Backdrop 之后），
但它在 `SetSiblingIndex` 之前**没有先把 Backdrop 归位**。构建日志显示
Backdrop 当时漂到了 index 1，于是 ArtLayer 被插到 2，反而压在了位于 0 的 Backdrop 上面。

即：**这个不变量没有任何一处强制**，任何一次节点顺序漂移都会静默地把画面糊掉，且**零报错**。

### 次因：ArtLayer 内部的背景图也排错位了

修复前 `ArtLayer` 的 12 个子里，`Bg_Dungeon` 排在 **index 10 / 12** ——
它在角色（6、7）、顶栏（2）、冷却列（3、11）之上，即使外层的 Backdrop 问题解决了，
背景图仍会盖住角色。**这是独立的一处顺序错误**，不能只修外层。

修复前 ArtLayer 顺序：

```
[0] HandCount_Monster  [1] Orb_Energy  [2] Hud  [3] CoolingScroll_Player
[4] Badge  [5] PlayedCard_Monster  [6] Char_Hero  [7] Char_Monster
[8] Badge  [9] HudBuff  [10] Bg_Dungeon   ← 背景在倒数第二层
[11] CoolingScroll_Enemy
```

## 修法（只动 `BattleArtLayerBuilder`，`Core/` 与运行时零改动）

1. **新增 `NormalizeBackdropOrder(canvas, log)`** —— 每次构建先把 `Backdrop` 摁到兄弟序 0。
   不依赖它"本来就在 0"，防任何一次推倒重建 / 手工拖动的漂移。
2. **`SiblingIndexAfterBackdrop` 语义澄清** —— 取 `backdrop.GetSiblingIndex() + 1`
   （在底板**之后** = 在底板**上面**），并在注释里写清「调用前必须先 Normalize」。
3. **`Bg_Dungeon` 收口** —— 所有子节点建完后，兜底把 `Bg_Dungeon` 拉回 ArtLayer 最底层
   （`SetAsFirstSibling`）。上面任何一个 `Build*` 若往 layer 里插节点，背景都可能被挤上去。
4. **新增 `VerifyLayerOrder(canvasGo, log)`** —— 存盘前自检
   `Backdrop.GetSiblingIndex() < ArtLayer.GetSiblingIndex()` 且 `Bg_Dungeon` 在 ArtLayer 序号 0；
   不合规就往 Console 砸 `Debug.LogError`。
   ⚠ **必须有这步**：这类错误的表现只是"画面不对"，控制台一条 error 都没有，
   全靠人眼看截图才发现 —— 自检把它变成一条能抓的报错。

- Edit 模式与 Prefab 资产双查，顺序一致（修复已落盘，不是只在内存里对）

## 教训

- **UGUI 的绘制顺序就是兄弟顺序**，「谁盖谁」不能用「谁先创建」的直觉推，要显式排。
- 不透明全屏底色（`Backdrop`）和背景图（`Bg_Dungeon`）**是两层不同的东西**，
  本次两处都错、症状还叠在一起，容易只看到一层。
- 顺序类不变量**没有编译期保护**，只能靠构建器自检 —— 参考 M21/M28 的"
  跨构建器挂组件 = 定时炸弹"，同属「静默失败」家族。
