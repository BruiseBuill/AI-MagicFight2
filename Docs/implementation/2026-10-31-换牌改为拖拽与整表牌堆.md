# 2026-10-31 · 换牌拖进换牌区、双方共用牌堆、发牌提速、结算加返回主菜单

本文记录当天的交互与发牌改动；牌堆方案以本节后续修正为准：**一局只有一副实体牌堆，双方都从堆顶抽、换掉的牌回堆底**。

## 1. 换掉的牌为什么「几乎必然又抽回来」

`BattleEngine.DoReplace` 原来是**逐张**处理的：

```
抽一张新牌 → 把这张旧牌回池 → 再抽下一张
```

开局 6 张手牌、牌堆剩 2 张。第 1 张换完之后旧牌就回到了池里，
第 2 张从「1 张新牌 + 1 张刚退回去的旧牌」里抽 —— **50%** 抽回自己刚换掉的那张；
第 3 张更高。玩家看到的就是「换了等于没换」。

**改法**：整批先抽完、最后统一回池（`DoReplace` ① ② ③ 步）。
同一批换牌期间旧牌根本不在池里，所以一张都不会抽回来。

## 2. 第 3 回合为什么不能换牌

牌组 = `BattleLaunch.DeckSize` = `BattleState.HandLimit` = **8 张**，
开局 6 张 + 第 2 回合 1 张 + 第 3 回合 1 张 = 8 张全到手，牌堆 `Remaining == 0`。
`IssueReplace` 里那句 `p.Deck.Remaining == 0 → _replaceSeat++` 于是必然命中 ——
第 3 回合的换牌拍根本没发出来。

**用户最终口径（2026-10-31，14:53 补正）**：标准战斗不是开局各分 8 张，而是
「拿一副牌出来供两名玩家玩」：双方在中途都从**同一副实体牌堆顶**抽牌；换牌把旧牌塞回**堆底**。
因为物理上只有一副牌，双方不可能拿到同一张。

**最终实现**：

- `BattleEngine.Create` 把所有座位卡池求并集，构造**唯一 `Deck`**；构造时洗一次。
- 标准战斗卡池 = 整张卡表（默认 44 张）；自定义战斗 = 双方所选 16 张。
  另一方已选的牌不能加入；`BattleLaunch.TrySetCustom` 提交时校验双方交集，重复则拒绝开战。
- `Deck.Draw()` 只取 `_cards[0]`（堆顶），`Deck.Return()` 只 `Add` 到尾部（堆底）。
- 旧实现里每个座位独立洗牌/随机回池的口径作废。

## 3. 换牌 = 把牌向上拖进换牌区

**用户口径**：开局的换牌和后续补牌的换牌，都改成把手牌**向上拖到手牌区上方那块区域**，
拖进去就视为换掉；这块区域略高于手牌区。

- `UiLayout.ReplaceZone*`：投放区 720 × 132，中心在 `HandAreaHeight + 120`。
- `HandView.SetReplaceZone(zone, hot)` + `ReplaceDropped` 事件：
  拖拽时按**牌的落点**（不是指针）判是否进区，进区回调点亮、松手抛事件。
- `DealView.EnsureDropZone()`：**运行时创建**这块区域（米白底 + 3px 金边），
  不进 Prefab —— 为一条槽去重跑 M7→M8→M11 会把别的构建器挂同子树的节点一起吃掉（铁律 4）。
- 层级插在 `Result*Root` 之前，结算界面永远盖得住它。

### 额度与「一起拖」

**用户口径（同日第二轮）**：

> 最多允许换三张；如果一次性选择了三张并一起拖动上去，之后就不会再有换牌机会；
> 先拖动了两张的话，仍然可以再换牌，但是再换牌的话，最多只允许选中一张了。

也就是**剩余额度**说了算：

- 点 / 划把手牌标记成「要换的」（上限 = 当前剩余额度，计数行 `已选 N / M`）；
- 把其中任意一张**向上拖进换牌区** → 标记的整批一次换掉；拖没标记的牌则只换它自己；
- 引擎换完把 `MaxSelect` 递减后**原地重发**同一条 `ChooseReplace`：
  3 张一次换完 → 额度归零，这一趟结束；先换 2 张 → 剩下 1 张额度，下次最多只能选 1 张。

引擎侧：`_replaceUsed` 记本趟已换张数，`IssueReplace` 的额度 = `limit - _replaceUsed`；
`DoReplace` 换完之后若还有额度且牌堆还有牌，`_phase = Phase.AwaitReplace` 重发。

「确认替换」键保留 —— 选中后拖上去是提交，点它也是提交。

## 4. 开局发牌为什么要 4~5 秒

实测（`StartBattle` → 换牌界面出现）：**4.2~5.5 秒**。

拆开看，两处都在白等：

1. `CardDrawnEvent` 的节拍 0.18s/张，双方各 6 张 = **2.16 秒**；
2. 更要命的是**每拍都会 `RaiseStateChanged` → `BattleUi.RefreshAll`**，
   发牌阶段每拍都重建整副手牌（还带飞行 ghost）——12 张牌就是 12 次全量刷新。

**改法**：

- `CardDrawnEvent` 节拍 0.18 → **0.06**；`ReplaceEvent` 0.22 → 0.12；
  `CardReturnedEvent` 0.18 → 0.12；
- `CoPlayBeats` 里**连续的 `CardDrawnEvent` 合并处理**：中间既不刷新也不让帧，
  收尾那一张才刷新 + 等待。手牌一次性铺开，逐张冒出来的观感交给
  `HandView` 的 `EnterDelay`（每张错开 0.035s）。

实测结果：**0.74~0.76 秒**（快进模式 0.76 / 正常 0.74，拍子已不再是瓶颈）。

## 5. 结算界面加「返回主菜单」

- **胜利**：原来只有「再来一局」。运行时克隆它得到一枚次按钮
  （`ResultWinView.EnsureHomeButton`：缩到 300×72、下移 104、底板换暗紫、文案「返回主菜单」），
  不改构建器、不碰 Prefab。点它走 `BattleUi.HandleQuitBattle` → `SceneRoutes.LoadHome()`。
- **失败**：那枚「退出」的行为一直是「回主菜单」，只是文案读不出来 ——
  运行时把文案改成「返回主菜单」（`ResultLoseView.Show` 里覆盖）。
