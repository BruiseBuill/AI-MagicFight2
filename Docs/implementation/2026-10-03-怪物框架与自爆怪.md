# 2026-10-03 · 怪物框架（按角色的发牌口径 + 回合行为算子）+ 第一只怪「自爆傀儡」

> 状态：实现完成（Core 万局回归已重跑；Unity 侧 Play 链路已实跑一次）
> 范围：`Core/Cards/DealProfile.cs`（新）· `Core/Characters/CharacterAbility.cs` · `Core/Characters/CharacterDefinition.cs`
> · `Core/Battle/BattleEngine.cs` · `Core/Battle/BattleLog.cs` · `Core/Ai/HeuristicAgent.cs`（注释）
> · `Unity/Configuration/CharacterConfig.cs` · `Unity/BattleDriver.cs` · `Unity/Ui/BattleUi.cs`
> · `Unity/Editor/MonsterBuilder.cs`（新）· `Tools/RuleSelfTest/MonsterScenario.cs`（新）
> 规则来源：用户 2026-10-03 口述（三条：怪物自有资产 / 第 N 回合行为 / 怪物发牌口径）

## 1. 为什么改

用户要「为自由设置怪物的能力」。动手前的现状是：

| 事项 | 改动前 |
|---|---|
| 怪物有没有自己的配置 | **没有**。`BattleCanvas.prefab` 的 `_participants` 填着 `DefaultPlayer.asset` / `DefaultMonster.asset`，两者都是 4/4、全 45 张牌池、无 AI 档案、无能力 |
| 一只怪的样子 | 共用 `BattleArtLibrary._monster` 一份 CharacterSet（换怪不换样子） |
| 发牌口径 | **整局一份**（`DefaultDealPolicy`：开局 6 张可换 3、第 2–3 回合各补 1）—— 所有座位只能同一套 |
| 怪物「第 N 回合做某事」 | **表达不了**。`CharacterAbility` 只有回血 / 抽牌 / 力量 / 减伤四个数值算子，没有规则级行为 |

所以要加三层：**按角色的发牌口径** → **规则级回合行为算子** → **一份可手调的怪物资产**。

## 2. 三层改动

### 2.1 按角色的发牌口径（`DealProfile`）

新增 `Core/Cards/DealProfile.cs`：`InitialHandSize` / `InitialReplaceLimit` /
`DrawFromTurn` / `DrawToTurn` / `DrawPerTurn` / `ReplacePerDraw`，不可变、构造即校验。
两个预设：

| 预设 | 开局 | 换牌 | 补牌 |
|---|---|---|---|
| `Human()` | 6 张 | 可换 3 | 第 2–3 回合各 1 张，可换 1 |
| `Monster()` | **8 张**（= `HandLimit`） | **不换** | **不补** |

`CharacterDefinition` 多一个 `DealProfile Deal`（**null = 用引擎那份 `IDealPolicy`**，
老构造点与老资产行为逐字不变）。引擎里所有读数收敛到四个方法
（`InitialHandSizeOf` / `InitialReplaceLimitOf` / `DrawOnTurnOf` / `ReplaceLimitOnTurnOf`），
`DoInitialDeal` / `DoBeginTurn` / `IssueReplace` 一律**按座位**取。

> ⚠ **`_replaceLimit` 这个字段被删掉了**。它原来是「本 Pass 能换几张」的共享值，
> 而开局那趟人类与怪物同时在名单里、上限不同 —— 留着它就会出现
> 「怪物被允许换 3 张」或「玩家只能换 0 张」这种按谁先被读到而定的行为。
> 现在它由 `IssueReplace` 按当前座位现算。

> ⚠ **「怪物不再补牌」不靠新规则实现**：8 张正好等于 `HandLimit`，抽牌入口
> `DrawCardToHand` 本来就按「手牌 + 冷却区 + 场上 ≥ 上限」拦下。把补牌区间写成空，
> 只是让第 2、3 回合的补牌拍**根本不发生**（否则会在那里白弹一次「无可替换」的过场）。

### 2.2 规则级回合行为算子

`CharacterAbilityOp` 从 4 个数值算子扩到 7 个，新增三个**规则级**算子：

| 算子 | 语义 |
|---|---|
| `SkipAttack` | 本次进攻**不出牌**，直接结束这个半场。⚠ 与规则 §3 的「手上无牌 → 掉 1 点」**不是一回事**：这条**不掉血** |
| `DamageOpponents` | 对敌方造成伤害 —— **不经防御结算、不受免疫光环影响**（即卡面口径里的「强制」） |
| `SelfDestruct` | 自身立即归零（不走伤害结算，`ReduceDamage` 插不上手） |

配套两样：

- `AbilityAmountSource`（`Fixed` / `OwnHp` / `OwnMaxHp` / `MissingHp`）——
  「自爆伤害 = 自己当前生命」这类口径必须是对局的函数，写死一个数表达不了；
- `CharacterAbilityDefinition.TriggerTurn`（**只在第 N 回合触发**，0 = 不限）——
  判在「消耗次数」之前，不满足回合时连使用次数都不该动。

引擎落点是一个新方法 `BattleEngine.ApplyTurnBehaviours(seat)`，替换掉原来那句
`ApplyAbilities(seat, TurnStarted)`。顺序与理由：

1. 回血 / 抽牌（与旧口径一致，先发生）；
2. **自爆**：把自身生命置 0，发 `SelfDestructEvent` —— ⚠ 这里**先不判终局**。
   否则「同归于尽」会在伤害落地之前就结束对局，被炸的那一方反而毫发无伤；
3. **强制伤害**：对每个敌方座位走一次常规 `ApplyDamage`（它自己会判一次终局）；
4. 统一补一次 `CheckDeath()`：自爆的那一方在这里才判负，于是「两边同时倒地」会被
   `DuelMode.TryFinish` 正确地判成**双方同时出局**。

之后 `DoBeginHalfTurn` 检查 `_skipAttack`：为真就 **直接进 `EndHalfTurn`**，
**不走** `DoAnnounceHalfTurn`（那条路会把「没牌」当成规则 §3，掉 1 点）。

### 2.3 一只怪 = 一份 `CharacterConfig` 资产

用户选定**只做 ScriptableObject 资产**（不做 GameObject Prefab）。一只怪的样子：

```
Assets/Resources/Monsters/Monster_Bomber.asset      # CharacterConfig
  characterId  monster.bomber
  displayName  自爆傀儡
  initialHp / maxHp   3 / 3
  useAllCards  ✔（全 45 张）
  aiProfile    （空 = 通用 HeuristicAgent）
  dealPreset   Monster                ← 开局 8 张、不补、不换
  abilities    [ DamageOpponents(OwnHp, turn 3) , SelfDestruct(turn 3) ]
  useCustomArt ✘                      ← 美术共用 BattleArtLibrary.Monster
```

`CharacterConfig` 新增的字段（全部在 Inspector 里可改）：

| 字段 | 说明 |
|---|---|
| `dealPreset` | `EngineDefault` / `Human` / `Monster` / `Custom` —— 翻成 Core 的 `DealProfile` |
| `dealInitialHandSize` … `dealReplacePerDraw` | 仅 `Custom` 生效的六个数字 |
| `abilities[].triggerTurn` / `amountSource` | 能力的新两列（第 N 回合 / 数值来源） |
| `useCustomArt` + `art` | 这只怪自己的动作组；**不勾**就沿用 `BattleArtLibrary.Monster` |

> ⚠ `useCustomArt` 这个 bool 不是多余的：`art` 是 `[Serializable]` class，
> 反序列化之后**永远非 null**（只是一组空 Clip）。用 `art != null` 当判据会让每只怪
> 都被绑上一份空美术 —— 症状是**怪物整个不见了，而且零报错**。

接线在 `BattleDriver`：

- 新增 `[SerializeField] CharacterConfig _monsterConfig`（建议指向 `Resources/Monsters/` 那份）；
- `ConfigFor(seat)` 的查找顺序 = **怪物资产（非本地座位）→ `_participants` 名单 → 兜底**。
  > ⚠ **必须是「怪物资产优先」**：本工程 `BattleCanvas.prefab` 里 `_participants`
  > **早就填着**老名单（`DefaultPlayer` / `DefaultMonster`）。若名单优先，新字段
  > **永远不生效**，而症状是「进 Play 一切正常」—— 只有去读怪物血量才会发现还是 4/4。
  > 这让 `_monsterConfig` 与名单不能同时用于「多个自定义座位」；需要那种配置时把它留空。
- `MonsterArtSet` 属性把这只怪的美术交给 `BattleUi`；
- 兜底路径（没配任何资产）也显式给了口径：本地座位 `DealProfile.Human()`、
  其余座位 `DealProfile.Monster()` —— 不显式给的话会落回引擎默认（＝人类 6 张）。

`BattleUi` 侧两处：

- `ApplyMonsterArt()` 在 `HandleStarted` 里换怪物的美术。
  ⚠ **不能放在 `WireArtLayer`**：那一步在 `Start` 里跑，而怪物资产是
  `BattleDriver.StartBattle` 才解析的（它比 `Start` 晚一帧，见 `CoAutoStart`）。
- 新增 `SelfDestructEvent` 的两处响应：`PlayCharacterBeats`（播一次受击插播）
  与 `HandleBeat`（顶部提示条「◇◇ 自爆（原生命 N）」）；
  `BattleDriver.BeatDuration` 给它 0.6 s。

## 3. AI 侧要不要跟着改（用户问的第三点）

**结论：出牌逻辑本身不用改，但有一处口径偏移与两处新边界，都需要知道。**

1. **流派判定不依赖「6」**。`HeuristicAgent.SelectArchetype` 读的是
   `HandOf(seat)` ——「第一次轮到自己出牌那一刻的手牌」。人类 6 张、怪物 8 张都能直接用，
   不需要分支。原文注释里那句「= 开局 6 张 + 替换结果」已订正为按座位口径。
2. ⚠ **但 `ArchetypeJudge` 的四个分数是按「张数」计的**（「力量 ≥8 的牌有几张」）。
   手牌多一张就多一点分数，而**高攻是四个流派里唯一纯按张数计分的** →
   8 张的怪物天然更容易被判成高攻。**这一轮没有改阈值**：改它会同时改变玩家的 AI 行为，
   属另一轮回归。
3. ⚠ **`CanOpenSlowZone`（区域减速的开启条件）要求「对方手牌 ≤ 3」**。
   怪物一张都不再补 → 它的手牌**一旦掉到 3 以下就永远 ≤3**，
   于是玩家侧的减速流派会比以前更容易开。这是规则改动带来的真实变化，暂按现状。
4. ⚠ **手牌耗尽是新的终局风险**：8 张不补，后期必然空手；
   那时 `DoAnnounceHalfTurn` 的「手上没牌 → 掉 1 点」与连击链的
   `Hand.Count > 0` 条件都会开始生效。自测里覆盖了「自爆怪第 3 回合手上仍有牌」这一条。

## 4. 验证

### 4.1 新增自测（`Tools/RuleSelfTest/MonsterScenario.cs`，6 条全 PASS）

| 断言 | 覆盖的失效方式 |
|---|---|
| 人类发牌口径不变（6 / 3 / 第 2–3 回合各 1 / 第 4 回合起不补） | 「顺手把人类也改成 8 张」 |
| 怪物发牌口径 = 8 / 0 / 不补 / 不换 | 预设写反 |
| 兜底角色带上各自口径 | 兜底路径漏传 `DealProfile` → 怪物变回 6 张 |
| 非法口径（0 张开局 / 补牌区间反向）在构造时被拒 | 静默接受坏配置 |
| **实跑 40 局**：怪物开局真拿 8 张、玩家 6 张，之后怪物**一次「回合补牌」都没有**，手牌峰值 ≤ 8 | 「不补牌」写进配置但引擎没读 |
| **自爆怪实跑**（命中若干局）：第 3 回合不出牌 → 强制伤害 = 它当时的生命（不打折、不算防御）→ 自身归零 → 玩家生命精确减少该值 → 终局 | 伤害取错来源（取初始生命 / 取上限）；自爆没落地；`DamageOpponents` 被防御吃掉 |
| **对照组**：只声明「第 3 回合不出牌」时**不掉血**、对局继续到第 4 回合 | 把 `SkipAttack` 走成规则 §3 的「手上没牌 → 掉 1 点」 |

断言还顺手修掉了 `RuleAssertions.CheckHandConservation` 里写死的
`expected = 6`（原来按回合 +1，遇到 8 张的怪物必然误报「手牌守恒被破坏」）。

### 4.2 万局回归（种子基 20261700）

| | 2026-10-01（改前） | 2026-10-03（本轮） |
|---|---|---|
| 异常 / 平局 | 0 / 0 | **0 / 1** |
| 平均回合 / 最长 | 6.62 / 3158 | **6.39 / 100** |
| 事件总数 | 1774250 | 1681330 |
| 玩家(先手)胜 | 4926（49.3%） | **5655（56.5%）** |
| AI(后手)胜 | 5054（50.5%） | **4336（43.4%）** |

- 最长回合 3158 → 100 是 2026-10-03 那条**全员 AI 100 回合上限**（`AiTurnLimit`）生效，
  与本次无关；那份基线文档此前没更新到。
- 违规样本仍是那 **12 条既有噪声**（`区域类选项的 k 或匹配张数非法`），
  类别逐字相同（落在 seed 20261700 ×6 / 20261701 ×3 / 20261714 ×3）。
- ⚠ **先手胜率 +7.2 个百分点是真的，不是噪声**。原因是怪物的**换牌机会没了**：
  老口径下它开局能换 3 张、第 2/3 回合各再换 1 张（`SimpleAiAgent.ReplaceWeakCards`
  专门扔掉力量 ≤1 的牌），新口径一次都不换。「开局多给 2 张、但一张都不许换」
  对 AI 是**净亏**。想让它更强 → 在怪物资产上把 `dealPreset` 改成 `Custom`
  并把 `dealInitialReplaceLimit` 设成 2 / 3。

### 4.3 Unity 侧 Play

`SampleScene` 实跑一局（用合成的 `OnPlayerDecision` 钩子替玩家应答）：

```
[PROBE] Attack seat=0 card=磁暴 turn=1 … Attack seat=1 card=烈焰斗篷 turn=2
[PROBE] Attack seat=0 card=自燃 turn=3
[PROBE] SelfDestruct seat=1 hpBefore=3
[PROBE] Damage seat=0 amount=3 src=自爆 turn=3
[PROBE] GameOver winner=-1 reason=双方同时出局
```

三件事同时成立：**第 3 回合怪物一次 `AttackDeclared` 都没有**、自爆伤害正好等于它当时的

进场读数 `seat1 hp=3/3 hand=8 name=自爆傀儡` —— 8 张手牌与 3 点血都真的落在对局里。

## 5. 已知遗留 / 未做

- ⚠ **只有 1 只怪**（用户口径「先做 1 只 + 框架」）。加第二只 = 在
  `MonsterBuilder.Specs` 加一行 + 跑一次菜单。
- ⚠ **`useCustomArt` 还没被真正用过**：本批怪共用 `BattleArtLibrary.Monster`，
  所以「换怪换样子」这件事**只留了入口、没验证过**。真要给某只怪换图时，
  需要先把它的动作帧导入 `BattleArtLibrary`（素材流程不变），再在这份资产上引用。
- ⚠ **自爆傀儡的数值是「致命的」**：伤害 = 它当时的生命，默认 3 点血。
  实测那局玩家在 3 回合内一次都没打穿它 → 被炸 3 点 → 平局（冒险里平局按失败算）。
  两个旋钮：`initialHp` 调到 2，或把 `amountSource` 改成 `Fixed`、`amount` 填 1
  （= 用户最初说的「强制减少玩家一点生命」）。
- ⚠ **`_monsterConfig` 与 `_participants` 不能同时用于多自定义座位**（见 §2.3）。
  DuelMode 是 1v1，当前够用；3 人以上时要把 `_monsterConfig` 留空、回到名单。
- ⚠ **`SkipAttack` 只有对照组在测**，没有真实的「不出牌但仍然活着的怪」。
- ⚠ **没有「第 N 回合」之外的计时口径**（例如「每 2 回合一次」「血量低于 X 时」）。
  `TriggerTurn` 是精确匹配的单回合；要别的口径得再加字段。
- ⚠ **地图 / 商店 / 强化 / 女巫工坊那几个场景没有怪物**，本次只接在 `SampleScene`。
