## 背景与目标

用户口径（2026-09-26，附商店界面参考图）：

1. 参考图里左下角站着主角 —— 我们的商店也得放进去一个**主角**；
2. 参考图右下角「离开」右边还有一个**背包键** —— 也要加，且**点了能看主角当前的卡池**；
3. 卡池口径 = **当前持有**（不是「本局启用的卡表子集」）；
4. 面板形态 = **全屏网格 + 滚动**；
5. 主角与 UI 素材都用工程 `Art/` 里已有的（`Art/Chars/Hero/*` + 已切好的 `Shop_BagIcon.png`）。

`Shop_BagIcon.png`（144×135）其实在 P4 落版时就切出来了，只是**当时版式里没用上**
（[P4 文档](2026-09-26-商店场景实施.md) §后续事项第 3 条写着「要不要放、放了开什么面板，待定」）——
本次就是那条待办的答案。

**本次不做**：主角的待机动画、背包里的长按看详情、背包键的数量角标、
以及 `ShopSceneEntry` 那段调试实现搬进 Core（正式的冒险流程还没接）。

## 方案与影响

### 1. 主角：一张静态立绘，摆位被货架反推出来

素材直接吃战斗那份 `BattleArtLibrary.Hero.Idle`（与战斗里是**同一位主角、同一张图**），
构建期把 `sprite` / 尺寸 / 锚点一次算好写进 Prefab：

| 项 | 值 | 来历 |
|---|---|---|
| 素材 | `Hero_idle_01.png` 188×185（待机只有 **1 帧**） | `BattleArtLibrary.Hero.Idle` |
| 显示尺寸 | **432.4×425.5** | 素材画布 × `ShopHeroScale = 2.3` |
| 脚底 | (215, 24) | 画布绝对坐标，锚点**左下** |
| `pivot` | (0.5, **0.038**) | 取素材自带的脚底锚点 `Clip.Pivot` |
| 头顶 | y ≈ 449 | 24 + 425.5 |

⚠ **「为什么是 2.3 倍、为什么站这么靠左」都是算出来的，不是照着参考图抄的**：
参考图里主角身高占屏 58%（≈622 px），但那家游戏的四张卡从 x≈488 才开始；
**我们的货架最左一张卡占 x 287…483**（`ShopShelfCenterX = 730` 那套算出来的），
主角横向只能占 **0…287**，否则一定压到第一张卡。取 2.3 倍之后：

- 横向 0…432（斗篷最宽处），但**头顶 449 < 卡底 472** → 与卡面**完全不重叠**，
  只与第一列价格牌（y 367…461）在角上擦一点；构建器把主角排在**货架之前**，
  于是价格牌压在他兜帽上 —— 读起来正是「他站在柜台前」。
- 素材只有 185 px 高，2.3 倍已经是「平涂低多边形还扛得住」的上限；再放大明显发糊。

⚠ **2026-09-27 之后上面那笔账的输入变了**（见
[商店场景实施](2026-09-26-商店场景实施.md) §4.1）：货架整排被用户手调到画布中心 **976**、
卡面又放大 10% → 最左一张卡落到 **x 523…739**，价格牌中心降到 405（占 362.8…447.4）。
**主角这一组数值（215 / 24 / 2.3）不需要动、也没有动**：他横向只占 0…432，
离新货架更远了；头顶 449 仍在卡底 458.4 之下。原来的推导结论（「站这么靠左」）
反而更宽裕 —— 记在这里只是免得下次有人拿旧数字（287…483 / 472）去复核时对不上。

⚠ **刻意不用 `CharacterView` / `SpriteAnimator`**：只有 1 帧，要的就是「一张图摆在该在的位置」。
那两个组件的 `_clip` / `_scale` 是**非序列化**字段，重开工程归零；
哪天有人给它加个 `OnEnable`，静态立绘会当场消失且零报错。构建期写死进 Prefab 没有这个面。

### 2. 背包键：占用右下角最右一格，「离开」让位

| 项 | 值 |
|---|---|
| 尺寸 | 92×86（素材 144×135 缩到与「离开」同高；比例差 0.3% → 用 `Image.Type.Simple`，不做九宫格） |
| 位置 | 右边距 64 / 下边距 44 |
| 「离开」 | `ShopLeaveRight` **64 → 176** = 64 + 92 + 缝 20 |

`transition = None`：底图自带木质描边与高光，再叠颜色过渡会打架，
更要紧的是 `ColorTint` 会把 `targetGraphic` 的常态色**刷上去**（整块变单色、图形消失）——
这条口径「离开」上已经定过。

### 3. 背包面板：`BagLayer` = 遮罩 + 面板 + 滚动网格

```text
BagLayer ← 排在 ShopCanvas 最后一个子节点（= 画在最上层），ShopBagView 就在这里，默认失活
├─ Veil        铺满画布的黑纱 0.62 —— **同时是关闭区**（点哪儿关哪儿）
└─ Panel       Peek_Panel 九宫格（复用 M25 那块底板），1620×880
   ├─ Title     「背包 · 当前卡池」
   ├─ Count     「N 张」
   ├─ Cards     1500×620 的滚动区（ScrollRect + 压暗背板）
   │  ├─ Viewport → RectMask2D → Content（GridLayoutGroup 6 列 + ContentSizeFitter）
   │  │                          └─ BagCardTemplate（`CardView_Hand.prefab` 实例，失活）
   │  └─ Scrollbar
   ├─ Empty     一张牌都没有时的提示
   └─ CloseButton 「关闭」
```

- **卡面仍复用唯一那份 `CardView_Hand.prefab`**（红线 9），列宽 196 与手牌 / 货位同一档；
  张数由数据决定（运行时按需克隆、失活复用），所以「卡池从 8 张变 40 张」不用回来改场景。
- 卡面子树自带的 `Graphic.raycastTarget` / `Button` / `CardInteractor` **全部关掉**：
  否则① 卡面会吃掉滚动的拖拽（列表拖不动），② 一次点击冒泡两遍。
- **遮罩与「关闭」都由面板自己接**（`ShopBagView.Awake` 运行时 `AddListener`，铁律 8）。
  `ShopView` 只做两件事：把背包键的点击转成 `Show`，以及在数据变了时重新喂一份卡池。
- **`Show()` 幂等**：重复调用只重排、不重建；面板**不在 `Awake` 里 `Hide`**
  （首次 `SetActive(true)` 才触发 `Awake`，同帧的 Hide 会把刚显示的内容按灭 —— 本工程已中招两次）。

### 4. 卡池口径合一：背包与货架共用一处「当前持有」

`ShopSceneEntry` 新增 `_owned`（运行时持有列表）与 `ResolveOwned()`：

- `_ownedCardIds` 填了 → 照它；**留空 → 回落到设计文档 §5.3 的 8 张起始牌池**
  （`a` 暴风雪 · `b` 冰风暴 · `c` 凝固 · `d` 寒流 · `f` 滚石冲击 · `k` 电弧 · `s` 喷泉 · `ag` 淬火）。
  ⚠ 原来留空等于「一张都没有」→ 货架从全 40 张里抽，与 §5.3 的口径**不一致**。
- 同一个 `_owned` 同时喂**两处**：货架的「未持有池」（补集）与背包的卡池。
  两者各算各的就会出现「背包里明明有暴风雪、货架还在卖暴风雪」——一眼假、零报错。
- **买下的牌当场进背包**：`OnSlotClicked` 把 id 加进 `_owned` 并重喂一次
  （不这么做的话，背包永远停在开局那 8 张，买完点开看不见新牌）。

### 5. 顺手修掉的真 bug：构建器 `AbsolutePath`

`ShopUiBuilder.AbsolutePath` 原写成
`Combine(工程根, assetPath.Substring("Assets/".Length))` ——
把 `Assets/` 摘掉却没补回工程根的 `Assets`，查的是 `<工程>/Scenes/Shop.unity`（不存在），
于是**恒返回 false**，`RunAll` 每次都当「场景还不存在」去**新建一个空场景**。
日志上只表现为「新建」两个字，实际后果是**场景里手改过的东西每跑一次构建就被抹掉**。
已改成保留完整资产路径；构建日志从「新建」变成「**打开** Assets/Scenes/Shop.unity / 拆掉旧 ShopCanvas」。

## 踩坑记录

1. ⭐⭐⭐ **`AbsolutePath` 把 `Assets/` 摘掉却没补回来** → 构建器**恒判「场景不存在」**，
   每次都新建空场景再存回原路径。日志只说「新建」，看不出任何异常，
   后果是**场景里手改过的东西每跑一次就被抹掉**（正是「手摆的节点活不过一次重跑」那一类）。
   判据：构建日志里那句「新建 / 打开」。**任何「查文件在不在」的辅助函数，写完先打印一次实际路径。**
2. ⭐⭐ **遮罩 + 面板的射线分工**：遮罩是「点哪儿关哪儿」，**面板那一层必须 `raycastTarget = true`**。
   否则点面板内部的空白会穿到遮罩上 —— 伸手去点「关闭」的途中面板先自己关了，**零报错**。
   验收必须真点一次「面板中心」与「面板外」两处，只点一处看不出区别。
3. ⭐⭐ **网格列宽是被算出来的**：滚动区 1500 − 滚动条 26 = 视口 1474，减网格 padding 各 14 → **1446**；
   6 列 × 230 + 5 缝 × 12 = **1440**（只余 6）。单元格一旦超过 231，第 6 列会被 `RectMask2D`
   **静默裁掉一截**。改 `ShopBagCellWidth` / `ShopBagSpacing` / 面板宽 / 视口右内缩，**四处要一起核**。
4. ⭐ **锁 Game 视图的「焦点」会给出坏帧**：第一次截图（背包开着）正常，
   隔一步再截拿到的是**纯相机底色**（1 种颜色、84 KB，正常帧 5–6 MB）。
   **判据就是文件体积与颜色数**；重截即可（本工程 M41 已记过这条）。
5. ⭐ **`execute_code` 用的 CodeDom 是 C# 6**：局部函数（`Vector2 A(float x, float y) {…}`）**编不过**，
   报的是一串 `Unexpected symbol`。要写就把坐标算成 `Vector3` 传进去，别定义局部函数。
6. ⭐ **探针里读 `CardDef.Name` 要用 `GetField`**：它是**字段不是属性**。
   写成 `GetProperty("Name")` 拿到 `null`，下一句 `GetValue` 直接 NRE，
   而 `execute_code` **只给一个 IL 偏移、没有行号**（本工程 M32 已记过同类，这是又踩一次）。
7. ⭐ **别在 `execute_code` 里 `Thread.Sleep`**：会给编辑器刷一条
   `PlayerLoop internal function has been called recursively`（在主线程的 PlayerLoop 里睡）。
   要等布局就 `Canvas.ForceUpdateCanvases()`。
8. ⭐ **`Box()` 的 `pivot` 是参数不是固定值**：主角那一下如果照抄别的节点给 `(0.5, 0.5)`，
   半个身子会沉到地面以下；给 `(0.5, 0.5)` 的**锚点**（而不是 pivot）则会让节点整体跑到屏幕外
   （`ShopHeroX` 是画布绝对坐标，见 `UiLayout` 商店段那条注释）。

## 后续事项

1. **主角是静态单帧**。`Art/Chars/_Source/Hero_Anim_Idle.png` 那张源表里其实有 **16 帧**，
   但 `Art/Chars/Hero/idle/` 下只切出 1 张（战斗侧同样只播 1 帧）。
   想做「站着呼吸」的待机：先把源表按同一套 pivot/尺寸切满 16 帧、重建美术库，
   再把商店主角换成 `CharacterView` 或补 `SpriteAnimator`（届时它才有意义）。
2. **背包里的卡不能长按看详情**（货位上的卡也不能）。要做的话复用 M38 那套
   「放大 = `CardView_Hand` 的嵌套实例」即可，但要单独接一条手势链。
3. **背包键没有数量角标**（参考图里也没有）。想加在 `BagButton` 上挂一枚 TMP，
   数据来源就是 `_owned.Count`。
4. ⚠ **`ShopSceneEntry` 里那段「扣钱 / 抽货架 / 持有列表」依然是调试实现**，
   正式接入 `AdventureCommand` / `RunSnapshot` 时**整段删**（P4 就记过的待办，本次又给它加了一条持有逻辑，
   一起搬走）。它现在相当于一张写着待办的字条。
5. 其余事件场景（`Rest` / `Event` / 结算页）命名与承载仍未定 —— 见
