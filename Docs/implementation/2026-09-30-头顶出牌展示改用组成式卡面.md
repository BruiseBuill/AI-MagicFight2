# 头顶出牌展示改用组成式卡面

> 状态：已落地 · 日期：2026-09-30 · 范围：战斗界面 `PlayedCardView`（M35 头顶出牌展示）

## 背景与目标

[上一轮](2026-09-30-卡面统一到插画与删除成品整图.md)把 `Assets/Art/Cards/` 那一族 760×1056
**成品整图**删掉之后，卡面只剩插画这一份图，于是头顶出牌展示 / 长按放大 / 飞行卡这三处
变成了**无框无字的插画** —— 卡名、力量、冷却、效果文字全都不在了。

用户口径（2026-09-30）：

> 当前双方显示在头顶的牌只有卡面插画，你需要让其显示方式和手牌当中的卡一致
> （仅大小不同，可以直接缩放）。

目标：头顶出牌展示改成**与手牌同一份组成式卡面**（`CardView_Hand.prefab`），
差别只有缩放 —— 不再有「插画版 / 组成式版」两套渲染路径。

本次**不含**：长按放大（`DetailPanel/Face` 已经是嵌套实例，早就吃组成式）与飞行卡
（`CardTransitView`）的同类改造；两者仍在显示无框无字的插画。

## 方案与影响

### 卡位里画什么（`PlayedCardView`）

- 新增序列化字段 `_cardPrefab`（类型 `CardView`，由构建器写进 Prefab）。
- 卡位（`Card1` / `Card2`）**不再**只是「一张铺满的 `Image`」，而是**容器**：
  运行时在它下面惰性 `Instantiate(_cardPrefab)`（节点名 `CardFace`，四角拉伸铺满卡位），
  然后 `Bind(snapshot, ViewMode.Mini, i)` + **`SetFaceWidth(卡宽)`** ——
  与 `CooldownView.Take` 里那句同一个口径（铁律 9：组成式卡面只有一份 Prefab）。
- 卡位自己那层纯色 `Image` 只当**占位**，`EnsureCard` 建出卡面时把它 `enabled = false`
  （留着会从卡面圆角外面透出一圈，还白搭一块挡射线的面）。
- `Layout(count)` 仍是尺寸唯一来源，新增把算出来的卡宽存进 `_slotWidth` 并回灌给已建好的卡面
  —— 单张 / 双张两套版式都能跟着变。
- **退化链**：`_cardPrefab` 为空（老 Prefab 没跑过 M11）→ 退回原来的「插画铺满卡位」，
  少一层信息但牌照样看得见，不白屏。

### 出牌展示不吃射线

`PlayedCard` 面板的 `CanvasGroup` 现在显式 `blocksRaycasts = false` / `interactable = false`
（构建期在 `Configure` 里写、运行时 `Show` 里再重申一次）。

两个原因：

1. 卡面 Prefab 自带 `Button` / `CardInteractor`，「展示用的牌」不该被当成能点的牌；
2. `Graphic.Raycast` 会**沿父链查 `CanvasGroup`** —— 面板这层一关到底，
   整棵子树（含卡面里十几个 `raycastTarget` 的图形）一次全部退出射线判定，
   不会去抢角色模型 / 拖拽面 / 冷却视口的点击。

### 构建器（`BattleArtLayerBuilder`）

`BuildPlayedCard` 新增 `CardFacePrefabPath = "Assets/Prefabs/Ui/CardView_Hand.prefab"`，
载入后经新的 `Configure(..., CardView cardPrefab, ...)` 参数写进两个 `PlayedCardView`；
取不到时**只记一条告警**并留空（运行时自动走退化链）。

### 已改动的文件

| 文件 | 改动 |
|---|---|
| `Assets/Scripts/Unity/Ui/PlayedCardView.cs` | 新增 `_cardPrefab` / `_cards` / `_slotWidth`；`BindFace` + `EnsureCard`；`Show` 的绘卡分支；`Layout` 回灌卡宽；`Configure` 增参 + 关闭射线 |
| `Assets/Scripts/Unity/Editor/BattleArtLayerBuilder.cs` | 新增 `CardFacePrefabPath` 常量；`BuildPlayedCard` 载入并向 `Configure` 传参 |
| `Assets/Prefabs/Ui/BattleCanvas.prefab` | `PlayedCard_Hero` / `PlayedCard_Monster` 两份 `PlayedCardView` 的 `_cardPrefab` 指向 `CardView_Hand.prefab` |

> ⚠ **这次没有重跑 M7 / M8 / M11**：改动只落在「卡位里画什么」这一层，
> Prefab 结构一行未动，所以走的是**定点写字段**（`PrefabUtility.LoadPrefabContents` →
> `SerializedObject` 改 `_cardPrefab` → `SaveAsPrefabAsset`），避开了 M7 推倒整棵 Canvas 的代价。
> 备份：`Artifacts/backups/2026-09-30-playedcard-face/`（`BattleCanvas.prefab` + 两个脚本）。

## 唯一来源与替代关系

- 卡面外观的唯一来源仍是 [`36-M38卡面统一到单一Prefab`](36-M38卡面统一到单一Prefab.md)
  定下的那一份 `Assets/Prefabs/Ui/CardView_Hand.prefab` —— 本次**没有**新增第二份卡面 Prefab。
- 头顶卡位的位置、尺寸、间距、衬底宽度的唯一来源仍是 `UiLayout` 的 M13/M20 段
  （见 [`33-M35头顶出牌展示双方化与飞向冷却槽`](33-M35头顶出牌展示双方化与飞向冷却槽.md)）。
- 本次替掉了 [`2026-09-30-卡面统一到插画与删除成品整图.md`](2026-09-30-卡面统一到插画与删除成品整图.md)
  里「头顶出牌展示 = 插画」那条结论；该文的其余结论（成品整图整族已删）仍然有效。
