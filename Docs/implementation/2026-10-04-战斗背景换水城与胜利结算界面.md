# 战斗背景换水城 + 战斗胜利结算界面

> 状态：已落地（截图验过） · 日期：2026-10-04 · 范围：战斗场景（`SampleScene` / `BattleCanvas`）、
> `BattleArtLayerBuilder`、`BattleUiBuilder`、`BattleUi`、新增 `ResultWinView`

## 背景与目标

用户这一轮要三件事：

1. 战斗场景换背景 —— 新图 `Bg_WaterCity_Battle-v1.png`（水城），「适用地图水城」；
2. 做**战斗胜利的结算界面**，参考图 `Assets/Art/Reference-5.png`：
   顶部徽记 + 「战斗胜利」横幅 · 「获得奖励」分隔线 · **三张卡选一张进手牌** · **+ 20 金币** ·
   「继续」回地图；
3. **失败界面暂不做**（等美术素材）。

参考图是**成品效果图**（带洞窟场景、光影、文字烘在画里、1672×940），不是白底 UI 套件图。
本工程历史上那批 `Ui/_Source/*.png`（Peek 弹窗、商店货架）才是「白底套件图 → 按 alpha 切」那条路。
从成品图直接抠元素会带一圈岩壁底色 + 阴影、放大到 1920 还糊 —— 见 §3「为什么没切图」。

## 方案与影响

### 1. 战斗背景

| 位置 | 改动 |
|---|---|
| `Assets/Scripts/Unity/Editor/ArtImportBuilder.cs` | 新增常量 `BattleBgFile = "Bg_WaterCity_Battle-v1.png"`；`SetAll(...)` 的 `background` 参数改成从它取；菜单文案同步 |
| `Assets/Scripts/Unity/Editor/BattleArtLayerBuilder.cs` | 背景节点 **`Bg_Dungeon` → `Bg_Stage`**（三处：`BuildBackground` / `RunAll` 的兜底收口 / `VerifyLayerOrder`）；cover 的原始尺寸**改成从 `Sprite.rect` 现读**，`UiLayout.BgNativeWidth/Height` 只作兜底 |
| `Assets/Art/Backgrounds/Bg_Dungeon.png` | **保留没删** —— 地图主题（水城 / 地牢…）还没做，随时能换回去 |

「改一行常量 → 重跑 `魔法乱斗/整理 · 配置新美术导入` → 重跑 M11」即可再换背景，不碰代码与 Prefab。

### 2. 胜利结算界面

新增一整块全屏界面 `Canvas/ResultWinRoot`（在 M8 构建器里建，**排在 Canvas 最后一个** = 画在最上）：

```
ResultWinRoot（铺满，默认 SetActive(false)）
├─ Bg           战斗背景 cover 铺满（BattleArtLibrary.Background）
├─ Veil         暗纱（UiTheme.ResultWinVeil，同时也是整块的射线面）
├─ Crest        顶徽记：三层同心菱形 + 中心点 + 左右一对横放的「翼」
├─ Banner       「战斗胜利」
│   ├─ Plate    RoundedRectangle（Sliced）暗紫 · Shade 下缘加深
│   ├─ TailLeft / TailRight   两个朝外的三角形（燕尾）
│   ├─ EdgeTop / EdgeBottom   3 px 金边
│   └─ Title    TMP（标题字体，68 号）
├─ Divider      「获得奖励」：左右细线 + 两侧菱形 + 中央文字
├─ Cards        三个 Slot（每个 = 暗衬 + 一份 CardView_Hand 实例）
├─ Gold         金币（Circle + Hex_Vertical + Diamond）+ 「+ 20」
└─ ContinueButton  牌匾 + 金边 + 两侧四角星 + 「继续」
```

版式常量全在 `UiLayout` 的「战斗胜利结算界面」段（**相对屏幕中心的偏移，y 向上为正**），
配色全在 `UiTheme` 的「战斗胜利结算界面」段。参考图 → 画布的换算写在 `UiLayout` 那段注释的表里。

运行时的交互在新增的 `App/Ui/ResultWinView.cs`：

- `Show(CardDef[], gold)` 绑三张候选卡、写金币数；
- 点卡 = 选中（暖金描边 + 抬升 `ResultWinCardLift`）→ 再点同张 = 取消；
- 点「继续」把「选了第几张」通过 `ContinueClicked` 报出去，**自己不做任何落盘**。

`BattleUi` 侧：

- `HandleFinished` 里 **赢了 → 新界面**，失败 / 平局仍旧走老的 `ResultRoot`
  （用户口径：失败界面等素材）。两条路共用的收尾抽成 `ShutdownAfterFinish()`；
- `ShowResultWin()` 现抽三张（`RollRewardChoices`，从 `CardCatalog.Builtin()` 洗牌取前 N，
  **不用 `CardCatalogAsset`** —— 后者会把已落盘的 `a+` 也当成一张独立的牌）；
- `HandleResultWinContinue(int picked)`：把选中的牌追加进 `_driver.ActiveSaveSlot` 的卡池
  （走 `SaveStore.TryLoadCardIds` → 追加 → `TrySaveCardIds`，**读的时候要叠加过强化册的目录**）、
  `MapRun.Gold += 20`（只在冒险里）、然后 `MapRun.ReportBattle(true)` + 回 `Map`；
  不在冒险里（单场景调试）则 `_driver.StartBattle()`。

### 3. 为什么没从参考图切图

试过一轮：对 `Reference-5.png` 做「局部背景减除（大半径高斯）+ 行列区间过滤 + 闭运算 + 填洞」。
结论是**不可用**：

- 元素自带一圈暗描边与投影，抠出来贴到水城这种亮背景上就是一圈脏边（原图背景是暗岩洞窟，
  两者的边缘本来就咬在一起）；
- 「战斗胜利」「继续」是**烘在图里**的字，要换成本工程字体就得先擦字再补底色，风险高；
- 原图 1672×940，横幅切出来只有约 570×125 —— 放到 1920 画布上必糊。

所以改成**按参考图的版式与配色、用 PolySprite 形状重建**：可无限缩放、可重跑、
文字走本工程 TMP 字体、尺寸精确。代价是金属质感不如原图（`RoundedRectangle` 是纯色块）。

> 真要「像素级复刻」的话，下一步不是抠图，而是**用图像生成重出一张透明底的 UI 套件图**
> （`Ui/_Source/661ca76a-….png` 那批就是这么来的），再按 alpha 切分。本轮没做。

## 唯一来源与替代关系

- **背景图的唯一来源** = `ArtImportBuilder.BattleBgFile`（→ `BattleArtLibrary._background` → `Bg_Stage`）；
- **版式**唯一在 `UiLayout.ResultWin*`，**配色**唯一在 `UiTheme.ResultWin*`，两边都不散落字面量；
- 与 `Docs/implementation/16-运行时UI预建与行动提示.md` 一致：节点全部**构建器预建**，
  运行时不 new 长期节点；
- 旧 `ResultRoot`（[`09-BattleUi实现说明`](../archive/implementation/09-BattleUi实现说明.md)）
  **仍然有效**，只是职责收窄成「失败 / 平局 / 单场景调试」。

## 验证

实跑并通过（Unity 2022.2.15f1c1 + MCP）：

1. `魔法乱斗/整理 · 配置新美术导入` → `BattleArtLibrary.Background = Bg_WaterCity_Battle-v1 (1536×1024)`；
2. `M8 · 构建 BattleUi` → `M11 · 构建 BattleArtLayer`：层级自检 `Backdrop(0) < ArtLayer(1)` 通过；
3. 进 Play 截图（`Captures/01_battle_watercity.png`）：水城背景 + 12 张手牌 + 双方冷却区正常；
4. 反射调 `BattleUi.ShowResultWin()` 后截图（`Captures/09_result_win.png`）：
   徽记 / 横幅 / 分隔线 / 三张真实卡面 / 金币 `+ 20` / 继续键全部就位；
5. 反射调 `ResultWinView.OnCardClicked(...)` → `SelectedIndex=1 · SelectedCardId=ab`，
   选中那张抬起 + 另外两张压暗（`Captures/08_result_pick.png`）。

**未实测**：点「继续」的真实落盘（会写 `save-test.json`，刻意没跑）。
链路复用商店 / 女巫工坊那套已验证的 `SaveStore`，风险低，但下次进冒险实跑时要顺手看一眼。
