## 2. 三条新机制

### 2.1 `RestoreAuraOnHpLoss`（火炬 `ap` 的 γ）

「每当你生命值减少时，此光环将恢复到可用状态」。

- 它**不是新的一类光环**：火炬的 α 是一条普通的 `AuraKind.AtkPower` 光环（打出去点亮 1 枚、用掉就没了），
  这条 γ 只是给那张牌加一条**补货规则**。
- 触发点挂在**两个掉血入口**上（`BattleEngine.ApplyDamage` 与 `CutMaxHp` → `PublishHpLoss`），
  走的是现成的 γ 暂停-恢复管线（`specialEvent = "owner.hp.lost"` → `_pendingSpecial` →
  `AdvanceSpecialEffects`），与潮汐 `e` 的「冷却完毕」完全同一条路。
- 真正补指示物的代码只有一处：`BuiltinEffects` 里的 `CardInstance.RestoreAura()`。
- ⚠ 为什么必须挂两个入口：只挂 `ApplyDamage` 的话，「被削生命上限顺带把 Hp 拉下来」那条路径
  就不会复活光环 —— 那种缺陷不报错、只是「偶尔不灵」。

### 2.2 `ReturnToHandIfLastHand`（地刺 `ar` 的 α）

「如果这是你手中的最后一张牌，进攻打出之后自动回手」。

- 条件由 `EffectDef` 构造时自动挂 `hand-at-play = 1`（与闪电球的 `ComboIfLastHand`、
  地震的 `SlowIfLastTwoHand` 同一条口径，阈值 1 = 出牌那一刻手上只有这一张）。
- 归 `EffectStage.AfterCooldown`（第 4 步「牌已进冷却区」之后）：把剩余冷却刷到 0，
  走的是**与「冷却完毕」完全相同**的回手路径（`CooldownOps.Refresh` → `ReturnToHand`），
  所以指示物作废 / 刻印熄灭 / `cooldown.completed` 事件全都自动成立。
- 条件不满足时整条不结算 —— 不弹决策、不消耗任何东西。

### 2.3 `RuleNote`（模仿 `x` 的 γ）

「未复制或防御时力量视为 1」——**纯卡面声明**，处理器是空实现。

- 规则落点其实在别处：`Copy`（未复制 → 不改 `EffectivePower`）+ `CardInstance.PowerLabelText`
  （隐藏力量恒显示 X）。卡面这一行只是把它写明白。
- 之所以仍然建一个算子：卡面要**单独占一行、带自己的 γ 符号**，而 `EffectDef` 必须有一个
  handlerId 才能入表。它的事件 id 是 `"rule.note"`，**没有任何发布者** —— 永远不会被结算。
- ⚠ `EffectRegistry.Validate` 硬性要求 γ 效果必须有 `specialEvent`，没有就是编译期能过、
  进战斗当场抛。所以这个「永远不发」的 id 是必需的。

### 2.4 雪崩 `an` 回到「可选」

卡面写的是「**可以选择**使你和对方的冷却区中剩余冷却为 1 的法术都被减速」。
`SlowZoneBoth` 从「自动、不发决策」改成发一条 `RequestKind.ChooseZoneValue` 决策：

- 选项只有一个（阈值由卡表定死，玩家选的不是 k 而是「执不执行」），**`Seat = -1` 表示双方**，
  所以处理器拿到选项后不看 Seat，直接对 `TargetSeats` 逐个施放。
- `Option.Count` 必须填（命中张数）：AI 的「选数值最集中的那一档」靠它打分。
