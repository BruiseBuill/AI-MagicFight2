## 1. 需求 1：瀑流的「同一张卡不能被加速第 2 次」

### 1.1 原缺陷（为什么旧实现只对了一半）

瀑流（y）有两条 α：

```
A(EffectOp.Haste, 1,          "加速")
A(EffectOp.HastePerHpLoss, 1, "你每损失 1 点生命值，加速一个不同的法术")
```

旧实现 `StartStage3Decision` 的**第一句**就是 `_excludeTargets.Clear()` —— 也就是说
排除名单的生存期是「**一个效果**」，不是「一张牌」。于是：

- 第 2 条 α **内部**确实互斥（每加速成功一张就加进名单，下一次候选表里就没有它）✅
- 但第 1 条 α 加速过的那张牌，在第 2 条 α 里**又回到了候选表里** ❌

表现：瀑流血损 ≥1 时，同一张牌可以被它加速两次。万局统计**完全无声**（守恒、事件数、胜负全对）。

### 1.2 现行实现

`BattleEngine`：

- 新增 `_excludeScope`（`AttackContext`）与 `_hasteTargetsMustDiffer`（bool）。
- `StartStage3Decision` 不再无条件清名单，而是：

```csharp
if (!ReferenceEquals(_excludeScope, _atk))
{
    _excludeScope = _atk;
    _excludeTargets.Clear();
    _hasteTargetsMustDiffer = HasDistinctHasteEffect(_atk);
}
```

- `HasDistinctHasteEffect(atk)` = 这次进攻的 ③ 阶段队列里**有没有 `HastePerHpLoss`**。
- `DoStage3Repeat` 里把「加速成功 → 记入排除名单」的判据从
  `Op == HastePerHpLoss` 改成 `_hasteTargetsMustDiffer && Op != Slow`。

三个刻意的口径：

1. **钥匙是 `AttackContext`，不是那张牌**。同一张牌回手后再打出是同一个
   `CardInstance` 对象，拿牌当钥匙会把上一次进攻的名单漏进下一次；
   `AttackContext` 每次进攻新建，天然是「一次结算」的精确边界。
2. **不能推广到所有 `Haste`**。湍流（ab，加速 ×2）的规则是「A 次可分配给同一张或不同张」
   （`engineering/04-架构与接口.md` 算子表）。所以判据是「这张牌的效果队列里**有没有**
   `HastePerHpLoss`」，而不是「这个算子是不是 Haste」。
3. **只有加速成功才记**（`ok`）。加速失败（那张牌已经不在冷却区）不该占名额。

### 1.3 需求 2 的引擎侧：把「做不到的事」从候选表里滤掉

减速的上限 = 该牌的基础冷却值（`CooldownOps.TrySlow` 的既有判据）。已经顶到上限的牌
列进候选只能是「点了什么都没发生」，属于「这一拍根本做不到的事」，
所以 `IssueStage3Repeat` 现在把它们**在生成 Options 时就过滤掉**（铁律 3）。

> ⚠ 这条过滤**改变了 AI 的可选集**（AI 不会再把减速浪费在顶格的牌上）。
> 已确认这不是行为回归：`EarthquakeScenario` 的布防条件因此从「冷却区有牌」
> 收紧成「有**能被减速**的牌」（`AnySlowable`），否则它在「场上只剩顶格牌」的局里误报。

### 1.4 自测（`Tools/RuleSelfTest/TorrentScenario.cs`）

不打乱随机发牌，只在**可成立的局面**上插手：某方手上有瀑流、双方冷却区合计 ≥2 张、
他已损 ≥2 点生命（第 2 条 α 至少问 2 次）、且存在一张「加速一次之后仍留在冷却区」的牌
（剩余 ≥2，当第一目标）。之后每次都故意挑候选表第一张 —— 最容易撞重复的打法。

断言**不是**「结果里没有重复」，而是「候选表逐位对得上」：
对每一次请求比对 `候选 uid 集合 == 该侧冷却区 uid 集合 − 本串已加速的那几张`。
（结果层可能因为那张牌恰好回手而侥幸不发生；候选表直接判出「引擎有没有把它重新列出来」。）

对照组（湍流 ab）断言**相反**的事：候选表**不得**被过滤 —— 第一次加速过的那张牌，
只要还在冷却区里就必须重新出现。少了它，「把所有加速都改成不能重复」这种改过头也能全绿。

实测：瀑流 3/3 命中（扫 4 个种子）、湍流 3/3（扫 5 个种子）；
卡表钉住「只有 y 带 `HastePerHpLoss`」（新加这张算子的牌要显式更新这条断言）。

## 2. 需求 2：不可选的牌「暗一些 + 点了弹浮字」

### 2.1 压暗但仍然可点（`CooldownView.Apply`）

旧实现把「压暗」与「吃掉点击」绑在一起（`SetInteractable(!_dimUnplayable || can)`），
点一张暗牌**什么都不会发生** —— 玩家读到的是「这游戏点不动」，不是「这张牌现在不行」。

现行：

```csharp
v.SetInteractable(true);          // 先设可点
v.SetDimmed(dimming && !can);     // 再设压暗（SetInteractable 内部会重置压暗，顺序不能反）
```

谁能点、点了算不算数仍然只由引擎的 Options 决定（铁律 3）；
`BattleUi` 拿到点击后回本拍选项里找，找不到才弹提示。

### 2.2 中央浮字（新 `FloatTipView.cs`，一个文件一个组件）

- 节点：`Canvas/FloatTip`，由 `BattleUiBuilder.BuildFloatTip` 预建
  （锚画面正中 + `ActionBannerY`，520×84，底衬用带 border 的 `CardBox.png` 九宫格 ——
  高度不能低于 76，否则四边被挤压变形）。
- **不吃射线**（CanvasGroup + 两个 Image/Text 的 raycastTarget 都关）：
  它出现的时机正是玩家在点冷却区的时候，挡一下就把操作打断了。
- 动画三段：淡入 0.10 s（原地弹出）→ 停留 → 边上升 48 px 边淡出，总长 0.95 s。
  「弹出点」就是 prefab 里的位置，上升只在最后一段发生 ——
  读到的顺序是「在这儿出现 → 抬起来 → 没了」。
- 与 `ActionBannerView` 分工：横幅讲「轮到谁 / 这拍结束」，本类只回答一个问题。
  两者**不会同屏**（横幅只在怪物侧节拍闪，浮字只在玩家挑目标那几拍出现）。

触发点：`BattleUi.OnCoolingCardClicked` → `PickCardOption` 返回 false → `NotifyRejectedTarget()`，
措辞按决策类型给（加速 / 减速 / 重置冷却 / 兜底）。**这不是规则判断**：
引擎已经把这类牌从 Options 里滤掉了，界面只是把「没有它」翻译成一句人话。

## 3. 需求 3：怪物执行效果的提示

`CooldownChangedEvent` 以前在提示条上**一个字都没有**（加速 / 减速 / 区域加减速 /
重置 / 立即冷却完成全都只进日志）。现在：

- **顶部提示条**：逐条翻译（`CooldownChangeLine`），例如
  `AI 区域减速「瀑流」 3 → 4`、`AI 消耗光环：「石盾」进攻力量 +2`。
  两个例外**不报**：「进攻开始 −1」「…进入冷却区」—— 它们是结算副产品，每半场对每张牌都发一条，
  报出来只会把真正的效果提示挤掉。区域类「无匹配目标」**要报**（正好解释「为什么什么都没发生」）。
- **中央横幅**（`PlayEffectBanner`）：只有**怪物**执行时才闪（用户口径只要求给怪物更多提示）。
  区域类一批只闪第一条（`_effectBatchShown`），不然一次区域减速 4 条事件会闪成一片。
- **归属判断**：`_actorSeat` 由 `TurnStartedEvent.Seat` / `AttackDeclaredEvent.Seat` 维护 ——
  `CooldownChange.Card` 是**被改的那张牌**的归属，而减速减的就是对方的牌，
  所以「是谁在加速 / 减速」只能从「这一半场是谁的」推出来。
- **`AuraActivatedEvent`**（光环激活）以前也无声，现在同样上提示条 + 怪物侧横幅。
- 为让「区域」可辨，`CooldownOps.TryHaste / TrySlow` 加了可选 `reason` 参数，
  `ApplyZone` 把「区域加速 / 区域减速」传进去写进 `CooldownChange.Reason`（纯可观测性，零规则影响）。

## 4. 需求 4：怪物出牌「从模型升起、逐渐出现」

`PlayedCardView.ShowFrom(cards, holdSeconds, fromWorld)`：

- 起点由调用方给（`BattleUi.ModelCenterWorld(seat)` = 角色 RectTransform 的
  `rect.center` 转世界坐标 —— 角色的 pivot 每帧随动作切，不能用 anchoredPosition 推）；
- 终点 = 头顶卡位（prefab 里那个 `anchoredPosition`，首次 Show 时记进 `_home`）；
- 三件事同时走：位移（OutCubic 0.42 s）+ 缩放 0.72→1 + alpha 0→1。
- **起点换算不手算**：先把 `position` 摆到那个世界点、读回 `anchoredPosition` 让 Unity 自己算
  —— 手算要处理「锚点参考点在父级局部空间的位置」（ArtLayer 铺满画布，锚点 (0,0) 对应父级局部
  (-960,-540)），错一个符号卡片就从屏幕外飞进来。
- 只在**怪物**侧启用（`BattleUi.ShowOnHead` 里按座位分流）。玩家自己那张牌从手牌区拖上去，
  起点另有其物，而且玩家自己知道打了什么。
- **不新增任何 [SerializeField] 字段**（时长 / 起始缩放读 `UiLayout` 常量，起点是运行时算的）
  → 这次改动不需要重建 Prefab。
- ⚠ `Update` 的早退条件改了：头顶出牌展示是**常驻**（hold = 0），旧版
  `_autoHold <= 0` 直接 return 会让入场动画永远不播。现在入场段独立于倒计时。

实测：`_introOffset = (3.88, -343.45)`（模型中心在头顶卡位下方 343 px）、
起始 scale 0.72 / alpha 0 → 结束 scale 1 / alpha 1 / 归位。

## 5. 需求 5：AI 用光环的识别动画 + 默认用掉

### 5.1 飞行演出

- `AuraIconView` 新增 `GlideToPoint(surface, fromWorld, toWorld, duration, onLanded)`：
  与 `GlideTo` 只差终点是**坐标**而不是槽位节点 —— 落地时**保留位置**（不换父、不归零，
  归零会把它拽回 surface 原点）。为此加了 `_flyPointTarget / _flyToWorld / _flyKeepPlace`。
- 新增 `SetRaycastTarget(bool)`：图标模板上唯一接射线的是外框（`Frame`），演出图标必须关掉 ——
  它停的位置正压在敌方冷却区上方，接着射线就会吃掉玩家的点击。
- `ArtLayer/AuraCastSeat`：由 `BattleArtLayerBuilder.BuildAuraCastSeat` 生成
  （锚左下，画布坐标 (1446.5, 560) = 怪物脚底中心 +200、`CharGroundY + 158`）。
  与光环槽位同一套理由：手摆的活不过一次重跑。
  ⚠ 落点会短暂压到敌方冷却区迷你卡（那一带 x ≥ 1226），一次性演出 + 飞行层在最上，可接受；
  想避开就调 `UiLayout.AuraCastX`。
- `HudBuffView.PlayCast(data, fromWorld)`：**单独一个池子** `_castPool`（绝不与 `Bind/Collect`
  用的 `_pool` 混，否则下一次 Bind 会把这枚正在飞的图标当「没配上的」回收掉）；
  落地 → 放大到 1.15 → 停 0.65 s → 淡出 0.25 s → 回池。
  `ClearCasts()` 供重开一局时把还在飞的也收掉（⚠ 只遍历池子会漏掉还在飞的）。
- 起点：`BattleUi` 在 `AuraConsumedEvent` 且座位是怪物时，先在
  `_enemyAuras` 里按**来源牌 uid** 找那枚图标此刻的位置（`AuraConsumedEvent` 没有「第几枚」，
  同一张牌的两枚指示物在屏幕上并排挨着，用哪枚当起点肉眼无差）；
  找不到就退回怪物模型中心。⚠ 必须在这一拍里做 —— 下一拍刷新后那枚图标就没了。

### 5.2 AI 默认用掉全部可用光环

`BattleCanvas.prefab` 里 `BattleDriver._aiUseAuras` 序列化存着 `0` —— **光改 C# 初值不生效**。
已用 Unity MCP 改成 `1`（`SimpleAiAgent` 的既有逻辑本就是「本拍能用的光环全带上」：
进攻拍带全部力量类，防御拍免疫优先、其次先报备再挑牌）。

## 7. 踩坑

- ⭐ **`shutil.copy2` 会连同 mtime 一起复制** → 还原源文件后它的 mtime 比 DLL 旧，
  增量编译判「最新」直接跳过，**跑的是旧 DLL**。这次靠「自测断言突然 FAIL」才发现。
  规矩：还原 / 批量写源文件之后 `os.utime(p, None)` 刷一遍，或者干脆删 `obj/` 重建。
- ⭐ **`EditorApplication.update` 在 Play 暂停时照样触发** → 「跑 N 帧再暂停」如果用
  update 计数，实际上一帧都没跑就暂停了（截图永远是旧帧）。要用
  `Time.frameCount >= start + N` 计数。
- ⭐ **编辑器在我两次 MCP 调用之间能跑几万帧** → 0.95 s 的浮字、1.35 s 的光环演出
  在「Show → 截图」之间早就播完自己隐藏了，表现成「明明 alpha=1 却截不到」。
  验证短动画要么把时长用反射拉到几百秒，要么用 frameCount 精确冻结。
- ⭐ **`FindObjectOfType` 可能返回 Prefab 资产里的那份实例**（`Resources.FindObjectsOfTypeAll`
  能看到两者）→ 对它 `Show()` 改的是资产、屏幕上没反应。**一律从 `BattleUi` 的序列化字段
  拿场景实例**。
- ⭐ 控制台开着 **Error Pause** 时，一条异常就会把 Play 挂起（`isPaused=True`、
  `unscaledDeltaTime=0`、frame 不涨），表现像「游戏卡死」。先查 `isPaused`。

## 8. 已知遗留

- ⭐ **既有问题（与本次改动无关，已用「还原引擎后复测」证实）**：内核没有**僵局 / 平局**判定。
  seed 20261601 会走出一条双方永远挡得住的「冷战」局（实测 3158 回合仍在继续，
  被自测的 20000 决策护栏拦下）。规则基线里只有「生命归零判负 / 上限归零即刻死亡」，
  没有回合上限。本版改动只是让这条路径**在另一个种子上冒出来**（20260923 种子基的第 678 局）；
  同时也让 20260916 种子基下的另一个僵局种子消失。**要根治需要补一条「回合上限 → 平局」规则**，
  属于规则改动，等用户定。
- 本机 Unity 进 Play 时会报 5 条 `MissingReferenceException: Texture2D destroyed`
  （进 Play 即报，早于任何对局逻辑；本版代码不创建 / 不销毁纹理）。疑似与 M11 重建后
  立刻进 Play 的域重载有关，未深究；若它触发控制台 Error Pause 会把 Play 挂起。
- 真机端到端提交链路仍未跑（M25 起的共同遗留）。
