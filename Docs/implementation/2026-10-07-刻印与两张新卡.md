# 2026-10-07 · 刻印（Sigil）+ 两张新卡：火炬 / 海啸

> 用户下达「一种新的触发方式 + 两张卡」。**刻印**给内核带进了第一处「**打出去只点亮、
> 之后每回合自动重放**」的效果 —— 它与光环共用同一套「挂在牌上 / 只有进攻时激活 / 回手作废」，
> 差别只有「一次性 vs 每回合再来一次」这一条。
> 卡表本身见 [02-卡牌图鉴](../rules/02-卡牌图鉴.md) §2026-10-07 增量；本文只记**实现口径**与踩过的坑。

## 1. 用户原文与当场拍板的口径

> 新增一种刻印效果，刻印类似于光环，只有进攻时会点亮，点亮了之后，与光环不同的是，
> 刻印每回合都会自动触发其效果。与光环相同的是，刻印回到手牌中时，本刻印效果也会消失。
>
> 火炬 4。4 · α刻印：每回合开始时获得光环：进攻力量加2
> 海啸 2，4 · α刻印：每次进攻结束时获得一次加速。β防御时增加等于手牌数的力量值

卡面文字有四处是**规则事实、不能猜**，当场问了用户（AskUserQuestion），四条都选了推荐项：

| 问题 | 结论 |
|---|---|
| 火炬的指示物会不会叠 | **累积叠加** —— 每个回合 +1 枚，冷却期间最多囤到「卡面光环数 + 冷却值」，回手清空 |
| 海啸 α 的「每次进攻结束时」 | **拥有者自己的进攻半场结束**；且**点亮它的那一拍立刻触发**（当拍即触发） |
| 海啸的 β 是不是刻印 | **不是** —— 普通 β 效果；手牌数取**出牌前**的张数（**含正在打出的这张**） |
| 「点亮」要不要看得见 | **要** —— 「类似于光环，只不过无法像光环一样拖动使用」 |

录入结果：

| 卡 | ID | 元素 | 力量 | 冷却 | 效果 |
|---|---|---|---|---|---|
| 火炬 | `at` | 火 | 4 | 4 | α **刻印**：每回合开始时获得光环：进攻力量 +2 |
| 海啸 | `au` | 水 | 2 | 4 | α **刻印**：每次进攻结束时获得一次加速；β 防御时 +（手牌数） |

卡表 45 → **47**；力量分布 4:5→**4:6** / 2:4→**2:5**；冷却 4:14→**4:16**。

## 2. 刻印怎么落进既有的六步流水线

### 2.1 它**不是新算子**，是给既有算子加的一层「触发方式」

卡表里写的就是普通的 `Aura` / `Haste`，外加一个 `EffectDef.Sigil`（`SigilTiming`）标记：

```csharp
A(EffectOp.Aura, 2, aura: AuraKind.AtkPower, sigil: SigilTiming.TurnStart, ...)   // 火炬
A(EffectOp.Haste, 1, sigil: SigilTiming.AttackEnd, mandatory: true, ...)           // 海啸 α
D(EffectOp.DefPlusPerHand, 1, ...)                                                 // 海啸 β
```

这样「效果本身长什么样」一条代码都没重写（光环的消耗 / HudBuff 图标 / 快照明细全都继续可用），
引擎只需要多做两件事：

1. 打出去那一拍的第 ⑤ 步 **只点亮**（`DoStage5 → LightSigils`）；
2. 之后每个点位把**同一条效果**再跑一遍（`DoBeginTurn` / `DoEndHalfTurn → PublishSigils`）。

> ⚠ 反过来做（新增 `EffectOp.SigilAura` / `SigilHaste`）会把「效果」和「触发方式」两件事揉进
> 算子名里，光环那一堆现成的东西（`AuraTokenCount` / `AuraEffectsOf` / `ValidateAuraTriggers` /
> HudBuff 图标明细）全都要各写一遍。

### 2.2 四个落点

| 环节 | 落点 | 判据 |
|---|---|---|
| **点亮** | `DoStage5` → `LightSigils(_atk.Card)` | 只看**本次作为进攻牌打出**的那张牌，且**只认 α**（一张带 β 刻印的牌被当成防御牌打出时不该亮） |
| **触发（TurnStart）** | `DoBeginTurn`（`TurnNumber` 自增之后、补牌与替换之前） | 「回合」= `TurnNumber` 自增那一刻（双方各一次进攻合起来算一回合） |
| **触发（AttackEnd）** | `DoEndHalfTurn`（与**虚弱递减**同一落点） | 「一次进攻半场」= 整条连击链，只算一次；点亮那一拍就会走到这里 ⇒ **当拍即触发** |
| **熄灭** | `CardInstance.ToHand/ToPool` + `CooldownOps.PutIntoCooldown/RemoveFromGame` | 与光环指示物**完全同一批**清空点 |

### 2.3 ⚠ 「不当拍结算」是一行不能漏的代码

`EnqueueEffects` 里必须把刻印从**当拍的效果队列**里摘出去：

```csharp
if (effect.Sigil != SigilTiming.None) continue;   // 刻印：打出去这一刻不结算，只点亮
```

漏了它的表现是「**打出去当拍白拿一次 + 以后每回合再拿一次**」= 凭空多算一次 ——
不报错、不崩、事件流也自洽，只表现为强度偏高。自测里专门有一条钉它
（`Hit.AuraAtPlay`：打出去那一拍结束前**不许**出现 `AuraActivatedEvent`）。

同一个 `absorbHaste` 扫描也要排除刻印（否则一条刻印 `Haste` 会被「充能」吸收成额外的加速次数）。

### 2.4 触发点要能弹决策 —— 走 γ 那条暂停-恢复管线

海啸的「获得一次加速」要**选目标**，而触发点在**六步之外**（半场收尾）。所以
`PublishSigils` 只把效果**排进 `_pendingSpecial`**（与潮汐 γ「冷却完毕」同一条管线），
由 `Advance` 循环里的 `AdvanceSpecialEffects` 在下一拍之前跑完 ——
AI / UI 两侧完全无感（铁律 3：规则只收敛在引擎一处）。

⚠ `PublishSigils` 因此**只入队、不结算**，可以安全地在遍历冷却区的前后调用。

## 3. 三个容易做错、且**不报错**的点

**① 火炬的指示物会突破「光环指示物 ≤ 卡面光环数」这条既有不变量。**
`RuleAssertions.EventWatcher` 判的是 `AuraTokens > Def.AuraTokenCount`；火炬的刻印每回合 +1 枚，
冷却期间必然超过卡面那 1 条。处理：新增 `SigilAuraSlack(def)` = 「有刻印光环就再给
`Cooldown` 个余量」（每回合 1 枚 × 在冷却区待过的回合数 ≤ 基础冷却值，是紧的上界），
**普通光环卡一点不放宽**。

**② 「进攻牌的 α 光环未点亮」这条断言对刻印卡是错的。**
火炬打出去当拍**只点亮刻印**，光环要等下一个回合开始才到账 —— 拿 `AuraLive` 判它只会误报。
处理：把这条断言拆成「**普通 α 光环** → 查 `AuraLive`」与「**α 刻印** → 查 `SigilLive`」两条，
并各带一个覆盖率计数（`AttackAuraChecked` / `AttackSigilChecked`）。

**③ 手牌数有**三**处口径，必须一致。**
`DefenseResolver.BuildOptions`（生成合法选项）、`BattleEngine.DoChooseDefense`（提交时复核）、
`RuleAssertions.CheckDefenseLegality`（自测独立重算）—— 少传一处就会出现
「界面说挡得住、引擎复核说不够」或者「自测误报」。
本次三处都改成传**出牌前**的手牌数（含正在打出的这一张），并且 `DefenseResolver` 的
`handCount` 是**可选参数**（不传 = 按 0 张算）—— 那是给「不涉及海啸」的调用点留的，
参与合法性判定的三处**必须传**。

## 4. 表现层：「点亮」要看得见，但拖不动

用户口径：「刻印也需要做可见标记，**类似于光环**，只不过**无法像光环一样拖动使用**」。
所以**不新建节点、不新建 Prefab**，直接复用 HudBuff 那一排图标：

| 位置 | 改动 |
|---|---|
| `CardSnapshot.Sigils` | 新增 `SigilSnapshot[]`（`Text` / `Timing` / `CardName`）+ `SigilLive` |
| `AuraIconData.Sigil` | 新布尔位：底色走 `UiTheme.AuraPlateSigil`（琥珀金）、角上不写数值 |
| `AuraIconView` | ① `OnBeginDrag` 直接拒绝（`Data.Sigil` 就 return）；② **不压暗**（刻印没有「本拍能不能用」这个概念，压暗会让玩家以为它没在生效）；③ 没有数值就把数值底衬一起收掉 |
| `BattleUi.BuildAuras` | 从冷却区快照里同时抽「光环指示物」与「已点亮的刻印」两张表 |
| `BattleUi.RefreshAuraIcons` | 喂给 HudBuff 的是**合并表**，但 `_playerAuras` / `_enemyAuras` **保持只有光环** |

⚠ 最后那一条是**必须**的：准备标记的落点（`HomeSlotFor` / `PreparedAuraView`）是按
`_playerAuras` 的**顺序数格子**的 —— 往里掺刻印会让「取消使用」的标记整体错位一格。
刻印的键位用 `200 + 序号`（光环指示物从 0 起、一张牌最多 2 枚），两边天然不撞。

## 5. 验证

### 5.1 自测（`Tools/RuleSelfTest/SigilScenario.cs`，6 条断言全 PASS）

「逼局面」的手法与 `NewCardsScenario` / `EarthquakeScenario` 同源：**不改随机发牌**，
在真的出现「手上正好有那张牌」的那一拍裁手牌 / 强制打出；每条断言要凑够 **3 次命中**、
最多扫 2000 个种子。

| 断言 | 结果 |
|---|---|
| 两张新卡的卡表结构（力量 / 冷却 / 元素 / 算子 / 刻印时机 / 光环条数）+ 海啸 β 的纯函数 | PASS |
| 火炬 α：打出去那一拍**只点亮、不给光环**；随后每个回合开始各 +1 枚「进攻力量 +2」（**累积到 2 枚**） | PASS（命中 3 / 扫 3 个种子） |
| 火炬：冷却完毕**回手**时，未用的指示物与刻印状态一起作废 | PASS（命中 3 / 扫 3 个种子） |
| 海啸 α：点亮它的那一拍结束时**立刻**触发一次加速（真的弹了选目标、真的减了 1 点冷却） | PASS（命中 3 / 扫 3 个种子） |
| 海啸 β：防御「需要的力量」= 攻击力量 −（2 + 手牌数），且提交后引擎复核通过 | PASS（命中 3 / 扫 3 个种子） |
| **反面**：带刻印的牌作为**防御牌**打出时，一条刻印都不许点亮 | PASS（命中 3 / 扫 3 个种子） |

⚠ **卡表变了，所以同一个种子的牌序也整体变了**：按既定口径不能拿「逐局与上一轮相同」当证据，
只能比**总量级**与**违规类别**。平均回合 6.39 → 6.37（基本不动）、事件 +0.29%（两张新卡）、

### 5.3 ⚠ 顺带修掉的两条**既有**红（都与本轮卡表无关，是「牌序重排后露头」）

1. **`AltarRiteScenario` 的可强化张数写死 `41 / 4`** —— 那是 45 张那轮的数，**上一轮就没跟着改**。
   本次 47 张：**43 / 4**（新增的火炬 4 / 海啸 2 都可强化）。
2. **`CoolHandScenario` 认不出「模仿复制了磁暴 / 充能」** —— 那个场景靠
   `_lastAttack[seat]` 反推「这一拍是哪条效果」，而模仿复制时 `_lastAttack` 记的是**模仿自己**
   （卡面上没有 `CoolHand*` 算子）⇒ 判据拿到 `EffectOp.None`，把「磁暴 / 充能的多选形状」误判成单选的。
   处理：**认不出源头时不给「应该是什么」的结论**，只要求这一拍自洽
   （多选 = 上限等于候选数、单选 = 1/1，两者引擎都合法），并把进攻牌名写进失败信息。
   ⚠ 判据逻辑本身**没动过** —— 这是卡表从 45 张变 47 张、牌序重排之后才在 `seed 8` 露头的一条
   **既有脆弱点**，不是本轮引入的。

## 7. 遗留

1. **刻印没有专属美术 / 动效**：可见标记复用光环图标（琥珀底色 + 拖不动），
   「点亮那一刻」没有额外演出。
2. **刻印一律拖不动**：拦截点在 `AuraIconView.OnBeginDrag` 的那一句 `Data.Sigil`。
   以后若要有「某张卡可以主动触发一枚刻印」，得重新设计（现在没有「使用刻印」这个动作）。
3. **卡池没动**：`ShopPool` / `UpgradePool` 是各 8 张的显式清单，火炬 / 海啸不在其中；
   战斗池 `BattlePool` 是 `useAllCards`，自动包含 47 张。
4. **`EffectSpec` 多了一格 `sigil`**：旧存档没有这一格时反序列化成 `SigilTiming.None`
   （正是老口径，不用搬运）—— 存档版本号没有因此升。
5. 自测末行仍是 ❌（12 条既有噪声），见 §5.4。
6. **万局数字整体变了**（牌序重排），见 §5.2 的 ⚠。
