## 2. 为什么不能直接用那个 prefab

`BigMagicCard.prefab` 是**3D 展示卡**，把它嵌进 UGUI 手牌实测会坏三件事：

1. **它是 WorldSpace 的**：根节点是 `Transform + SpriteRenderer`（连 RectTransform 都没有），
   子节点 `Canvas` 的 `renderMode = WorldSpace`。直接挂到 Overlay 画布下，
   它会按世界尺寸铺开，整屏都是它的一部分。
2. **圆角材质是 ShaderGraph**：`RoundBox` / `RoundBoxLine` 为 3D 卡写的，UGUI 下
   **不吃顶点色**、`_MainTex` 也不走 `CanvasRenderer.SetTexture` 那条路 ——
   实测整张卡渲染成**纯白 + 一条红边**，插画和颜色全丢。
   读图发现 `_size` 的 G / B 通道被当成宽高、`_ColorMask` 还被接到 SampleTexture2D 的 UV 上，
   参数含义没有文档，调不出来。
3. **它的效果面板是「抽出式」的**：`Content/BG` 是 620×1118.5 —— 比卡本身（872）还高，
   上下都露在卡外。3D 展示里那是「可以把文字板抽出来」的卖点，196×272 的手牌上放不下。

所以做法是：**版式照抄，零件自己搭**。
节点结构、锚点、pivot、anchoredPosition、尺寸、字号**逐字取自 prefab**
（见 `UiLayout` M17 段的注释，每条都写了它在 prefab 里的对应写法）；
圆角与描边换成九宫格图；效果面板收回卡内。

      Text (TMP)                冷却数字，fs 155，**深色**
    Name                        卡名：锚(0.5,1) pivot(0.5,1) pos(50.7, −47.1) 301.2×93.6
      （衬底）                    自加的半透明暗底（见 §5）
      Name                      TMP，fs 72，超宽自动缩到 52
    Content                     效果面板（620×300，收回卡内）
      BGLIne                    面板描边

## 4. 图文混排（α / β / γ → 剑 / 盾 / 感叹号）

### 4.1 链路

```
Core: TriggerSymbol.Of(EffectTrigger)   // α / β / γ 字符（规则事实）
   ↓ CardDef.EffectTextWithSymbols      // 每条效果一行，行首带符号
App : TriggerSpriteLibrary.ToRichText   // α → <sprite name="attack">
   ↓
TMP : 效果文字挂 TriggerIconSprite（SpriteAsset）→ 行内排进图标
```

- **为什么符号定义放 Core**：`Docs/rules/01-规则基线.md` §通用原则写明「卡面符号即结算时机」
  —— 哪个符号对应哪个时机是**规则事实**，不是表现层口味。表现层只负责把字符换成图。
- **为什么用 `<sprite name=...>` 而不是「同码位自动替换」**：把 α 的码位（U+03B1）
  注册进 SpriteAsset 也能自动替换，但字体里本来就有 α 字形时**谁赢取决于查找顺序**
  （字体优先 → 图标不出现，而且是静默的）。显式标签没有这个不确定性。
- **降级**：SpriteAsset 不存在（干净检出没跑过生成菜单）时 `ToRichText` 原样返回，
  TMP 照常渲染 α / β / γ 字符（正文字体 `Google-Regular` 有这几个字形，
  `UiKitBuilder.ConfigureTmpFonts` 已把它挂成仓耳渔阳体的 fallback），不会变成空方块。

### 4.2 图标大小与对齐（都是从卡面量出来的，不是拍的）

`TriggerSpriteAssetBuilder` 里两个常量：

| 常量 | 值 | 来历 |
|---|---|---|
| `IconEm` | **1.12** | `Card_08_h_沉重打击.png` 里剑的墨迹高 42 px、同行汉字墨迹高 33 px；汉字墨迹 ≈ 0.88 em → em ≈ 37.5 px → 剑 ≈ 1.12 em |
| `IconTopEm` | **1.04** | 剑的墨迹顶在基线上方 1.04 em、底在下方 0.08 em，与同行汉字墨迹（0 ~ 0.88 em）**几乎同心**（0.48 vs 0.44 em） |

TMP 渲染 sprite 时 `spriteScale = 字号 / faceInfo.pointSize`，所以 `pointSize` 是由
「图标内容要多高」**反解**出来的（257.78），不是随手填的数。
`bearingY = Pad + IconTopEm × pointSize`，让**内容**顶边（不是格子顶边）落在该落的地方。

### 4.3 图集口径

三张图标共用一块 1024×1024 透明画布且**没有缩放过** —— 画布内的相对大小就是设计稿的
相对大小（剑比盾瘦、感叹号比盾宽）。所以：

- 取三者的**并集包围盒**当统一取景框，一起裁、一起缩放 → 相对大小保住。
  各自按自己的包围盒拉到同高的话，三个符号会变得一样大，肉眼能看出不协调。
- 单元格**贴着内容裁 + 四边留 4 px**，不做正方形：正方形里内容只占中间一条，
  为了不让相邻文字离得远就得给负的 bearingX —— 没必要。紧裁之后
  `advance` 就等于「图标宽度 + 一点点」，中英混排的间距自然。

脚本跑完会把它算出的 `CellWidth / CellHeight` 直接打印出来，照抄进
`TriggerSpriteAssetBuilder` 即可（不一致的后果是**安静错位**：从相邻格里取样，
半个盾牌 / 半个感叹号，TMP 不报任何错）。

## 5. 与 prefab 的两处（+一处）必要偏差

1. **圆角与描边**：prefab 靠 ShaderGraph，UGUI 下不可用（见 §2）。
   改成九宫格圆角图：`CardBox`（填充，圆角 30、线宽 0 填充） /
   `CardBox_Line`（描边，圆角 30、线宽 4），由 `build_card_box.py` 生成。
   ⚠ 九宫格的 border（38）必须 ≥ 圆角 + 内缩，否则圆角被拉成椭圆，**Unity 不报任何警告**。
   `UiKitBuilder.EnsureCardBoxImporters` 每次构建都对一遍（`.meta` 被重导就会丢）。
2. **效果面板高度**：1118.5 → 300（收回卡内，见 §2.3）。宽度仍用 prefab 的 620。
3. **卡名衬底**（额外加的一层）：prefab 的 `Name` 节点没有底，名字直接压在插画上。
   本作 40 张插画明暗差异很大（「寒流」几乎是白的），白字会读不出来 ——
   在**同一块矩形**上补一层半透明暗底，位置与尺寸仍按 prefab。

## 6. 踩的坑

1. **`TMP_SpriteAsset` 的 `version` / `faceInfo` / `spriteGlyphTable` / `spriteCharacterTable`
   都是 `internal set`** —— 跨程序集赋不了值（编译期 CS0200）。
   `PropertyInfo.CanWrite` 对它们返回 **true**（存在 setter），极易误判成「可以赋值」；
   实际那个 setter 不可见。只能落到私有序列化字段（`m_Version` / `m_FaceInfo` /
   `m_SpriteGlyphTable` / `m_SpriteCharacterTable`）上。
2. **`FaceInfo` 没有公开构造函数**，且 `m_FaceIndex` / `m_UnitsPerEM` 没有公开属性 ——
   结构体装箱改字段再拆箱。`unitsPerEM = 0` 会让某些 TMP 版本在算 sprite 缩放时除零。
3. **白字在亮底上等于没有**：力量星爆的中心是一团亮米白，第一版把力量数字设成白色，
   截图里**完全看不到数字**（一度以为 TMP 没渲染，其实 mesh 正常、只是糊在底里）。
   prefab 自己用的是深灰（0.189）—— 照抄即可。
4. **`Name` 框一行只放得下 4.18 个字**（301.2 宽 / fs 72），而本作最长卡名正好 4 字
   （「冰封铠甲」「烈焰斗篷」）—— 不留神就会被省略号截成「冰封…」。
   加自动缩放（下限 52）解决。
5. **MCP 桥在进出 Play 模式时最容易断**（`WebSocketTransportClient.SendJsonAsync` 抛异常后
   不再重连，工具全部超时）。本次断了两次，都是等 1–2 分钟自己重连回来的
   —— 断线时**不要**急着改代码，先 `read_console` 探活。
