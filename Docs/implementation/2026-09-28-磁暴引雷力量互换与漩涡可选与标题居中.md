## 2. 磁暴 / 引雷的基础力量互换

### 2.1 卡表

`Assets/Scripts/Core/Cards/CardLibrary.cs`：

```csharp
Add(11, "l", "磁暴", 2, 3, CardElement.Electric, ...);   // 力量 3 → 2
Add(13, "n", "引雷", 3, 3, CardElement.Electric, ...);   // 力量 2 → 3
```

⚠ 两张牌**各自的效果参数都没动**，别顺手改了：

| 卡 | 没动的那个数字 | 它是什么 |
|---|---|---|
| 磁暴 | `CoolHandForAtk(A = 3)` | 「**每冷却一张**进攻力量 +3」的加值（与基础力量是两回事） |
| 引雷 | `Aura(A = 6)` | 「使本次打出的法术（**基础力量 ≤6**）获得连击」的阈值（与引雷自己的力量无关） |

力量**分布**也因此不变（2 与 3 各少一张、各多一张）——
`CardLibrary.ValidatePowerDistribution` 的 `1:3 / 2:4 / 3:5 / …` 硬断言仍然成立，
`Tools/RuleSelfTest` 里没有任何逐卡数值断言被触发。

### 2.2 卡面烘焙的数字（这一条不做就是个坑）

40 张成品卡面 `Assets/Art/Cards/Card_<序号>_<卡ID>_<卡名>.png`（760×1056）是**美术成品整图**，
**卡名 / 力量 / 冷却 / 效果文字全部烘焙在像素里**（见 [06-美术与字体规范](../engineering/06-美术与字体规范.md)）。
三处地方直接吃这张整图：

| 用它的地方 | 代码 |
|---|---|
| 选牌弹窗的卡框 | `HandPickView.FaceSpriteFor` → `CardArtLibrary.GetArt` |
| 长按看完整卡面 | `CardDetailView` |
| 头顶出牌展示 / 飞行卡 | `PlayedCardView` |

而**手牌 / 冷却迷你卡**是 M16 起的「组成式卡面」（插图画 + TMP 现场渲染文字），走的是
`GetIllustration`。也就是说：**只改卡表的话，手牌会显示 2、选牌弹窗里的同一张牌却还是 3** ——
同一张牌两个数，玩家一眼就能看见。

所以本轮把两张卡面的**力量数字重画了**：

* 两张卡的力量图标是**同一份橙色星芒模板**（逐像素验证：把两枚数字的字形排除后，
  图标区域差异 **0**），所以做法是「**互换两枚数字**」而不是重画。
  两枚字形（含黑色描边）用连通域定位 → 外扩 3 px 取掩膜 → 互相搬运，
  掩膜再扣掉「插画绿」（引雷的插画是黄绿色，星芒里没有这个色），避免把背景色搬过去；
  掩膜边缘残留的几像素旧描边用邻域均值抹掉。
* 结果：`Card_12_l_磁暴.png` 的力量由 **3 → 2**、`Card_14_n_引雷.png` 由 **2 → 3**，
  其余像素（卡名、冷却、效果文字、插画、卡框）**逐字节不变**。
* 原图备份在 `Artifacts/backups/2026-09-28-cardface-power/`（同名两份 PNG + 当时的
  `BattleCanvas.prefab` / `SampleScene.unity`）。

> ⚠ **以后改任何卡的力量 / 冷却，都要连带处理 `Art/Cards/` 里那张整图** ——
> 它不像手牌那样是 TMP 渲染的。判断标准：这个数字会不会出现在「选牌弹窗卡框 /
> 长按放大 / 头顶出牌」这三处。会 → 图也得改。

## 3. 漩涡改成「可以不移出」

### 3.1 引擎

卡面原文是「**可**将冷却区中的一张法术永久移出游戏，获得加速 ×3」——「可」就是可选。
`BuiltinEffects.Remove` 现在给 `Request` 传 `allowEmpty: true`：

```csharp
return Request(c, RequestKind.ChooseRemoveFromGame, "移出·获加速", options,
    allowEmpty: true);        // → MinSelect = 0、MaxSelect = 1、不发 Skip
```

`Request` 里 `allowEmpty` 与 `optional` 的差别（2026-09-27 立的口径，这里沿用）：
**两者都让 `MinSelect = 0`，但只有 `optional` 会额外发一条「跳过…」选项**。
漩涡与磁暴 / 充能同属「可以空着确认」这一类 → **不发 Skip**，界面上少一个语义重复的按钮。

不移出时引擎的行为：`Pick(choice)` 拿到 `null` → `yield break`，**既不移出牌、也不给加速**
（那一句 `if (pick == null || !c.RemoveCard(pick.Card)) yield break;` 原本就在，
本轮只是第一次真的会走到）。界面上则表现为：一打开确认键就是亮的（`MinSelect = 0`），
点它 = 放弃这一拍。

### 3.2 自测（连带改了四处，其中一处是加强）

`Tools/RuleSelfTest/RemoveFromGameScenario.cs`：

* 形状断言从 `1 / 1` 改成 `0 / 1`，报告文案、注释同步改。
* ⭐ **新增「空提交」那一半**：`RunOne` 现在按 `hits % 2` **交替**跑两种提交 ——
  偶数次命中「一张都不选、直接确认」，奇数次命中「选第一张」。
  空提交那一路不是只看形状，而是**真回一个 `OptionIndices` 为空的响应**，然后在
  `engine.Submit` 之后立刻复核两件事：

  1. **引擎真的收下了** —— `BattleEngine.Submit` 返回 `void`，`EffectWindow` 拒掉时是
     **静默 return**，唯一信号是 `Pending` 仍指向同一个对象，所以比的是
     `ReferenceEquals(before, after)`；
  2. **那张候选牌还在冷却区里**（`CoolingZone.Contains(card)`）= 真没移出。

  这一条是本次改动的要害：只断言 `MinSelect = 0` 证明不了「引擎会接受空数组」。
  本轮 4 次命中里 **空提交 2 / 选一张 2**，两种路径都跑到了。

另有一条**通用**断言要一起放行 ——
`RuleAssertions.CheckRequestShape` 里那句「允许放弃的决策必须带 Skip」的**白名单**：

```csharp
if (req.MinSelect == 0 && req.SkipOption == null
    && req.Kind != RequestKind.ChooseCoolHandCards
    && req.Kind != RequestKind.ChooseRemoveFromGame    // ← 本轮加
    && req.Kind != RequestKind.ChooseReplace)
{
    return false;
}
```

> ⚠ 这条白名单**必须跟着改**，否则表现是「万局跑完 40 局时报结构非法」——
> 而且报的是**通用**那条断言（「所有决策请求的选项结构合法」），
> 看名字根本猜不到是漩涡。本轮第一次跑自测正是踩在这里。

## 4. 选牌弹窗的标题「没放进框里、偏上了」

### 4.1 根因：删掉副标题之后，标题没有跟着重新居中

面板底图 `Assets/Art/Ui/Peek_Frame.png`（431×556）顶部是一条**梯形 title band**：

| 结构 | 原图行号 |
|---|---|
| band 上亮边 | 44…47 |
| **可放字的暗色内槽** | **48…103**（高 56，**中心 ≈ 75.5**） |
| band 下亮边 | 105…108 |

而标题的取值一直是 `HandPickTitleTop = 35` → 文字框中心 = `35 + 46/2 = 58`。

58 这个数是**「标题 + 副标题」两行时代**量出来的：当时标题下面还有一条
「已选 N / M」的计数（中心 ≈ 105），两行合起来才在 band 里看着居中。
**2026-09-27（M42）用户要求删掉那条计数之后，标题没有重新居中** ——
于是单行标题整整偏上约 **18 px**：文字上缘贴到 band 上亮边，下面空出一大片。
用户 2026-09-28 的截图正是这一条。

### 4.2 改法与取值

`Assets/Scripts/Unity/Ui/UiLayout.cs`：

```csharp
public const float HandPickTitleTop = 53.5f;   // 35 → 53.5（中心 76.5，字墨迹中心 ≈ 75.5）
```

量法（截图实测，1280×720 与 2880×1620 两次都对得上）：
`m44_handpick_01_no_subtitle.png` 里标题白像素的行范围是 **65…106**（面板内坐标 /1.5 → 43.3…70.7），
字墨迹中心 ≈ 57，与算式给的中心 58 一致；要把它对到内槽中心 75.5，就是**下移 18.5**。

改完要**重跑构建器**（这块浮层的节点树由构建器生成，改常量不会自己生效）：

```
魔法乱斗/M8 · 构建 BattleUi（接线 + 浮层）
```

跑完 `Prefabs/Ui/BattleCanvas.prefab` 里 `HandPickLayer/Panel/Title` 的
`m_AnchoredPosition.y` 从 `-35` 变成 `-53.5`。⚠ 重跑前后做过节点结构核对：
**381 个 GameObject，名字与数量逐项一致**，没有任何手摆节点被冲掉
（`Prefabs/Ui/BattleCanvas.prefab` 与 `SampleScene.unity` 也一并备份在 §2.2 那个目录里）。
