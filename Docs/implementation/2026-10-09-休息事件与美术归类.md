## 2. 场景长什么样 / 怎么响

```
Rest.unity
├─ RestCanvas (Prefab)
│  ├─ Backdrop          近黑整屏（UiTheme.RestPlaceholderBackdrop = #05070B）—— 占位
│  ├─ RestButton        暖金实心块 460×150 @ 中心 y=620 + 一行近黑文字
│  ├─ Title             「休息」（与其它事件同一条标题带 y=1002）
│  ├─ Hint              「点击休息，恢复全部生命」（y=372）
│  └─ LeaveButton       右下角「离开」（与商店 / 石台 / 宝箱同一张底图、同一套边距 64 / 44）
└─ RestSceneEntry       挂在场景根（**不进 Prefab**）
```

一次交互只有两步：

1. **点「休息」** → `RestView.SetRestLabel("已休息")` + `SetRestDone()`（关掉可点）；
   `RestSceneEntry` 同时 `MapRun.RestoreFullHp()` → 引导行改成「生命已恢复满（4 / 4）」。
2. **点「离开」** → `MapRoutes.LeaveToMap()` 回地图，地图那边结算这个节点。

「只回一次血」有**两道闸**：视图把那颗按钮的 `interactable` 关掉，入口自己还有一个 `_rested` 标记
—— 双击 / 脚本误调都不会重复记账（实跑验过）。

**⚠ 为什么「恢复当前生命」就等于「连上限一起恢复」**：地图层看到的生命上限恒等于
`MapRun.DefaultHp`（= `BattleState.InitialHp` = 4，见 `MapRun.CurrentHpMax`）——
战斗中能被削掉的那部分上限（`EffectCutMaxHp`）本来就不带到地图上，每场战斗结束都会回到它。
所以 `RestoreFullHp()` 只是把局外当前生命写成 `DefaultHp`，玩家在地图上看到的就是「4 / 4」。
⚠ 它**直接赋值**而不是走 `SetPlayerHp`：后者带一条「< 1 夹到 1」的兜底
（那是给战斗回写用的，防止把「已死」写成一个还要被夹的值）。

**⚠ 为什么这段是占位**：正式场景（美术）还没做好 —— 用户要的是「黑屏加按钮」。做好之后
把背景图归位进 `Art/Backgrounds/`，在 `RestUiBuilder.BuildCanvas` 里照
`TreasureUiBuilder.BuildBackground` 的 cover 写法加一层背景即可 ——
版式常量（标题带 / 引导行 / 离开键）与其它事件场景同源，一行都不用改。

## 5. 踩坑 / 决策记录

1. **这次**没**重跑 P7 地图构建器**：`M44`（全局覆盖层）会往 `MapCanvas` 里加右上齿轮 / 右下卡池键，
   而 `MapUiBuilder.RunAll` 是**推倒重建整棵 `MapCanvas`** —— 重跑 P7 会把 M44 那两个键静默冲掉
   （还得连带重跑 M44 → M45）。所以这里只**定向补 `_nodeIcons`**：
   `PrefabUtility.LoadPrefabContents` 改 Prefab 那一份 + `SerializedObject` 改场景里那份内联 Canvas，
   改完复核两份都是 9 格、且子节点数不变（仍 9 —— 证明 M44 的节点没被动）。
2. **`MapSceneEntry` 的字段不在 `GameObject` 上**：`gameObject.GetType()` 返回的是
   `UnityEngine.GameObject`，`SerializedObject(gameObject)` 里也没有 `_randomSeed`
   —— 必须先 `GetComponents` 找到那个 `MonoBehaviour` 再 `new SerializedObject(comp)`。
   （症状：`FindProperty` 返回 null，紧接着 `.boolValue` 吃一个 NullReference。）
3. **`codedom` 片段里的几个名字**：`SceneManager.CanStreamedLevelBeLoaded` **不存在**，
   它是 `Application.CanStreamedLevelBeLoaded`；`Scene` 在 `UnityEngine.SceneManagement`
   而不是 `UnityEditor.SceneManagement`。
4. **`bg.jpg` 是转码不是改名**：`.jpg` 直接改扩展名会得到一个坏文件；而且工程里背景一律是 PNG，
   `ArtImportBuilder.CollectPngs` 只扫 `.png`（不转码就永远拿不到 Sprite 导入参数）。
5. **权重表必须重新归一化**：两次追加节点（宝箱、休息）都把七项之和钉在 100 ——
   直接塞一项会让每种节点的实际出现率被静默稀释（改完没人看得出来，只能靠算）。
6. **休息不复用 `Camp`**：`Camp` 既是「起点」这个位置语义、又是「营地」这张图，
   而休息是路上可以走进去的一个**事件**（有场景、有交互）。合并会把「起点」这件事弄脏。
