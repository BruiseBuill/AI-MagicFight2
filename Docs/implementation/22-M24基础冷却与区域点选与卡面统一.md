## ① 冷却区卡面显示「基础冷却」，不是剩余冷却

**用户口径**：冷却区里的牌，卡面那个数**就是基础冷却值**，卡面无需修改。

于是 `CardView.RefreshCooldown` 里那条「迷你卡取 `RemainingCooldown`、手牌取 `BaseCooldown`」的
分支删掉，三处形态一律 `card.BaseCooldown`：

```csharp
public void RefreshCooldown(CardSnapshot card)
{
    Card = card;
    if (_cool != null) _cool.text = card.BaseCooldown.ToString();
    ApplyPowerText();   // 见 ④：重刷时要把力量预览重新下一次
}
```

**那「还剩几回合」看哪里？** 看它**排在第几行** —— 冷却区四行按
`rowIndex = Clamp(4 - remaining, 0, 3)` 分行（`CooldownView.BindGrouped`），
最上一行还剩 4 回合、最下一行还剩 1 回合。这个信息本来就在版式里，
不需要再画一个会变的数在卡面上；卡面写死的数反而与「三处样式统一」冲突。

顺带把 `RefreshCooldown` 的注释改成正确口径（旧注释写的是「迷你卡 = 剩余」）。

## ② 区域加速 / 减速改成「直接点冷却区」

**用户口径**：需要选的时候，**双方的冷却区都亮起来**，点哪一片就是选了那一侧；
顶上的选项浮层只留一个「不选择」。
**澄清后的粒度**：**保持 k 粒度**（引擎给的一档都不少），**只把入口换成点冷却区**。

### 引擎侧一个字符都没改

`BattleEngine.IssueZoneValue` 仍然按「(座位, 剩余冷却 = k)」一档一个 `Option{Kind=ZoneValue}`，
`SlowZoneBoth`（雪崩）仍然是单个 `Seat = -1`。改的只有界面。

### 一个点击怎么落成一档

`BattleUi.OnCooldownZoneClicked(seat)`：

| 该侧的档数 | 行为 |
|---|---|
| **恰好 1 档** | 这一次点击的含义是唯一的 → 直接 `Pick` 提交 |
| **多档** | 一个点击表达不了「选哪一档」→ 退回浮层，**只列该侧的那几档 + 「不选择」** |

只列该侧的档是刻意的：玩家点的是哪一片，浮层里出现的就该是哪一片的档。

### 亮起来的是「冷却区那一片」本身

`CooldownView` 新增两个显示态：

- `SetZonePickable(bool)` —— 此刻是不是区域决策；
- `SetZoneSeats(HashSet<int>)` —— 具体哪几侧能点。

高亮**不新增节点**：直接给预建的滚动视口
（`ArtLayer/CoolingScroll_Player` / `…_Enemy`，平时是全透明 Image）那一张 `Image`
涂半透明的暖金色（`UiTheme.ZonePickableEdge` @ alpha 0.16），关掉就是回到全透明。
这样绕开了 M21 的教训（运行时 new 的节点会被构建器推倒重建冲掉）。

`SlowZoneBoth` 只有 `Seat = -1` 一个选项 → 没有任何一侧可点 → 两侧都不点亮，
它的档走浮层（`_zoneBothOptions`）。

### ⚠ 落在卡面上的点击必须单独接

这是本轮最容易漏的一点。**只在视口上挂 `IPointerClickHandler` 是不够的**：
迷你卡是视口的下层子节点，EventSystem 派发 `pointerClick` 时是从射线命中的那个节点
**往上冒泡、遇到第一个能处理的节点就停**（`ExecuteEvents.ExecuteHierarchy` 的语义）。
卡片自己带 `Button`，所以**点在牌面上时永远到不了视口**，只有点「牌与牌之间的空隙」才生效 ——
而冷却区一行放满 4 张迷你卡，空隙少得可怜，等于这个入口基本点不动。

改法是把两条路并成一条：`CooldownView.OnCardClicked` 在区域档那一拍先判
`_zonePickable && _zoneSeats.Contains(SeatOf(card))`，命中就走同一个 `ZoneClicked`
（`SeatOf` 用 `_playerShown` / `_enemyShown` 两张在显示的列表查座位）。

用 `IPointerClickHandler` 而不是 `Button` 做接收器，是为了避开 `Selectable` 的
「颜色是替换不是乘算」（会把视口的透明底换成灰）以及和 `ScrollRect` 拖拽抢事件。

顶上的浮层：区域档那一拍调 `TargetPicker.Show(string.Empty, SkipOnlyList(...))`
——**只剩一个「不选择」**（新增 `ShowSkipOnly` 的底层实现 `SkipOnlyList`）。

## ③ 三处卡面样式统一（长按放大不再用成品整图）

**用户口径**：手牌、冷却区、放大查看三处统一，**统一按手牌来**。
**选定的做法**：改用**组成式卡面**，尺寸加大到便于看清。

`CardDetailView` 原来塞的是 `Art/Cards` 里那张 760×1056 的**成品卡面整图**
（`CardArtLibrary.GetArt`）—— 于是同一张牌手牌一个样、放大看又一个样，
而且图上的数值是烘焙死的，①的基础冷却与④的光环加值在图上根本改不了。

新版：`_art : Image` → **`_card : CardView`**，`Show` 里直接 `Bind(card, ViewMode.Hand, 0)`。
节点由新的

```csharp
UiKitBuilder.AddCardSurfaceTo(GameObject host, float cardWidth, float cardHeight, body, title)
```

生成 —— 它和手牌/迷你卡走的是**同一段 `BuildCardSurface`**。三处**物理上共用同一棵节点树**，
「统一」是结构上的，不靠两份版式对齐。差别只剩缩放，而缩放本来就只加在 `CardRoot` 一个节点上。

与 `BuildCardPrefab` 刻意不同的两点：不产 Prefab，也不挂
`Button` / `CardInteractor` / `HandCardState` / `Glow` / `CanvasGroup` / `LayoutElement`
—— 看牌浮层是纯展示，点它拖它都没有意义（`CardView` 里这些引用本来就全是空安全）。

`BattleUiBuilder.BuildDetail` 相应改成：`DetailPanel` 下建一个 `Face`（396 × 550.23），
把 `AddCardSurfaceTo` 挂上去，回填 `CardDetailView._card`。尺寸不变，仍是中央净空 420 里
的一大块（比手牌 196 宽大一倍，字也跟着大一倍）。

### 顺手拆掉一颗哑弹

旧版 `CardDetailView.Awake()` 里有一句 `Hide()`。而构建器收尾时已经
`SetActiveIfFound(topArea, "DetailPanel", false)` —— 于是场景加载时 `DetailPanel` 是失活的、
`Awake` 不会跑；**第一次 `Show()` 把面板置活的那一刻才触发 `Awake`**，
`Hide()` 当场把刚打开的面板又关掉。

症状是「**本局第一次长按不出牌、第二次起正常**」，零报错。这正是
`DropArrowView`（2026-09-17）、`PlayedCardView`（2026-09-20）中过两次的同一类坑
（「构建器置失活 + 运行时 Show」的组件禁止在 `Awake` 里 `Hide()`）。
初始隐藏交给构建器，本类不再自己收口。

## ④ 光环加值同步到手牌显示

**用户口径**：把增加进攻 / 防御力量的光环放进准备区之后，手牌上显示的**力量数值要同步**。
**澄清后的显示方式**：**「原值 + 加值」（如 5 → 8）并染高亮色**。

`CardView` 新增纯表现态的预览：

```csharp
SetPowerPreview(int bonus)   // 0 = 无预览，按卡面原值
ApplyPowerText()             // 有预览且卡面力量是纯数字 → 显示 Card.Power + bonus
ApplyPowerColor()            // 预览中染 UiTheme.PowerPreview，否则还原卡面原色
```

- 力量读的是**快照的 `Card.Power`**（`EffectivePower`），所以「原值」本身就已经含了
  模仿复制等引擎侧的改写；只有卡面 `PowerText` 是纯数字（`IsNumericPower`）才预览 ——
  未复制时卡面写 `X`，没有「X + 3」这种东西。
- 高亮色 `UiTheme.PowerPreview` 刻意取**深棕**（`0.62, 0.34, 0`）：力量徽标底是星爆的
  亮米白，浅色会整块糊进去（与 `CardPowerNumber` 用深灰是同一个理由）。
- `RefreshCooldown` 末尾补一次 `ApplyPowerText()`：冷却区每 tick 都会重刷整列，
  不补的话冷却区一动就把手牌上那份预览冲回卡面原值。

`BattleUi` 侧（`ApplyHandPowerPreview` → `PreviewBonusFor`）决定「预览多少」：

- 只在 `ChooseAttackCard` / `ChooseDefense` 两拍预览（其它拍没有落点）；
- 只预览 `_handPlayable` 里的牌 —— 光环加值只作用于**当时正在打出的那一张**
  （`rules/01-规则基线.md` §6.2），给一张打不出的牌画加值是画一个不存在的结果；
- 合值 = `_preparedKeys` 对应选项里 `AuraKind` 与本拍场合匹配的那些的 `Value` 之和
  （`BonusApplies`：`AtkPower` 只进攻、`DefPower` 只防御、`AtkOrDefPower` 两者都可；
  连击 / 免疫不是「力量 +N」，不参与）。

⚠ **这里画出来的数不参与任何规则** —— 真正加不加、加几张，仍然只由引擎在提交那一刻
按 `Options` 决定（铁律 3）。所谓「同源」靠的是两边都读同一份已准备集合，
而不是界面替引擎算账。

`HandView.ApplyPowerPreview(Func<CardSnapshot,int>)` 是这层的入口（遍历在显示的手牌下发）。

## 遗留 / 已知取舍

- **组成式卡面的比例与槽位差 5 px**：设计空间是 622 × 872（0.7133），而
  `UiLayout.DetailFaceHeight` 沿用的是成品图的 0.7197 → 396 宽的卡面实际高 555.16，
  比 550.23 的槽位高约 4.9 px，上下各溢出 2.46 px。浮层没有底图也没有遮罩，
  溢出落在空白区（上到 1002 ≤ 1080、下到 351.5 > 手牌区上沿 344），视觉无差别。
  真要抹平就改 `DetailFaceHeight` 的除数，但那会连带 `DetailHeight` 与 prefab 里的值一起动，
  收益不值这个风险。
- **点冷却区在「多档」时会退回浮层**：这是「保持 k 粒度」的直接代价。
  若将来想连这一步也省掉，就得让引擎在某一侧只给出**一个**汇总档
  （例如「该侧全部 +1」），那属于规则改动，不在本轮范围。
- **`SeatOf` 依赖 `_playerShown` / `_enemyShown`**：卡片不在任何一张列表里时返回 -1、
  点击照旧走 `CardClicked`。若将来冷却区的卡片容器改成复用池以外的结构，这里要一起看。
- 提示类颜色（区域高亮 `ZonePickableEdge`、力量预览 `PowerPreview`）**只在 `UiTheme` 里定义一次**，
  运行时只改 `Image.color` / `TMP_Text.color` 的值，不再往 prefab 里写死色
  —— 与「提示色只写在 prefab」那条并不冲突：那一条约束的是**判定底色**这类需要手调的提示，
  这里两个是「按状态切换」的数值色，和 `CardPowerNumber` / `CardCoolNumber` 同类。
