## 2. 怪物卡池资产化（第 1 条）

**没有新增任何抽牌逻辑** —— `CharacterConfig.CreateDefinition` 本来就先看 `cardPool`、
引擎抽牌只按 `Core.CardPool` 走。这一轮只是把卡池**从「不存在」变成「一份可编辑的资产」**。

一只怪现在是**两份资产**：

```
Assets/Resources/Monsters/Monster_Basic.asset     # CharacterConfig：血量 / 卡池引用 / AI / 行为 / 发牌口径
Assets/Resources/Pools/MonsterPool_Basic.asset    # CardPoolConfig ：这只怪能打哪些牌
```

`MonsterBuilder` 里加了三件事：

| 位置 | 行为 |
|---|---|
| `MonsterSpec.PoolFileName` / `PoolCardIds` | 加一只怪时一并声明它的卡池文件名与内容（`PoolCardIds` 为空 = 全卡表） |
| `EnsurePool` | **缺失才建**：卡池是内容，会被人直接改资产 —— 每次跑构建器重写等于把编辑器里的改动静默抹掉（与 `CardPoolBuilder` 同一条口径） |
| `PointPool` | **增量补线**：本批之前建的怪（`Monster_Bomber`）身上 `cardPool` 是空的，而「缺失才建」不允许覆盖它 → 单独补**这一处引用**，血量 / 行为 / 美术 / 发牌口径一律不碰 |

默认内容 = **`useAllCards = true`（全 45 张）** —— 与改造前怪物「全卡」的行为**逐字一致**，
所以这次接线不会悄悄改变任何一场对局。想限定某只怪能打哪些牌：

> 打开 `MonsterPool_<怪名>.asset` → 取消勾选 `useAllCards` → 在 `cardIds` 里填基础卡 ID。
>
> ⚠ **至少 8 张**：怪物开局要一次抽满 8 张（`DealProfile.Monster`），而
> `CharacterDefinition` 的构造器会按角色的 `minimumCardCount` 校验卡池 —— 配少了不是
> 「少发几张」，是**进战斗当场抛异常**。构建器在生成时会对配不足 8 张的 `PoolCardIds` 打警告。
>
> ⚠ 想让两只怪共用一份卡池：把它们资产上的 `cardPool` 指到同一个 `CardPoolConfig` 即可。

**换怪**：`Assets/Prefabs/Ui/BattleCanvas.prefab` → `BattleDriver` → 「本场战斗的怪物资产」那一格。
⚠ 构建器现在**只在那一格为空时**才会接第一只怪 —— 你在 Inspector 里挑过的那一只不会被悄悄换回去
（加第二只怪之后这条尤其重要；改前它每次都覆盖）。

## 3. 第二只怪：基础傀儡（第 3 条）

`Monster_Basic` / `monster.basic` / **基础傀儡**：4/4 血、`abilities` 是**空数组**（不是 null）、
通用 AI、`dealPreset = Monster`、卡池 `MonsterPool_Basic`（全 45 张）。

它是「最普通的一只怪」—— 没有任何回合行为，用作常规遭遇与**对照组**
（自爆傀儡那条路径一直缺一个「什么都不做的怪」来对照）。

加第三只怪的流程 = 在 `MonsterBuilder.Specs` 里加一行 + 跑一次菜单
「魔法乱斗/怪物 · 生成怪物资产 + 接进战斗（缺失才建）」。

## 4. 玩家带伤入场（第 2 条）

落点是 **`MapRun` 的一个新字段**（与金币同一口径：跨场景的运行态都放这里，退出 Play 归零）。

| 量 | 在哪 | 含义 |
|---|---|---|
| `MapRun.PlayerHp` | 局外（跨场景） | 玩家的**局外当前生命**。**`0` = 还没有持久状态**（第一次进场沿用角色资产的初始生命 = 满血） |
| `CharacterDefinition.InitialHp` | 本场战斗 | 入场当前生命 = 局外当前生命（`BattleDriver.BuildSetup` 用 `WithHp` 换掉） |
| `CharacterDefinition.MaxHp` | 本场战斗 | 入场上限**不变** = 角色资产的正常上限（战斗内被削的上限不写回局外） |

三处接线：

1. **Core** `CharacterDefinition.WithHp(int initialHp, int maxHp)` —— 建定义的最后一步换两个数。
   ⚠ **夹取在方法内做**（`1 ≤ initialHp ≤ maxHp`，`maxHp ≥ 1`）：构造器断言 `initialHp > 0`，
   而冒险层把 `Hp <= 0` 的角色直接发来时，夹成 1/1 继续比在构造器里抛异常把整局卡住要好。
2. **读** `BattleDriver.BuildSetup` —— 本地座位 `WithCardPool` 之后追加
   `if (MapRun.HasPlayerHp) character = character.WithHp(MapRun.PlayerHp, character.MaxHp);`
   ⚠ 判据是「局外有没有一份当前生命」，**不是**「有没有在冒险里」—— 单场景调试同样走这条路，
   否则会分成「冒险里带伤、单场景满血」两套口径，而玩家看到的永远是后者。
3. **写** `BattleUi.HandleFinished` —— `win && !draw` 时
   `MapRun.SetPlayerHp(_driver.GetPlayer(LocalSeat).Hp)`。
   ⚠ **只在玩家赢时写**：输 / 平局时玩家生命是 0，写回去等于给失败编一个血量（失败已由
   `ReportBattle(false)` 表达）；更关键的是**「重试」需要的正是局外那份「入场前」的值** ——
   写回 0 会让重试变成 1 血开局。

由此得到的完整行为：

```
第一场：局外 0        → 入场 4/4 → 打赢剩 2 → 局外写 2
第二场：局外 2        → 入场 2/4 → 打赢剩 2 → 局外写 2（战斗内回血的增量一并带走）
第三场：局外 2        → 入场 2/4 → 打输      → 不写（局外仍 2）
      失败界面「重试」 → 回到本场最开始的状态（仍是 2/4，不是 1 血）
「退出到主菜单」/ 开新冒险 → MapRun.Clear() / StartNew() → 局外回 0 → 下一场满血
```

⚠ **地图顶栏仍然不显示生命**（规格 §6.4 要求「地图页要能看当前生命 / 上限」，尚未做）——
玩家目前只能在**战斗里**看到自己带了多少伤进来。

## 6. 已知遗留 / 未做

- ⚠ **地图顶栏不显示生命**（同上 §4）。要让玩家在地图上看到血量得改 `MapUiBuilder`，
  且按工程惯例**两处都补**（Prefab + 场景）。
- ⚠ **`MapRun.PlayerHp` 不落盘** —— 与金币一样只活在**一次 Play** 内（退出 Play 归零）。
  真正的冒险存档是规格 §5.5 / P6 的事。
- ⚠ **没有「休息治疗 / 事件加血」** —— 规格 §3.4 的 `RunMaxHp` 与「提高上限时当前生命同步 +Δ」
  都还没做，因为冒险事件系统本身还没落地。现在只有「出生满血 → 逐场带伤 → 死」这一条线。
- ⚠ **战斗结束的写回挂在 `BattleUi.HandleFinished`**：如果以后有第二条「离开战斗」的路
  （例如从设置里直接退出到主菜单），那条路**不会**把生命写回局外。要补就在那里加同一个调用。
- ⚠ **`_monsterConfig` 仍是单个引用** —— 一场战斗只能指定一只怪，「随机挑一只」或
  「按地图节点 / 层数选怪」都还没有（DuelMode 1v1 够用）。
- ⚠ **`MonsterPool_*` 目前都是「全 45 张」**：这一轮只把卡池**摆到了资产上**，
  没有真的给某只怪配出一份有区分度的清单 —— 那是内容工作，改 `cardIds` 即可。
- ⚠ **排查记录**：验证途中控制台出现过一条 `CharacterDefinition.cs(160,36): error CS0111:
  already defines a member called 'WithHp'`，但磁盘上只有一个 `WithHp`。它是**中间态编译**留下的
  陈旧错误（真实来源未复现），而 Error Pause 把它变成了「Play 里帧不涨、对局 turn 恒为 0」。
  处理方式：**停 Play → 清控制台 → `AssetDatabase.Refresh(ForceUpdate)` + `RequestScriptCompilation()`
  → 重查 == 0 error**，之后 Play 正常。下次遇到「帧不涨」先读一次 `Time.frameCount`（两次读数一样
  = 编辑器暂停），再查控制台 error，别先怀疑对局逻辑。
