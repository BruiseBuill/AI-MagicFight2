## 2. 虚弱：本作第一个「状态」

在此之前，引擎里的效果全是**即时**的（改冷却、改力量、改手牌）；
虚弱是第一个**挂在某一方身上、跨回合持续**的东西，所以链条比一般效果长。

### 2.1 规则口径（用户 2026-09-29 明确）

| 项 | 口径 |
|---|---|
| 作用对象 | **被攻击的目标**（对手）—— 不是双方，也不是自己 |
| 效果 | 该方打出的牌 **最终进攻力量 ×50%、之后向上取整** |
| 取整 | 7→4 · 9→5 · 5→3 · 2→1（⚠ 不是「砍掉一半再向上取整」，那样 7 会得 3） |
| 范围 | **只削进攻力量**，防御力量不受影响 |
| 递减 | 该方**自己的一个进攻半场结束后** −1 层 |
| 叠加 | 可叠加、无上限 |

### 2.2 落点

| 位置 | 做了什么 |
|---|---|
| `PlayerState.WeakenStacks` | 层数（`internal set` —— 只有引擎能改） |
| `PlayerState.Weakened(power, stacks)` | **取整函数只此一份**：`(power + 1) / 2` |
| `AttackContext.FinalPower` | 唯一的折扣点：`Weakened(BasePower + BonusPower, WeakenStacks)` |
| `EffectOp.Weaken` | 新算子，① 力量阶段，`Targets = Opponent` |
| `BattleEngine.DoAnnounceHalfTurn` | 开拍时把层数**快照**进 `AttackContext` |
| `BattleEngine.DoEndHalfTurn` → `DecayWeaken` | 进攻半场收尾时 −1 |
| `AttackPowerResolvedEvent.WeakenStacks` | 事件带上层数，界面才能印对力量 |

### 2.3 三个容易做错的点

**① 打折必须只在 `FinalPower` 一处。**
这个数就是「防御方需要面对的力量」—— 防御合法性（`DefenseResolver.BuildOptions`）、
免疫光环的区间判定、提示条文案全都读它。分散打折必然漏一处，
而漏掉的表现是「虚弱没生效」：不报错、不崩、只悄悄影响平衡。

**② 事件里必须带 `WeakenStacks`。**
`BattleUi` 收到 `AttackPowerResolvedEvent` 会直接印
「进攻力量 N · 需要 ≥N 才能挡住」。折扣只发生在引擎内部、事件里不体现的话，
玩家看到的是「提示说 7、实际只打 4」—— 那是 bug 的样子。

**③「一次进攻结束」= 整个连击链，不是单次追加。**
递减放在 `DoEndHalfTurn`（连击循环 `Stage6 → BeginHalfTurn` 的出口），
所以一次带连击的进攻只减 1 层。
「手牌为空、无法进攻 → 掉 1 点」那条路径也走这里，同样算一次进攻结束。

**④ 目标范围必须显式写 `Opponent`。**
`EffectDef` 的默认目标是 `Participants`，在 1v1 下 `Mode.EffectSeats` 会把施法者
自己也圈进去 —— 表现是「打完毒刺，自己下回合也变虚弱」。
所以卡表里那一行必须写 `targets: EffectTargetScope.Opponent`；
`WeakenScenario` 的静态断言里也专门钉了这一条。

## 3. 击穿：第 7 种光环

`AuraKind.QuickRefill = 7`。它与 `EffectOp.QuickRefill`（陨石 / 喷泉 / 地动波 / 雪崩自带的那种）
是**同一条规则**，区别只在发放方式：那个是打出时就绑在自己身上，
这个是**存成一枚指示物**，可以留给后面某一拍打出的大牌用 —— 所以它必须能作用于「别人的牌」，
这只有光环这条路做得到。

| 位置 | 口径 |
|---|---|
| `AuraResolver.UsableIn` | 与连击同侧：**只有进攻场合**能用 |
| `AuraResolver.IsPowerBonus` | **返回 false** —— 它减的是冷却、不是力量，不能进防御侧的补值预算 |
| `AuraResolver.DescribeEffect` | 「本次打出的法术获得快速回填（进入冷却区时剩余冷却额外 −1）」 |
| `BattleEngine.ApplyAuraOnAttack` | 写进**本次打出那张牌的** `EffectContext.CooldownReduction`（第 ④ 步读它） |

⚠ 写的是「那张牌的 `EffectContext`」而不是 `_atk` 上的某个字段：
快速回填的语义就是「这一张进冷却时少等一回合」，与 `EffectOp.QuickRefill` 走同一个落点。
那张牌的 context 在 `SplitEffects` 里已经建好，而 `ApplyPreparedAttackAuras` 必然晚于它。

## 4. 界面：血条旁的「虚弱 ×N」

虚弱的全部表现是「它打出来的牌力量只有一半」，而这件事发生在结算内部 ——
不画出来的话，玩家看到的是「对面明明 7 的牌只算 4」。

- 节点：`Badge_Weaken`（`Bg` + `Text`），挂在 **ArtLayer** 上，
  与头顶「生命 n/m」徽标同因**不挂在角色节点下**（角色 pivot 随动作帧切，挂进去会跟着抖）。
- 位置：头顶徽标**正上方再叠一行**（`UiLayout.CharWeakenGroundOffset`）。徽标只有 132 宽，横向塞不下第二行读数。
- 双方各一枚：玩家会被削、怪物也会被削。
- 层数为 0 时整块 `SetActive(false)`；`CharacterView.SetWeaken` 里先比一次 `activeSelf` ——
  它跟着血量读数每拍刷新，每拍都写一次会让 UI 面板每帧重建批次。

### ⚠ 走错的一步（记下来）

第一版把徽标加在 `PlayerBarView`（中央信息条）上，并为此把 `PlayerBarHeight` 从 220 加到 264。
构建出来才发现**战斗里根本看不到** —— M11 美术层会把 `PlayerBar` / `EnemyBar` **收起**
（`RetiredNodes`），战斗界面用的是 ArtLayer 的顶部状态栏与角色头顶徽标。
已经回滚（`PlayerBarHeight` 回 220、`PlayerBarView` 的字段与绑定删净），改挂到 `CharacterView`。

**教训**：改任何「看得见的东西」之前，先确认**它在战斗里到底是不是活的** ——
`BattleArtLayerBuilder.RetiredNodes` 就是那份「看起来在、其实被停用」的名单。

### 自测

```
cd Tools/RuleSelfTest
dotnet build --nologo -p:UseSharedCompilation=false
dotnet run --no-build -- 10000 20261700
```

`WeakenScenario.cs` 两层验证：

1. **静态** —— 取整表（7→4 / 9→5 / 5→3 / 2→1 / 无层数不变）、两张卡的卡表结构
   （含 `Targets == Opponent` 与 `IsPowerBonus(QuickRefill) == false`）；
2. **动态** —— 扫种子把「手上正好有毒刺 / 击穿」的局面逼出来，强制打出，再在事件流上核对：
   施加 2 层 → 被施加者进攻力量折半 → 它进攻结束 −1 层；
   光环点亮（类型 = QuickRefill）→ 消耗 → 那张牌进冷却区时剩余冷却 −1。
   每条要凑满 3 次样本，**样本不足一律算失败**。

### 本次结果

- 自测 **全绿**：数据类 / 不变量 / 规则类断言全部 PASS，新增 4 条虚弱断言 PASS。
- 万局：**异常 0 · 平局 0 · 平均 6.54 回合**。
- 对照组（临时把 `Weakened` 改成恒等函数）：平均 6.29 → 说明虚弱本身让对局平均长约 0.25 回合，符合预期。

## 6. ⚠ 两个**既有**问题（与本次改动无关，但这次才被量出来）

这两条都用「把虚弱折算临时改成恒等」的对照组复核过，**对照组里一模一样**：

1. **`RuleAssertions` 有一条常年违规**：「区域类选项的 k 或匹配张数非法」。
   根因是 `BuiltinEffects.Cooldown` 生成 `OptionKind.ZoneValue` 选项时**没有设 `Option.Count`**，
   而断言要求 `Count >= 1`。修法二选一：生成处补 `Count = 命中张数`，
   或者断言只查 `Value`。（万局里每次区域决策都会报一条。）
2. **存在超长对局**：最长回合 **3158**（平均只有 6.5）。内核**没有平局判定**，
   双方一直互相挡住就会一直跑下去。本次两张新卡不影响它（对照组同样 3158）。
