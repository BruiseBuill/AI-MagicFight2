# 07 · 卡牌插画美术与 AI 生图工作流

> 状态：现行规范 · 建立日期：2026-09-30 · 适用范围：`Assets/Art/CardArt/` 及其 `_Draft/` 草稿
>
> 本文记录本作卡牌插画的共同视觉语言、LikeAI 生图接口、密钥边界、资源落位和验收流程。
> 卡牌规则与卡牌 ID 仍以 `Docs/rules/01-规则基线.md`、`Docs/rules/02-卡牌图鉴.md` 和
> `CardLibrary` 为准；本文不定义新卡牌。

## 1. 资源职责

卡牌插画是**无框、无字、无数值**的图像层。卡名、力量、冷却、效果文字由运行时卡面组件渲染，不能烘焙进插画。

| 情况 | 放置位置 | 命名 | 是否进入运行时映射 |
|---|---|---|---|
| 已有 `CardDef` 的正式插画 | `Assets/Art/CardArt/` | `Card_<两位序号>_<卡ID>_<卡名>.<ext>` | 是，重建 `CardArtLibrary` 后使用 |
| 还没有规则或卡 ID 的候选图 | `Assets/Art/CardArt/_Draft/` | `Draft_<元素英文>_<中文名>[_<构图标签>].<ext>` | 否，先保留备用 |
| 原始参考、过程图、接口响应 | 项目外本机目录或 `Artifacts/` | 使用带版本的描述性名称 | 否 |

正式图与草稿图不能混放。新增图片后让 Unity 生成对应 `.meta`，不要手写或删除 GUID。

## 2. 现有卡牌插画的共同美术语言

这套结论来自 `Assets/Art/CardArt/` 中水、冰、火、地、草、电等元素的现有插画，而不是来自第三方 UI 或角色资源。

### 2.1 形体与构图

- **纵向卡牌构图**：现有原图主要是约 `784×1168`，部分高分辨率图为 `1024×1536`；后续优先生成 `1024×1536`，保留纵向约 `2:3` 比例。
- **强轮廓、强方向**：主体可从边缘切入或冲出画面，使用斜向、旋转、汇聚、上冲等动势，缩小到卡牌尺寸仍能读出元素和动作。
- **前中后景分层**：背景只负责衬托主体，前景可以用少量碎片、波纹、地面或能量痕迹承接动作；不要堆叠复杂环境。
- **留白要服务轮廓**：留白不是装饰性背景，而是让主形体边缘清楚；动态攻击类插画可以减少留白并让主体压满画面。

### 2.2 形面、材质与光

- **低多边形抽象插画**：以三角形和不规则多边形切面组织体积，保留清晰的面与面之间的色阶。
- **硬边块面明暗**：优先使用平面色块、锐利高光和明确的深色内腔；避免照片式连续渐变。
- **元素感来自形体和光**：水用浪冠、泡沫、涡流、冲击线；火用尖锐火舌和热裂面；电用环状放电和折线；不要依赖文字或图标说明元素。
- **纹理少而有效**：允许少量水沫、碎片、喷溅和边缘颗粒，但大几何形必须先读出来。
- **不是写实 3D 渲染**：不追求真实摄影、真实材质反射或复杂体积雾；目标是有魔法感的二维几何插画。

### 2.3 颜色系统

每张图使用一个元素主色组，再用近白色或深色建立明度对比。不要跨元素随意混入强烈的无关色。

| 元素 | 建议色组 | 形体关键词 |
|---|---|---|
| 水 Water | 清蓝水光、深海潮汐、软水浅青、波纹靛蓝、近白水沫 | 浪墙、涡流、泡沫、流线 |
| 冰 Ice | 冰晶蓝白、冷霜浅蓝、飘雪薄荷蓝、锐冰青光 | 冰晶、霜面、碎冰、锐角 |
| 火 Fire | 烈焰橙红、熔岩红金、深焰红紫、焦炭火光 | 火舌、裂面、爆燃、热核 |
| 石 / 地 Earth | 砂土黄褐、岩灰石色、赤铁赭石、暗森泥土 | 岩块、断层、冲击波、盾面 |
| 草 Nature | 亮草绿、柔和嫩绿、自然树丛绿、绿金 | 藤蔓、叶刃、荆棘、孢子 |
| 电 Lightning | 暗色切面：炭灰板岩、烟灰蓝、灰紫、深青、暗橄榄；亮色：亮青蓝、青绿、荧光黄绿、近白电光；明暗面积按主体功能与构图决定，不设固定比例 | 闪电、放电环、蓄能核心、折返电流、雷霆分支、屏蔽弧面 |

电系新图必须综合参考「雷鸣」「电弧」「闪电」「磁暴」「引雷」等现有卡牌，不能只套用「引雷」的大面积高亮，也不能把电系统一处理成深蓝水晶。暗色负责体积、背景切面、内层和屏蔽空间；亮色负责电流核心、受力边缘、放电路径和视觉焦点。亮暗的面积与明度必须根据主体是蓄能、释放、攻击还是防御来安排，不设固定的亮暗比例。

### 2.4 必须避免

所有生成任务默认加入以下约束：

- 不要文字、汉字、字母、数字、符号、Logo、品牌、水印或卡牌边框。
- 不要近现代物体、建筑、船、车辆、人物或动物，除非卡牌概念明确要求。
- 不要照片感、游戏 3D 模型感、柔焦、过度体积雾、平滑渐变和油画笔触。
- 不要把 UI、卡名、力量、冷却、效果说明画进图片。
- 不要照搬另一张卡的主体构图；复用的是共同视觉语法，不是复制单张图片。

## 3. 可复用提示词结构

新图统一使用结构化提示词，而不是只写一句元素名称。完整模板见
[卡牌插画生图提示词模板](../templates/卡牌插画生图提示词模板.md)。

固定顺序如下：

1. `Use case` 与 `Asset type`：说明这是游戏卡牌插画。
2. `Primary request`：只描述这张图的核心动作或对象。
3. `Scene/backdrop`：限定抽象背景和必要的前景。
4. `Subject`：描述主形体、尺度、方向和视觉焦点。
5. `Style/medium`：固定低多边形、硬边切面、平面色块和魔法感。
6. `Composition/framing`：固定纵向卡牌画幅、视角、主体占比和动势。
7. `Lighting/mood`、`Color palette`、`Materials/textures`：补充明度、色组和材质表现。
8. `Text`、`Constraints`、`Avoid`：明确禁止文字、现代物体、水印和风格漂移。

提示词应描述“共享风格 + 本张图的差异动作”。不要把所有已有卡名或元素故事塞进同一次请求。

## 4. LikeAI 生图接口

### 4.1 当前接口

文生图使用同步接口：

```text
POST https://api.likeai520.cc/v1/images/generations
Authorization: Bearer <本机 key>
Content-Type: application/json
```

卡牌插画的默认请求体：

```json
{
  "model": "gpt-image-2",
  "prompt": "<结构化提示词>",
  "size": "1024x1536",
  "quality": "high",
  "output_format": "png",
  "response_format": "b64_json",
  "background": "opaque",
  "n": 1
}
```

接口返回 `data[0].b64_json`。将 Base64 解码为 PNG 后再进行视觉检查；不要把完整响应 JSON 或 Base64 写进项目。
LikeAI 文档还提供 `/v1/images/edits`，只有在用户明确要求改图、并明确提供编辑目标时才使用。

### 4.2 Key 的边界

- Key 只能保存在项目外的本机目录，例如 `C:\Users\<用户名>\.codex\local-secrets\likeai-image.key`。
- 仓库内的脚本、提示词、文档、日志、截图、命令示例都不能包含真实 key。
- 推荐通过 `-ApiKeyFile` 或环境变量 `LIKEAI_IMAGE_API_KEY_FILE` 指向 key 文件；脚本只读取，不打印 key。
- 发现 key 进入 Git、日志或聊天记录时，应立即在服务端撤销并重新生成，不要只删除本地文本。

项目内的可复用调用器是 [`Tools/ImageGeneration/Generate-LikeAiImage.ps1`](../../Tools/ImageGeneration/Generate-LikeAiImage.ps1)。

### 4.3 可复用调用命令

```powershell
pwsh -File Tools/ImageGeneration/Generate-LikeAiImage.ps1 `
  -ApiKeyFile 'C:\Users\<用户名>\.codex\local-secrets\likeai-image.key' `
  -PromptFile 'Artifacts/work/imagegen/海啸-扑岸.prompt.txt' `
  -OutputPath 'Artifacts/work/imagegen/海啸-扑岸.png' `
  -Size '1024x1536' `
  -Quality high
```

生成目录建议放在项目外的 `C:\Users\<用户名>\.codex\generated_images\<project>/`；确认结果后，再复制到 `Assets/Art/`。
不要直接覆盖已有图片，除非用户明确要求替换；版本化输出名，例如 `海啸-扑岸-v2.png`。

## 5. 从生成到 Unity 的工作流

1. **分析基准**：选 3–6 张现有卡牌，至少包含同元素代表图和 1–2 张不同元素图；记录共性，不复制单张构图。
2. **写提示词**：从模板复制，填写主体动作、视角、主体占比和元素色组；默认无输入图。
3. **本机生成**：调用 LikeAI，输出到项目外；保留生成图和提示词文件，便于回溯。
4. **视觉验收**：检查主体、元素识别、轮廓、低多边形切面、配色、文字/水印/现代物体禁项，并缩小到卡牌显示尺寸复核。
5. **落位**：有卡牌定义时进入 `Assets/Art/CardArt/`；无卡牌定义时进入 `Assets/Art/CardArt/_Draft/`。

## 6. 交付前检查表

- [ ] 图片只包含插画，不含文字、数字、Logo、水印和卡框。
- [ ] 低多边形面、硬边色块和元素色组与本作一致。
- [ ] 构图方向符合卡牌含义，不是静态素材或普通风景图。
