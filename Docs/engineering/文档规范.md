# 文档规范

> 状态：现行 · 更新日期：2026-10-30 · 范围：文档归属、写作与维护。

| 内容 | 维护位置 |
|---|---|
| 启动与导航 | 根 `README.md`、`Docs/README.md` |

规则规定预期行为，代码说明实际行为。两者冲突时记录差异，不因已有实现或测试通过而改写规则。实现记录不能覆盖现行规范，较新的日期也不表示更高优先级。

## 写作要求

- 使用 UTF-8、LF、一个一级标题，标题下注明状态、日期、范围。
- 状态使用“现行”“变更记录”“验证记录”“历史”“待确认”或“模板”。
- 现行文档只保留当前结论，删除重复推导、聊天口吻、过时待办和叠加式补丁；旧结论需要追溯时移入归档。
- 将规则、实现、配置、验证结果分别表述。未确认项集中记录，不写“暂按推论实现”后又标成已确认。
- 数值与长清单只在所属文档维护，其他页面链接引用。接口完整签名以源码为准，避免复制易过期的类型定义。
- 核对日期只覆盖实际检查的内容；静态阅读不称为运行、交互或视觉验收。
- 现有主题文件名保持稳定；新变更、验证记录使用 `YYYY-MM-DD-主题.md`。模板见 [模板索引](../templates/README.md)。

## 维护流程

1. 修改主题文档；规则变更同时检查卡表、实现差异和当前基线。
2. 保留正在编辑文件中的已有有效修改，不以旧版本覆盖工作区。
3. 历史快照保留原始结论，并注明状态与现行入口；修复迁移后的相对链接。
4. 新增文档加入索引；截图放 `Captures/`，原始输出放 `Artifacts/`。
5. 按下述轻量标准检查；无需为日常修改单独编写验收报告。

## 轻量检查原则

用户明确要求优先缩短等待时间，降低日常验收标准和强度。本节覆盖旧文档、历史记录、模板中的高强度验收要求。

- 文档修改：快速看差异；有链接或目录调整时运行一次文档检查即可。
- 代码修改：默认只做一次编译和与改动直接相关的少量检查；小改动可仅编译。
- 规则自测：默认 `--quick`，只跑定向场景。不默认跑百局、千局、万局随机对战、全卡检查、完整 EditMode 或全流程回归。
- 界面与美术：只看改动处是否可用、是否明显错位或缺图；不强制多轮截图、所有分辨率或逐像素验收。
- 只有已发现具体故障或用户明确要求时才扩大检查；通过后即停止，不为追求覆盖率继续追加测试。
- 测试环境缺依赖时优先使用已有工具；不为日常验收安装大型运行时或长时间排查无关环境问题。
- 如实说明检查过什么及明显遗留问题即可；未跑全面测试不阻止交付，也不宣称全面通过。

Markdown 链接相对当前文档目录，命令默认从仓库根目录执行。通用文档不硬编码本机绝对路径；外部文件缺失时不再作为现行规范的唯一依据。
