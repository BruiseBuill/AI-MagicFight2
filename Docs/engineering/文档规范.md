# 文档规范

> 状态：现行 · 核对日期：2026-09-25 · 范围：文档组织、维护与验收

## 信息归属

| 内容 | 唯一维护位置 |
|---|---|
| 项目启动与导航 | 根 `README.md`；不复制规则或模块进度 |
| 已落地能力、已知问题、验证边界 | `Docs/00-当前基线.md` |
| 玩法、卡表、规则决策 | `Docs/rules/` |
| 跨模块的当前交互约定 | `Docs/design/` |
| 架构、目录、命名与协作规范 | `Docs/engineering/` |
| 单次实现变更及其原因 | `Docs/implementation/` |
| 启动、环境、排障 | `Docs/operations/` |
| 执行过的验证及证据链接 | `Docs/validation/` |
| 已被替代的设计和实现记录 | `Docs/archive/` |

实现记录是一次变更的快照，不能因为日期较新就取代规则、接口和当前规范。
冲突时先核对代码和资源，再修订唯一来源；未确认的结论标为待核对。
个人工具记忆可以辅助查找，但交付所必需的知识必须进入仓库。

## 格式与命名

- 使用 UTF-8、LF、一个一级标题；标题下标明状态、日期、适用范围。
- 状态使用「现行」「变更记录」「历史」「待核对」「模板」；历史文档必须链接替代入口。
- **核对日期只表示实际核对过的内容**；仅修链接或迁移目录时，不更新玩法或视觉验收日期。
- 现行规范使用稳定的主题名；已有编号文件保留名称，避免无价值的链接迁移。
- 新实现记录使用 `YYYY-MM-DD-主题.md`，模块号可写入正文；不再维护“下一个编号”。
- 验证记录使用 `YYYY-MM-DD-主题.md`，说明环境、范围、方法、结果、未覆盖项。
- 复制 [变更记录模板](../templates/变更记录模板.md) 或 [验证记录模板](../templates/验证记录模板.md) 后填写；模板占位符不能当作验证结论。

## 路径与证据

- Markdown 链接相对**当前文档目录**；代码块中的命令默认从仓库根目录运行。
- 通用文档和工具不得硬编码某台电脑的工程绝对路径；本机差异集中写在运维说明。
- 截图放 `Captures/`，机器可读结果与审计产物放 `Artifacts/`，脚本放 `Tools/`。
- 已归档的原始输出保持内容不变；移动时修改指向该输出的链接，不伪造重跑结果。
- 路径迁移必须同步代码中的字符串路径、工具输入输出、文档链接及索引。

## 每次变更的维护范围

1. 先改本次涉及的唯一来源，再按需写实现记录；无需为每次排版变动更新规则决策。
2. 只有状态、验证边界或遗留问题发生变化时才更新当前基线。
3. 新增文档加入所属目录索引；被替代文档移入归档并链接替代入口。
4. 运行 `python Tools/Repo/verify_repo.py`；改 Unity 资源时再运行资源检查。
5. 如未运行 Unity、未点击或未做视觉验收，明确写出，不使用“全部通过”代替范围说明。
