# 项目目录规范

所有路径相对 Unity 项目根目录。

| 路径 | 用途与维护要求 |
|---|---|
| `Assets/Scripts/Core/` | 纯 C# 规则，禁止依赖 UnityEngine |
| `Assets/Scripts/Unity/` | 表现桥、UI；`Editor/` 为编辑器构建器 |
| `Assets/Tests/EditMode/` | NUnit 规则与回归测试 |
| `Assets/Scenes/`、`Assets/Prefabs/` | 场景与可复用预制体 |
| `Assets/Resources/` | 运行时加载的映射表等，保持既有加载路径 |
| `Assets/Art/`、`Assets/Font/` | 项目美术与字体 |
| `Assets/ThirdParty/`、`Assets/Plugins/`、`Assets/TextMesh Pro/` | 第三方资源，保留厂商目录和依赖 |
| `Assets/Settings/` | 渲染等 Unity 设置资源 |
| `Packages/`、`ProjectSettings/` | 依赖清单与项目设置 |
| `Docs/` | **只放可读的文本**（规则、工程、实现、运维、验证、历史归档）—— 见下方「Docs 内部分层」 |
| `Tools/RuleSelfTest/` | 链接 Core 源码的 .NET 9 自测 |
| `Tools/art-audit/`、`Tools/font-audit/` | 资源处理脚本与审计报告，保留脚本约定路径 |
| `Tools/Mcp/` | 本地 MCP 启动脚本 |
| `Captures/` | **各类运行 / 核对截图**（含 `art-review/`），不导入 Unity |
| `Library/`、`Temp/`、`Logs/`、`obj/`、`UserSettings/` | 本机缓存及生成数据，不作为源码维护 |
| `.workbuddy/` | 既有工具状态，保留，不移入 Assets |

新增 MonoBehaviour/ScriptableObject 使用与类型名一致的独立 `.cs` 文件，避免序列化丢失引用。
移动 Unity 资源须通过 AssetDatabase，同时保留 `.meta` GUID。不要直接改动 Resources 加载路径、插件和程序集边界。

## Docs 内部分层（2026-09-23 起）

| 位置 | 内容 | 性质 |
|---|---|---|
| `Docs/README.md` | 唯一入口：三层读法 + 按任务路由 + 维护约定 | 索引 |
| `Docs/00-当前基线.md` | 状态板：模块表 / **验证程度** / 已知遗留 / 现行表现层速查 | 现行 |
| `Docs/rules/` `engineering/` `operations/` | 规则、架构与规划、启动与排障 | 现行 |
| `Docs/implementation/` | 实现记录；`README.md` 是**按模块排**的索引，逐篇标了「现行 / 历史」 | 混合 |
| `Docs/validation/` | 按日期的验证范围 / 结果 / 限制（**正式验证结果写这里**） | 终态存档 |
| `Docs/archive/` | 已被替代的草稿 | 不作依据 |

**硬约定**：

1. **`Docs/` 不放二进制大图**。运行 / 核对截图一律落 `Captures/art-review/`，
   命名 `m<模块>_<主题>_<序号>_<状态>.png`，文档里用相对路径引用。
   （2026-09-23 之前堆在 `Docs/art-review/` 的 285 MB 已整体迁走，见该目录里的说明。）
2. **一件事只有一个来源**：规则在 `rules/`、接口在 `engineering/04-架构与接口.md`、
   现状在 `00-当前基线.md` —— 别在入口页或实现记录里复述。
3. **实现记录写清「性质」**：标题下必须有一行 `> **性质**：现行 / 历史 · **最后核对** <日期>`；
   历史档要写明「别照它改代码」。
4. **源码备份放工程外**：`E:\UnityProject\_CardFight2_Backups\`（本工程不是 git 仓库，
   跑「推倒重建」类构建器前先手工备份 `BattleCanvas.prefab` 等）。
