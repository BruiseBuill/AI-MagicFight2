# 项目目录规范

> 状态：现行 · 核对日期：2026-09-25 · 范围：目录职责、资源引用与迁移

所有路径相对仓库根目录。先按资源是否被 Unity 导入划分，再按用途放置；不为了目录整齐改变运行时加载键。

## 仓库结构

```text
Assets/                        Unity 导入的资产与源码（均保留 .meta）
  Art/                         项目美术
    Cards/                     烘焙完整卡面
    CardArt/                   无字插画；_Draft/ 为未实装候选
    Chars/                     角色动作帧；_Source/ 为原始动画表
    Icons/                     图标与 TMP 图集；_Source/ 为原拼图
    Ui/                        可使用的 UI 切图；_Source/ 为源图集
    Fonts/                     源字体、TMP SDF 与字体材质
    Backgrounds/  Fx/          背景、特效
    _Reference/                版式参考，不是运行时贴图
  Prefabs/Ui/                  可复用界面与卡面
  Resources/                   运行时 Resources.Load 的入口资产
  Scenes/                      游戏场景
  Scripts/Core/                纯 C# 规则
  Scripts/Unity/               Unity 桥、配置、UI；Editor/ 放构建器
  Tests/EditMode/              Unity 测试
  Settings/                    渲染设置与场景模板
  ThirdParty/                  第三方美术
  Plugins/  TextMesh Pro/      按插件约定保留的内容
Docs/                          可维护文本；入口见 Docs/README.md
Tools/                         可执行工具与工具说明
Artifacts/                     审计结果、原始验证输出；work/ 为可重建临时结果
Captures/                      运行或核对截图，不导入 Unity
Packages/  ProjectSettings/   包依赖和项目配置
```

## 资源之间的关系

| 来源 | 处理者 | 输出 / 消费者 |
|---|---|---|
| `Art/Chars/_Source/` | `Tools/art-audit/slice_*` | 动作帧与 `anim_frames.txt` → `ArtImportBuilder` → `BattleArtLibrary` |
| `Art/Ui/_Source/`、`Art/Icons/_Source/` | 切图脚本与 Unity 构建器 | UI / 图标切片 → 映射库、Prefab |
| `Art/Cards/`、`Art/CardArt/` | `UiKitBuilder` | `CardArtLibrary.asset` → 运行时卡面组件 |
| `Art/Fonts/` 源字体 | TextMeshPro 字体资产 | SDF / fallback → UI；Dynamic SDF 仍依赖源字体 |
| `Resources/Characters/` | 角色配置与设置构建器 | `BattleDriver` 加载配置 |
| `Scripts/Core/` | Unity asmdef / .NET 链接编译 | 游戏规则、EditMode、自测 |
| `Tools/` | 人工执行 | 可交付报告放 `Artifacts/`，核对截图放 `Captures/` |

`_Source/`、`_Reference/` 和 `_Draft/` 保持在现有导入流程可识别的位置；它们的用途不同于成品。
不要因名称包含 Source 就把被构建器读取的文件直接移出 Assets。待调整源素材管线时，必须一起改构建器与切图脚本。

## 必须保持的契约

- MonoBehaviour / ScriptableObject 类型与 `.cs` 文件同名；程序集依赖只能向下，Core 不依赖 UnityEngine。
- Unity 资源和目录必须带 `.meta`；在编辑器运行时用 `AssetDatabase.MoveAsset` 移动，校验迁移前后 GUID。
- `Resources` 只放加载入口及必要配置；原始大图、全部字体、截图不得整体塞进去。
- 加载键如 `BattleArtLibrary`、`CardArtLibrary`、`TriggerIconLibrary`、`TriggerIconSprite`、`Characters/DefaultPlayer` 保持稳定。
- GUID 引用会随资产移动，**字符串路径不会**：必须同步 `LoadAssetAtPath`、工具输入输出、文档链接。
- 不因整理目录修改插件结构、包内容、程序集边界或用户手调的 Prefab / 场景。
- 字体保留原有分类名；成品卡面与无字插画不能合并，消费者不同。

## 工具与产物

- `Tools/Repo/` 放仓库检查；`Tools/art-audit/`、`font-audit/` 保留可定位的处理工具。
- `Tools/archive/` 是一次性旧脚本，只用于追溯；不纳入当前操作流程。
- 正式运行结果按日期记录；不要在原始历史日志上覆盖写入本次结果。
- 缓存 `Library/`、`Temp/`、`Logs/`、`UserSettings/`、`bin/`、`obj/` 与 `Artifacts/work/` 不提交。
- 本仓库已使用 Git。执行会重建 Prefab 的工具前，先确认工作区差异，并保留可恢复的副本或检查点；未提交修改也需要保护。

## 迁移检查

1. 记录目标资产 GUID、字符串路径与当前工作区差异。
2. 移动并同步引用；不重新生成已有 `.meta`。
3. 执行 `python Tools/Repo/verify_repo.py` 和 `python Tools/art-audit/verify_layout.py`。
4. Unity 刷新、编译，再确认主要资源可加载；文档中写明是否做过 Play / 视觉验收。

本轮迁移和验证见 [结构整理报告](../validation/2026-09-25-文档与资源结构整理.md)。
