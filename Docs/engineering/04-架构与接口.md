# 架构与接口

> 状态：现行 · 核对日期：2026-10-30 · 范围：源码结构与主要契约，静态核对。

## 分层

| 层 | 位置 | 职责 |
|---|---|---|
| Core | `Assets/Scripts/Core/` | 卡牌、角色、战斗状态、结算、决策、AI；不依赖 UnityEngine |
| App | `Assets/Scripts/Unity/` | 配置、对局驱动、场景与 UI |
| Editor | `Assets/Scripts/Unity/Editor/` | 场景、Prefab、卡牌及美术构建器 |
| 验证 | `Assets/Tests/EditMode/`、`Tools/RuleSelfTest/` | Unity 测试与独立 .NET 自测 |

App 依赖 Core；Core 不引用 App。Core 使用 C# 9 和显式种子的 `Rng`。自测链接同一份 Core 源码，不维护副本。

## 数据与入口

| 类型 / 文件 | 职责 |
|---|---|
| [CardLibrary](../../Assets/Scripts/Core/Cards/CardLibrary.cs) / `ICardCatalog` | 内置卡表及可替换目录；规则文本见卡牌图鉴 |
| `CardDef` / `EffectDef` | 静态数值、效果触发、参数、条件和强制标记 |
| `CardInstance` / `PlayerState` / `BattleState` | 单局卡牌、角色与对局状态 |
| [BattleSetup](../../Assets/Scripts/Core/Battle/BattleSetup.cs) / `IBattleMode` | 参战者、敌我关系、行动顺序与终局；当前模式为 `DuelMode` |
| `CharacterConfig` / `CharacterDefinition` | Unity 角色资产与纯 C# 定义 |
| [DealProfile](../../Assets/Scripts/Core/Cards/DealProfile.cs) | 按角色配置发牌；Unity 对战统一使用 `Duel()` |
| [BattleLaunch](../../Assets/Scripts/Unity/Configuration/BattleLaunch.cs) | 标准 / 自定义战斗入口与牌组校验 |
| [GameSettings](../../Assets/Scripts/Unity/Configuration/GameSettings.cs) | 控制方式、经典卡池、AI 难度、本机座位 |
| [BattleDriver](../../Assets/Scripts/Unity/BattleDriver.cs) | 组装对局、控制器分发、事件播放 |
| `SceneRoutes` | 场景切换入口 |

`BattleLaunch.Validate` 要求每方 8 张且本方不重复。标准战斗从同一洗牌序列分配；经典模式的卡表过滤由 `GameSettings.Filter` 统一处理。基础规则不在 UI 或 AI 中重复实现。

## 决策与表现

[BattleEngine](../../Assets/Scripts/Core/Battle/BattleEngine.cs) 通过 `Advance()` 推进，在需要输入时设置 `Pending`；外部用 `Submit(DecisionResponse)` 回填。

- `DecisionRequest` 提供座位、合法选项和选择范围。UI 只提交引擎给出的选项，不能自行构造力量不足的防御。
- `IParticipantController` 的 `BeginDecision / Submit / TryTakeResponse / Cancel` 统一决策端口；现有人类、AI 控制器，网络控制器尚未实现。
- `IAgent.Decide` 负责从合法选项中选择；策略偏好不是玩法规则。
- UI 读取 `Snapshot.cs` 中的快照和 `BattleLog.cs` 中的事件，不直接修改战斗状态。
- AI 元素预判经 `BattleDriver.ForecastAttackElement` 获取；预判基于当前局面，不能保证后续出牌不变。

## 效果与冷却

[EffectRegistry](../../Assets/Scripts/Core/Battle/Effects/EffectRegistry.cs) 登记处理器，[BuiltinEffects](../../Assets/Scripts/Core/Battle/Effects/BuiltinEffects.cs) 实现内置效果。
五个效果阶段为 `Power`、`Defense`、`Cooldown`、`AfterCooldown`、`Aura`；引擎另负责入冷却和连击，因此玩家规则仍按六步描述。

冷却修改集中于 [CooldownOps](../../Assets/Scripts/Core/Battle/CooldownOps.cs)。正在结算的牌使用 `InPlay` 区域，与冷却区分离；加速归零回手时清理来源光环。
光环准备、实际消耗与无效退回共用 `AuraResolver` 判定。

新增效果时同步触发条件、处理器阶段、目标范围、可选性、卡面描述和验证。引擎保留的移除、成长、刻印等算子不等于当前卡表仍使用这些机制；漩涡不使用移除算子。

规则要求及代码偏差见 [规则与实现差异](../rules/03-规则与实现差异.md)，不以旧接口示例或代码注释覆盖规则。

## UI 与资源

静态 UI 节点由构建器预建并序列化；变更布局同时检查场景、Prefab 和组件接线。坐标与操作规范分别见 [战斗信息布局](../design/战斗信息布局.md)、[战斗交互](../design/战斗交互.md)。

卡面使用统一组成式组件：插画、卡框、图标和 TMP 文本。资源迁移须保持 GUID 与加载路径契约，见 [目录规范](项目目录规范.md)。
