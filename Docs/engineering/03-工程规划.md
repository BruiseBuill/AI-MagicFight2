## 5. 关键设计

### 5.1 暂停-恢复状态机

规则结算同步顺序，Unity UI 异步等点击。引擎推进到需要外部输入时停下、抛出 `DecisionRequest`，
AI 即时应答、玩家由 UI 渲染选项后回填。详见 `Docs/engineering/04-架构与接口.md` §4。

### 5.2 规则约束收敛在一处

「防御方不能打出挡不住的牌」在**引擎生成选项时**过滤——AI 与 UI 都拿不到非法项。
同类约束（`[强制]` 效果不可跳过、未写对象的效果可改目标）也都在 M4 统一处理。

### 5.3 表现与逻辑解耦

`BattleLog` 记录结构化事件，M6 订阅后切成动画，M4 不知道 UI 存在。

## 6. AI 设计

**本期最简策略（`SimpleAiAgent`）**

- **进攻**：有牌就打，选当前**力量最高**的一张。
- **防御**：能挡就挡，选**刚好够的最小牌**（省大牌）；挡不住则放弃。
- **目标类**：加速选己方**剩余冷却最小**的牌；减速选对方**力量最高**的冷却牌；区域类选当前数值最集中的一档。
- **光环**：**不使用**（留开关，默认关）。
- **其余**：一律取第一个合法选项。

> **2026-09-20 口径收紧（用户要求）**：**加速一律给自己、减速一律给对手**。
> 落地在 `SimpleAiAgent.PickDensestZone`（区域类**先按立场过滤、再在有利档里比密度**，一张都不占优就放弃）
> 与新增的 `PickRefreshTarget`（「立即冷却完成」只动自己的牌；「重置对方冷却」本来就只给对方的牌）。
> 回归闸门 = `RuleAssertions.CheckingAgent.CheckTargetPolarity`（万局不许出现一次立场错）。
> 详见 `Docs/implementation/19-M20出牌展示与手牌数与AI目标.md` §2.2。

**升级位**：`IAgent` 是接口，后续可换 `HeuristicAgent`（局面评估：血量差 / 手牌质量 / 冷却节奏）
→ `SearchAgent`（浅层搜索）。评估所需特征在 `BattleState` 里已齐备，无需改内核。

## 7. 界面设计

```
┌──────────────────────────────────────────────────────────────┐
│ ┌─ 我的冷却区 ─┐                 ┌──────────────┐ ┌─ 敌方冷却区 ─┐ │
│ │  竖排迷你卡  │   [你]   ⇄   [AI]              │ │  竖排迷你卡  │ │
│ │  卡名+力量   │   生命圆点      生命圆点         │ │              │ │
│ │  剩余冷却    │   未用光环亮点   手牌 ×N(不可见)  │ │              │ │
│ └──────────────┘                                └──────────────┘ │
│                                                                  │
│              ┌──── 我的手牌（大卡，点选出牌）────┐                  │
│              └──────────────────────────────────┘                  │
└──────────────────────────────────────────────────────────────┘
```

| 看不到对方的牌 | 对方手牌不显示内容，只显示 `手牌 ×N`；冷却区是明牌（减速要选目标） | ✅ |
| 不要战斗日志 | 主界面不放，收进**设置**，默认关闭 | 🔶 `LogPanel` 已建好、默认关，开关留给 M10 |

**M7 已落地的界面**（`Assets/Prefabs/Ui/BattleCanvas.prefab`，截图 `Captures/art-review/m7_uikit_02.png`），
**M8 已把它接上真数据**（截图 `Captures/art-review/m8_uikit_01_replace.png` ~ `m8_uikit_04_result.png`，
接线方式与踩坑见 `Docs/implementation/09-BattleUi实现说明.md`）：

- 8 张手牌横排实测放得下（8 × 208 + 7 × 16 = 1776 ≤ 1920）。
- 冷却区迷你卡超过 4 张自动折成第二列（`MiniCardGrid`），最多 8 张也顶不穿上部区域。
- 迷你卡上「力量」是白字、「剩余冷却」沿用卡面右上角冷却圆点的浅蓝 —— **用颜色区分两个数字**；
  剩余 1 点时变琥珀色，提示「下个半场就回手」。
- 光环指示物亮点按卡面数量显示（双光环 2 个），未使用亮琥珀 / 用完变灰；
  被磁暴之类「按基础冷却」送进冷却区的牌没有光环，整排不显示。
- 生命用「圆点 + 数字」双读法：圆点看剩几点，数字表达上限被削（第 4 点画成深色）。

> ✅ **手牌上的效果文字不可读 —— 已于 M8 解决**：卡面 760×1056 缩到 208 px 后效果文字只剩约 11 px。
> 解法不是放大手牌（8 张横排已占屏宽 92.5%，没有横向余量），而是**在舞台中央开一层详情浮层，
> 用 TMP 按 `CardLibrary` 的效果文本重新排版**（19 px，长文案自适应到 14 px），
> 顺带在每条效果前挂上触发符号。实现见 `Docs/implementation/09-BattleUi实现说明.md` §3.3。
>
> **卡面占位方案作废**：美术已到位、卡面是烘焙好的整卡，不再需要「色块底 + TMP 文本」。
> 但**冷却区迷你卡仍必须用「卡框 + TMP 文本」合成**（剩余冷却是动态值），这一条没变；
> 光环指示物同样只能运行时叠加。

**交互状态机**（M6 `BattleDriver` 已按此落地）

```
Boot → DealUi（发牌 + 至多换 3 张）→ 对局循环
对局循环：
   我进攻选牌 → [选光环] → AI 防御 → 结算演出
   → AI 进攻选牌 → [选光环] → 我防御（出牌 / 放弃）→ 结算演出
   → 回合数 +1，若为第 2/3 回合则双方补牌
   → 循环至一方 Hp = 0 → 结算画面 → 再来一局
```

> 状态机在引擎侧（`BattleEngine` 的 `Phase` 枚举），`BattleDriver` 只负责把它翻译成
> 「AI 即时应答 / 玩家等点击」两种处置，并把每次 `Advance` 产生的事件流切成节拍回放。

**字体**：✅ 已选型并**已接入** —— 正文 **Noto Sans SC**、标题 **站酷仓耳渔阳体 W03**、英文点缀 **ZCOOL Addict Italic 02**。

### 规则断言用例

**规则类**

1. 防御方拿不到「力量不足」的选项（引擎层过滤）
2. 双发 + 对方放弃 → 只扣 1 点
3. 双发 + 只有 1 张够挡 → 不能部分防御，只能全放弃
4. 守护 × 双发 → 守护只挡 1 次
5. 免疫光环 × 双发 → **整个双发被免疫**
6. 加速不能作用于正在攻防的牌
7. 减速后剩余冷却不超过基础冷却值
8. 剩余冷却归 0 → 立即回手
9. 进攻开始时只有进攻方自己的冷却区 −1
10. 连击的追加进攻不重复触发冷却 −1
11. 光环回手时未使用即失效
12. 光环加成本次有效，不永久改造牌面
13. 免疫光环只对之后的防御生效
14. **免疫光环消耗后整个攻击被免疫，且不需要再打出防御牌**（2026-09-18 口径，旧推论 P1 作废）
14. 生命上限削减后 `Hp = min(Hp, MaxHp)`
15. **生命上限归零 → 即刻死亡**
16. 手牌满 8 后不再获得新牌
17. 第 2、3 回合开始各补 1 张
18. 未标 `[强制]` 的效果可以跳过；`[强制]` 的不可跳过
19. 有牌时不能主动放弃进攻；防御方可以主动放弃

**数据类**

20. **40 张卡的力量分布 = 1:3 / 2:4 / 3:5 / 4:5 / 5:6 / 6:5 / 7:5 / 8:4 / 9:2 / X:1**（与原始文档统计完全吻合）
21. 每张卡至少有 1 条效果；双光环卡（af / aj）的指示物数为 2
22. 40 张卡逐张行为用例

## 13. 规则疑点结案（2026-09-16 用户确认）

| # | 疑点 | 结论 | 实现 |
|---|---|---|---|
| Q1 | 「快速回填」标的是 α（陨石 / 喷泉 / 地动波） | ✅ **确认按 α 解读** —— α 就是「进攻时触发」，所以**做防御时不会触发快速回填** | 已按此实现，无需改动 |
| Q2 | 寒流（d）的「重置对方一个法术的冷却时间」标 α | ✅ 同上，做防御时不触发 | 已按此实现 |
| Q3 | 防御侧光环投入方式 | 已被当前交互规范替代 | 所有可用光环逐枚拖动使用，不再自动消耗 |
| Q4 | 连击把进攻方手牌打空时，追加进攻静默作废 | ✅ **确认**：「连击之后没有手牌，当然就无法追加进攻」 | 已按此实现 |

> **沉淀成一条通用判定规则**：**卡面符号即结算时机**。α / β / γ 不是「效果分类标签」，
> 而是硬性的触发时机 —— 一条效果只要标了 α，无论它的字面语义多像「常驻关键字」
> （比如「本牌进入冷却区时 +1」），都只在作为**进攻牌**打出时结算。
> 后续加卡按这条判定即可，不会再产生同类歧义。
