# 第一部分 · 模块划分

## 1. 分层与依赖铁律

整个工程切为 **4 层 + 1 条旁路**，依赖**只允许向下**：

```
Core 基础模块（卡表 / 状态 / 冷却 / AI）
        ↓
Core 结算引擎（BattleEngine + Decision）
        ↓
表现桥（BattleDriver）
        ↓
表现层 UI（UiKit / BattleUi / DealUi / SettingsUi）

旁路：tools/RuleSelfTest ──链接源码──> Core（不进玩家包体）
```

**四条铁律**

1. `Core` 层出现 `using UnityEngine` 即为**架构违规**——靠 asmdef 的 *No Engine References* 在**编译期强制**，不是靠自觉。
2. 依赖只能向下；**表现层不得反向调用引擎**，只能通过「只读状态快照 + 事件订阅」获取信息，通过「提交决策」影响对局。
3. `Core` 必须**确定性**：所有随机走自实现的 `Rng`（显式种子），为将来联网同步与 bug 复现留路。
4. 语言锁 **C# 9**（Unity 2022.2 上限），禁用 C# 10+ 语法。

## 5. 模块间接口契约

```csharp
// —— Core 对外唯一入口（M4 暴露，M5/M6 消费）——
public sealed class BattleEngine {
    public BattleState State { get; }
    public DecisionRequest Pending { get; }        // null 表示可继续推进
    public bool IsOver { get; }

    public void Advance();                          // 推进到下一个决策点或终局
    public void Submit(DecisionResponse response);  // 回填外部决策
    public event Action<BattleEvent> OnEvent;       // 结构化事件流（UI 订阅）
}

// —— 决策请求 / 响应（M4 定义，M5 实现，M6 渲染）——
public sealed class DecisionRequest {
    public int       Seat;          // 谁要决策
    public RequestKind Kind;        // 进攻选牌 / 防御 / 加速选目标 / ...
    public IReadOnlyList<Option> Options;   // 全部合法选项（含 Skip，除非 [强制]）
    public string    Prompt;        // 给 UI 的提示文案
}

// —— AI 接口（M5）——
public interface IAgent {
    DecisionResponse Decide(DecisionRequest request);
}
```

**注意 `Options` 的语义**：「防御方不能打出挡不住的牌」这条规则，在**引擎生成选项时**就已经过滤掉了——UI 和 AI 都不可能选到非法项。规则约束收敛在 M4 一处，M8/M5 不需要重复判断。

# 第二部分 · 规则基线

> 编码时的唯一依据，均已逐条与你确认。

## 6. 资源与胜负

- 初始 **4 点生命值**，上限默认 4（可被削减）。
- 手牌上限 **8 张**；满 8 后不再获得新牌，回手完全依赖冷却。
- 任一方生命归零 → 结束。

## 7. 回合结构

- 双方各进攻一次 = **1 回合**。
- **第 2、3 回合开始时**，双方各补 1 张（各最多替换 1 次）。
- **进攻开始时**（该半场开始时），进攻方**自己**的冷却区全体剩余冷却 −1，归 0 立即回手。
- 防御方在自己的防御阶段**不做**冷却结算。

## 8. 单次进攻流程

1. 进攻方从手牌选 **1 张**打出。
2. 防御方二选一：
   - 打出一张**力量 ≥ 攻击方力量**的手牌（或「守护」牌，无视力量差）→ 挡住；
   - **放弃防御**（可主动放弃）→ 掉 1 点生命。
   - ⚠ 防御方**不允许**打出挡不住的牌。
3. 无人能防 → 掉 1 点生命。

## 9. 冷却系统

- 每张牌有**基础冷却值**；使用后立即进冷却区，剩余冷却 = 基础冷却。
- **加速** 剩余 −1；**减速** 剩余 +1（**上限 = 基础冷却值**）。
- **区域加速/减速**：选某一个「剩余冷却数值 k」，把该区中所有剩余冷却 = k 的牌全体 ±1。
- 剩余冷却归 0 → 立即回手。
- ⚠ **正在攻防的两张牌在结算全部完成前不进冷却区**，因此不受任何冷却类效果影响。
- ⚠ 冷却只有上述通路，别无其它增减方式。

## 10. 效果分类符号

| 符号 | 含义 | 触发时机 |
|---|---|---|
| α | 进攻时效果（剑） | 该牌作为**进攻牌**打出时 |
| β | 防御时效果（盾） | 该牌作为**防御牌**打出时 |
| γ | 特殊效果（圆圈） | 见卡面文字（如「冷却完毕时」） |

## 11. 关键字

| 关键字 | 语义 |
|---|---|
| 进攻力量 +? | 本次进攻力量 +?（仅进攻时） |
| 连击 | 本次结算完后**再进攻一次**，再打一张（对手需再次防御） |
| 双发 | 对方需打出**两个**法术防御，两个力量都需 ≥ 攻击力量；对方选择不防御时**只掉 1 点** |
| 快速回填 | 本牌进冷却区时，剩余冷却额外 −1 |
| 守护 | 无视力量差异，必定挡住 |
| 重置冷却 | 目标剩余冷却恢复为基础冷却值 |
| 立即冷却完成 | 目标剩余冷却归 0，立即回手 |

## 12. 光环

- **一次性辅助技能**，每个光环一份指示物。
- **获得**：带光环的牌**作为进攻牌打出**时获得（所有光环均标注 α）；该牌进入冷却区后光环才生效。
- **使用**：该牌**位于冷却区期间**，在满足场合限制时消耗一枚指示物，把加成作用于**当时正在打出的那一张牌**，**仅该次有效**，不永久改造牌面。
- **失效**：该牌冷却完毕回手时，未使用的指示物全部作废。
- **场合限制**：

| 光环类型 | 可用场合 |
|---|---|
| 进攻力量 +N（含「获得连击」） | 仅进攻时（出牌之前或同时） |
| 防御力量 +N | 仅防御时（出牌之前或同时） |
| 进攻 +3 或 防御 +3 | 进攻或防御皆可，使用时选择 |
| 免疫力量 ≥6 / ≤3 的攻击 | 仅防御时 |

- **双光环**：两条相同光环 = 两个独立指示物，可一次用掉两个，也可分两次各用一个。

## 13. 结算顺序

```
① 效果/光环带来的进攻力量增加 → 双发 → 攻击
② 防御力增加（含守护） → 防御
③ 加速 / 减速 / 其他冷却改动 / 查看对方手牌并使其进冷却
④ 本次的进攻牌与防御牌进入冷却区 → 快速回填
⑤ 光环激活（获得指示物）
⑥ 连击（追加一次完整进攻）
```

同优先级的多个效果，玩家可自行指定顺序。未标 `[强制]` 的效果均可选择不执行。

## 14. 生命上限削减

先结算回血，再削上限，最后 `Hp = min(Hp, MaxHp)`。（例：2/4 吃「恢复 1、上限 −1」→ 3/3。）

# 第三部分 · 关键设计

## 15. 结算引擎：暂停-恢复状态机

规则结算天生**同步顺序**，而 Unity UI **异步等点击**。为同时满足「命令行可测」与「UI 可交互」，引擎采用显式暂停-恢复：

```
engine.Advance();
   └─ 按步推进六步流水线
   └─ 需要外部输入 → 停下，engine.Pending = DecisionRequest

AI 座位   → driver 调 ai.Decide(req) 立刻拿到答案 → Submit → Advance
玩家座位  → UI 渲染 req.Options → 玩家点选 → Submit → Advance
```

好处：引擎不依赖协程、不依赖 `MonoBehaviour`；自测时两个座位都是即时的，可以一路循环到终局。

**演出与逻辑解耦**：`BattleLog` 记录结构化事件（`AttackDeclared` / `DefenseResult` / `CooldownChanged` / `DamageTaken` / `AuraConsumed` …），M6 订阅后切成动画，M4 完全不知道 UI 存在。

## 16. AI 模块

**本期最简策略（`SimpleAiAgent`）**

- 进攻：有牌就打，选当前**力量最高**的一张；无牌可打则跳过（掉 1 血）。
- 防御：能挡住就挡，选**刚好够的最小牌**（省大牌）；挡不住则放弃。
- 目标类：加速选己方**剩余冷却最小**的牌；减速选对方**力量最高**的冷却牌；区域类选当前数值最集中的一档。
- 光环：**不使用**（留开关，默认关）。
- 其余一律取第一个合法选项。

**升级位**：`IAgent` 是接口，后续可换 `HeuristicAgent`（局面评估：血量差 / 手牌质量 / 冷却节奏）→ `SearchAgent`（浅层搜索）。评估所需特征在 `BattleState` 里已齐备，无需改内核。

## 17. 界面设计

```
┌───────────────────────────────────────────────────────────┐
│ ┌─ 我的冷却区 ─┐              ┌──────────────┐ ┌─ 敌方冷却区 ─┐ │
│ │  竖排缩小卡  │    [你]  vs  [AI]            │ │  竖排缩小卡  │ │
│ │  显示剩余冷却 │   生命圆点    生命圆点        │ │              │ │
│ └──────────────┘   未用光环亮点 手牌×N(不可见)  └──────────────┘ │
│                                                             │
│              ┌─────── 我的手牌（大卡，点选出牌）───────┐        │
│              └──────────────────────────────────────┘        │
└───────────────────────────────────────────────────────────┘
```

**你定下的四条**

| 要求 | 落实方式 |
|---|---|
| 左边玩家、右边敌人 | 左右对峙，中间留出牌通道 |
| 你的牌在下方 | 底部全宽手牌区，大卡横排，8 张时刚好铺满 |
| 冷却区放最左侧、卡牌缩小 | 左侧竖排窄卡（44×32），只显示剩余冷却数字；敌方冷却区**对称**放到最右侧 |
| 看不到对方的牌 | 对方手牌**不显示内容**，只显示 `手牌 ×N`；冷却区是明牌（因为加速/减速需要选目标） |
| 不要战斗日志 | 主界面不放，收进 **M10 设置** 里 |

**卡面占位方案**（美术未到之前）：色块底 + 左上**力量**、右上**冷却**、下半**效果文字**；α/β/γ 用剑/盾/圈三个图标区分；冷却区里未使用的光环在卡角显示亮点，用完变灰。

**交互状态机**

```
Boot → DealUi（发牌 + 至多换 3 张）→ 对局循环
对局循环：
   我进攻选牌 → [选光环] → AI 防御 → 结算演出
   → AI 进攻选牌 → [选光环] → 我防御（出牌 / 放弃）→ 结算演出
   → 回合数 +1，若为第 2/3 回合则双方补牌
   → 循环至一方 Hp = 0 → 结算画面 → 再来一局
```
