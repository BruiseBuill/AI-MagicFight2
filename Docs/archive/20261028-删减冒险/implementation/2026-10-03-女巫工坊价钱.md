## 1. 用户口径

> 「女巫工坊的事件当中，强化是需要花费金币的。所花费的金币的计算公式如下
> 40（基础值）* 被消耗卡的冷却值 / 被消耗卡的力量值 / 被消耗卡的效果数量（1 或者 2）
> *（Max（（被消耗卡的冷却值 - 被强化卡的冷却值），1）
> 并且你需要准备一些提示词，以便玩家能快速搞清楚为什么价格发生了变化。」

原话里有两点是这次的核心：**公式本身**，以及**「为什么变化」要说清楚**（不是把价钱摆出来就完了）。

## 2. 公式落地

```
价钱 = 40 × 被消耗牌的冷却 ÷ 它的力量 ÷ 它的效果数 × max(两牌冷却差, 1)
```

`WitchWorkshop` 里新增一节（**与「谁能献祭 / 谁能当目标」那批判据分开** —— 价钱只看两张牌身上的四个数）：

| 成员 | 作用 |
|---|---|
| `CostBase = 40` / `MinCooldownGap = 1` | 公式里那两个常数，**想整体调价只改这一处** |
| `TryCost(sac, tgt, out cost, out error)` | 唯一算法；算不出来时给**给玩家看的原因** |
| `Cost(sac, tgt)` | 同上，失败返回 `0`（界面用） |
| `MinCost(sac)` | **底价** = 冷却差取下限时的价钱（只选了一张牌时显示「30 金起」） |
| `Gap(sac, tgt)` | 冷却差（带 `Max(…, 1)` 下限），单独暴露是为了文案与断言都能读它 |
| `CanAfford(gold, cost)` / `CostShortfall(gold, cost)` | 买不买得起与那句提示 |
| `CanConfirm(sac, idx, tgt, gold, out reason)` | **新重载**；价钱那一条排在**最后** |
| `CostFormula()` / `CostLine()` / `CostRuleLine()` / `CostFloorLine()` / `CostChangeLine()` | 五句**给玩家看的字**，全部写在 Core |

四条口径上的取舍：

1. **除不尽就四舍五入，且至少 1 金**（`AwayFromZero`）。公式本身会有小数
   （例：`40×2÷9÷2 = 4.44`），价钱是整数。
2. **价钱不算进「谁能当目标」**。目标合格与否只看卡面（恰好 1 条效果 / 未强化 / 不连锁），
   没钱是**另一层**：`CanConfirm` 五条之后再判钱，这样玩家先看到的是「操作还没做对」。
3. **不带金币的 `CanConfirm` 重载保持原样**。它是规则侧入口（自测、将来的 AI 都用它），
   「玩家有没有钱」不该绑死在纯规则判定上 —— 自测里有一条断言专门盯这个。
4. **力量 / 效果数为 0 也不崩**。公式里这两项是分母；卡表当前 45 张牌的力量都 ≥ 1、
   效果数都是 1 或 2（正好对上用户说的「1 或者 2」），但守卫还是要写，
   `TryCost` 会安全退出并给出原因。

### 价钱的实际区间（实测，供调参参考）

全表 45 × 44 = **1980 对**牌，价钱区间 **9 ~ 320 金**（`CostBase = 40`）：

| 位置 | 例 | 价钱 |
|---|---|---|
| 最便宜 | 献祭 冷却2 / 力量9 / 效果2，目标冷却 ≥ 2 | **9** |
| 常见中段 | 献祭 冷却3 / 力量5 / 效果2，目标冷却2（冷却差 1） | 12 |
| 常见中段 | 献祭 冷却4 / 力量4 / 效果2，目标冷却2（冷却差 2） | 40 |
| 最贵 | 献祭 冷却4 / **力量1** / **效果1**，目标冷却2（冷却差 2） | **320** |

⚠ **开局金币只有 50**（`MapRun.DefaultGold`）。也就是说这个公式下**大半组合是买不起的**，
能轻松买下的集中在「高力量 + 多效果」那几张。这不是 bug，但如果实机手感偏贵，
**只改 `WitchWorkshop.CostBase` 一个数**就能整体缩放（改成 20 ≈ 全表腰斩）。

## 3. 「为什么价钱变了」怎么讲

用户要的不是一个数字，是**能自己估价的脑子**。所以提示词分三层，**都在 Core 里拼好**，
界面只负责摆上去（界面自己拼句子 = 两套说法必然分叉）：

### ① 挑牌那一刻：口诀（浏览层那行说明）

| 空位 | 提示 |
|---|---|
| 献祭 | `被消耗的牌：冷却越高 / 力量越低 / 效果越少 → 花费越贵` |
| 目标 | `只有「1 条效果且未强化」的牌能当目标；它冷却越低 → 花费越贵` |

⚠ 这两行压在浏览层的 **900 宽 / 字号 26**（约 31 个字）里，再长就会溢出面板 ——
改文案要连着这一条一起看。

### ② 只选了一张（献祭）：底价 + 口诀（`CostFloorLine` + `CostRuleLine`）

价格牌那一行**藏起来**（公式要用到目标的冷却，这时根本算不出来；显示 `0` 会被读成「这次免费」），
明细行写：

```
底价 40 × 冷却3 ÷ 力量5 ÷ 效果2 = 12 金起；右边那张冷却比它低时会更贵
冷却越高越贵 · 力量越高越便宜 · 效果越多越便宜 · 目标冷却越低越贵
```

`MinCost` 就是**这个献祭牌的最低价**（冷却差再小也只会被 `Max` 抬回 1），所以「12 金起」是准确值不是估算。

### ③ 两张都选了：等式，或者「比刚才」

- **没换过牌** → 明细是等式：`40 × 冷却4 ÷ 力量8 ÷ 效果1 × 2 = 40 金`
  （冷却差被下限抬起来时写成 `1（冷却差 0，按下限算）`，让玩家看得出「目标冷却比献祭牌高也不会更便宜」）
- **换过牌** → 明细换成变化解释（`CostChangeLine`）：

```
比刚才 20 金 → 40 金（贵了 20）：目标冷却 4→2（更贵）
```

`CostChangeLine` 是**纯函数**（连「上一次价钱 / 上一次那两张牌」都当参数），
逐项比 冷却 / 力量 / 效果数 / 目标冷却，指出**哪个因素动了、往哪边动**；
没有变化时返回空串，界面退回等式。状态行同时补上花费：
`确认后，《X》会被消耗，「e」转移到《Y》（花费 40 金）`。

## 4. 界面改动

| 位置 | 改动 |
|---|---|
| 场景右上角 | 新增 `GoldLine`（「金币 50」）—— 本场景没有商店那条 `Hud_Bar`，不摆余额的话玩家只能从「确认键为什么灰着」反推 |
| 主浮层状态行下方 | 新增 `CostRow`（`LeftLabel`「本次强化花费」+ `Plate`（复用商店 `Shop_PricePlate.png`）+ `RightLabel`「现有 N 金」）与 `CostDetail`（等式 / 变化解释） |
| 主浮层确认键 | 判据换成**带金币**的 `CanConfirm`；确认成功后扣钱、刷右上角、写回 `MapRun` |

三行的 y 是**一起定的**（状态 −160 / 价格牌 −232 / 明细 −304）：
面板底部两个按钮的顶边在 −344，明细再往下挪 4px 就压到按钮上，而且零报错。

新建节点走的是**补丁路**（菜单 `魔法乱斗/P6 · 给主浮层补「价钱」两行`，`PatchCostArea`），
**不是**重跑 `RunAll` —— 理由是那条老规矩：重建会冲掉用户手调过的东西。
补丁**同时补 Prefab 与当前场景**（见 §6）。

金币的来源与商店同口径：`MapRun.HasActiveRun` 时用 `MapRun.Gold`（地图顶栏那一本账），
否则用本场景 Inspector 上的 `_gold`（默认 50）；确认后 `MapRun.SetGold` 写回。
**退出 Play 会回到 50** —— 金币目前不是存档字段。

## 5. 验证

- `Tools/RuleSelfTest` 新增 `WitchWorkshopScenario.CheckCost`（同一支脚本的第 ⑧ 层）：
  ① 手算样本（`80` / `40` / 四舍五入 `4.444→4`）与底价；② 缺牌 / 力量 0 / 零效果三条边界不崩且有原因；
  ③ 四个因素的**方向**（冷却↑贵 · 力量↑便宜 · 效果↑便宜 · 目标冷却↑便宜）；
  ④ 全表 1980 对逐对算一遍（顺便把价钱区间打进报告）；⑤ 钱刚好够 / 差 1 金 / 老重载不受影响；
  ⑥ 五句文案都写得出来、且**变化解释只在真的变了的时候给**。
  ⚠ 「换目标」那条断言**必须挑 CD4 的献祭牌**：CD3 的牌配任何真目标冷却差都被 `Max` 抬到 1，价钱压根不变（空跑）。

## 6. ⚠⚠ 本次再次撞上的那条老坑

**构建器「存 Prefab」≠ 场景里变 Prefab 实例。**
`WitchUiBuilder.RunAll` 是「在场景里建 → `SaveAsPrefabAsset`」，场景里留的是**它自己的一份拷贝**
（`PrefabInstanceStatus = NotAPrefab`）。所以新节点必须**两处都补** ——
`PatchCostArea` 里两段代码（Prefab 装 `LoadPrefabContents` / 场景里 `FindObjectsOfType<WitchView>`）
不是冗余，删了就是「进 Play 界面照旧、零报错」。
补丁顺带把老场景 `WitchSceneEntry._gold` 从「字段还不存在读出来是 0」补成 50
（已经是正数的不动 —— 那可能是人调的）。

## 7. 没做的事

- 价钱**不随存档**（金币本身还不是存档字段）。
- `MapRun.Gold` 是唯一账本，所以「女巫工坊花掉的钱」在地图顶栏能看到、但重启 Play 就没了。
- 浏览层格子里**没有逐张标价**（格子组件 `UpgradePickerCell` 与强化场景共用，动它风险高）；
  价钱只在两个空位都填好之后给一个准数。
