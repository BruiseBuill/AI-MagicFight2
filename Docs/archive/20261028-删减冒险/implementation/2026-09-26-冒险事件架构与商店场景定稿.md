# 2026-09-26 · 冒险事件架构与商店场景定稿

> **性质**：设计定稿记录（**只改文档**，零代码 / 零场景 / 零资产）
> **最后核对**：2026-09-26

## 背景

用户提出两点，需要先钉死架构再动手：

1. **地图、事件、战斗三者分离**；**战斗本身是一种特殊的事件**；**每种事件类型能单独出场景调试**。
2. 因此**第一批先做一个商店场景**，便于调试。

## 决定（用户口径）

### 架构

| # | 决定 |
|---|---|
| N1 | 三层分离，只通过 Core 的 `AdventureCommand` / `RunSnapshot` / `BattleRequest` / `BattleResult` 通信 |
| N2 | **战斗节点与其他节点同级**（都是 `NodeType` 的一种），但**不走事件页**，而是切到战斗层 |
| N3 | **每种事件类型有自己的场景**，可单独进 Play；第一批做 `Shop.unity` |

⚠ N3 **取代**实施规格 §12 与上位文档 §12 的"一个 `Adventure.unity` + 同一流程桥切容器"。

### 商店

| 参数 | 值 |
|---|---|
| 货位 | **4 个**：3 张原价 + 1 张特价 |
| 价格 | 原价 **20** 金 / 特价 **10** 金 |
| 商品来源 | **玩家尚未持有**的卡（`RewardPoolIds` − `OwnedCards`） |
| 备货 | 未持有池**无放回抽 4 张**，再由派生种子随机指定 1 张为特价 |
| 缺货 | 未持有 < 4 张 → 缺的位置显示 **"卖光了"**（不可点、不显示价格） |
| 服务 | **首版不做**删牌 / 强化（接口位保留） |
| 调试金币 | **50**（仅商店独立场景；冒险正式初始金币仍 30） |
| 离开 | 始终提供；`LeaveShop` = 完成节点；不能返回 |

## 独立场景契约（E1–E4）

| # | 契约 |
|---|---|
| E1 | 不依赖地图：一份入口参数（`DebugRunSeed`）即可自行构造上下文 |
| E2 | 不依赖前一节点：不读 `Route`、不假设 `Revision` |
| E3 | 不写真实存档：调试默认 `InMemoryRunSaveStore` |
| E4 | **Core 一行不改**：独立场景只换入口，不是写第二套商店（红线 3 的场景层表述） |
