# 全局设置键与卡池查看（M44）

> **性质**：现行实现记录 —— 每个场景的右上角「设置」键与右下角「卡池」键由同一套
> `GlobalOverlayLayer` 提供，与当前代码一致，可照此改。
> **最后核对**：2026-10-05

## 1. 要的是什么（用户 2026-10-05 原话）

1. **设置按键移到游戏的右上角（所有场景）**；
2. **设置里增加一个「退出」按键**，点击后退出到选存档界面；
3. **所有场景的右下角加一个「查看当前卡池」的按键**；
4. **战斗场景**里，卡池中**本局已经抽取过**的卡**变暗**。

开工前对齐的四个口径（用户逐项确认）：

| 问题 | 选定 |
|---|---|
| 设置面板里放什么 | **所有场景统一只放退出**（战斗原有的「重新开始 / 测试卡池」一并去掉） |
| 「已抽取」按哪个口径 | **本局抽到过手牌**的牌（不是存档的 `everOwnedIds`、也不是「已打出过」） |
| 卡池面板显示什么 | **当前那一份玩家卡池**（战斗中 = 本局实际用的那份，见 §5.2） |
| 开始场景 Home 要不要这两个键 | **都不加**（Home 本身就是选存档，放「退出到选存档」= 自己点自己） |

⚠ **设置层节点刻意不叫 `SettingsLayer`** —— 那是 M39 旧设置层的名字（`SettingsUiBuilder`
里 `Find("SettingsLayer")` 找的就是它）。重名会让「旧层删干净了没有」没法用名字表达，
将来想恢复 M39 的人一 `Find` 就会撞上这一棵。

## 4. 落地方式：两种场景两套落点（别照抄）

| 场景 | 场景里那份 Canvas | 构建器怎么补 |
|---|---|---|
| **战斗** `SampleScene` | `BattleCanvas.prefab` 的 **PrefabInstance**（场景文件里只有 `PrefabInstance` 块） | **只改 Prefab**，场景自动同步 |
| **地图 / 商店 / 石台 / 女巫** | **内联拷贝**（真正的子节点写在 `.unity` 里） | **Prefab 与场景两处都补**（`EditPrefab` + `EditScene`） |

- 商店场景**故意不建卡池键**：它的右下角本来就是背包键（打开的就是主角当前卡池），
  再叠一枚会正好压在同一格上。
- Home **完全不加**。
- 本层是**重建式**的（重跑会拆掉整棵 `GlobalOverlayLayer` 重建）。这是新加的层、还没有人
  手工调过；将来若有人在这一层上拖过节点，要改成 M40/M43 那种「只补缺失节点」的增量写法。

## 5. 三条容易踩的实现点

### 5.1 监听器一律运行时接

两枚常驻键与面板里的按钮**全部**在 `Awake` + `OnEnable` 里用可重入的 `Hook()`（先 Remove 再 Add）接。
构建器只写序列化字段。理由见铁律 8：编辑模式接的监听器不是序列化数据，存盘即蒸发。

### 5.2 卡池数据：战斗要「注入」，不能各读各的

`GlobalOverlayView.LoadCardPool` 有**两条**取数路径：

- `CardsProvider != null`（战斗注入）→ 直接用它；
- 否则 → `SaveStore.TryLoadCardIds(档位, Resources.Load<CardCatalogAsset>("CardCatalog"))`。

**为什么战斗非要注入不可**：战斗本局的牌堆是 `BattleDriver.BuildSetup` 里
`SaveStore.TryLoadCardPool(ActiveSaveSlot, …)` → `character.WithCardPool(pool)` 解析出来的
**那份角色定义**。当那个档**还不存在**时它会回退到角色自带的卡池（全 45 张），
于是「存档里的卡池」与本局牌堆不是同一份 —— 不注入的症状是
**玩家手里那几张牌在卡池面板里一张都找不到**（2026-10-05 实测：本局手牌
`a,v,aj,m,ag,d`，面板读存档读出 `p,l,ag,o,an,x,am,q,j+,ap`，交集只有 1 张）；
而且「读主存档」在文件缺失时**会当场新建一个**存档。
战斗侧注入的是 `GetLocalCharacterDefinition().CreateCardPool().Resolve()`
—— 与 `BuildSetup` 同源，两边永远一致（实测 45 张 vs 压暗 6 张 = 本局手牌 6 张）。

其余四个场景仍读存档（它们没有「本局」这个概念）：
`GameSession.HasChosen ? GameSession.Slot : 构建器填的 _slot`，与各场景自己读档的口径一致
—— 所以单独打开某个场景进 Play 调试，主菜单一个字节都影响不到它。

### 5.3 「本局已抽」的账记在 `BattleUi`

- `HashSet<string> _drawnCardBaseIds`：`RefreshAll` 里每拍把 `CollectHand(LocalSeat)` 的
  `CardId` 归一成基础 ID 加进去，**只增不减**（「曾经抽到过、后来打出 / 换走」的也算）；
- `HandleStarted` 里清空（新一局的牌不该是灰的）；
- 两边都过 `CardUpgrade.BaseIdOf` —— 手牌里可能是强化版（`c+`），卡池里也是，不归一就永远对不上。

⚠ 它**不参与任何规则结算**，纯粹是卡池面板的展示态。

## 6. 「退出到主菜单」做了什么

```csharp
HideAll();
MapRun.Clear();          // 放弃这一趟冒险
GameSession.Forget();    // 忘掉这次选档
SceneManager.LoadScene(MapRoutes.HomeScene);
```

顺序不能反：反过来的话 Home 的 `Awake` 会读到还没清掉的运行态。
与战斗失败界面上那枚「退出」（`BattleUi.HandleQuitBattle`）**同一套语义**
——「放弃这一趟，回开始界面重新选档」。

Home 没登记进 Build Settings 时 `LoadScene` 会抛，这里捕获并给一句人话（指向
`魔法乱斗/P0 · 构建 Home 场景`），不让「点退出什么都不发生」变成查不出来的问题。

## 7. 与 M39 旧设置层的关系

- **旧层已从全部 Canvas 上移除**：`GlobalOverlayBuilder.ApplyToRoot` 会找同名
  `SettingsLayer` 且挂着 `SettingsView` 的节点并删掉它（判据带组件，避免误删同名装饰节点）。
- **源码保留没删**：`SettingsView.cs` / `SettingsUiBuilder.cs` / `CardPoolEntryView.cs` /
  `M40SettingsBuilder.cs` / `M43SettingsRevealToggle.cs` 都还在，但**已没有任何节点引用它们**
  —— 想恢复那块「可编辑的测试卡池」界面时还有得可依。
  ⚠ 它们的菜单入口仍然存在（M39/M40/M43），现在跑会报错或无效（M39 的 `Find("SettingsLayer")`
  拿到的是新版设置层、没有 `SettingsView`，会抛「SettingsLayer 存在但没有 SettingsView」）。
- 战斗里**顶栏那颗齿轮仍然可用**（`HudView.GearClicked` 也接的是新面板）——
  等于右上一枚新键 + 顶栏一枚旧点击区，两个入口打开的是同一块面板。

## 8. 验收

| 项 | 结果 |
|---|---|
| Unity 编译 | **0 error / 0 warning** |
| 反射 | 5 个 Canvas（战斗 / 地图 / 商店 / 石台 / 女巫）各有 `GlobalOverlayLayer`；`GlobalOverlayView` 7 个字段 + `CardPoolView` 9 个字段**全非空**（商店 `_poolButton` 为 null 属预期）；`BattleUi._overlay` 非空 |
| 静态核对 | 5 个 prefab + 4 个场景：`m_Script: {fileID: 0}` **0**、旧 `SettingsLayer` 节点 **0**、`SettingsView` **0** |
| Play · 战斗 | 合成指针**真点**右上角设置键 → 面板开 + `BattleDriver.IsPaused = true`；点「继续游戏」→ 关 + 恢复；点右下角卡池键 → 开，**45 张 / 压暗 6 张 = 本局手牌 6 张**；点「关闭」→ 关；点「退出到主菜单」→ **真的切到 `Home`**，且 `MapRun.HasRun=False`、`GameSession.HasChosen=False` |
| Play · 地图 | 覆盖层在，右上角设置键 + 右下角卡池键都在（截图） |
| Play · 商店 | 覆盖层在；`_poolButton` 为 null（预期）；设置面板能开；商店原有的背包键 / 背包面板**未受影响** |
| 截图 | `Captures/art-review/m44_pool_battle.png`（卡池面板 + 压暗 + 底部的说明行）、`m44_settings_battle.png`（设置面板）、`m44_map_keys.png`（地图上的两枚键） |

⚠ **石台 / 女巫工坊两个场景只做了静态核对**（节点与字段），没有逐个进 Play 真点
—— 它们的落法与地图完全相同（同一套 `SceneTarget` 循环）。
⚠ **自动化点面板内部按钮要在节点激活之后「下一帧」点**：`SetActive(true)` 的同一次
`execute_code` 调用里，即使 `Canvas.ForceUpdateCanvases()` 也**射线不到**（`over == null`）。
本轮第一遍就踩了这条，分两次调用（先开、再点）即成功。真机不受影响（玩家点击必然在下一帧）。

## 9. 还没做 / 已知边界

- **旧设置层的源码留着没删**（见 §7），属于「无引用的死代码」；要清就走
  「只读审计 → 确认 → 再删」那套。
- **商店的背包面板没有合并进 `CardPoolView`**：两者版式同源但各有一份实现
  （商店那份要在买牌后就地刷新）。将来若要合并，注意商店的 `Show` 会被 `ShopSceneEntry` 反复调。
- **石台 / 女巫工坊未逐个进 Play 真点**（见 §8）。
- **卡池面板不能长按看详情**（与商店背包一致）。
- **卡池面板的显示顺序 = 卡表顺序**（`CardPool.Resolve()` 的固定顺序），没有按元素 / 力量排序。
