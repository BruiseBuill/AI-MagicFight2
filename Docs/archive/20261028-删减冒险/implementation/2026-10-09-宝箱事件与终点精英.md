## 2. 场景长什么样 / 怎么响

```
Treasure.unity
├─ TreasureCanvas (Prefab)
│  ├─ Bg_Treasure          Bg_Dungeon.png，cover 铺（1.25×，1920×1237.5）
│  ├─ Chest                 ← 全场**唯一**吃射线的东西（Button + Image 同一个节点）
│  ├─ GainRoot              「+50」+「金币」两行，**默认失活**
│  ├─ Title                  「宝箱」
│  ├─ Hint                   「点击宝箱，把它打开」
│  └─ LeaveButton            右下角「离开」（与商店 / 石台同一张底图、同一套边距 64 / 44）
└─ TreasureSceneEntry       挂在场景根（**不进 Prefab**）
```

一次交互只有两步：

1. **点箱子** → `TreasureView.SetOpened()` 把 sprite 换成开着的那张 + `ShowGain(50)`
   + 引导行改成「箱子里装着 50 枚金币，已经归你了」+ 关掉箱子自己的点击；
   `TreasureSceneEntry` 同时 `MapRun.SetGold(Gold + 50)`。
2. **点「离开」** → `MapRoutes.LeaveToMap()` 回地图，地图那边结算这个节点。

「只给一次钱」有**两道闸**：视图开过就把 Button 的 `interactable` 关掉，
入口自己还有一个 `_opened` 标记 —— 双击 / 脚本误调都不会重复记账（实跑验过）。

四成，而且**零报错**（症状只是「箱子莫名其妙很小」）。裁完之后，「宽度定、高度随图」才成立。

## 4. 终点精英（用户自己写卡组的那一只）

**它是第 7 只怪**（`MonsterBuilder.Specs` 最后一项），与那六只**刻意不同**：

| 项 | 六只测试怪 | `Monster_Boss` |
|---|---|---|
| 血量 | `TestHp = 1`（测试期口径） | **4**（= `BattleState.InitialHp`） |
| 血量同步 | `SyncHp = true` —— 每次跑构建器都拉回 `TestHp` | **`SyncHp = false`** —— 只在建资产那一刻写，之后归用户 |
| 卡组 | 各 8 张（配死的流派牌） | **`useAllCards = true`（全 45 张）= 占位，等用户填** |
| AI 档案 | `power` / `double` / `combo` / `slow` 之一 | 留空 = 通用 `HeuristicAgent` |
| 回合行为 | 自爆傀儡有两条 | 空数组 |

**⚠ 卡组为什么不能留成空**：怪物开局要一次抽满 8 张（`DealProfile.Monster`），
而 `CharacterDefinition` 构造器会按 `minimumCardCount = 8` 校验 ——
卡池不足 8 张**不是"少发几张"，是进战斗当场抛异常**。所以默认给「全卡表」当占位。

**怎么接上战斗**：`BattleDriver` 多一格 `_bossConfig`，判定走新属性 `IsBossBattle`
（= `MapRun` 里**正在进入的那个节点**是不是 `MapNodeType.Boss`）。
查找顺序变成四项：**终点专用怪 → 本场怪物 → 名单里那一份 → 兜底**。

- **单场景调试不受影响**：直接在编辑器里点开 `SampleScene` 进 Play 时 `MapRun` 是空的 →
  `IsBossBattle` 恒 false → 用的还是 `_monsterConfig`（独立场景契约 E1/E2）。
- **判据只有一处**：战斗侧不自己算「这是第几层 / 是不是最后一场」。

**用户要改的两处（都在资产上，不用碰代码 / Prefab）**：

| 想改什么 | 打开 |
|---|---|
| **卡组** | `Assets/Resources/Pools/MonsterPool_Boss.asset` → 取消 `useAllCards` → 填 `cardIds`（≥ 8 张，基础 ID） |
| 血量 / 名字 / 行为 / AI 档案 | `Assets/Resources/Monsters/Monster_Boss.asset` |

⚠ 重跑 `魔法乱斗/怪物 · 生成怪物资产 + 接进战斗（缺失才建）` **不会**动这两处
（`SyncHp = false`，卡池走「缺失才建」；`_bossConfig` 只在它是空的时候才接）。

## 6. 踩坑 / 决策记录

1. **新 `.cs` 文件不会被自动导入**（本轮最大的一次空转）：用 Python 直接往 `Assets/Scripts/`
   写文件之后，`refresh_unity {mode,scope,compile}` 返回 `refresh_triggered: false` ——
   Unity 侧**根本没扫这个目录**（`.meta` 都没生成），于是「编译 0 错误」而新类型
   `GetType(...) == null`。判据 = **看 `.meta` 在不在**；修法 = `refresh_unity {}`（空参数）。
   ⚠ 别把这种「0 错误」当成功 —— 它可能只是**那三个文件压根没进编译**。
2. **`Map/` 的编号已经排到 09**（08 / 09 是两张桥），所以宝箱图取 **10**。
3. **`TreasureGainCenterY` 首版 790 太挤**：开着的那只箱子顶边到 y≈667，下面那行「金币」
   落在 686 —— 与箱盖只差 19。截图看出来后挪到 **830**。
4. **换图必须同时换尺寸**：开箱那张比关箱那张高 24%（411×333 → 835×830）。
   `Image` 的矩形由 `TreasureView.ApplyChestSize` 按 **sprite 自身宽高比**现算，
   并且**关掉 `preserveAspect`** —— 开着它会让「命中区（按 RectTransform）」与
   「画面（按图）」各说各话。
5. **金币数额放在 `UiLayout` 是权宜**：它是内容 / 经济，不是版式。正式接入冒险经济时
   应搬进 Core 的冒险配置（与商店价格同族），到那时 `UiLayout.TreasureGoldGain` 删掉、
   由事件场景从配置读。**现在只有这一处**，所以还不会分叉。
6. **`MonsterSpec.SyncHp` 这个新字段是为了不冲掉用户的手改**：那六只测试怪的血量由
   `TestHp` 常量统一覆盖（用户要求「所有 AI 都 1 血」），但精英的血量是**内容** ——
   同一份构建器里必须能表达这两种口径。
7. **`ArtImportBuilder` 没动**：那四张图已经按它的口径手工归位了，重跑「整理 · 配置新美术导入」
   不会碰它们（也不会漏 —— `MoveOne` 对已在位的是幂等）。新增的美术导入参数由
   `TreasureUiBuilder.EnsureSpriteSettings` 钉住（Sprite / PPU 100 / 关 mipmap /
   AlphaIsTransparency / Clamp / Bilinear）。
