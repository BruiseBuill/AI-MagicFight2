# 卡牌获取池 + 战斗奖励动画 + 战斗失败界面（重试 / 退出）

> **性质**：现行实现记录 —— 与当前代码一致，可照此改
> **最后核对**：2026-10-05
> **范围**：`Core/Cards/CardAcquisition.cs`（新增）· `SaveStore` / `PlayerData`（存档 v3）·
> `BattleUi` · `ResultWinView`（补动画）· `ResultLoseView`（新增）· `BattleUiBuilder` ·
> `ShopSceneEntry` · `BattleDriver._saveSlot` 默认值

## 1. 用户这一轮要什么（原话口径）

1. **待获取卡池 = 所有卡的卡池**；游戏开始时玩家随机获得 8 张，这 8 张从待获取池变成「已获取」；
2. 任何**涉及卡牌获取的场景**（战斗奖励 / 商店货架），展示出来的牌里：
   - 玩家**获得过**的牌，出现概率 **0** —— **包括获得之后又把它消耗掉的情况**；
   - **曾经展示过但没获得**的牌，出现概率 **减半**（用户选定：**固定减半一次**，不累积）；
   - 其余（从没展示过的）概率相等；
3. **战斗胜利**：固定给 3 张候选卡 + 20 块钱，三张只能选一张，**要动画**；
4. **战斗失败**：要有「重试」与「退出」两个键；重试 = 回到本场战斗最刚开始的状态。

另外三条用户在本轮开工前拍板的选项：

| 问题 | 选定 |
|---|---|
| 减半是否累积 | **固定减半一次**（权重恒为 1/2） |
| 开局 8 张 vs 女巫工坊门槛（9） | **只改成 8 张，门槛不动**（开新档第一次进女巫工坊会提示「无法进行特殊强化」，这是预期） |
| 战斗读哪个存档 | **默认档 Test → Main**（战斗奖励 / 商店 / 女巫工坊共用同一份卡池与获取状态） |
| 失败界面「退出」 | **冒险里回地图（判失败）／单场景里停战** |

## 2. 规则落在哪一层

### 2.1 Core：`CardAcquisition`（纯函数，零 UnityEngine）

```
权重单位：从没展示过 = 2 · 曾展示过 = 1 · 已获得 = 0
```

- 用**整数**权重而不是 1.0 / 0.5：`Rng` 只提供整数均匀抽样（`Next(int)`），
  总权重是整数时一次 `rng.Next(总权重)` 就能按区间取卡 —— 比例精确、
  **不引入浮点**，「同种子 → 同一批牌」这条可复现性不依赖浮点误差。
- `Draw(catalog, acquired, offered, count, rng)`：**无放回**抽 `count` 张；
  可用卡不足时抽几张算几张（不补、不报错）。
- 比较一律走 **基础 ID**（`CardUpgrade.BaseIdOf`）：存档里写 `a`，目录里可能有 `a+`，
  不归一的话「已获得的 a」挡不住「a+」。
- 它**只做抽**，不碰存档 —— 谁被展示由 App 侧记账。

### 2.2 存档：`PlayerData` 的两个新字段（存档 v2 → v3）

| 字段 | 含义 |
|---|---|
| `everOwnedIds` | **曾经获得过的卡**（基础 ID，只增不减）。语义上是 `cardIds` 的超集 |
| `offeredIds` | **曾经展示过但没获得**的卡（基础 ID）。被获得时从这里移出 |

- **为什么不能只用 `cardIds`**：那张单子表达「现在持有」—— 女巫工坊献祭掉一张之后它会少一项，
  而规则要的是「**获得过**就永不再出」。所以必须单独记一笔。
- **v2 → v3 的迁移 = 什么都不用搬**：旧档缺这两个键 → `JsonUtility` 留空列表；
  `Normalize` 每次读写都把 `cardIds` 补进 `everOwnedIds`（持有蕴含获得过），
  于是老玩家手里的 10 张牌自动全部被排除。实测：主存档读回 `acquired = 10`。
- 新方法：
  - `TryLoadAcquisition(slot, out acquired, out offered, out error)` —— `acquired` = `cardIds ∪ everOwnedIds`；
  - `TryRecordOffered(slot, ids)` —— 展示那一刻记账（已获得的不会被记进这张单子）；
  - `TryGrantCard(slot, id)` —— **一次写完三件事**：进 `cardIds`、进 `everOwnedIds`、从 `offeredIds` 移出。
    分三次写会在中间失败时留下「牌拿到了、获得记录没落盘」的存档（与 `TryConsumeAndUpgrade` 同一条道理）。
- 起始牌 `MainStartingCardCount` **10 → 8**。

### 2.3 两个接入点

| 场景 | 抽牌 | 记账 |
|---|---|---|
| 战斗胜利奖励（`BattleUi.RollRewardChoices`） | `CardAcquisition.Draw(CardCatalog.Builtin(), …)`，种子取**本局种子** | `Show` 前先 `TryRecordOffered`（三张已摆到玩家眼前）；点「继续」时 `TryGrantCard` |
| 商店货架（`ShopSceneEntry.DrawShelfCards`） | 同上（4 个货位） | `BuildShelf` 末尾 `RecordOffered`；买入时 `PersistGranted` → `TryGrantCard` |

- 「**展示**」的时机 = 牌真的被摆到玩家眼前那一刻（奖励界面的三张 / 货架的四个位），
  **不是**进随机池那一刻 —— 玩家看了没拿才算「展示过而没获得」。
- 两处读的是**同一份**存档状态（2026-10-05 起战斗默认档也是 Main），所以
  「战斗奖励里被排除掉的牌，商店货架上也不会出现」。
- 商店的**调试口径**（Inspector 写了 `_ownedCardIds`，或主存档读不出来）**完全不碰存档**，
  退回「未持有的等概率洗牌」—— 独立场景调试契约 E1–E3。

## 3. 战斗胜利奖励的动画（`ResultWinView`）

三张候选**一张一张弹出来**：每张从 `UiLayout.ResultWinCardEnterScale`（0.72）放大到 1
（OutBack 回弹）并淡入，相邻两张错开 `ResultWinCardStagger`（0.10 s）；选中时那一张打一记
「落定」脉冲（1.08 → 1）；点「继续」时选中的那张再亮一下（→1.10）、其余缩小淡出，
走完 `ResultWinCloseSeconds`（0.24 s）才真的报 `ContinueClicked`（事件里才落盘 / 切场景）。

- 动画挂在**卡位（Slot）**上，不是卡面上：卡面内部那份缩放被 `SetFaceWidth` 占着 `CardRoot`，
  动卡面根节点的 `localScale` 迟早打架。
- **⚠⚠ `TweenScale` / `TweenCanvasAlpha` 只能运行时 `AddComponent`，不能由构建器挂**：
  这两个类与基类 `UiTween` 写在同一个文件 `UiTween.cs` 里，而「进 Prefab 的 MonoBehaviour
  必须一文件一类」—— 构建器挂上去存 Prefab 时 `m_Script` 会被写成 `{fileID: 0}`
  （本轮实测：3 个卡位 × 2 个补间 = **6 个空脚本组件**，而备份里这个计数是 0）。
  这与 M25 / M32 那两次事故是同一个坑。`ResultWinView.BindTweens()` 在 `Awake` 里
  「有就取、没有就补」，本项目 `PeekView` / `MonsterHandView` / `HandPickView` /
  `HudBuffView` / `MapView` 也都是这么办的。
- **⚠ 淡入要动卡位那枚 `CanvasGroup`，不要动卡面自己的那枚**（`CardView.SetAlpha`）。
  两者是两个不同的 CanvasGroup：卡面那枚一旦被置 0，卡位那支补间把它拉回 1 也救不回来 ——
  症状是「三个卡位摆得好好的、卡面全透明」，**零报错**（本轮实踩并已修）。

## 4. 战斗失败界面（`ResultLoseView` + `ResultLoseRoot`）

与胜利界面**同一套版式语言**（顶徽记 + 牌匾横幅，两者共用构建器的
`BuildCrest` / `BuildBanner` 两个 helper）：

```
ResultLoseRoot（铺满，默认 SetActive(false)）
├─ Bg      战斗背景 cover 铺满
├─ Veil    暗纱（同时也是整块的射线面）
├─ Crest   顶徽记（与胜利界面共用）
├─ Banner  「战斗失败」横幅（与胜利界面共用）
├─ Hint    「原因　·　回合数 N　·　种子 S」
└─ RetryButton（重试）· QuitButton（退出）
```

- **重试** = `_driver.StartBattle(_driver.LastSeed)`。**不用**无参的 `StartBattle()` ——
  那个会按 `_driver._randomSeed`（默认随机）抽新种子，那是「换一局打」而不是
  「回到本场最开始的状态」。同种子可复现的前提是外层状态没变（同卡池 + 同强化册 +
  同怪物配置）—— 失败不发奖励，所以这条前提成立。
- **退出** = 冒险里 `MapRun.ReportBattle(false)` + 回地图（该节点结算成**旅程结束**）／
  单场景里 `StopBattle()` 停战。
- **平局**在冒险里按失败算（规格 §4.3），所以它也走这一块，只把横幅文字换成「平局」。
- 旧的 `ResultRoot` **保留为兜底**：老 Prefab（没跑过 M8 重建）里 `_resultLose` 是 null
  → 跳过新界面、走老浮层，不会变成「输了之后什么都没有」。

## 5. 存档口径的一个连带改动

`BattleDriver._saveSlot` 默认值 **`SaveSlot.Test` → `SaveSlot.Main`**。
理由：获取状态是按存档记的，若战斗读 Test 而商店读 Main，就会变成两份账 ——
「战斗奖励里排除掉的牌，商店里照样刷出来」。
⚠ 副作用：单场景调试时战斗现在也用主存档的 8/10 张卡池（不再走 `BattlePool` 全 45 张那一档）；
想回到旧手感就把 Inspector 上那一格切回「战斗测试档」。

## 7. 还没做的 / 边界

- **冒险里失败不再是终局**：重试键让玩家能在战斗节点原地重打。
  这是用户 2026-10-05 明确要的；但它改变了「打输就结束」的旧语义，
  将来若要恢复「输一次就完」，删掉重试键即可（`ResultLoseView` 与 `BattleUi.HandleRetry` 各一处）。
- **开局 8 张 < 女巫工坊门槛 9**：开新档第一次进女巫工坊提示「无法进行特殊强化」（用户选定）。
- **`everOwnedIds` 只增不减**，没有「重置收藏」入口；重开一局要删 `save-main.json`。
- **奖励候选没有按难度 / 流派加权**：现在只有「已获得 = 0 / 曾展示 = 减半 / 其余等概率」这一套。
- 商店的 `_seed` 仍然让同一颗种子给同一批货（可复现截图）；获取状态是叠加在它之上的权重，
  所以「同种子 + 同获取状态」才完全可复现。
