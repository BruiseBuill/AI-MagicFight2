## 2. 核心认识：图集是「整层」不是「元素拼版」

`542f45c2` 不是干净的元素 kit，而是**参考图去掉背景与人物之后压平的一整层** ——
上面烘着「旅者 / 铁卫 / 72-80 / 125 / 冷却区N / 1-1」这些**动态文字**。

| 情况 | 例子 | 口径 |
|---|---|---|
| 烘焙文字**每行固定**、永远正确 | 冷却槽的 `4` + `冷却区4` | 直接切出来用，**不擦**（那一行永远就是这个值） |
| 烘焙文字是**动态值** | 顶栏三处数字、能量球 `1/1` | **擦掉 → TMP 重排** |
| 烘焙的是**动态内容** | `SlotR_CD1` 里画了一张敌方卡面 | 擦成空槽（扫出来的 —— 空槽上永远挂着一张红卡，是假的） |

### 擦文字：三个都真踩过的坑

1. **不能只擦「亮像素」。** 文字带深色描边，比面板还暗，亮阈值抓不到 → 回填后原地留字形黑影。
   做法：亮阈找字形 → 取包围盒外扩 4–5 px → **整块挖**。
2. **不能按「最近的非掩码像素」取样。** 血量数字紧贴红心、资源数字紧贴钱袋，
   最近邻会直接吃到图标色 → 回填后留一道红 / 黄横向拖影。
   做法：给每个擦除窗口指定一段**干净面板条**当取样源，逐行取同色（纵向渐变原样保留）。
3. **不能漏掉「数字背后的辉光」。** 血量数字背后烘了一层红色辉光，亮度只比面板高一点但**饱和度很高**，
   只按亮度判定会漏 → 擦完数字还留一道红色横条。
   做法：判定加一条「不像面板」（低饱和 + 面板亮度区间之外）。

另外：**条顶的高光边不能当取样源**。名字区第一版用「纵向插值（上下都是面板）」，
结果上边取到条顶高光，整块填成亮色补丁 —— 最后三个窗口统一改成只从右侧面板条横向取样。

### 能量球

宝石是渐变曲面，线性插值会留条纹，改用**扩散补洞**（迭代邻域均值，400 轮 + 24 轮平滑）。
顶栏是平色面板，用逐行横向插值更精准。**两种补洞按场景分配**，不是一刀切。

## 3. 动画表切分

### 为什么不能按等距网格切

这是 AI 生成的**动画参考表**，不是标准 sprite sheet：帧间距 224–314 px 不等、
帧宽 179–326 px 不等（姿势把腿 / 尾巴 / 光效撑开了）。所以分段要靠**列剖面**。

### 分段：靠「窄段并入」，不能靠「缝宽合并」

- 按 alpha>100（主角）或抠底前景（怪物）做列剖面，空缝切段。
- **光效会桥接窄缝**：怪物攻击行在 50–170 的亮度阈值下都分不开（能量波横跨半个表），
  退化成「用帧标签中心当参考、再在 ±60 px 内找剖面最低点」定切点。
- **碎片要并回主帧、相邻帧不能并**：防御行末尾有个 33 px 宽、被打破的护盾光点；
  而攻击行相邻帧的缝只有 7 / 16 px，防御行碎片与主帧的缝却有 25 px。
  → 按「缝宽 < N 就合并」必然两边错一个。正确判据是**按段宽**：宽 < 60 px 的当碎片并入前一段。

**切点要让光效留在它自己那一帧里**：怪物攻击 4 的能量波一直拖到 ~1450，
若取「相邻帧标签中心的中点 1269」会把波劈成两半，后一帧看起来像站了两只怪。
正确口径 = 切点落在光效尾端之后的空档（实测 296 / 584 / 960 / 1460）。

### 对齐：锚点取「身体」，不取包围盒

帧包围盒包含光效（攻击 3 的月牙、攻击 4 的能量波），按包围盒居中会让身体一帧一跳。
做法：

- **锚点 x = 竖直跨度最大的那一列**（身体比光效高，抢不走锚点）
- **锚点 y = 内容底边**（脚底）
- 把所有帧按锚点对齐到**同一张画布**上 → 同一动作的帧尺寸相同、锚点落在同一像素。

播放时把 RectTransform 的 pivot 切成该动作的锚点（`anim_frames.txt` 传过去），
`anchoredPosition` 保持不变 → **等价于脚底钉在原地**，换动作角色不跳。

> ⚠ **sprite 的 pivot 不参与绘制**（简单 `Image` 是按 RectTransform 铺图的），
> 所以锚点只能落在 RectTransform 的 pivot 上。这条差点搞反。

### 行标题：位置是「右上」，不是左上

主角表每行的标题（「待机动画」等）在**行带右上**（实测 x 424+ / y 43–70，后面还拖一条通栏分隔线），
正好压在**待机第 1 帧的头顶**上。第一版掩码按「左上角 x 20..200」设 → 完全没遮住，
于是标题被切进了 `Hero_idle_01.png`，直到进 Unity 截图才看见。

> **教训**：掩码范围必须按实测包围盒设，不能凭「一般排版习惯」猜。
> 怪物表同理但方向相反 —— 它的标题在左上、且在行带**上方**，所以不受影响。

## 4. Unity 侧

### 新增文件

| 文件 | 职责 |
|---|---|
| `Ui/BattleArtLibrary.cs` | **取图唯一入口**（ScriptableObject）。含 `Clip`（帧序列 + 画布尺寸 + 锚点 + fps）与 `CharacterSet` |
| `Ui/SpriteAnimator.cs` | 极简帧动画播放器：按 fps 换 sprite，顺带切 RectTransform 的 pivot |
| `Ui/CharacterView.cs` | 舞台角色：绑素材 / 待机循环 / 插播动作 / 头顶徽标 |
| `Ui/HudView.cs` | 顶栏 + 能量球：绑 `PlayerSnapshot` → 名字 / 生命 / 资源 / 手牌数 |
| `Editor/ArtImportBuilder.cs` | 归位 + 导入设置 + 重建 `Assets/Resources/BattleArtLibrary.asset` |
| `Editor/BattleArtLayerBuilder.cs` | 建 `ArtLayer` 节点树 + 接线 |

**没有生成 AnimationClip + Animator**：本工程界面全部由编辑器脚本程序化构建，
Clip 要额外维护 controller / 状态机 / 过渡，成本远高于收益；帧序列在切图时已经对齐好了。

### 节点结构（`BattleCanvas` 下新增唯一节点 `ArtLayer`）

```
BattleCanvas
├─ Backdrop             （M7，纯色）
├─ ArtLayer             ← 新增，紧跟 Backdrop 之后 = 在所有界面元素之下、背景之上
│  ├─ Bg_Dungeon        cover 铺满（等比放大到「宽高都不小于画布」，多的裁掉）
│  ├─ Char_Hero         CharacterView（Image + SpriteAnimator）
│  ├─ Badge             ← 头顶徽标**不挂在角色下**：角色 pivot 会随动作变，挂进去徽标会抖
│  ├─ Char_Monster / Badge
│  ├─ Orb_Energy        Image + TMP「n/m」
│  ├─ SlotL_Col / SlotR_Col
│  │  └─ SlotL_CD4..CD1  每行 = Image(槽图) + Cards(迷你卡挂载点)
│  ├─ Hud                Image(条) + Name + Subtitle + HpNumber + ResNumber + GearButton
│  └─ Buff_1..5         状态图标行
├─ TopArea              （M7/M8，其中两处旧节点被 SetActive(false)）
└─ HandArea             （M7，底板 + 手牌）
```

**为什么单独一个 ArtLayer 而不改 M7/M8**：M7 一旦重跑会推倒整棵 Canvas，M8 接线也跟着重来。
把新美术收敛进一个自有节点，老的两条构建链一行都不用改。

**旧节点处置**：`PlayerCoolingPanel` / `EnemyCoolingPanel` / `PlayerBar` / `EnemyBar` 职责已被新层接管，
构建时 `SetActive(false)`。**不删** —— `CooldownView` / `StageView` 仍有字段指向它们，留着停用比留悬空引用安全。

### 冷却区：按剩余冷却分 4 行

`CooldownView` 新增 `_playerRows` / `_enemyRows`（各 4 个 RectTransform，下标 0 = 冷却区4）。
填了就走「分组分行」；留空退回单一 Grid 的老行为（向后兼容）。

- 行号 = `4 − 剩余冷却`（剩余 4 → 第 0 行）
- 同一行多张卡**水平重叠**摆放（步进 22 px），因为槽位横向空间被「冷却区N」标签占掉了；
  超过 4 张不再摆（剩下的靠行的数字体现）
- 尺寸与位置**必须在 `CardView.Bind` 之后设**：老布局靠父级 GridLayoutGroup 兜，
  新布局没有布局组，得自己来

### 槽位映射（本作没有「金币」概念）

| 参考图 | 本作 | 理由 |
|---|---|---|
| ❤ `72/80` | `Hp/MaxHp`（如 `4/4`） | 规则固定 4 点生命，不套参考图的数值 |
| 💰 `125` | 冷却区里**未使用的光环指示物数** | 本作唯一「可消耗资源」概念 |
| 名字下小字 | 手牌数 | 对方手牌数本来就是公开信息 |
| 能量球 `1/1` | `手牌数 / 手牌上限` | 位置最贴手牌，读数语义一致 |
| ⚙ 齿轮 | 打开战斗日志面板 | M10 未做设置面板，LogPanel 早就建好、一直缺入口 |
| 状态图标 ×5 | 前 2 个常态 + 未用光环数点亮 | 本作还没有状态系统，槽位是真的、语义是占位 |

**卡牌一律用本作自己的** `Art/Cards/` 那 40 张 —— 参考图里那 5 张手牌样式不切、不用。

```
配置新美术导入  →  M7 · 构建 UiKit  →  M8 · 构建 BattleUi  →  M11 · 构建 BattleArtLayer
```

## 5. 事故与修复：源表被自己的脚本删掉

`ArtImportBuilder` 第一版的归档逻辑是「先删 `_Source/` 里的 Python 副本，再 `MoveAsset` 搬原件」。
删除的判定条件只看了「副本存在」——

> **重跑第二遍菜单时，`_Source/` 里躺着的已经是上一次搬进去的原件**，
> 于是被当成副本删掉。三张源表的 PNG + `.meta` 一起没了，`AssetDatabase.DeleteAsset` 也不进回收站。

修复：判定条件加上 `File.Exists(from)`（源还在原位才说明目标是副本），
第二次重跑就走 `MoveOne` 的「已在位」分支，幂等。

同时**把源图归档从 Python 脚本里摘掉**（Python 只产成品），从根上消掉「两边都在写同一个目录」这个组合。

> **教训**：「清理旧的 Python 产物」这类逻辑，判定条件必须写成
> 「**能证明它是产物**」而不是「**目标位置有文件**」。幂等脚本的重跑路径要专门想一遍。
