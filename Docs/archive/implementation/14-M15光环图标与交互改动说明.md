## 2. #1 冷却区迷你卡 ×1.5 —— 账要重算，别只改卡宽

迷你卡从 `60×83` 放到 `90×125`（90 / 0.7197 ≈ 125，卡面比例不变）。

**行距必须一起改**：旧 `SlotRowPitch = 103` **比新卡高 125 还小**，四行会互相压掉一截。
重算后的竖向预算（画布 1080，手牌区上沿 = 1080 − 344 = 736）：

```
槽顶 214 + 3 × 130（行距） = 第 4 行槽顶 604
迷你卡轴心在行的上边、竖直居中于行 → 卡上边 = 604 − 15、下边 = 604 + 110 = 714 ≤ 736 ✔（余 22）
相邻两行的卡片间隙 = 130 − 125 = 5 px ✔
```

迷你卡**内部**的版式（力量底块 / 冷却底块 / 卡名条 / 光环亮点 / 字号）也一起 ×1.5，
并新增 `SlotMiniPad` / `SlotMiniCooldownExtra` / `SlotMiniCooldownBaseHeight` / `SlotMiniPipRow*`
把原先散在 `UiKitBuilder` 里的魔法数字（2 / 16 / 14 / 44）收进 `UiLayout` ——
**迷你卡的版式是烘在 M7 的 Prefab 里的**，所以改这几个常量必须重跑 M7。

## 3. #2 点一下不再等于出牌

`BattleUi.OnHandCardClicked` 改成「**只处理发牌替换**（那本来就是点牌标记的多选交互），
其余一律不提交」。原写法直接 `TryPickByCard` → `Pick` → 把牌打出去，
和「拖进判定区松手才出牌」并存时，手一抖点歪就把牌丢了。

点的时候手牌仍会亮一下（`HandView.OnCardClicked` 自己置亮 `_selectedUid`），反馈够用。

**冷却区的牌仍然可以点** —— 那是「选一个目标」（加速 / 减速 / 移除 / 复制目标）的语义，
**但光环选项除外**：它的入口已经搬到 HudBuff 的图标上了。

## 4. #3 HudBuff 光环图标区

### 4.1 结构

```
BattleCanvas/ArtLayer
└─ HudBuff（铺满画布！）
   ├─ PlayerGroup（锚左上，45 / 119）   ← 玩家在左
   ├─ EnemyGroup （锚右上，镜像）        ← 敌人在右
   ├─ IconTemplate（失活模板：Frame / Plate / GlyphA / GlyphB / ValueBg / Value / Dim）
   └─ Tooltip（长按浮层：Name / Body / Hint）
```

图标 = **按类型上色的底版 + 符号（剑 / 盾 / 感叹号，取自 `TriggerIconLibrary`）+ 数值**：
红 = 进攻力量、蓝 = 防御力量、紫 = 攻防二选一（并排画剑与盾）、青 = 连击、金 = 免疫（≥N / ≤N 分高低位）。

### 4.2 三条关键口径

1. **一枚指示物一个图标**（用户原话「相同的 buff 不堆叠」）——
   数据源是 `CardSnapshot.AuraTokensDetail`（新增）：剩余几枚就摆几个图标，
   双光环的卡（冰封铠甲 / 火灾）如实显示两个。
2. **「能不能用」由引擎说了算**：引擎本拍的 `Options` 里凡是 `AuraSource != null` 的，
   按 `(来源牌 Uid, 指示物序号)` 记进 `BattleUi._auraOptions`；
   图标只有命中这张表才点亮（金色外框、可拖），否则压暗。
   `AuraTokenIndex` 是这一批给 `Option` 新增的字段 —— 双光环两枚同型，
   只靠「哪张牌 + 哪种光环」分不出玩家拖的是哪一枚。
3. **拖到「自己的手牌区」= 使用**：落区 = 整块 `HandArea`（全宽 × 344），
   拖进去亮一片很淡的提示底（`Canvas/HandArea/AuraDropHint`，M8 建的），松手命中引擎选项才生效；
   用不了的光环拖过去什么都不发生，图标自己弹回原位。

### 4.3 长按浮层

三行：`来源卡名 · 光环` / 卡表里的效果原文（`EffectDef.Text`，取不到就退回
`AuraResolver.DescribeEffect`）/ 怎么用（能用时金色「把图标拖到自己的手牌区即可使用」）。

浮层挂在图标**下沿**往下长（图标行贴着画布顶，没地方往上摆），
贴左右边时会把浮层拽回画面内。图标被用掉之后浮层跟着收（`_tipKey` 比对）。

## 5. #4 免疫光环：消耗即免伤，不再出牌

**规则改动**（用户口径，`Docs/rules/01-规则基线.md` §6.5）：

- 消耗免疫光环 = **整个攻击（含整个双发）被免疫，并且不需要再打出一张防御牌**；
- 引擎在 `DoChooseDefenseAura` 里**就地判定防御成功**、发出 `DefenseResolvedEvent{UsedImmune, Cards 为空}`，
  然后直接跳到第 ③ 步 —— `AwaitDefense` 这一拍整个跳过，省下的牌留在手上；
- 旧推论 **P1「免疫后仍须交一张防御牌」作废**；`DefenseResolver` 里的 `immuneApplied` 分支随之删除；
- 免疫光环不再要求「防御方手上还有牌」（`FinishStage1` 去掉了 `defender.Hand.Count > 0`）。

### 为什么必须专门写一条自测

`SimpleAiAgent.UseAuras` **默认 false** —— 万局随机对局里 AI 从来不用光环，
所以「免疫光环消耗后会发生什么」这条路径在「跑一万局」的统计里**一次都不会被走到**，
全绿也证明不了它是对的。`Tools/RuleSelfTest/AuraScenario.cs` 用脚本化双方把局面逼出来：

- 攻击方第一次叫牌时，往防御方冷却区塞一枚「免疫力量 ≤3」的指示物，并挑一张力量最小的牌打出去；
- 防御方那一拍**必须选「消耗免疫光环」**；
- 断言四条：必须发出 `UsedImmune` 的成功结算且**零张防御牌** / 此后不得再向防御方索要防御牌 /
  防御方不因这次攻击掉血 / 防御方手牌张数前后不变。

跑法：`cd Tools/RuleSelfTest && dotnet run --no-build -- 3000 20260916`
（这条断言固定扫 seed 1..800，取到 3 次命中即通过）。

## 7. 踩坑

1. **拖到手上时图标被手牌盖住**。图标原本挂在 `HudBuff` 名下自由移动，而 `ArtLayer`
   在 Canvas 里的兄弟序很靠前（紧跟 Backdrop），M7/M8 的界面全在它上面 ——
   一拖到手牌区就「消失」了。改法：拖拽期间挂到**画布根**并 `SetAsLastSibling()`，
   松手由 `Layout()` 挂回组内。画布根与 HudBuff 的局部坐标一致（都铺满、轴心居中），坐标换算不受影响。
2. **`Image.type = Sliced` 需要 Sprite 自带 border**；`Sprite.Create` 现搓的九宫格图
   **不是 Asset**，存进 Prefab / 场景会被丢掉 → 落区提示底改用 `ThirdParty/PolySprite/RoundedRectangle.png`
   （工程里的真资源）。同类隐患：`DropArrowView` 的箭头三角也是运行时生成的，重载之后会丢。
3. **`AssetDatabase.DeleteAsset` 与 `System.IO.File.Delete` 都会被 MCP 的安全检查拦下**；
   清理由菜单截图产生的文件改成「先用 shell 移出 Assets 再删空目录」。
4. **`include_image: true` 的同步截图才是实时的**：`screenshot_file_name` 那条异步路径
   在 Unity 窗口失去焦点后会一直返回**旧帧**（表现为「改了但截图不变」，极容易误判成代码没生效）。
5. 自测里的驱动器必须 `engine.Start()` 再 `Advance()` —— 少了 `Start()` 会一路推到
   `Phase=Finished` 然后触发死循环保护，报「引擎推进次数超限」。

## 9. M15-b：冷却区再放大一轮（面积 +40%）

用户 2026-09-18 追加要求：「冷却区当中的卡片的大小继续加大 40%（注意冷却区的高度间距）」。

### 9.1 为什么不是线性 +40%

线性 +40% 是 `126×175`。**竖向放不下**，这不是保守估计、是硬约束：

```
4 行卡片需要的竖向跨度 = 3×行距 + 卡高 ≥ 3×175 + 175 = 700 px
冷却列可用的竖向带     = 736（手牌区上沿）− 115（顶栏下沿 109 + 6）= 621 px
```

就算把光环图标行整个搬走、把可用带顶到 115，上限也只到 **h ≈ 155（线性 +24%）**。
→ 与用户确认后改用**面积 +40%**：`f = √1.4 ≈ 1.183`，**90×125 → 106×149**
（11250 → 15794 = **+40.4%**）。行距 130 → **157**，槽顶 214 → **142**。

### 9.2 这一轮的竖向账（卡高 149 / 行距 157）

```
迷你卡轴心在行的上边、竖直居中于行 →
  卡上边 = 槽顶 − (149 − 95)/2 = 槽顶 − 27
  卡下边 = 槽顶 + (149 + 95)/2 = 槽顶 + 122
第 1 行槽顶 142 → 卡 115 … 264
第 4 行槽顶 142 + 3×157 = 613 → 卡 586 … 735 ≤ 736 ✔（余 1 px）
相邻两行卡片间隙 = 157 − 149 = 8 px ✔
```

⚠ **行距必须 ≥ 卡高**：这一轮如果把行距留在 130，上下两行的卡会叠掉 19 px，
而压掉的正好是「卡名条」或「力量/冷却底块」—— 不是「只压几像素」能糊过去的。

### 9.3 代价：光环图标块必须让位（这一段是这一轮真正的取舍）

冷却列从 199…714 抬到 115…735 之后，原来贴在左右上角的**光环图标行被吃掉了位置**：

```
左侧那一带现在长这样：
  冷却卡最右 558 ｜ 中央面板族 750…1170（Picker / Deal / Detail 都是 420 宽居中）
  玩家块只有 566…718 这一条 152 px 的竖带
敌方镜像：冷却卡最左 1328 ｜ 面板右沿 1170 → 敌块 1170…1322（152 px）
```

于是 `HudBuff` 的布局从「贴边的一横排（8 枚/排）」改成
**「各自贴在冷却列内侧的一小块（2 枚/排，向下换行）」**：

* `HudBuffPlayerX = 566`（块左沿）、`HudBuffEnemyX = 598`（块右沿到屏幕右边的距离 = 1920 − 1322）
* `BuffIconPerRow = 2`；行距 80 → 8 枚也只要 4 行 = 119…439，不侵入冷却卡，也不侵入中央面板
* 图标尺寸仍是 72（**没有为了塞进去而缩小**），玩家在左、敌人在右的口径不变

> 换句话说：**「冷却卡变大」和「光环图标单占一条横带」这两件事在 1080 高里是互斥的**。
> 如果哪天希望光环图标回到贴边的横排，就得把冷却卡退回 h≈133（面积只 +13.5%）。
