## 2. #1 回手 —— 这是一个「事件全对、数据全错」的内核缺陷

**症状**：trace 里照打「seatX 某某 冷却完毕回手」，冷却区也确实少一张，但那张牌**从此失联**
——既不在 `Hand` 也不在 `CoolingZone`。该方总牌数永久少一张，越打越空，
最后靠「手上无牌」白掉血输掉。

**根因**：`CardInstance.ToHand()` 只把 `Zone` 字段改成 `Hand`；`PlayerState.Hand` 这个**列表**
只有引擎在发牌时用 `Hand.Add` 维护。`ReturnToHand` 把牌移出 `CoolingZone` 之后
**忘了挂回 `Hand`**。这与当年 `PutIntoCooldown` 漏挂 `CoolingZone` 是同一类 bug：
**改了牌自己的字段、没改归属列表**。事件数量、冷却数值全对，万局统计查不出来。

**修复**（`CooldownOps.cs`）：

```csharp
card.ToHand();
if (!owner.Hand.Contains(card))
{
    owner.Hand.Add(card);   // ⚠ 不做手牌上限判定：总牌数 = 8 = 上限，
}                           // 「手上 8 张」时冷却区必为空，物理上不可能溢出
```

**防复发**（`Tools/RuleSelfTest/RuleAssertions.cs` 的 `EventWatcher`）：

* `CardReturnedEvent` 发出时，那张牌**必须已在** `Hand` 里、且不在 `CoolingZone`；
* 每个半场开始（没有牌处于攻防中）断言**手牌守恒**：
  `手牌 + 冷却区 + 已移出 = 6 + (回合≥2) + (回合≥3)`。

**回归**：10,000 局 0 异常 / 0 违规全部通过；平均回合数 4.59（修复前牌会流失、局偏短）；
Unity EditMode 8/8。

## 3. #2 弧形 —— 从「抛物线近似」改成真圆

旧写法：`y = baseY − 固定下沉量 × k²`，**下沉量与横跨宽度是两个独立常数**，
随便改一个就能调出「弧很平、牌转很凶」这种不成形的形状（截图里就是一条歪斜的直线）。

新几何（`HandView.Update`）：

* 所有牌的**底边中点**落在**同一个圆**上，圆心在画面正下方；
* 每张牌的旋转角 = 它在圆上的**圆心角**（牌的「上」方向沿半径朝外）→ 牌与弧线处处相切；
* 圆半径不直接给，由「横向半跨距 S = pitch·tMax」与「半张角 A」反解：`R = S / sin(A)`；
  下沉量 `R(1−cosA)` 是**被动量**，物理上不可能与横跨/摆角不匹配。
* 整排抬到「最外侧那张的最低角 = 手牌底边距 22」：
  `baseY = R(1−cosA) + (卡宽/2)·sinA`（后者是转角额外压低量）。

**竖向预算**（8 张满手 · 总角 22° · 卡 196×272）：
`A = 11° → R ≈ 3573 → 下沉 ≈ 65.5 → baseY ≈ 84 → 中间牌顶边 ≈ 378 ≤ 地平线 402` ✔
（手牌区没有 Mask，顶边略高于手牌区上沿 344 是**有意**的 —— 参考图里扇面就是压到场地上）。

调参口诀：**想改弧深浅 → `HandFanTotalAngle`；想改横向排布 → 卡宽/间隙/`HandFanSideMargin`**；
`HandFanSag` 已删除（不要再加回来）。

## 4. #3 判定区 + 指向箭头

**为什么废掉「拖到角色身上」**：角色节点的 `sizeDelta` 每帧随动作帧变，
判定框只能外扩（`DropTargetInflate` 已删），手感是「时灵时不灵」。

**结构**（M8 构建器新建，挂在 Canvas 根最后 → 绘制顺序压过所有元素）：

```
BattleCanvas
├─ PlayZone        不可视判定区：纯 RectTransform，无 Graphic（不绘制、不挡射线）
│                  尺寸 1200×270，下沿距底边 430（版式账见 UiLayout §M13）
└─ DropArrow       铺满画布（负责屏幕坐标 ↔ 画布局部坐标换算）
   └─ Arrow        pivot 在杆尾；运行时设 anchoredPosition + 旋转角
      ├─ Shaft     无 Sprite 的 Image = 纯白矩形，sizeDelta 即长短粗细
      └─ Head      运行时生成的 32×32 三角 Sprite（半像素羽化）
```

**口径**：

* 拖进判定区（判**牌的落点**）→ 出箭头 + 点亮目标角色；出区即收；松手即提交对应决策。
* 方向由**当前这一拍问的是哪件事**决定，不由鼠标落在谁身上：
  `BattleUi.HandleDecision` 把 `ChooseAttackCard → 敌 / ChooseDefense → 己` 翻成座位号调
  `HandView.SetDropIntent`；其余决策（替换 / 光环 / 选目标）传 −1 → **牌拖不起来**。
* 依然不做规则判断（铁律 3）：落点座位 → `OnHandCardDropped` → 到 `Options` 里找那张牌，
  找不到（比如拿力量 2 去挡力量 8）就什么都不发生，牌弹回。

> **⚠ M15（2026-09-18）起：点一下不再等于出牌**。用户口径「单次点击无法直接出牌进攻 / 防御，必须拖动」，
> 于是 `BattleUi.OnHandCardClicked` 只再处理**发牌替换**（那本来就是点牌标记的多选交互），
> 其余一律不提交 —— 否则「点一下就能出牌」和「拖进判定区才能出牌」并存时，手一抖点歪就把牌丢了。
> 详见 `Docs/archive/implementation/14-M15光环图标与交互改动说明.md` §3。

**两个实测踩坑**：

1. **判定必须用「逻辑落点」，不能用牌的实时视觉中心** —— 排布是每帧平滑趋近的，
   快速一甩时视觉中心要晚几帧才到，会出现「甩进区里松手却没反应」。
   落点 = `_dragLocal + (0, 卡高×DragScale/2)`（pivot 在底边中点），与指针零滞后。
2. **`DropArrowView` 不能在 `Awake` 里 `Hide()`** —— 根节点在构建器里就是失活的，
   首次 `Show` 调 `SetActive(true)` 那一刻才触发 Awake，Awake 里的 Hide 会把箭头
   **在亮起的同一帧按灭**（实测：第一下拖进判定区箭头不出现，第二下才出现）。

## 5. #4 对手头顶出牌展示

> **已由 M20 改写（2026-09-20）**：版式改成按张数自适应（单张居中、衬底收缩），
> 时长语义改成「进攻常驻到玩家防御结算 / 防御定时 2 s 并闸住节拍」，并且修掉了
> 「Awake 里 Hide 导致本局第一次 Show 不显示」这个缺陷。
> **当前口径以 [M20 实现说明](../../implementation/19-M20出牌展示与手牌数与AI目标.md) 为准**，本节保留当时的设计与账。

* 新视图 `Ui/PlayedCardView`：深色衬底 + 暗金描边 + **两个卡位**（双发防御要交两张），
  显示 2.6 s 后 0.35 s 淡出；卡面整图走 `CardArtLibrary`。
* 节点 `PlayedCard_Monster` 由 **M11 构建器**建在 ArtLayer 上（与血条徽标同层），
  **固定锚点**不挂角色节点下（角色 pivot 随动作帧变，挂进去会抖 —— M11 已知坑）。
  锚点 = `(CharMonsterX, CharGroundY + CharBadgeGroundOffset + 108)`，
  卡体 822~982，与徽标（773~815）留 7 px、离画布顶 1080 留 98 px。
* 触发点（`BattleUi.PlayCharacterBeats`）：AI 座位的 `AttackDeclaredEvent`（进攻打出的那张）、
  `DefenseResolvedEvent` 且防御成功（交出的那批）。**只展示 AI 座位** —— 玩家自己刚点出去的牌
  他当然知道，重复亮一遍只会把舞台弄乱。
* ⚠ 实测踩坑：锚点必须用**左下**（`CharMonsterX` 是画布绝对坐标），
  锚到 `(0.5,0)` 会在画布中心之上再加一次 1290 → 牌跑到 x=2187，屏幕外。
