## M39 · 角色与卡池确认（2026-09-25）

- AI 与人类共用角色状态，通过控制器区分操作来源。“AI 出牌不显示”经用户澄清是笔误，原演出保留。
- 每名角色独立有限牌堆，替代第二轮 D1 的双方共享 40 张牌堆；每种卡一张，双方可有同名牌。
- 配置增加最少卡牌数，人类玩家默认 8，低于门槛不能保存。
- 卡池保存成功后立即重开并重新发牌。
- 已损失生命改用各角色本局初始生命减当前生命，下限 0，替代第二轮 C2 固定 4 的基准。
- 四人只要求扩展接口，具体模式与界面留待后续。

## 冒险模式定稿（2026-09-25）

规划与工程落法：[冒险模式规划](../design/冒险模式规划.md) · [冒险模式实施规格](../design/冒险模式实施规格.md) · [问答归档](../design/冒险模式规划-待确认问题.md)。

### 规则层（已进本文与 `01-规则基线.md`）

| # | 议题 | 决定 |
|---|---|---|
| 1 | 回合上限 | **每场最多 40 个完整回合**（1 回合 = 双方各进攻一次，连击的追加进攻不计）。到限未分胜负 → **判 seat 0（人类玩家）失败**，原因「回合上限」。字段可配但必须存在。⚠ 引擎**尚未落地**（P0 / P1），落地后重跑万局回归 |
| 2 | 「双方同时出局」 | 用户确认**不可能发生**；但 `DuelMode.TryFinish` 里确有该分支（`BattleSetup.cs:67`），保留为防御分支，映射时按玩家失败处理并告警，不得删成 NRE |
| 3 | 战斗内「放弃」 | **没有**该选项（Q18）。战斗只有胜 / 败；败 = 直接结束整局 |
| 4 | 生命上限的两层 | 「战斗内上限」与「局外正常上限」分开：战斗一结束，上限**立刻回到局外水平**，**当前生命不恢复**（Q15 / Q13） |
| 5 | 提高冒险生命上限 | 当前生命**同步增加同样的量**（Q21）。降低时 `Hp = min(Hp, RunMaxHp)` |

### 范围层（只进设计文档，不改本文）

| # | 议题 | 决定 |
|---|---|---|
| 6 | 平台与输入 | **PC + 鼠标**；移动端不进首版验收 |
| 7 | 单章节奏 | **短局 8 层**（含 Boss），15–25 分钟 |
| 8 | 冒险内「重开本场」 | **保留**，但 **不记录尝试次数**；**不做战斗统计** |
| 9 | 首版事件 | **只有商店类 / 强化卡牌 / 回血**；**「离开」也算完成节点**；事件随机抽取 |
| 10 | 卡池变大 | **不考虑"稀释"** —— 每张卡强度近乎等价，变大只增加组合可能 |
| 11 | 精英奖励 | **没有专属奖励池** |
| 12 | 敌人配置 | 卡池 / 生命需精细配置，首版先简单配；AI 用最简单策略 |
| 13 | 结局存档 | 通关 / 失败 / 放弃后保留**只读战绩**，`继续` 不再显示该槽位 |
| 14 | 待确认（不阻塞） | Q25 事件战斗是否仍属首版 · Q26 是否给「放弃冒险」入口 · Q27 结算页展示什么 |

## 第五轮 · 头顶出牌展示双方化与离场时机（2026-09-23，用户四点要求）

| # | 议题 | 决定 | 理由 |
|---|---|---|---|
| V1 | 玩家自己打出的牌是否上头顶 | **上** —— 与怪物同一套规则（新增 `ArtLayer/PlayedCard_Hero`） | ⚠ **推翻第四轮 U5 的旧口径**。理由：经过光环加值 / 双发之后，头顶那张牌的数值与手牌上看到的并不一样，玩家恰恰需要在这一刻确认「我实际打出去的是哪张、多大」 |
| V2 | 防御牌的展示时机 | 先挂在**防御方自己**的头顶（与进攻牌对称） | 攻守双方都要看得见「交了什么牌挡」 |
| V3 | 防御牌何时进冷却区 | 与**对方的进攻牌同刻** —— 一方的进攻牌进冷却区，就是另一方的防御牌进冷却区的时机 | 引擎第 ④ 步（`BattleEngine.DoStage4`）本来就把「本次进攻牌 + 本次防御牌」放进同一个缓冲、一起 `FlushCooldown`。所以 UI 只要照快照走就天然同时，**不需要为它加任何协调逻辑**（`Core/` 零改动） |
| V4 | 头顶牌的消失方式 | **不再有固定停留时长**；唯一判据 = 该牌出现在冷却区快照里 —— 那一刻它从头顶**飞向**那个冷却槽 | 旧口径两个都是写死的时长（进攻「常驻到防御结算」、防御「停 2 s」），与引擎推进脱钩。`UiLayout.PlayedCardDefenseHold` 因此**作废**（保留定义只为不让旧文档引用变悬空）。飞行动画复用 `CardTransitView`，新增「头顶起点」通道 |
| V5 | 卡面力量 / 冷却数字的字体 | **千图马克手写体** | 用户先在 prefab 上手改好，随后把口径**固化进构建器**（`UiKitBuilder.CardNumberFontPath`），避免「哪天重跑 M7 把手工改的冲掉」；冷却区迷你卡同步成同一字体 |
| V6 | 同侧连击（一回合连打两张） | 后打的**整体覆盖**头顶面板，先打的那张退化为「直接出现在冷却槽」（不走飞行动画） | 面板只有两个卡位、且「覆盖」语义与 M20 的单张/双张版式一致；这是可接受的退化，已在代码注释里写明 |

## 第四轮 · 手牌交互改版（2026-09-17 下午，用户四点要求）

| # | 议题 | 决定 | 理由 |
|---|---|---|---|
| U1 | 冷却完毕回手 | **必须挂回 `PlayerState.Hand` 列表**；不做手牌上限判定 | 原实现只改 `Zone` 字段，牌彻底失联（事件与日志却全对）。总牌数 = 8 = 上限，「手上 8 张」时冷却区必为空，物理上不可能溢出，所以加分支反而危险。并补两条断言：`CardReturnedEvent` 时牌必须在 `Hand`；半场开始手牌守恒 |
| U2 | 手牌弧形 | **真圆弧**：底边中点共圆、旋转 = 圆心角、半径由半跨距与半张角反解（R = S/sinA） | 旧「横排 + 独立下沉量」两个常数各自为政，能调出不成形的弧；真圆下弧深浅是被动量。`HandFanSag` 删除 |
| U3 | 出牌判定 | **不可视判定区**（1200×270，屏中央）：拖进区出箭头、松手即出；废掉「拖到角色身上」 | 角色 sizeDelta 每帧随动作变，外扩判定时灵时不灵。方向由当前决策类型定（ChooseAttackCard→敌 / ChooseDefense→己），UI 仍不做规则判断 |
| U4 | 箭头颜色 | 进攻 = 红 `FF4D4D`、防御 = 蓝（玩家主色 `4FC3F7`） | 用户口径「红色指向敌人 / 蓝色指向自己」；橙（敌方主色）在地牢火光背景里读不出来 |
| U5 | 对手出牌展示 | AI 座位的进攻牌 + 防御交牌在**头顶**展示 2.6s 后淡出；玩家自己的牌不展示 | 对方手牌不可见，靠顶部提示条一行字认不出卡面；玩家自己刚出的牌自己知道，重复亮只会乱。位置 = 血条徽标正上方（固定位，不挂角色节点下） |
| U6 | 判定用逻辑落点 | 判「指针换算出的牌底边 + 半卡高」，**不判牌的实时视觉中心** | 排布每帧平滑趋近，快速甩牌时视觉中心晚几帧到，会出现「甩进区里松手没反应」 |

## 第一轮 · 规则澄清（2026-09-16 09:59）

| # | 议题 | 决定 |
|---|---|---|
| 1 | 防御方能否打出力量不足的牌 | **不能**。挡不住就是掉 1 点血，不存在"硬出一张小牌陪跑" |
| 2 | 冷却 −1 的归属与时机 | 发生在**进攻开始时**，只减**进攻方自己**的冷却区 |
| 3 | 双发被防不住扣血点数 | **只扣 1 点** |
| 4 | 生命上限削减的结算 | 按常规：先回血 → 再削上限 → `Hp = min(Hp, MaxHp)` |
| 5 | 平局判定 | 本阶段**不做** |
| 6 | 光环的本质 | **一次性辅助技能**；进攻光环只能进攻时用、防御光环只能防御时用、免疫光环只能防御时用 |
| 7 | 两条相同光环 | **双光环** = 两个独立指示物，可一次用两个或分两次用 |
| 8 | 光环生效时机 | 牌**进入冷却区之后**才生效 → 免疫光环只对之后的防御生效 |
| 9 | 卡面数字 | 第 1 个 = 力量，第 2 个 = 冷却 |
| 10 | 主动放弃防御 | **允许** |
| 11 | 光环的加成范围与时效 | 仅作用于**本次正在打出的那张牌**，**单次有效**，不永久改造牌面；使用必然在出牌之前 |
| 12 | AI 强度 | 先做最简版：有牌就打、能防就防 |
| 13 | 美术与字体 | 稍后导入，先用程序化占位 |
| 14 | 文档末尾的统计数字 | 用户当时称"仅供编辑参考，不需要在意"（**后经核对：第 1 组实为力量分布，且与本表完全吻合**，见 `Docs/rules/02-卡牌图鉴.md`） |

## 第二轮 · 完备性审查结案（2026-09-16 10:30）

### 必答项

| # | 议题 | 我方默认 | **最终决定** |
|---|---|---|---|
| A1 | 双发 × 防御方只有 1 张够挡的牌，能否部分防御 | 不能 | ✅ **不能部分防御**。要么交两张都够的牌，要么一张都不交、掉 1 点血（双发的核心就是"必须交两张"） |
| A2 | 进攻方有牌时能否主动放弃进攻 | 不能 | ✅ **不允许**（有牌却放弃进攻是无意义的行为） |

### 第四轮 · M9 实现期发现的问题（2026-09-16）

| # | 议题 | 最终决定 | 理由 |
|---|---|---|---|
| D7 | 补牌替换的**候选范围** | `IssueReplace` 只把**本座自己刚补到的那张**作为候选；候选为空就跳过该座位的替换趟 | D2 说的是「替换**刚补的那张**」。原实现把双方补到的牌混在一个池子里整个交给当前座位，对手的牌也成了候选 —— `DoReplace` 会因归属不符静默跳过，AI 因此白费一次替换。符合铁律第 3 条：非法选项在生成 `Options` 时就过滤 |
| D8 | 替换的**多选提交时机** | 点手牌 = 标记 / 取消标记；**只有点「确认替换」才回填**，一次把标记的序号全部提交 | 引擎的 `ChooseReplace` 是 `MinSelect=0 / MaxSelect=3` 的多选决策。M8 里点一张就立刻回填一个序号，加上 `DoReplace` 之后 `_replaceSeat++`，实际只能换 1 张，与「至多 3 张」不符 |
| D9 | 发牌台按钮的**文案来源** | 「不替换 / 保留这张」直接用引擎 Done 选项的 `Label`，UI 不写死 | 同一颗按钮在开局（「不替换，开始对局」）与补牌后（「保留这张，继续」）语义不同；文案跟着引擎走，将来增删场景不用改界面 |
| D10 | `CardView._button` 未接线的修法 | 在 `UiKitBuilder` 里加 `WireButton(view)`，两个卡片 Prefab 建完后各调一次 | 这是**实现缺陷**不是规则问题：Button 挂在节点上但 `CardView` 拿不到引用，于是点击监听从未建立、`SetInteractable` 也成了空操作。见 `Docs/archive/implementation/10-DealUi实现说明.md` §6.1 |

如果其中任何一条与你的设计意图不符，直接指出来，我会同步改规则基线与实现。

## 一个可复用的通用原则

原始 FAQ 中藏在"4 人游戏"小节里的这条，实际是**全局通用**的：

> 所有没有明确写对象的效果都可以指定其他目标。
> 例如"对方"指的是攻击目标，"你"指的是使用者；明确写了目标的情况下，则无法更改目标。

本次用它消解了"使一张法术立即冷却完成"（未写对象）这类卡的歧义。今后遇到类似措辞，一律按此原则处理。

## 2026-09-23 · M32 充能效果顺序 + 选牌弹窗三处收口（用户口径）

1. **「充能的效果执行异常（导致充能会无限判定），请你严格参考效果执行顺序」** ——
   用户给的期望节奏是「**充能打出之后，对方是先防御，然后再执行加速，
   再执行选择冷却手牌加速，然后结束**」。
   这条是**引擎真缺陷**：③ 阶段的效果（`CoolHandForHaste`）结算完被错写成回 `Phase.Stage1`，
   而 `FinishStage1()` 第一句就把 **①③ 两阶段共用**的 `_cursor` 归零、并且**直接落到「问防御」**，
   于是「防御 → 加速 → 选牌 → 防御 → …」无限重放。
   定为规矩：**效果结算完回到 `EffectClassifier` 给它归属的那个阶段**（① 类回 ①、③ 类回 ③），
   不按「顺手」统一写。断言：**一段进攻只结算一次防御**。
2. **选择键（确认键）位置错了** —— 「显然不应该在上方，应该把它移动到（面板自带的按钮座）的位置」。
   根因是 M31 把按钮从面板搬进满屏根时**把换算式的符号写反了**（`+220.5` 而非 `−220.5`），
   按钮被镜像到面板顶部压住标题。换算口径从此只准写在
   `UiLayout.HandPickConfirmCenterYFromCenter()` 一处。
3. **「移除掉这个确认键的背景，就用按钮座那个背景」** —— 确认键不再画自己的底图
   （M30 那条素材 `HandPick_Confirm.png` 纵向 174 → 58 被硬压成发白扁条），
   `sprite = null` 露出 `Peek_Frame.png` **自带的**底部按钮座；
   可用态 = 全透明，不可用态 = 半透明暗纱（保留「现在还不能按」的反馈）。
   素材与它的九宫格 border 常量**保留但当前无消费者**，仍进导入参数校验。
4. **「移除 handpick layer 里的 indexBadge，不需要序号」** —— 卡框左上角的序号角标整个删掉
   （节点 / 字段 / 属性 / 主题色 / 字号常量改名）。**序号仍按点选顺序回填给引擎** ——
   「显示不显示」与「回填什么」是两件事。

（实现与验收见 [M32 实现说明](../implementation/30-M32充能循环修复与选牌弹窗三处收口.md)。）

1. **「取消使用光环时，光环会从左侧立即消失，然后回到原位，你需要为其做一个动画」** ——
   定的口径：取消**不是**「标记删掉 + 图标复位」两个瞬变，而是**那一枚自己走回默认位**。
   具体三条：
   ① 位移 0.30 s（OutCubic），**缩放不变**（两端都是成品尺寸，与「飞入」的 0.55→1 区分开）；
   ② **落地那一刻** HudBuff 里那枚原图标才显出来（位置 / 尺寸 / 图案一致 → 接缝看不见），
   落地前它必须一直隐着（否则同一枚指示物会两份同时出现在屏幕上）；
   ③ 取消的是中间那一枚时，其余标记用 0.16 s **滑行**补齐空出来的那一格（不再瞬移）。
   实现见 [M34](../implementation/32-M34取消光环飞回动画与齿轮接线修复.md)。
2. **「点击右上角的齿轮及设置键之后，游戏没有重新启动，请检查是功能没有实现，还是被遮挡了」** ——
   查明是**功能没接上**：齿轮既没被遮挡（对中心的射线只命中它自己）、点击区与烘在条上的齿轮
   也对得上（差 ~1.5 px），`HudView._gearButton` 与 `GearClicked` 订阅都在 ——
   但 `gear.onClick` 上**运行时监听器为 0**。真因：构建器是在**编辑模式**里
   `onClick.AddListener(...)`，而 `UnityEvent` 的运行时监听器**不是序列化数据**，存 Prefab 时蒸发。
   定为规矩：**监听器一律在运行时按序列化字段自己接**，不许交给构建器接。
3. **知识库分层**：`Docs/` 的入口不再兼作变更日志（现状收敛到 `00-当前基线.md`）；
   实现记录加「现行 / 历史」标注与按模块的索引；**截图移出知识库**
   （`Docs/art-review/` → `Captures/art-review/`，285 MB）。

## 2026-09-23 · M36 瀑流互斥 / 不可选提示 / 怪物提示 / AI 演出（用户口径）

1. **「卡牌瀑流的加速逻辑当中，还有一条是同一张卡不能被加速第2次」** ——
   查明旧实现**只对了一半**：排除名单每处理一个效果就清一次，于是
   「每损失 1 点生命加速一个不同法术」那串内部确实互斥，
   但**第 1 条 α「加速」已经加速过的那张牌，在第 2 条 α 里又回到候选表**。
   定为口径：**整张瀑流内同一张牌只被加速一次**（两条 α 共用一份排除名单，
   名单的生存期 = 一次进攻）。⚠ 不推广到普通「加速 ×N」—— 湍流等牌的规则仍是
   「可分配给同一张或不同张」，判据是「这张牌的效果队列里有没有 `HastePerHpLoss`」。
2. **「加速减速时，冷却区当中无法被加速或减速的卡，应当暗一些」+「点了应当弹出一段
   无法被加速或减速的文字，在中间弹出，向上移动且迅速变透明消失」** ——
   两句话拆成两半落地：
   ① **引擎**把「这一拍做不到的事」从候选表里滤掉（减速：剩余已达基础冷却值；瀑流：已加速过的），
   这是铁律 3 的既有口径，不是新规则；
   ② **界面**把滤掉的那类牌画成**压暗但仍可点**（旧版把压暗和吃点击绑在一起，点了毫无反应），
   点了在画面中央弹一条浮字（0.95 s：淡入 → 停留 → 上移 48 px 淡出，不吃射线）。
3. **「怪物在执行效果（加速减速区加区减等）时，应当给予更多的提示」** ——
   冷却改动与光环激活以前在提示条上**一个字都没有**。现在逐条翻译成人话上顶部提示条，
   **怪物**执行时额外闪一次中央横幅（区域一批只闪一条，不然一次区域减速 4 条事件闪成一片）。
   「进攻开始 −1」「…进入冷却区」**不报**（结算副产品，报出来只会把真正的效果提示挤掉）；
   区域「无匹配目标」**要报**（正好解释「为什么什么都没发生」）。
4. **「加入AI的出牌动画（从其模型，向上移动，并逐渐出现的动画）」** ——
   只做**怪物**侧（玩家自己那张牌从手牌区拖上去，起点另有其物）：
   起点 = 怪物模型当前帧中心，位移 0.42 s + 缩放 0.72→1 + alpha 0→1。
5. **「AI使用光环时也应当有一个光环移动的过程来帮助玩家识别（移动到怪物的模型的右侧），

   ① 怪物消耗光环时，那一枚从敌方光环行飞到 `ArtLayer/AuraCastSeat`

   ② `BattleDriver._aiUseAuras` 改为 **true**（⚠ 它序列化在 Prefab 里，光改 C# 初值不生效）。

   规则基线只有「生命归零判负 / 上限归零即刻死亡」。**要根治需要补一条「回合上限 → 平局」规则**。

## 2026-09-27 · M42 战斗场景四处调整（用户口径）

1. **「充能这张卡有两个效果，但应当是第 2 个效果先执行，然后计算出总的加速次数，
   再玩家开始选择加速」** ——
   旧顺序是「先问一次加速（那 1 点基础加速）→ 再选冷却手牌 → 每冷却一张再问一次」，
   玩家在**还不知道总共能加速几次**的时候就得先把第一次加速分配掉。
   定为口径：**充能的两条 α 合成一条流程** ——
   「选冷却手牌（`CoolHandForHaste`）→ 总次数 = 1 + 冷却了几张 → 一次性把加速目标问完」。
   ⚠ 这是**引擎口径**不是界面口径：实现落在入队层
   （`BattleEngine.EnqueueEffects` 把同卡同触发的 `Haste` 吸收进 `CoolHandForHaste`），
   卡表一行没动 → **卡面文字顺序也不变**。
   ⚠ 记一条更一般的规则：**「决定能得到多少次」的效果，必须先于「把这些次数发出去」的效果**；
   模仿（`Copy`）复制来的效果表走同一条入队口径，否则复制一份充能会得到两批加速。
2. **「怪物的意图，当前的有效点击判定区域太小，应当覆盖整个怪物模型」** ——
   查下来**主因不是点击面尺寸，而是射线归属**：敌方冷却列的滚动视口（674×621，
   x 1226…1900 / y 344…965）盖住了怪物模型右半边，而它自己没有任何点击处理器，

## 2026-10-01 · 女巫的工坊 · 特殊强化场景（P6 · 用户口径）

用户把它描述为「本游戏当中还有另外一种强化卡牌的场景」，并给了五条：

1. **「玩家点击水晶球之后，弹出强化卡牌界面，如果玩家当前卡池中只有 8 张牌，
   则改为提示无法进行特殊强化」** —— 门槛常量 `WitchWorkshop.MinPoolSize = 9`。

   （用户确认：**左 = 献祭 · 右 = 强化目标**）。

   用户原话是「**否则无法确认**」，也就是允许选中、只是确认键按不下去。

   ⚠ 消耗**只在本局内存生效**（用户确认）：退出重进场景卡池会恢复成资产里那份；

4. **「第 2 张牌只能放置当前只有一个效果且没有任何强化的卡」** —— 两条判据：
   **`CardDef.Effects` 恰好 1 条**（用户确认「**光环也算一条**」）+ **`CardUpgrade.IsUpgraded` 为假**。
   与 `CardUpgrade` 一样**不写卡 ID**（效果条数与 `+` 后缀都是卡表里已有的事实）。
   ⚠ 刻意**没有**排除「力量为 X」的牌（模仿 `x`）：那条排除属于 P5 的「基础力量 +2」口径，
   本批还没有强化效果，不该提前替将来的效果定规矩。
   界面上不合格的格子**压暗并写出原因**（而不是从列表里去掉 —— 玩家要能看见
   「我有这张牌、它为什么不能当目标」，直接消失会被当成 bug）。
5. **「先不做强化的具体效果，之后再做」** —— 确认之后**不**生成新卡、

## 2026-10-02 · 冒险地图（P7 · 用户口径）

来源：用户直接口径，四条：

1. **「地图是随机生成的，除了起始节点和最终的节点。起始节点一定是 camp」** ——
   起点固定 `MapNodeType.Camp`、终点固定 `Boss`，中间层加权随机。
   ⚠ **「随机」管的是路线与分岔，不是「这次没有商店」**：整张图**保底**至少各有
   1 个商店 / 女巫工坊 / 石台 —— 这三张节点图是专门做的，某次一个都没抽到玩家就整局看不到它们。
   正式接入冒险经济时可以去掉（`MapGenerator.EnsureType` 两行）。
   ⚠ **「营地」是起点专用**，没有对应场景；冒险的休息机制还没做，所以**不凭空造第 8 种节点类型**。
2. **「中间虽然是随机生成，但摆的位置一定要能够用桥连接上」** —— 正面回答是三层保证：
   **生成器**（每条边两端**行号差 ∈ {0, +1}**，且同两层不允许交叉边，违反就整张重生成）、
   **版式**（`UiLayout.MapNodePosition` 是唯一一处坐标换算；2026-10-06 起是六向格 ——
   边长 240 × 行距 207.85 × 每行左移半格 −120）、
   **表现**（`MapView.PlaceBridge` 拿两端点的实际像素差反解桥的缩放与旋转）。
   ⚠ 第 1 层的行号**不能随机**：起点层只有 1 个节点，6 条路径独立随机时有 3% 概率全落在同一行
   → 那一层宽度 1 → 紧接着一列全是单行道（实测 1000 个种子里 38 个中招）。改成 **round-robin**。
3. **「当点击到某一个节点之后，玩家移动到这个节点上，如果有这个节点对应的场景的话，
   就进入到该场景内」** —— 分两拍：先播棋子移动（0.42 s），到位**停 0.24 s**（不留这一下玩家
   读不到「我走到了哪一格」），再查表切场景；**没有对应场景的节点当场结算这一步**。
   ⚠ 「能不能点」的唯一判据是 `MapRun.IsReachable`（必须是当前节点的**直接后继**且没走过，
   不跳层 / 不回头 / 不同层横跳）；界面上的高亮框与命中区都按它开关，**不在界面里再判一遍**。
4. **「在场景里点击离开键之后，也应当返回到地图」** —— 事件场景（商店 / 石台 / 女巫工坊）的
   「离开」调 `MapRoutes.LeaveToMap()`；战斗场景没有「离开」，改成**结算面板那个键在冒险里
   变成「回到地图」**（普通场景照旧是「再来一局」）。
   ⚠ **结算只在地图那一边发生**（`MapSceneEntry.Awake` 读到 `PendingIndex` 才结算）——
   「离开时结算一次 + 回地图又结算一次」会把同一个节点算两遍。

## M44 · 全局设置键与卡池查看（2026-10-05）

| # | 议题 | 决定 | 为什么 |

## 2026-10-08 · 双发选牌 / 强化门禁 / 卡池手写优先级（用户口径）

| # | 议题 | 决定 | 为什么 |
|---|---|---|---|
| M1 | 双发防御怎么选两张 | **累积标记**：点一下加一张、再点一下取消（点第二张**不清**第一张）；拖进判定区的牌**并进集合**；**不满两张什么都不提交、已选一个都不取消**；刚好两张才去引擎给的成对选项里找这一对 | 用户原话：「点击另外一张牌，并不会使得上一张牌的选中状态消失」「只选中一张牌……和现在一样会防御失败，然后弹回去，但并不取消这张牌的选择」。旧口径「第一张钉住 + 第二张配对」两个缺口：钉住的辉光不认点击（被单选逻辑换掉）、失败的尝试会把已选清掉 |
| M2 | 满两张后拖第三张 | **顶掉最早那张**（后点 / 后拖的优先） | 玩家刚拖进来的那张一定在集合里 —— 那正是他刚表达的那一张 |
| M3 | 取消怎么操作 | **再点一下已标记的那张**（提示条同步改写） | 「再拖一次已选的那张可以取消」这条旧手势与新口径「拖拽不动已选」直接冲突，只能搬到点击上 |
| M4 | 强化过的牌 | **任何一种强化后都不能再次强化**（力量 / 冷却 / 词条 / 转移四轴一起挡） | 用户原话：「进行任何一种强化后的牌，都不能再次进行强化」。后缀不叠加 ⇒ 卡面上看不出「强化过几次、朝哪个方向」，允许再来一次就等于「6 点的暴风雪+ 悄悄变成 9 点」 |
| M5 | 强化版的**祭品**资格 | **不动**（照样能献祭） | 祭品只是被拿走，它身上没有东西要「单独成立」（女巫那边限制连锁牌是另一回事） |
| M6 | 手写优先级放哪 | **卡池 SO**（`CardPoolConfig.useManualPriority` + `priorities`） | 用户原话：「此选项直接放在卡池的 SO 当中就行了」——「这只怪能打哪些牌」与「它先打哪张」是同一个策划问题 |
| M7 | 数值方向 | **越小越先打**（与代码里的 `Tier` 同方向） | 用户原话：「与代码中的档位同方向」 |
| M8 | 与自动计算的关系 | 开了手动 ⇒ **代码不再给任何卡赋值**：登记过的用表里的数；**未登记的一律并列最低**；四流派档位、回血卡的全局覆盖、怪物子类偏爱**全部让位** | 用户原话：「一旦启用了手动，代码当中就不能再对卡的优先级再赋值」。刻意**不做**「两套刻度混着比」的折衷 —— 混起来没人算得清 |
| M9 | 挂到 AI 的路径 | `CardPoolConfig → CharacterConfig.CreateDefinition → CharacterDefinition.CardPriorities → MonsterAgentFactory.Create → HeuristicAgent.ManualPriorities` | AI 在 Core、读不到 `ScriptableObject`；与既有的 `AiProfile` 走同一条路径（「这只怪怎么打牌」是角色的一部分） |
| M10 | 取档位的门开在哪 | 新方法 **`PriorityFor`**（`DecideAttack` 与 `PredictNextAttack` 共用），**不在** `PriorityOf` / `DefaultPriority` 里 | 那两个是子类可整体覆写的（`BerserkerAgent` 就先判自己的「最爱卡」）—— 门开在里面，手写顺序会被子类偏爱盖掉。顺带保证「预判与实战同源」 |
| M11 | 手写优先级的作用范围 | 只管**出牌选择** | 防御口径、流派判定、光环用法、`IsCardAllowed` 禁卡都不动（用户：「进攻逻辑也按代码中来处理」） |
