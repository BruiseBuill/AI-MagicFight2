# 战斗信息布局

> 状态：现行 · 日期：2026-10-30 · 范围：战斗界面信息分配、动作入口与新增美术需求。

## 信息逐项判断

战斗中的信息按“谁的状态”“当前需要处理什么”“发生了什么”分开。顶部只回答当前回合与行动方，不再承载事件流水账。

| 信息 | 位置与形式 | 显示时机 / 原因 |
|---|---|---|
| 回合数、进攻方、防御方、连击阶段 | 顶部中央 300×44 小标识 | 持续显示当前阶段，事件不能覆盖；连击明确标识 |
| 玩家/对手生命与生命上限 | 对应角色头顶生命格 | 保留现有亮/暗/上限削减状态，取消远处重复数字 |
| 虚弱层数 | 对应角色旁状态标记 | 保留现有状态显示；新施加时局部反馈 |
| 光环来源、类型、剩余指示物 | 角色头顶旁逐枚图标；长按原有详情 | 图标就是资源，不另列总数；已准备光环仍在手牌侧准备区 |
| 光环消耗、激活 | 所属角色附近短提示 | 两秒淡出，不抢回合标题 |
| 玩家手牌数量 | 实际手牌扇形 | 不重复显示；本局手牌上限已有明确可见空间 |
| 对手手牌数量 | 对手右下方现有“手牌 ×N” | 保留按住查看入口，遵循已知/未知情报 |
| 角色身份、头像 | 实际角色模型 | 当前固定对战不另占一条头像横栏 |
| 打出的牌与卡名 | 原有头顶出牌卡面 + 出牌方附近短提示 | 完整信息在卡面，避免再塞入顶栏 |
| 最终进攻力量、双发 | 两名角色间战况区，突出力量数值 | 力量结算后保留到下一次进攻；不会被冷却或光环提示替换 |
| 防御阈值、光环补值 | 战况区第二行 | 只读决策快照；双发显示需要两张及补值预算 |
| 双发已选数量 | 手牌上方短条“已选 N / 2” | 随实际选择更新，避免长篇操作说明 |
| 无效双发组合 | 同一手牌提示位置短暂警告 | 随后恢复已选数量，不改选中的牌 |
| 结束进攻 | 屏幕右侧，底边 176、距右边 24，156×72 | 引擎提供 Skip 时出现；尚未出牌、连击追加均走同一入口 |
| 放弃防御 | 同一右侧动作按钮 | 标明“生命 -1”；结束进攻按引擎给出的代价显示，追加连击不扣血 |
| 跳过效果 / 完成选择 | 同一右侧动作按钮 | 只提交引擎提供的 Skip/Done；从中央列表移除同一选项 |
| 换牌数量与确认 | 换牌面板内 | 现有面板已经有计数，不再在顶部重复“至多 3 张”；补牌上限以请求为准 |
| 手牌送入冷却、查看手牌 | 原有专用选牌/查看弹窗 | 保留弹窗自己的标题、确认入口，右侧不再重复确认；随机查看不泄露牌名 |
| 加速、减速、重置、立即冷却完成的选取目标 | 手牌上方短提示 + 原有目标高亮 | 提示只说明当前待选对象，不写长教程 |
| 区域效果冷却档选择 | 两侧冷却槽高亮；选择摘要在手牌上方 | 直接选择实体区域，不把每档改成顶部文字按钮 |
| 双方区域 / 多效果 / 结算顺序 | 原有选项面板标题与选项 | 没有单一实体目标时才使用列表；标题与选项放在一起 |
| 冷却值变化、回手 | 对应侧冷却区上方短提示 + 原有卡牌移动 | 常规回合递减不刷屏；效果导致的变化保留；明细进入日志 |
| 防御成功、免疫、放弃、无法防御 | 战况区结果行 | 与本次进攻保持关联，下一攻击清除 |
| 受伤、治疗、生命上限变化、自爆 | 对应角色附近短提示 + 原有角色动作 | 明确受影响对象，保留现有不做全屏红闪的约定 |
| 查看手牌 | 对应角色局部短提示 / 专用弹窗 | 不把隐藏卡牌内容泄露到公共提示 |
| 回手等完整过程 | 原有卡面/状态更新与战斗日志 | 不为每条内部事件增加常驻面板；当前卡表未使用的成长、刻印、移除算子不列作现行玩法 |
| 胜负、结束原因、重试与退出 | 原有结算界面 | 清空战况、选择及临时反馈，防止旧状态残留 |
| 设置 | 右上角齿轮 | 保留全局入口 |
| 完整事件明细 | 原有战斗日志 | 用于追溯，主界面只保留即时决策所需的信息 |

## 层级与行为

规则与实现尚未一致的内容见 [规则差异清单](../rules/03-规则与实现差异.md)；本表规定信息归属，不表示所有规则已经在界面生效。

以 1920×1080 为参考画布，沿用 CanvasScaler。战况区中心 x=855，力量行 y=635，防御行 y=576；位于两名角色之间，不能遮住角色、生命、手牌和拖牌箭头。信息节点不拦截鼠标射线。

顶部阶段不闪烁替换。手牌选择条中心靠近手牌上方，操作错误最多停留 1.2 秒；角色与冷却反馈两秒淡出。决策提交立即撤销旧按钮，进入下一选择重新绑定合法选项。重新开局、终局清空所有临时信息。

节点由 `BattleUiBuilder` 预建并序列化。菜单“魔法乱斗/重建战斗信息布局”只重建本功能节点，避免影响场景中的角色、美术、设置和其他接线；完整 M8 构建也包含这套布局。
