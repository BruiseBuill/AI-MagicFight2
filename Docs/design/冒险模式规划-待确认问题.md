| Q7 | 退出恢复 | 战中退出 → 从同一场战斗开始恢复（同敌人 / 同卡池 / 同种子），允许重新操作 |
| Q8a | 平台与输入 | **PC + 鼠标**；移动端不进首版验收 |
| Q9 | 正常战败与跨局成长 | 战败结束本次冒险；卡池 / 强化 / 资源清零；首版无跨局成长 |
| Q9b | 单章时长与节奏 | **短局 8 层**（含 Boss），15–25 分钟 |
| Q10a | 战斗削减的生命上限 | 战后恢复到**局外正常上限**，但不额外治疗当前生命 |
| Q10b | 僵局规则 | **回合上限 = 40 回合**；到上限未分胜负 → **判玩家失败** |
| Q11 | 强化次数与方向 | 每张牌最多一次；从适用方向中选一个 |
| Q12 | 冒险内「重开本场」 | **保留**；⚠ **不记录尝试次数**（两轮口径有修正，见 R1） |
| Q13 | 带伤入场的本场上限 | **本场上限 = 局外正常上限**（即 2/6 入场模型） |
| Q14 | 牌池变大后的抽取 | **不需要考虑稀释**：每张卡强度近乎等价，卡池变大只增加组合可能 |
| Q15 | 通关 / 放弃后的存档 | 保留**只读战绩**，主菜单 `继续` 不再显示该槽位 |
| Q16 | 回合上限的精确口径 | 1 回合 = **双方各进攻一次**；连击的追加进攻不额外计回合；字段可配但**必须存在** |
| Q17 | 双方同时出局 | **不可能发生**（但代码里有该分支，实现侧保留为防御分支，见第 5 节） |
| Q18 | 事件战斗中的「放弃」 | **没有**该选项；只有胜 / 败，败 = 直接结束整局 |
| Q19 | 首版事件种类 | **只有商店类 / 强化卡牌 / 回血**；**「离开」也算完成节点** |
| Q20 | 事件抽取方式 | **随机抽取**（权重 + 条件过滤后归一化），一次选择为主 |
| Q21 | 提高冒险生命上限 | 当前生命**同步增加同样的量** |
| Q22 | 敌人配置与 AI | 敌人卡池 / 生命需要精细配置，**首版先简单配**；AI **用最简单的策略** |
| Q23 | 精英专属奖励池 | **暂不做** |
| Q24 | 冒险形态 | **Slay-the-Spire 式**：地图上活动，节点里进事件 / 战斗 |

## 5. 本轮实际读代码的结论（已写进实施规格）

> 完整清单见 [实施规格](冒险模式实施规格.md) §3 / §4 / §7 / §10，这里只列影响决策的几条。

| 结论 | 依据 | 影响 |
|---|---|---|
| `CardPool(IEnumerable<string>, ICardCatalog = null)` **已存在**，`Add` 会向 catalog 校验，`Resolve()` **按 catalog 顺序**返回 | `Core/Characters/CharacterDefinition.cs:18/34/52` | 玩家专属目录方案可直接落地；但目录 ID 集合必须与 `OwnedCards` 完全一致，否则改牌序 |
| `CharacterDefinition` 断言 `initialHp > 0` 且 **`maxHp >= initialHp`** | 同上 `:80` | 2/6 入场合法；但「本场上限 < 当前生命」会被构造器抛异常，**适配器要先夹取** |
| `PlayerState.InitialHp/Hp/MaxHp` 全部来自角色定义 | `Core/Battle/PlayerState.cs:34` | **不需要改引擎**就能决定入场血量；`BattleState.InitialHp = 4` 只是默认角色取值 |
| `BattleState` 常量 `HandLimit=8 / InitialHandSize=6 / ReplaceLimitInitial=3 / DrawTurnsMax=3` | `Core/Battle/BattleState.cs:15-19` | 起步 8 张池**刚好每场抽干**；池 >8 才会出现「抽不到」（Q14 已确认不在意） |
| `DuelMode.TryFinish` 双方同时出局时 `WinnerSeats` 为**空列表** | `Core/Battle/BattleSetup.cs:67` | Q17 说不可能，但代码里有该分支 → 保留为防御分支，**不要删成 NRE** |
| `CardLibrary` 共 **40 张**；基础冷却只有 **2–4**，没有 0 / 1 | `Core/Cards/CardLibrary.cs` | 起始牌池 8 张全部存在；「基础冷却已是 1 不显示周转型」这条**永不触发**（代码仍要留着） |
| 上位文档 §17.3 的三个强化示例与卡表**逐条一致**（凝固 3/2 减速×2、冰风暴 5/4 光环防御+2、淬火 7/3 光环进攻+2） | 同上 `:40 / :36 / :149` | 内容侧可按这三条做样板 |
| `CardDef` / `EffectDef` 都在 Core，`CardDef` 不可变 | `Core/Cards/CardDef.cs:56` | 强化 Resolver 在 Core 内构造新 `CardDef` 可行，不需动 Unity 资产 |
| ⚠ `Ui/SettingsView.cs:76` 与 `Ui/BattleUi.cs:2835` 都调**无参** `StartBattle()`，无参版按 `_randomSeed` 决定是否换种子 | `Unity/BattleDriver.cs:217-220` | 冒险里必须**固定种子**，否则「同敌人 + 同种子」当场失效 |
| 自动开局是 `_autoStart` + 等一帧的 `CoAutoStart` | 同上 `:197-211` | 冒险场景关掉 `_autoStart` 即可 |
| `CutMaxHp` 已实现 `Hp = min(Hp, MaxHp)`；`IsDead => Hp <= 0 || MaxHp <= 0` | `BattleEngine.cs:1372-1392`、`Snapshot.cs:199` | 战后恢复上限必须在**冒险层**做，战斗内不会自己恢复 |
| `Rng` 无公开的中途状态导出 | 上位文档 §2 已记录 | 存档保存"已生成结果"而不是"随机状态" |
