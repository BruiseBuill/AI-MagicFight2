# 当前手牌与光环交互

> **性质**：现行总述 —— 「现在手牌 / 光环怎么响应」先读这一篇
> **最后核对**：2026-09-30（出牌那一刻「用不上的光环」按取消处理已并入）

生效日期：2026-09-20（光环默认位 / 准备位 / 取消手势，见 [20](../implementation/20-M21光环摆位与取消手势.md)）。手牌部分与 2026-09-18 相同。

## 手牌

`BattleUi.OnHandCardClicked` 在进攻和防御决策中不提交选项。`CardInteractor → HandView → OnHandCardDropped` 只有在中央出牌判定区松手、方向与当前决策匹配时才提交合法选项。
发牌替换仍点击标记；把手牌送入冷却等效果目标仍可点击。无效落点退回手牌，不改变对局。

## HudBuff

`BattleCanvas/ArtLayer/HudBuff` 下的 `PlayerGroup` 为玩家，`EnemyGroup` 为敌人。数据来自双方冷却区的 `CardSnapshot.AuraTokensDetail`，每枚剩余指示物对应一个图标，同类型不合并数量。来源回手、移除或指示物消耗后，图标同步回收。

**默认位（2026-09-20）**：图标排在**角色头顶血量徽标旁边** —— 主角侧从徽标右缘往右、怪物侧从徽标左缘往左，一行横排、与徽标同高（中心线 y = 265）。
玩家块左缘 565.5、怪物块右缘 1144.5，都由 `CharBadge*` 常量推导（`UiLayout.HudBuffPlayerX` / `HudBuffEnemyX`）。
一排 8 枚 × 步进 80：双方各准备 4 枚以上时两排会在画面正中叠在一起（实际对局通常 1~3 枚）。

可用性以当前 `DecisionRequest.Options` 为准，按座位、来源牌 UID、剩余指示物索引匹配。当前卡表中双光环两枚效果相同；未来若增加一张卡带不同种光环，必须升级逐枚持久身份，不能直接复用当前数量模型。

长按显示来源、效果与可用提示，松手或移开收起。`AuraTooltipView.cs` 是独立可序列化组件，场景和 BattleCanvas 预制体均需有效接线。敌方和不可用图标允许查看，不能拖动。

**使用（2026-09-20）**：可用己方图标拖入**自己的 HandArea**（屏幕底部通栏 344 px，与出牌的中央判定区**不是同一个区**）并松手才消耗一个合法选项。拖动经过手牌区时点亮 `HandArea/AuraDropHint` 提示底 —— 它是**通栏纯方块**（不赋 Sprite），alpha 0.06；颜色只写在预制体的 `Image.color` 上，代码一个字节都不写。松手后原图标从 HudBuff 消失，标记带飞入动画落到**手牌区左侧**的槽位排好。拖动期间置于 Canvas 上层，HUD 刷新不会把它拉回原位。

**取消（2026-09-20，动画于 2026-09-23 补上）**：把这枚标记**再拖一下**即视为取消（不看落点、拖拽开始就生效）。旧口径是「标记收起、指示物回到默认位」——两步都是**瞬间**的（标记当场消失、图标当场出现在原位），用户 2026-09-23 要求补动画，现在改成：**那一枚标记自己从手牌区左侧滑回默认位**（0.30 s，缩放不变），**落地那一刻** HudBuff 里那枚原图标才显出来（位置 / 尺寸 / 图案完全一致，接缝看不见）；若取消的是中间那一枚，其余标记用 0.16 s 滑行补齐前面空出来的那一格。实现见 [32-M34](../implementation/32-M34取消光环飞回动画与齿轮接线修复.md)。「拖出判定区才取消」的旧手势仍已废弃，判定区与光环彻底解耦。

**出牌那一刻的退回（2026-09-30）**：出牌时一并提交的那几枚光环，若引擎判定「这一次用不上」，则**既不生效也不消耗**，界面上按**同一条「取消使用」动画**处理 —— 标记从准备位滑回默认位，落地那一刻 HudBuff 里那枚原图标才显出来。三种情形：① 打出的牌**卡面自带连击**（连击不可叠加）；② 连击光环的**阈值**不满足（该牌基础力量 > A）；③ **沉重打击**（该牌进攻力量不能增加 → 本次准备的光环整批无效）。判据只在 `AuraResolver.CollectRefunded` **一处**（引擎与界面调的是同一个函数），实现见 [2026-09-30](../implementation/2026-09-30-飞行卡改用组成式卡面与连击光环退回.md)。⚠ 「放弃防御」那条路同样不消耗，但**不播**归位动画（标记直接收起、图标随即在原位出现）。

那排「已准备光环」标记的槽位（`PreparedAura/Slot0…Slot7`）与 HudBuff 的图标槽位**都由构建器按 `UiLayout` 常量生成** —— 手摆在 Prefab 里的版本会被 `Cleanup` / ArtLayer 推倒重建冲掉（M20 丢过一次）。要挪位改常量后重跑 M8 / M11。

## 防御与免疫

进入防御前，引擎列出所有符合当前条件的光环。力量加值逐枚主动消耗，记入本次 `ContextDefenseBonus`；结束光环选择后进入防御出牌。未主动消耗的光环不参与防御预算。双发沿用原规则：两张防御牌所缺力量之和不得超过本次已投入预算。

免疫按最终攻击力量过滤，多个满足条件的来源都可选。消耗后立刻发送 `DefenseResolvedEvent`（成功、`UsedImmune=true`、出牌列表为空），跳过防御选牌，覆盖整个双发及未挡住攻击导致的额外伤害。空手仍可免疫。跳过则进入普通防御，指示物保留。

旧的防御光环自动分配代码已移除。UI 与 AI 都通过相同合法选项提交，不在表现层另写规则。

## 点击怪物（2026-09-26）

点一下怪物模型，在它头顶弹出一个**「思考框」**：里面**只有一枚元素符号**，
代表这只怪物**下一次进攻会打出哪张牌**的元素 —— **不显示是哪一张牌**（用户口径）。
约 **2 秒**后渐隐并轻微上浮消失（弹出 0.16 s → 停留 → 渐隐）。

- 可点区域是 `BattleCanvas/ArtLayer/Char_Monster_Click`（320×340 的**全透明**面，
  挂在怪物身上、避开血条徽标与「手牌 ×N」标签）。用 `IPointerClickHandler` 而不是 `Button`
  —— 要的是一块完全不可见的点击面，不要 Selectable 的悬停 / 按下换色。
- **预判口径 = 最简 AI 的实际选牌逻辑**（有牌就打、选当前**有效力量**最高的一张）；
  手牌为空 → 不打任何符号。⚠ 这是**预判不是保证**，AI 策略变了要同步改
  （`Core/Ai/AttackForecast.cs`）。
- 以下时机**不弹**：发牌台还开着（对局没真正开始）、结算浮层已铺、怪物手牌为空、该元素缺图。
  开局 / 终局会强制收起。连点怪物 = 同一个泡重新弹一次，不叠泡。
- 元素符号图在 `Assets/Resources/Elements/`，七系见 [卡牌图鉴](../rules/02-卡牌图鉴.md)。

实现见[点击怪物思考框与七元素图标](../implementation/2026-09-26-点击怪物思考框与七元素图标.md)。
