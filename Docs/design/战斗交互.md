> 状态：现行 · 核对日期：2026-10-31 · 范围：代码中的输入方式；滑动选牌改动已在 Play 模式下按真实手牌验收；区域 + 单体并列拍按代码与自测核对（待 Play 验收）。

玩法见 [规则基线](../rules/01-规则基线.md)，布局见 [战斗信息布局](战斗信息布局.md)。交互只回填引擎提供的合法选项。

## 手牌与目标

| 操作 | 行为 |
|---|---|
| 进攻 / 单牌防御 | 拖动手牌，在中央合法出牌区松手提交；单击不出牌 |
| 双发防御 | 点击或横向滑动选最多两张，再拖入出牌区提交一组合格防御牌；拖动其中一张时两张一起被拖动 |
| 无效拖放 | 手牌返回（恢复扇形倾斜）；双发未凑成合法组合时保留选择，不提交 |
| 换牌 / 手牌效果目标 | 点击或横向滑动刷选，在对应面板确认；数量限制由决策提供 |
| 滑动选牌（画刷） | 一次横向滑动 = 一支画笔，见下节 |
| 冷却区目标 | 点击高亮卡牌 = 对**这一张**加速 / 减速；点击高亮的冷却槽（槽位徽标）= **区域**加速 / 减速的某一档 |
| 区域 + 单体并列（暴风雪 a） | 同一拍里两套目标同时可点：点槽位先结算区域、点卡片先结算单体；另一条随后再问，不丢效果 |
| 跳过 / 完成 | 右侧动作区提交当前决策的 Skip / Done；专用弹窗使用自己的确认入口 |

主动结束进攻的生命代价由引擎给出，追加连击为 0。双人选牌时可提出平局，界面显示观察进度。默认有利效果直接触发，仅目标选择或有代价的效果保留操作。

### 滑动选牌 = 画刷

整次滑动是一支画笔，笔尖扫过的牌统一变成**同一个状态**；不是「逐张点击」的批量版。

- 笔刷状态在按下那一刻由**起点牌**决定：起点还没选 → 整次都加选；起点已经选了 → 整次都取消。一次手势只有一种状态，来回划不会反复反选。
- 指针对一帧只上报一次，所以按**线段**补点：两帧之间跨过的牌也算划过。
- 上限由本次决策给出，选满后继续划过的牌**不再增加**，并且**不**顶掉已选的：

| 决策 | 最多同时选中 |
|---|---|
| 进攻 / 单牌防御 | 1 |
| 双发防御 | 2 |
| 开局换牌 | 3（引擎 `MaxSelect`） |
| 第 2 / 3 回合补牌替换 | 1 |
| 磁暴 / 充能 / 电弧选牌 | 引擎 `MaxSelect`（电弧 1） |

### 手牌三态

| 状态 | 表现 |
|---|---|
| 未选中 | 扇形排布，带倾斜 |
| 已选中 | 辉光 + 上浮，仍在扇形里（保留倾斜） |
| 正在拖动 | 摆正（0°）+ 放大 + 跟手；双发时同组两张并排一起搬，放弃拖动后回到扇形、恢复倾斜 |

**不变量**：手牌里没有第四种状态 —— 只要不是正在拖，每张牌都必须回到扇形倾角。
没拖进判定区、拖进去又放弃、决策中途被收回，三者都走同一条收口（`HandView.ResetDragPose`）；
手势在窗口外抬起等导致 `DragEnd` 丢失的情况，由 `HandView.LateUpdate` 在抬起那一帧兜底收掉。

## 光环

- 双方冷却区的可用指示物逐枚显示，同类型不合并；长按查看来源和效果。对手或当前不可用的光环只可查看。
- 将己方可用图标拖入手牌区，准备对应光环；拖入手牌区不应一概描述为“已经消耗”。实际生效及消耗由引擎结算。
- 再次拖动已准备标记可取消。出牌时提交已准备光环；无效光环按 `AuraResolver.CollectRefunded` 的结果退回。
- 防御光环须主动选择，未选择的加值不计入预算；免疫符合条件时可直接完成防御，不提交防御牌。
- 来源回手、指示物消耗或失效后同步更新图标。动画时长、坐标不在本文重复维护。

## 信息可见性

对手手牌按已知 / 未知信息显示。查看效果中的未知牌使用牌背，不通过选项、提示或日志泄露名称。
点击对手角色可显示当前局面的 AI 出牌元素预判；由 `BattleDriver.ForecastAttackElement` 提供，不承诺后续一定出该牌。

同机双人热座会随当前决策切换本机座位和手牌视角，不代表已具备网络对战或隐藏信息隔离。

## 维护

`BattleUi` 负责决策绑定，`HandView`、`HudBuffView`、`PreparedAuraView` 等负责输入与展示。新决策、重开和终局时清理旧选择、准备态与提示；节点接线同时检查场景及 Prefab。
